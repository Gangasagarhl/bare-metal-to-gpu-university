  2. F19b (3). H1: the checker is wrong. H2: the description has a wrong arrow (or another fault). Deciding fact: the last3 column is a plain shift register of the sampled bits and shows 010 at cycles 4, 9, 14 and 22, so by the specification ("found = 1 in the cycle after the last three sampled bits were 0, 1, 0") found must be 1 there; the same checker passes the correct design (seq010.out). Marking: two hypotheses 1, deciding evidence 1, specification 1.
  3. F19c (5). The faulty line: default: next = S0; // S010: pattern reported, start again. Mira's S010 forgets this and goes to S0 on both inputs, so it loses the overlap (cycles 4, 9, 14) and even a new 0 that arrives right after a detection: on 0, 1, 0, 0, 1, 0 the correct machine ends in S010 (found) and Mira's in SA (exam_checks.out, F19c; the cycle-22 case).   4. F19d (4). (i) Wrong twice: the specification says overlaps count, and cycle 22 is missed although its pattern shares no bit with the detection at 19, so the machine is wrong even under Mira's own reading. (ii) Both reports show 4 $_DFF_P_ (and 15 versus 14 cells). The description declares a 2-bit state register (4 states in binary need 2 flip-flops), so 4 flip-flops for 4 states means the tool re-encoded the states one flip-flop per state, the one-hot encoding of F1-19 (the run.sh step seq010_fsm, which records the tool's own encoding messages, was added on 2026-10-25 and is pending a run: Yosys was not installed in that session; the one-hot reading follows from the counts alone). Design on paper (25 points): what to look for

  • Interface: inputs sampled at the rising edge; Moore lamps, visible in the cycle that follows the edge (start sampled at edge 3 → wash cycles 3–8, rinse 9–12, dry 13–15, done from 16: exam_checks.out, P, and dishwasher.out).
  • States (reference): IDLE, WASH, RINSE, DRY, DONE, PAUSE; 6 states → 3 bits binary. Timer: counts the cycles already spent in the phase, 0..5 → 3 bits. Resume register: which state to return to after a pause, 3 bits. Total 9 flip-flops (exam_checks.out, P; matches the synthesis report). Also full marks: one pause state per phase (PAUSE_W, PAUSE_R, PAUSE_D; 8 states, still 3 state bits, no resume register) — the candidate's flip-flop count must then match their own synthesis report.
  • Arrows that are often missing: IDLE with start = 1 and door_open = 1 stays IDLE; DONE ignores start and leaves only on door_open = 1; door_open = 1 has priority over the phase timer in WASH, RINSE and DRY; PAUSE with door_open = 1 stays.
  • The last-cycle case: in the reference run the door is sampled open at edge 35, right after the sixth wash cycle (cycle 34). The machine must resume in RINSE (cycles 36–39), not in WASH: the reference stores resume <= after when the phase has just finished. The pause in DRY (sampled at 42, after dry cycles 40 and 41) resumes DRY for exactly one more cycle (43).

Verilog (25 points)

Reference structure (dishwasher.v): next-state always @(*) with next = state; first and default: next = IDLE; for codes 6 and 7; one clocked block for state, timer and resume with synchronous reset (state IDLE, timer 0, resume WASH); timer and resume held in PAUSE, cleared in IDLE and DONE, timer cleared when a phase finishes; output block with the four lamps decoded from the state alone. Typical faults and the testbench line they produce (from the testbench source): timer cleared on entering PAUSE → "wrong number of wash cycles" (or rinse, dry) at the DONE cycle; resuming WASH after the pause at edge 35 → "wrong number of wash cycles"; a lamp left on in PAUSE → "phase lamp while the door is open"; start accepted with the door open → "phase lamp while the door is open" and "lamp on while idle" at cycle 24; DONE left on start → "done lamp not held". Any -Wall warning costs the 5 build points.

Course project — reference notes

Reference solution. pc_branch.v (program counter: reset, load, branch with a two's-complement offset, inc, hold, in that priority; WIDTH = 8) and ram256x8.v (256 × 8, synchronous write with write enable, asynchronous read), with the marker's acceptance test project_tb.v. Run (project.out): "256 words written and read back: 0 wrong"; the edge with we = 0 leaves mem[7] = 5d (= 7 XOR 0x5A); 16 consecutive fetches from 100 leave pc at 116; branches: load 5, +10 → 15, −3 (offset 0xFD) → 12, −13 wraps to 255, +6 wraps to 5; priorities: branch over inc → 7, load over branch → 200, reset over everything → 0, then inc → 1 and hold → 1; RESULT: PASS (memory unit and program counter: all checks). Lint: no warnings for either file (project_lint.out).

Synthesis readings. pc_branch: 67 cells, of which 8 $_SDFFE_PP0P_ (the 8 bits of pc; synchronous reset to 0; enable = "some control is active", hold otherwise) and the rest logic for the adder, the incrementer and the selection (project_synth.out). ram256x8 kept as a memory: one $mem_v2 cell (4 cells in all) (project_ram_mem.out); mapped to 4-input LUTs and flip-flops instead: 2048 $_DFFE_PP_ (256 words × 8 bits, each with the write enable of its word) and 2040 $lut, 4088 cells (project_ram_lut.out). What a candidate should conclude: on an FPGA the memory should go into block RAM (F1-22), because built from flip-flops and LUTs it costs thousands of cells; whether a given device's block RAM can implement this asynchronous read is a device question that F1-22 leaves in an "unverified" box, which is one reason for the registered-read extension.

Marking notes. Run the candidate's two files unchanged with project_tb.v; a FAIL loses the acceptance part of "Correctness and tests" but the candidate's own tests can still earn the rest. Common faults: offset treated as unsigned with no wrap test; branch below inc in the priority; write without the we check (the we = 0 check prints the wrong value); a registered read without an adjusted testbench. The HW202 hand-over note should say that the RAM's word width (8 bits) is the one change needed for a 16-bit CPU, while the counter only needs WIDTH.
