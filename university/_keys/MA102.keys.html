Final question F27 — forensic answer (12 points)

Evidence: the paper shows university/labs/MA102-P/freezer_bug.out exactly as the Lab Engineer's run printed it.

  1. Observation (2). "byte 0xFD -> freezer: 253 C", "0xF6 -> 246 C", "0xEC -> 236 C" and "0xE2 -> 226 C" are impossible: a freezer's range is −40 to 40. The bytes: 0x04 = 00000100, 0x00 = 00000000, 0xFD = 11111101, 0xF6 = 11110110, 0xEC = 11101100, 0xE2 = 11100010. The two readings that look fine (4 and 0) have a leftmost bit of 0; every impossible one has a leftmost bit of 1.
  2. Hypotheses (3; at least two needed, 1.5 each). A: the freezer sends wrong bytes (a broken sensor). B: the bytes are right but the program reads them as unsigned, although the freezer's description says they are signed two's complement bytes. C: the bytes were meant to be signed but the program printed the byte in the wrong base (hex read as decimal).
  3. Evidence-based conclusion (4). Every impossible value is at least 128, so its sign bit is 1; printed value − 256 gives 253 − 256 = −3, 246 − 256 = −10, 236 − 256 = −20 and 226 − 256 = −30, all sensible freezer temperatures within −40 to 40, while the two readings below 128 are unchanged. An error of exactly 256 on exactly the sign-bit-set bytes is the signature of an unsigned reading of a signed byte (F0-24), which proves B. A is ruled out: the bytes decode to sensible temperatures, so the sensor sent correct data. C is ruled out: 0xFD is 253 in decimal, so the base is right. Root cause: the program stores the byte in an unsigned variable (const unsigned temperature = byte;) instead of reading it as std::int8_t.
  4. Fix and verification (2). Read the byte as a signed byte: const int temperature = static_cast<std::int8_t>(byte);. The fixed program must print 4, 0, −3, −10, −20, −30. It did:
byte 0x04 -> freezer: 4 C
byte 0x00 -> freezer: 0 C
byte 0xFD -> freezer: -3 C
byte 0xF6 -> freezer: -10 C
byte 0xEC -> freezer: -20 C
byte 0xE2 -> freezer: -30 C

  1. Prevention (1). Test with a byte whose sign bit is set, for example 0xFF (which must print −1) or the boundary −40 (0xD8); and write the type to match the description ("signed byte" → std::int8_t) with a range check that reports any reading outside −40 to 40.
