DESIGN NOTE - driver "edu4" for PCI device 1234:11e8 (DR401, F4-17)
Status: approved for the QEMU stage only. Documentation tier: see F4-15 (the forensic answer);
this design uses only the observed specification of F4-16 because no document was opened.
One row per aspect of curriculum section 5.4. "Where found" names the evidence.

## Bus binding
PCI, matched by vendor 0x1234 and device 0x11e8 (no class code applies: class 00 ff 00).
One instance per function found; no parent other than the PCI host bridge.
Where found: F4-14 devreport.out; F4-15 boottrace.out ("NO DRIVER" before this driver).

## Resources
BAR0: 32-bit memory BAR, 1 MiB, placed by the firmware (0xfea00000 in the F4-14 run).
No I/O BAR. No interrupt used (polled driver). No DMA. No clocks, resets or regulators (PC).
Where found: F4-14 devreport.out (size probe) and qmp_compare.out (QEMU agrees on the size).

## Initialization sequence
1. Size and read BAR0 (decoding off during the size probe). 2. Command register: memory
decoding on, bus mastering off. 3. Read ID; all ones = device gone; any value other than
0x010000ed = unknown revision, refuse to bind. 4. CHECK: write a pattern, expect its inverse.
5. Interrupt-status path: raise 0x1, expect IRQ_STATUS = 0x1, acknowledge, expect 0.
No reset method is known (none observed); no firmware to load.
Where found: F4-16 spec_observed.txt, "Sequence the working driver uses".

## Register model
32-bit accesses only (the only width observed). Little-endian x86 host: no conversion
needed. No read-to-clear behaviour observed: reads of STATUS and IRQ_STATUS did not change
them. Writes are posted: the driver always reads a register back before relying on an
effect (CHECK, IRQ_STATUS). Offsets 0x80-0x98 are never touched (purpose unknown).
Where found: F4-16 annotate.out, parts 2 and 3.

## Interrupts
Not used in this version: the device is polled through STATUS bit 0. The IRQ_RAISE /
IRQ_STATUS / IRQ_ACK registers are exercised only as a self-test. Whether the device signals
INTx or MSI was not observed: next step before an interrupt-driven version.
Where found: F4-16 spec_observed.txt, open questions.

## DMA and cache coherency
None. Bus mastering is switched off so that the device cannot write to memory even if an
unknown register (0x80-0x98) started a transfer.
Where found: design decision; F4-16 spec_observed.txt (0x80-0x98 unknown).

## Power states
D0 only. No PCI power-management capability was examined. Nothing to save across suspend in
this version (no state is kept in the device between computations).
Where found: design decision; capability list not yet walked (F4-17 open item).

## Error handling
Every wait has a timeout: 50,000,000 time-stamp counter ticks per computation (chosen for
the emulator; to be re-measured on real hardware). A read of 0xffffffff from STATUS means the
device is gone (on real PCIe, reads after surprise removal return all ones): report and stop.
After every computation the driver re-reads ID and stops if it no longer reads 0x010000ed:
in QEMU a BAR whose decoding was switched off reads 0, which looks like "not busy" (version 1
of this driver returned zeros as results: F4-17 forensic lab).
Where found: curriculum 5.4 "Error handling" row; F4-17 removal.out and forensic.out.

## Hot-plug and lifetime
The device is not hot-pluggable on the q35 machine as configured. The driver still treats an
all-ones read as removal and never loops without a bound.
Where found: design decision.

## Upper interface
compute(n) -> n! modulo 2^32, a function call inside the kernel; a character device in a
later version.
Where found: F4-17 run (driver.out): results equal n! modulo 2^32 for n = 0..14.

## Trust
Values read from the device are not used as indices or lengths. The only value the driver
interprets is STATUS bit 0, and the loop around it is bounded.
Where found: design decision (curriculum 5.4 "Trust" row).

## Observability
Counters: computations, polls, timeouts, removals; a dump() of ID, STATUS, IRQ_STATUS.
Where found: edu4.cc dump().
