PLAN - receive buffer of the serial console driver (SE301, F12-01)
Written before the code; approved by: (learner) and (one peer).

Data structure
  D1  A ring of 8 bytes (a power of two) between the receive interrupt (producer)
      and the console task (consumer).
  D2  Two free-running unsigned counters, head (bytes written) and tail (bytes read).
      Number of bytes held = head - tail. Empty when head == tail; full when
      head - tail == 8. Full and empty can never be confused.
  D3  The slot of counter c is c % 8.

Failure modes and what the code does about each
  F1  Console task reads when nothing arrived: pop() reports "no byte"; never blocks.
  F2  Bytes arrive faster than the task reads (a paste): when full, the NEW byte is
      dropped and a drop counter is increased. Bytes already held are kept.
      Rejected alternative: overwrite the oldest byte (loses the start of a command).
  F3  The counters pass the largest value of their type: unsigned arithmetic wraps,
      and head - tail is still correct.

How the acceptance tests observe success (one test per line above)
  P1  (F1)     pop() on a new ring returns false.
  P2  (D1, D3) bytes come out in the order they went in, across the end of the array.
  P3  (D2, F2) after 9 pushes into an empty ring: 8 bytes held, 1 dropped, and the
               8 bytes read back are the FIRST 8.
  P4  (D2)     after exactly 8 pushes, size() is 8 (full is not mistaken for empty).
  P5  (F3)     with both counters started 3 below their largest value, 8 bytes go in
               and come out unchanged.
