OBSERVED SPECIFICATION - PCI device 1234:11e8 (class 00 ff 00), BAR0 (1 MiB memory BAR)
Written by the observer from evidence only: trace.out, annotate.out and observe.out of this lab
(QEMU 8.2.2, machine q35, TCG; one driver run). Not checked against any vendor document.
Every line says what was SEEN; "unknown" means the evidence does not say.

Offset  Name (ours)     Access seen      What the evidence shows
0x00    ID              read only (seen) always 0x010000ed; never written by the driver
0x04    CHECK           write, read      a read after writing V returned ~V (bitwise inverse)
0x08    COMPUTE         write, read      after writing N, 0x20 bit 0 became 1; when it returned
                                         to 0, 0x08 read N! (5 -> 120, 10 -> 3628800)
0x20    STATUS          read             bit 0 = 1 while a COMPUTE is in progress, then 0;
                                         other bits: always 0 in this run (meaning unknown)
0x24    IRQ_STATUS      read             0 at rest; after a write of V to 0x60 it read V;
                                         after a write of V to 0x64 it read 0
0x60    IRQ_RAISE       write            reads return 0xffffffff (write-only, or not readable)
0x64    IRQ_ACK         write            reads return 0xffffffff (write-only, or not readable)
0x80,
0x88,
0x90,
0x98    unknown         read only (seen) read 0 at rest; the driver never wrote them; their
                                         purpose is unknown from this evidence
others  (none)          read             0x0c-0x1c, 0x28-0x5c, 0x68-0x7c, 0x84, 0x8c, 0x94, 0x9c,
        in 0x00-0xfc                     0xa0-0xfc: always 0xffffffff (probably not implemented)

Sequence the working driver uses (its self-test):
  1. enable memory decoding in the PCI command register; read BAR0
  2. read ID
  3. write CHECK, read CHECK, expect the inverse
  4. for each N: write COMPUTE = N; poll STATUS until bit 0 = 0; read COMPUTE
  5. write IRQ_RAISE = V; read IRQ_STATUS (= V); write IRQ_ACK = V; read IRQ_STATUS (= 0)

Open questions (need more observation or the documentation):
  - Does the device raise a real interrupt (INTx or MSI) on IRQ_RAISE? Not observed: the
    kernel ran with interrupts disabled and traced only memory accesses.
  - What do STATUS bits other than bit 0 do? What happens on COMPUTE while busy?
  - What are 0x80-0x98? (Read as 0; possibly a DMA engine; NOT safe to guess: never write
    an unknown register on a device you cannot afford to lose.)
  - Is 0x00's value a version number? Its meaning is not observable.
