Story hook

Analogy

Amara can now ride well: she steers back into her lane, she does not let a long drift build up, and she brakes early when she comes in fast. Her little brother is about to start riding to school, and she wants to write her know-how on a card he can follow every day without her.

Writing it down turns out to be harder than riding. "Steer back into your lane" needs an answer for odd moments: what if the lane markings vanish under leaves? What if he is already steering as hard as he can? What if he starts the ride from a standstill, with no idea how fast he was going a moment ago? A good card answers those questions, and Amara tests each rule on a quiet path before she hands it over.

This chapter does the same with the PID controller of F9-17 to F9-20. It becomes a small C++ library with a clear interface, rules for the awkward cases (saturation, the first call, bad sensor values, gain changes) and ten unit tests that run on every build. The library is the course project: F9-22 uses it on a motor kit, and later courses reuse it.

What you will be able to do

  • Implement a discrete PID controller in C++ with output limits, anti-windup, derivative on measurement and a derivative filter.
  • Explain each design choice of the interface: a fixed period, a factory that refuses bad settings, an integral stored in output units.
  • Write unit tests whose expected values are computed by hand, and use them to catch regressions.
  • Show with a simulation that anti-windup removes the overshoot of F9-18.
  • Diagnose a controller that went silent from a log containing inf and nan.
Jargon box
PID controller (discrete)
Simple words: a PID controller that runs as a program, once every period. Analogy: Amara's card, read once at every lamp post. Precise: u[k] = Kpe[k] + I[k] + D[k], with I updated by a running sum and D by a difference over one period T; MA301 (F0-66) derives it. U1B1
Conditional integration
Simple words: stop adding to the integral while the output is stuck at its limit and the error would push it further. Analogy: not building up more "I've been off for ages" while already steering as hard as possible. Precise: an anti-windup method: the integral update is skipped when the unclamped output is beyond a limit and the error has the sign that drives it further beyond. B1D1
Derivative filter
Simple words: smoothing applied to the rate of change before D uses it. Analogy: judging speed from the last few lamp posts, not from one twitch of the head. Precise: here a first-order low-pass rf += α(r − rf) with α = T/(τ + T); τ = 0 means no filter. U1D1
Bumpless transfer
Simple words: changing settings or modes without a jump in the output. Analogy: changing gear without a jolt. Precise: a property of a controller implementation: switching gains, or switching from manual to automatic, leaves u[k] continuous. Storing the integral in output units makes gain changes bumpless. B1R1
Input validation (control)
Simple words: checking every number before the controller uses it. Analogy: ignoring a lane marking that is clearly a leaf. Precise: refusing non-finite setpoints and measurements (NaN, ±∞, MA302) and invalid configurations, so that one bad value cannot poison the stored state. D1R3
Unit test
Simple words: a small program that checks one piece of code against an answer you worked out in advance. Analogy: trying each rule of the card on the quiet path. Precise: an automated check of one unit (here one behaviour of Pid) with a known input and an expected output computed independently; SP101 introduces them. U1

Layer 1 — the kid explanation

So far the PID controller lived inside each program, written again every time. Now it gets its own box with buttons on the outside: "here is the target and the measurement, tell me what to do". Inside the box are the three rules P, I and D, and some extra rules for awkward moments. If the motor is already at full power, stop adding up the error. If the reading is nonsense, ignore it and say so. If this is the very first reading, do not guess how fast things were moving.

Before anyone uses the box, we test it: ten little checks, each with an answer worked out on paper first. If someone later changes the box and breaks a rule, a check fails at once.

Layer 2 — the student explanation

The interface

Listing 1, pid.hpp, is a header-only library in the namespace rb. A PidConfig holds the gains, the period, the output limits, the derivative filter's time constant and a switch for anti-windup. A Pid object is made only through Pid::create, which returns std::optional<Pid>: an invalid configuration (a period of 0, limits in the wrong order, a negative gain, a NaN) gives no controller at all, so a running controller always has valid settings. The library allocates no memory and throws no exceptions, so the same file can later run on a microcontroller. D1U1

The caller promises one thing: call update(setpoint, measured) exactly once per period. The period is part of the configuration, not read from a clock. A controller that measures the time between calls itself inherits every glitch of that clock; the forensic lab shows one. D1R3

One update, step by step

  1. Check the inputs (lines 57–60). A NaN or infinite setpoint or measurement is refused: the call is counted and the previous output is returned. The stored state is not touched.
  2. P (lines 61–62): Kp·e.
  3. D on the measurement (lines 64–72). The rate is (y − yprev)/T, but only from the second call on: on the first call there is no previous sample, and inventing one would create a start-up kick (F9-19). The rate passes the filter with α = T/(τ + T), and D = −Kd·(filtered rate).
  4. I with anti-windup (lines 74–83). The candidate integral adds Ki·T·e. If the output would be beyond a limit and the error pushes further that way, the candidate is thrown away (conditional integration). The integral is also clamped to the output range: it may never on its own ask for more than the actuator can give.
  5. Sum and clamp (line 84): u = P + I + D, limited to [outMin, outMax].

Two further methods complete the interface: reset(output) forgets the past and restarts from a known output (after an emergency stop, for example), and setGains changes the gains while running, refusing invalid ones. D1

Why the integral is stored in output units

F9-18 wrote the I term as Ki·(running sum of e·T). This library stores the product instead: I += Ki·T·e, already in volts (or newtons). The two give the same output while Ki is constant. They differ when Ki changes: with a stored sum, quadrupling Ki quadruples the I term on the next call, a jump in the output; with a stored product, the past stays as it was and only future errors are weighted by the new Ki. Unit test 10 checks this: the output before and after changing Ki from 1 to 4 is the same (run R1). It also makes the windup check simple, because the integral can be compared directly with the output limits. D1R1B1

Ten tests with hand-computed answers

Listing 2 checks each behaviour with a value computed independently of the code: P only gives 0.5 × 0.8 = 0.4; ten integral steps give 2 × 0.01 × 10 = 0.2; a measurement rising 0.01 in 0.01 s gives D = −1; the filter with α = 0.1 reaches 1 − 0.9³ = 0.271 of the rate after three steps; and so on. All ten pass (run R1). A test that compares the code with itself, or with a number copied from its own output, would prove nothing. R1D1

Windup, fixed

Listing 3 repeats the windup experiment of F9-18 through the library: the motor of F9-16 (τ = 0.1961 s, 98.04 rad/s per volt), a step from 0 to 900 rad/s, Kp = 0.05, Ki = 0.25, limit 12 V. With anti-windup switched off, the integral reaches 25.55 V at 0.3 s (more than twice the limit), the speed peaks at 1078.6 rad/s (19.8 % overshoot) and stays above 909 rad/s (1 % over) for 0.86 s. With anti-windup on, the integral is 4.77 V at 0.3 s and the speed reaches 900.0 rad/s without overshoot (run R2). R2U1

Layer 3 — the engineer's depth

Other anti-windup methods. Conditional integration is the simplest. Another common method feeds the difference between the requested and the actually applied output back into the integrator, so the integral is pulled towards a value consistent with saturation ("back-calculation" or "tracking"). It needs a tracking gain, and it also works when the true actuator limit is not known exactly inside the controller, if the applied value can be measured. B1 discusses both. B1

Not verified — check before relying on this

That B1 presents back-calculation (tracking) anti-windup, and what tracking time constant it suggests, is recalled from general knowledge, not read in this build. This chapter gives no formula or rule for it. The Source Researcher must check the PID chapter of "Feedback Systems" and record the section in the RB202 dossier (gate G1). The library implements only conditional integration, which its tests verify.

The filter coefficient. The filter rf[k] = rf[k−1] + α(r[k] − rf[k−1]) with α = T/(τ + T) is the backward-Euler discretisation of a first-order low-pass with time constant τ (MA301 F0-66). It is stable for every τ ≥ 0, because 0 < α ≤ 1. After k samples of a steady rate it has reached 1 − (1 − α)k of it (Figure 2). With τ = 0.09 s and T = 0.01 s, ten samples (0.1 s) bring it to 65 %: the filter costs lag, which is the price for the smoothing measured in F9-19. D1U1

double, float or fixed point. The library uses double. Many small microcontrollers have hardware support only for single precision, or none at all. Moving to float changes rounding: a running sum of tiny increments can stop growing once each increment is below the resolution of the stored sum (MA302 covers this). Fixed-point implementations make the scaling explicit and are common in very small devices; this course keeps double and leaves the port to later courses. U1D1

Order matters. The windup check uses the candidate integral plus P and D (line 75), not last period's output. Testing saturation on stale values lets the integral run one step too far each time the output reaches a limit. D1

How the hardware actually does it

On a microcontroller the call to update is placed in a periodic task: a hardware timer (HW204) raises an interrupt every T, or a scheduler runs the control task at a fixed rate. Each period the task reads the sensor, calls update, and writes the actuator. Jitter (a call made a little early or late) acts like a small error in T; a task that misses whole periods should be detected and handled (for example by a watchdog, HW204), not hidden by measuring "the time since the last call". U1

A Pid object holds state and is not safe to share between an interrupt and the main program without care: if the main program calls setGains while the interrupt runs update, the interrupt can see half-changed gains. Change gains inside the control task, or between periods with interrupts held off. How your kit provides timers, interrupts and critical sections comes from its documents (F9-22). U1

Worked example

Problem. The configuration of Listing 3: Kp = 0.05, Ki = 0.25, Kd = 0, T = 0.01 s, limits ±12 V. On the first call the setpoint is 900 rad/s and the motor stands still. Trace one call of update with anti-windup on and with it off. Then compute α for τ = 0.09 s, and the output of unit test 5.

  1. Inputs are finite: continue. e = 900 − 0 = 900 rad/s.
  2. P = 0.05 × 900 = 45 V. D: first call, rate = 0, D = 0.
  3. Candidate I = 0 + 0.25 × 0.01 × 900 = 2.25 V. Unclamped sum: 45 + 2.25 + 0 = 47.25 V > 12 V, and e > 0: it pushes high.
  4. Anti-windup on: the candidate is discarded; I stays 0. Off: I = 2.25 V. In both cases the output is clamp(47.25 or 45) = 12 V. The difference is invisible in the output now, and decisive later: the off case adds 2.25 V on this call and a little less on each later call as the error shrinks, which is how it reaches 25.55 V at 0.3 s in R2.
  5. Filter: α = 0.01/(0.09 + 0.01) = 0.1. Test 5 makes three steps of a rate of 1, so the filtered rate is 1 − 0.9³ = 0.271 and D = −0.271 with Kd = 1.

Every number in the unit tests can be found the same way, with a pencil, before the code runs. D1R1R2

Summary


    

  • A reusable PID is a small class with a validated configuration, a fixed period, and one update per period.
    • 

  • Inside update: refuse bad inputs, P on error, filtered D on measurement (none on the first call), conditional integration with an integral clamp, then clamp the output.
    • 

  • Storing the integral in output units makes gain changes bumpless and the windup check simple.
    • 

  • Anti-windup turned 19.8 % overshoot into none on the F9-18 windup case (R2).
    • 

  • Tests need independently computed answers; ten such tests pass (R1). One unrefused non-finite value can silence a controller for good (R3).

Forensic lab answer key


    

  1. Call 151: the D term is inf. On the same row the clock reads 1500 ms, the same as call 150, so dt = 0.000 s.
    2. 

  2. The error changed by a tiny amount between calls 150 and 151 (the motor moved slightly), and dividing a non-zero number by dt = 0 gives infinity in floating point (MA302). Had the error been exactly equal, 0/0 would have given NaN directly.
    3. 

  3. clamp(∞) is the upper limit, 12 V, so call 151 sends a 10 ms full-voltage pulse. On call 152 dt is normal again and the raw D is finite, but the filter computes ∞ + 0.2·(finite − ∞) = ∞ − ∞ = NaN, and NaN stays NaN in every later update. The clamp of a NaN returns NaN (all comparisons with NaN are false), so the command is NaN from then on.
    4. 

  4. The 12 V pulse speeds the motor to 343.6 rad/s. From call 152 on, the driver treats the NaN command as 0 V (stated in the program), so the motor coasts down with its time constant: 343.6, 326.5, 310.3 … 228.5 rad/s. The driver does exactly what it was told; it is not broken.

Three features: a fixed, configured period (no dt from the clock, so no division by 0); input validation (a non-finite value would have been refused); and keeping the stored state clean (the library never lets a non-finite value into the integral or the filter).
