Story hook

The school's caretaker keeps a thick binder at the front desk. It says, in the caretaker's own shorthand, how this particular building works: "Boiler: valve 3, then switch B." "Corridor bell wires: room 4's bell goes to switchboard input 21." "To close the building for the night: write 0 in box S5, then pull lever 13." Every school's binder is different, because every building is different. The head teacher cannot run the building without reading it.

Some pages are plain lists: "room 4 → input 21". Some are procedures with conditions: "if the heating is in winter mode, use valve 3, otherwise valve 5". You can read the lists with a ruler and a pencil. The procedures need someone who can follow the shorthand step by step.

ACPI is that binder. The firmware writes it; the kernel reads it to learn how this machine powers off, which interrupt wire each PCI slot uses, and what the power button does. In this chapter you read the plain lists yourself, with a parser you write, and you see exactly where a real interpreter becomes necessary.

What you will be able to do

  • Find the fixed ACPI hardware from the FADT: PM1 event and control blocks, the PM timer, the SCI, SMI_CMD.
  • Switch a PC into ACPI mode and handle the System Control Interrupt for the power button.
  • Parse AML definition blocks: PkgLength, NameStrings, Scope, Device, Name, Method, OperationRegion and Field.
  • Read \_S5 and power the machine off through PM1a_CNT.
  • Route a PCI device's INTx pin through _PRT and a link device to an IOAPIC input, and prove the route.
  • Explain what only an AML interpreter can do, and decide between porting ACPICA or uACPI and writing more.
Jargon box
FADT (Fixed ACPI Description Table)
Simple words: the table that says where the basic power-management registers are. Analogy: the first page of the caretaker's binder: where the main switches are. Precise: the ACPI table with signature "FACP": I/O addresses of the PM1 event and control blocks, the PM timer and the GPE blocks, the SCI interrupt number, SMI_CMD with the ACPI_ENABLE value, flags, and the address of the DSDT. D1
AML (ACPI Machine Language)
Simple words: the compact byte code in which firmware describes devices and procedures. Analogy: the binder's shorthand. Precise: the encoding of ASL source in the DSDT and SSDTs: a tree of named objects (Scope, Device, Name, Method, OperationRegion, Field …) and method bodies with expressions, executed by an interpreter. D1
Namespace
Simple words: the tree of all names the AML defines. Analogy: the binder's table of contents. Precise: a hierarchy of 4-character name segments from the root \ (for example \_SB.PCI0.S08), built by loading the definition blocks. D1
SCI (System Control Interrupt)
Simple words: the one interrupt all ACPI events share. Analogy: the night bell; the caretaker's log says which door rang it. Precise: a level-triggered, shareable interrupt (on PCs usually ISA IRQ 9) raised by fixed events (power button, PM timer carry) and general-purpose events (GPEs) whose enable bits are set. D1
Sleep state S5 and \_S5
Simple words: "soft off", and the package that says which number means it on this machine. Analogy: "write 0 in box S5, pull lever 13". Precise: \_S5 is a Package whose first two elements are the SLP_TYP values for PM1a_CNT and PM1b_CNT; writing SLP_TYP with SLP_EN (bit 13) enters the state. D1
_PRT (PCI routing table)
Simple words: the list saying which interrupt wire each PCI slot's pin is connected to. Analogy: "room 4's bell goes to input 21". Precise: an object under a PCI root bridge returning a package of {address (device << 16 | 0xFFFF), pin (0–3 for INTA–INTD), source (a link device or 0), source index (a GSI when source is 0)}. D1
Link device
Simple words: a programmable interrupt router described in AML. Analogy: a switchboard plug whose position the binder describes. Precise: a device with _HID PNP0C0F and _PRS (possible resources), _CRS (current), _SRS (set) and _DIS (disable) objects. D1

Layer 1 — the kid explanation

Analogy

The binder has lists and procedures. A list ("room 4 → input 21") you can read and use at once. A procedure ("if winter, valve 3, else valve 5") must be followed step by step by someone who understands the shorthand. The night bell rings in one place for every door; the caretaker then looks at the board to see which door it was, and resets that door's light.

Every PC comes with tables written by its maker that describe how this exact computer is wired: where the power switch is, how to turn the machine off, which wire each card's interrupt uses. Some parts are plain data, which a small program can read. Other parts are little programs themselves, which need a proper interpreter. In this chapter you read the data parts and use them to switch the computer off when someone presses its power button.

Layer 2 — the student explanation

Fixed hardware: the FADT

The FADT gives I/O ports for a small set of registers every ACPI PC has. In QEMU's q35 machine (R2): PM1a event block at 0x600 (4 bytes: 2 status, 2 enable), PM1a control at 0x604 (2 bytes), the PM timer at 0x608 (24 bits), GPE0 at 0x620 (16 bytes), SCI on ISA IRQ 9, and SMI_CMD at port 0xB2 with ACPI_ENABLE = 2. D1 R2 At boot the firmware may still own these registers (System Management Mode handles events). Writing ACPI_ENABLE to SMI_CMD asks it to hand over; the hand-over is complete when SCI_EN (bit 0 of PM1 control) reads 1. R2: "SCI_EN set after writing 0x2 to port 0xb2". R2

The PM timer runs at a fixed 3.579545 MHz. Counting it for 200 ms of the kernel's own clock gave 3567615 ticks per second in the final run, 0.3 % below nominal; an earlier run gave 3683840, 2.9 % above. Both clocks are emulated under TCG, without KVM; the spread says something about the emulation, not about the timer. D1 R2

The power button

The power button is a "fixed event": pressing it sets PWRBTN_STS (bit 8) in PM1 status; if PWRBTN_EN (bit 8 of PM1 enable) is set, the SCI is raised. The SCI handler reads PM1 status, handles each set bit and clears it by writing 1 to it. In R2 the handler saw status 0x0101: bit 8 (the button) and bit 0 (TMR_STS, the PM timer's carry, which sets regardless of its enable bit and did not raise the SCI). D1 R2

The DSDT and AML

Everything machine-specific beyond the fixed hardware is in AML: the DSDT (one table, always present) and any SSDTs. QEMU's DSDT is 8294 bytes; the lab's walker finds 257 named objects in it: 33 devices, 69 methods, 106 names, 7 operation regions, 24 field units, one processor and 2 mutexes (R3). R3 The kernel prints the device list (R2), which is the milestone's namespace dump.

Shutdown

To enter S5 the kernel needs SLP_TYP for this machine. It is in \_S5, a Package of integers. QEMU's is Package(4) {0, 0, 0, 0}: SLP_TYPa = 0 (R3). The kernel writes (SLP_TYPa << 10) | SLP_EN | SCI_EN = 0x2001 to PM1a_CNT with a 16-bit write. QEMU then reports SHUTDOWN {"guest": true, "reason": "guest-shutdown"} on its monitor and exits (R2). D1 R2 On a real machine, the kernel first runs the \_PTS method ("prepare to sleep") and the device _PS3 methods, and syncs the file systems; none of that is possible without an interpreter, and the lab kernel has no file systems to sync.

PCI interrupt routing

A PCI function reports which INTx pin it uses (the e1000: pin A); which IOAPIC input that pin reaches depends on the board. The DSDT says so in _PRT. In QEMU's DSDT, _PRT is a Method that returns one of two packages, PRTP (8259 mode) or PRTA (APIC mode), depending on a variable \PICF that the OS sets by calling \_PIC(1). The lab cannot call methods, so it reads PRTA directly. Entry 4 says device 1, pin A → GSIF; GSIF's _PRS says GSI 21, level, active high, shared. Three interrupts forced on the NIC arrived on IOAPIC pin 21 (R2). D1 R2 R3 The PCI "interrupt line" register said 10: the BIOS's choice for 8259 mode, not the APIC route.

Layer 3 — the engineer's depth

AML encoding

A definition block is a 36-byte table header followed by a TermList. Objects with a body start with an opcode and a PkgLength: the top two bits of its first byte say how many more bytes follow (0–3); with none, the low six bits are the length; otherwise the low four bits are the lowest nibble and each following byte adds eight bits. The length counts from the first PkgLength byte to the end of the object. D1 Names are 4-character segments (A–Z, 0–9, _, padded with _), optionally preceded by \ (root) or ^ (parent), with DualNamePrefix 0x2E (two segments) and MultiNamePrefix 0x2F (count byte, then segments). Some opcodes are one byte (Name 0x08, Scope 0x10, Method 0x14, Package 0x12); others are 0x5B followed by a second byte (Device 0x5B 0x82, OperationRegion 0x5B 0x80, Field 0x5B 0x81). D1 amlcheck.cpp tests these rules on hand-written byte strings (R1).

What a walker can and cannot see

A walker that understands only declarations can list every Scope, Device, Name, Method, OperationRegion and Field at definition level. It cannot know what a Method returns, cannot evaluate expressions that are not literal data (Name(X, Add(1, 2)) is legal) and must skip If/Else/While blocks at definition level, which real DSDTs use to declare objects conditionally (by OS version, by board revision). QEMU's DSDT has none at definition level (R3: "0 If/Else/While blocks … skipped, complete"). Real laptops' DSDTs make heavy use of them and of SSDTs loaded by methods. D1 R3

Name resolution is another limit. A relative name in AML is searched first in the current scope and then upward through the parents. PRTA's sources are written as GSIF inside \_SB.PCI0, and the device is \_SB.GSIF: found one level up. The lab hard-codes that step (f411_main.cc lines 91–96); a real implementation implements the search rule. D1

Interrupt resources

_PRS, _CRS and _SRS hold resource templates: a sequence of small items (tag byte: type in bits 6–3, length in bits 2–0) and large items (tag byte with bit 7 set, 16-bit length). The Extended Interrupt descriptor (large item 0x09) has a flags byte (bit 0 consumer, bit 1 edge, bit 2 active low, bit 3 shared) and a list of 32-bit interrupt numbers; the old IRQ descriptor (small item 4) has a 16-bit mask and an optional information byte. An End Tag (small item 0x0F) closes the template. D1 R1 checks the decoder on a hand-made Extended Interrupt descriptor (GSI 21, flags 0x09). R1

The SCI, GPEs and the EC

The SCI is level-triggered and shared: the handler must check PM1 status and every enabled GPE status bit, clear what it handled, and run the matching _Lxx or _Exx method for GPEs (L = level, E = edge). On laptops the Embedded Controller raises a GPE, and its _Qxx query methods report battery and lid changes; battery state comes from _BIF/_BIX and _BST methods, temperatures from thermal zones' _TMP. All of those are methods: no interpreter, no battery. QEMU's q35 DSDT has no thermal zone and no battery (R3). D1 R3

The decision: port an interpreter

The curriculum's build step says: "port ACPICA or uACPI rather than writing your own at first". D6 This chapter's walker is the step before that: it teaches the encoding and gives a working shutdown and routing path on simple firmware, and it is a test oracle for the interpreter you port next. An interpreter needs an OS services layer from your kernel: memory mapping of physical addresses, locks and semaphores with timeouts, port and PCI configuration access for OperationRegions, a way to install the SCI handler, and stall and sleep functions. D2

How the hardware actually does it

On a PC the fixed ACPI registers live in the chipset's power-management unit (the platform controller hub on Intel systems), at I/O addresses the firmware chose. The power button is a pin of that unit; the PM timer is a counter clocked from the 14.318 MHz reference divided by four. D1 Before the OS takes over, the same unit's events go to System Management Mode: an SMI, invisible to the OS, runs firmware code. Writing ACPI_ENABLE to SMI_CMD triggers one more SMI in which the firmware reconfigures the unit to raise the SCI instead and sets SCI_EN. D1 In QEMU the unit is part of the ICH9 model, and SeaBIOS (the firmware here) implements the SMI_CMD hand-over. D5

Writing SLP_EN starts a hardware sequence: the chipset asserts its sleep signals, the power supply's "power on" line is released, and the machine loses power except for the standby rail, which keeps the power button and wake logic alive. A partial write cannot start it: SLP_EN is in the upper byte of the 16-bit register. QEMU's model exits the emulator when the guest enters S5. D1 R2

Interrupt routing on modern boards: a PCI Express device sends INTx as messages ("Assert INTA", "Deassert INTA") up to the root port, which maps them, swizzled by the device number on each bridge, to an IOAPIC input. The _PRT describes the result for the root bus; for devices behind bridges the OS applies the swizzle itself unless the bridge has its own _PRT. D1 D4

Worked example

Task. Decode three things by hand from the lab's DSDT: (1) the \_S5 bytes of Figure 3, (2) the PkgLength 0x4B 0x02, (3) the _HID value 0x080AD041 printed for \_SB.PCI0 in R3.

Step 1. 08 = NameOp; 5F 53 35 5F = "_S5_" → \_S5 (root scope); 12 = PackageOp; 06 = PkgLength (top bits 00: one byte, length 6, counting the 06 itself, the 04 and four elements); 04 = NumElements; 00 00 00 00 = four ZeroOps. SLP_TYPa = 0, SLP_TYPb = 0. R3

Step 2. Lead byte 0x4B = 01 00 1011: two top bits 01, so one more byte follows; low nibble 0xB. Next byte 0x02 contributes 0x02 << 4 = 0x20. Length = 0x20 | 0xB = 0x2B = 43 bytes. R1's second test line says exactly this.

Step 3. An integer _HID is a compressed EISA ID, stored as the bytes 41 D0 0A 08. The first two bytes read big-endian are 0x41D0 = 0 10000 01110 10000 in binary: three 5-bit letters 16, 14, 16 → 'A' + 15, 'A' + 13, 'A' + 15 = P, N, P. The next bytes 0A 08 give the hexadecimal digits "0A08". The ID is PNP0A08, a PCI Express root bridge; _CID 0x030AD041 decodes the same way to PNP0A03 (PCI bus). D1 R3

Check. The host tool, built from the same aml.cc, reads the DSDT the kernel dumped (R3); step 1 matches its raw bytes, step 2 matches R1. Step 3 is not checked by any program in the lab: the link devices' _HID 0x0F0CD041 is a second test case (it should decode to PNP0C0F, the link device ID).

Where the analogy breaks


    

  • The binder runs itself. AML procedures are executed by the OS's interpreter, but they read and write hardware registers through OperationRegions: the "binder" acts on the building directly, with the OS's hands.
    • 

  • The binder can change. Methods can load further tables (SSDTs) at run time and declare objects conditionally; the table of contents is not fixed when the binder arrives.
    • 

  • The caretaker still has a room. SMM firmware keeps running after the hand-over and can still take interrupts the OS never sees. "Handing over the keys" is partial.
    • 

  • The night bell is a level, not a ring. The SCI stays asserted while any enabled status bit is set; one unhandled bit makes it "ring" forever.
    • 




Common mistakes and debugging


    

  • Symptom: the power button does nothing. Cause: still in legacy mode (SCI_EN clear), PWRBTN_EN not set, or the SCI routed edge-triggered. Find it: poll PM1 status after pressing; if bit 8 is set but no interrupt came, the routing is wrong. Fix: the MADT override for IRQ 9 says level, active high (R2).
    • 

  • Symptom: an SCI storm right after enabling. Cause: a status bit set before enabling, or a GPE enabled without a handler. Find it: print PM1 and GPE status in the handler. Fix: clear status before setting enables; enable GPEs only with their method.
    • 

  • Symptom: "shutdown" returns and the machine keeps running. Cause: wrong SLP_TYP (\_S5 not read), a byte write, or the PM1b block forgotten. Find it: read PM1a_CNT back. Fix: the forensic lab.
    • 

  • Symptom: the walker stops early on a real DSDT. Cause: an opcode at definition level that it does not handle (expressions in Name, conditional declarations, External). Find it: the stop offset and opcode; look the opcode up in D1. Fix: handle it or move on to an interpreter.
    • 

  • Symptom: a PCI device's interrupts never arrive although _PRT was read. Cause: the PRTP (PIC) table used in APIC mode, or the interrupt line register trusted. Find it: force an interrupt as the lab does and check which IOAPIC input sees it. Fix: call \_PIC(1) (with an interpreter) and use the table _PRT returns.
    • 




Transition box

Where you came from: F4-02 parsed the static ACPI tables (RSDP, RSDT, MADT, MCFG); F4-08 programmed the IOAPIC from the MADT. What carries over: table checksums, packed structures read field by field, the IOAPIC routing API, level-triggered handlers that clear their cause. What changes: the description of the machine is now a byte-code language, part data and part program; the kernel must parse a tree and, for full support, run code written by the firmware vendor. What comes next: F4-12 returns to a PCI device with rings and DMA, the HD Audio controller, whose codec is described by a graph read at run time, a little like the namespace here.

Safety
On real hardware, a wrong SLP_TYP can enter a sleep state the firmware does not expect (S3 without saved state) and a wrong write to an OperationRegion can reprogram voltage regulators or the embedded controller. Never write ACPI registers on a machine you cannot afford to have to power-cycle by unplugging, and never execute AML methods by hand-made guesses on a laptop with unsaved work or a battery you care about.

  • S5 = SLP_TYP from \_S5 plus SLP_EN, written to PM1a_CNT (and PM1b) with a 16-bit write (R2, R4).
    • 

  • AML is a tree of declarations plus code; a walker reads the declarations and data, only an interpreter runs methods (R3).
    • 

  • PCI routing comes from _PRT and link devices, not from the interrupt line register; prove a route by forcing an interrupt (R2).
    • 

  • The next step is porting an interpreter; the walker becomes its test oracle.

Forensic answer key


Observation. "sci: power button at t=424 ms … PM1 status bits seen 0x0101": the button reached the kernel. "S5: writing 0x2001 to PM1a_CNT"; 2 s later "PM1a_CNT reads 0x0001". QMP saw POWERDOWN but no SHUTDOWN event.


Root cause. 0x2001 = 0010 0000 0000 0001; 0x0001 = only bit 0. Bits 13 (SLP_EN) and 12–10 (SLP_TYP) are missing: the write reached only the low byte. pm.cc line 111 uses outb (an 8-bit OUT to port 0x604) under F411_BYTE_WRITE; PM1_CNT is 16 bits wide (FADT PM1_CNT_LEN = 2, R2), and SLP_EN lives in the high byte at port 0x605.


Hypotheses separated. "Wrong SLP_TYP" (the \_S5 value misread) would still leave SLP_TYP bits other than the expected ones in the read-back, and the write line would show a different value; "the high byte was never written" fits 0x0001 exactly, since bits 0–7 of 0x2001 are 0x01. The read-back line separates them. (Whether real chipsets read SLP_EN back as 0 after a successful write is not established here; in this case the machine did not switch off, which is the stronger evidence.)


Injection. Built with -DF411_BYTE_WRITE.


Fix and verification. outw (line 113); rerun: QMP shows SHUTDOWN {"guest": true, "reason": "guest-shutdown"} and QEMU exits with 0 (R2).


Wrong answers. "The firmware refuses S5": nothing in the log shows a refusal; the register never received the request. "The SCI handler did not run": its line is in the log.


Prevention. Access ACPI registers with the width from the FADT (PM1_CNT_LEN, or the Generic Address Structure's access size in ACPI 2.0+ fields); add a read-back check after every sleep request.
