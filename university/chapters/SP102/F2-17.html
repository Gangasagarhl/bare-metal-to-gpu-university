Story hook

Analogy

Kofi does not write a new page in the kitchen's procedure book every time he needs a small instruction. He grabs a sticky note: "count the orders under 10 minutes", sticks it on the procedure "count", and hands both to a cook. Sometimes the note copies a number onto itself: "under 10 minutes". Sometimes it points at something in the kitchen: "add each time to the tally board by the door".

There is a catch. A note that says "the tally board by the door" is useless if the board is taken down. A note that copied "price: 5" in the morning still says 5 in the evening, even though the menu changed.

In C++ the sticky note is a lambda: a small function written in place. Whether it copies a value or points at something is decided by its capture list, and both of the catches above are real bugs you will meet in this chapter.

What you will be able to do

  • Write lambdas and pass them to standard algorithms instead of separate named functions.
  • Choose capture by value or by reference, and explain the lifetime consequence of each.
  • Store callables in std::function and build simple callbacks.
  • Write generic and mutable lambdas.
  • Explain what the compiler generates for a lambda, using sizes and symbol names.
  • Diagnose a lambda that keeps an old value, and one that refers to a variable that no longer exists.
Jargon box
Lambda expression
Simple words: A small function written exactly where you need it. Analogy: A sticky-note instruction. Precise: An expression [captures](parameters) { body } that creates an unnamed function object; the return type is usually deduced. D1, D2
Closure
Simple words: The object a lambda expression creates. Analogy: The note itself, with whatever was written on it. Precise: An object of a unique, compiler-generated class type, whose data members hold the captured values and whose operator() runs the body (R2, R4). D2, R2, R4
Capture
Simple words: What a lambda takes with it from the place where it was written. Analogy: A number copied onto the note, or "the board by the door". Precise: An entry in the capture list: [x] copies x into the closure (by value); [&x] refers to the original x (by reference); [n = expr] creates a new member initialised from expr. D2
std::function
Simple words: A box that can hold any function-like thing with a given signature. Analogy: A holder on the wall that takes any note saying "do this with a table number". Precise: The class template std::function<R(Args...)> (header <functional>), which stores a copy of any callable with that signature and calls it through one interface. D2, R3
Callback
Simple words: A function you give to someone else so they can call it later. Analogy: "When the bell rings, do this." Precise: A callable passed to and stored by other code, which invokes it when an event happens (R3). R3, D1
Generic lambda
Simple words: A lambda that works for many types. Analogy: A note with a blank, like the recipe card of F2-14. Precise: A lambda with auto parameters; its operator() is a member function template, instantiated per argument type (R4). D2, R4

The idea in pictures

Figure 1 shows what the three captures of Listing 1 and Listing 2 contain. A by-value capture is a copy inside the closure. A by-reference capture leads back to the original variable.

Layer 1 — the kid explanation

Sometimes you need a tiny instruction only once, like "is this order quick?". Writing a whole named function far away for it is tiring, and the reader has to go and find it. A lambda lets you write the tiny instruction right where you use it.

A lambda can take things with it from where it was written. It can make a copy ("remember the number 10") or point at the original ("go and look at the tally board"). A copy stays the same even if the original changes later. A pointer always sees the newest value, but only as long as the original still exists.

You can also keep a lambda in a box and use it later, like a note stuck on the bell: "when you ring, carry the food to the table".

Layer 2 — the student explanation

Writing lambdas

A lambda has three parts: [capture list](parameters) { body }. Listing 1 shows the common forms. Each produced the output recorded in R1:

  • No capture: the comparison of F2-15 written in place inside std::sort; the longest order is curry.
  • Capture by value [limit]: the lambda keeps its own copy of 10 and counted 2 quick orders.
  • Capture by reference [&total]: the lambda adds to main's total, which became 54.
  • A lambda in a variable: label(orders.back()) called like a function.
  • A generic lambda [](auto x): works for int (42) and std::string ("haha").
  • A mutable lambda with its own counter [next = 100]: tickets 100, 101, 102.

R1

Prefer explicit captures ([limit], [&total]) over the defaults [=] (copy everything used) and [&] (refer to everything used). The explicit list shows the reader exactly what the lambda depends on. D3

Value or reference?

The rule follows from F2-12: a reference must not outlive what it refers to. If the lambda is used only during the current statement, as with an algorithm call, capturing by reference is safe and lets it change or read the current value. If the lambda is stored, returned or given to someone who calls it later, capture by value, so that it owns what it needs. The lab's slower_than(limit) returns a lambda and therefore captures limit by value. Listing 5 shows what happens otherwise: a lambda returned from make_reader referred to a local variable that was already gone, and AddressSanitizer reported stack-use-after-return. R8, R5, D3

Capture by value has its own trap: the copy is taken when the lambda is created. A later change to the original is not seen. That is the forensic lab. R6

Storing lambdas: std::function and callbacks

Every lambda has its own unnamed type, so you cannot write that type in a vector or a member declaration. auto works for a local variable. To store "anything callable with this signature", use std::function. In Listing 3, class Bell keeps a std::vector<std::function<void(int)>>; two parts of the program register actions. One captures the counter by reference, the other copies the waiter's name. Ringing twice carried food to tables 4 and 9 and counted 2 rings. R3, D2

Layer 3 — the engineer's depth

A lambda is a class

For each lambda expression, the compiler writes a new class. The captures become its data members; the body becomes its operator(), which is const unless the lambda is mutable; the lambda expression creates one object of that class. This is why a by-value capture cannot be changed without mutable: the body is a const member function (F2-12). A lambda with no captures can also convert to a plain function pointer, which matters for C interfaces such as qsort or a firmware callback table. D2, R4

The cost of std::function

A lambda passed directly to a template such as std::sort is part of the instantiation: the compiler sees its body and can inline it. std::function hides the type, so every call goes through an indirect call. If the closure is too big for the space inside the std::function object, storing it may also allocate memory. Use std::function where you need to store callables of different types (callbacks), and templates or auto parameters where you only pass them through. D1, D2

Not verified — check before relying on this

How large a closure may be before this library's std::function allocates, and whether calls through it are inlined at -O2, were not measured in this build. Measure it (SP202, F2-33 "Profiling basics", then SP302) before relying on either.

Capturing this

Inside a member function, a lambda that uses members captures this, a pointer to the object, not a copy of the members. If the lambda is stored (for example registered as a callback) and the object is destroyed, the lambda dangles exactly like Listing 5. Write [this] explicitly so that the dependency is visible, or capture copies of the needed members. D2, D3

Where the analogy breaks


    

  • A sticky note pointing at "the board by the door" is just useless when the board is gone. A lambda referring to a dead variable reads whatever is now in that memory: undefined behaviour, which may look correct (R5 needed a sanitizer to be seen). R5
    • 

  • All sticky notes look alike. Every lambda expression has its own distinct type, even two with identical text, which is why storing them needs auto or std::function. D2, R4
    • 

  • A note is paper; a closure can be large. Capturing a std::string by value copies the whole string into the closure (R2: 32 bytes for the object alone, plus any heap characters). R2
