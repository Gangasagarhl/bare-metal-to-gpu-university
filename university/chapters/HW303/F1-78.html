Story hook

The take-away stand buys a new combination oven. It comes with three documents: a glossy leaflet ("cooks 40 meals an hour, 230 V, 3 kW"), a thick service manual with a chapter for every knob and menu, and a single page titled "known issues". Amara, in a hurry, reads the leaflet and starts cooking. The oven beeps at her. She presses buttons until it stops. The meals come out raw in the middle.

The next morning she opens the thick manual. It is boring and exact: "the timer starts only after the preheat phase has completed; to skip preheat, hold START for 2 s". Every surprise from the day before is written there, in a place she can find once she knows how the manual is organised.

Microcontrollers come with the same three documents: a datasheet, a reference manual and an errata sheet. This chapter teaches you to find the register, the bit and the sentence you need, and to turn them into working code without guessing. The exam of this course asks you to configure a timer "from the reference manual alone"; this chapter's lab is that exam, practised on a manual written for the purpose.

What you will be able to do

  • Choose the right document (datasheet, reference manual, core manual, errata sheet, application note) for a question.
  • Navigate a reference manual: memory map, clock and reset chapter, peripheral chapters and their fixed structure.
  • Read a register description: address = base + offset, reset value, bit fields, access types, reserved bits.
  • Configure a timer from a reference-manual excerpt alone, citing a section for every register write, and check the result on an executable model.
  • Diagnose "the timer runs at the wrong speed and the LED goes crazy" from the manual's buffering and flag-clearing rules.
Jargon box
Datasheet
Simple words: the short document about one chip: what is inside, its pins, its electrical limits. Analogy: the oven's leaflet. Precise: the per-part document giving features, pinout and package, absolute maximum ratings, operating conditions, electrical and timing characteristics and ordering codes; it rarely explains how to program peripherals. D1 D2
Reference manual
Simple words: the thick document that explains every peripheral and every register of a chip family. Analogy: the oven's service manual. Precise: the family-level programming document containing the memory map, the clock/reset/power chapter and one chapter per peripheral (functional description and register descriptions); the core itself is described in a separate core or architecture manual. D1 D3
Errata sheet
Simple words: the list of things in the chip that do not work as the manuals say. Analogy: the "known issues" page. Precise: a vendor document listing silicon defects per device revision, each with its effect and a workaround; it overrides the reference manual for the revisions it names. D1
Register map
Simple words: the table of all registers of one peripheral, with their positions. Analogy: the diagram of the oven's control panel. Precise: a table of register names, offsets from the peripheral's base address, reset values and (often) a bit-field summary; the absolute address is base + offset. D3 R1
Reset value
Simple words: what a register contains right after reset. Analogy: the knob positions the oven leaves the factory with. Precise: the value each bit takes on reset, given per register; firmware must not assume any other value, and "x" or "undefined" marks bits without one. D3
Reserved bits
Simple words: bits you must leave alone. Analogy: the screws marked "service only". Precise: bits without a documented function; manuals specify how to write them (typically "keep at reset value" or "write 0"), which is why firmware uses read-modify-write or writes complete documented values. D3 R1
Write-1-to-clear (W1C)
Simple words: a flag you clear by writing 1 to it, not 0. Analogy: a "done" lamp you switch off by pressing it. Precise: an access type in which writing 1 to a bit clears it and writing 0 has no effect; it lets software clear one flag without disturbing others set by hardware meanwhile. Other manuals use read-to-clear or write-0-to-clear for similar flags: the access column decides. D3 R1
Buffered (preload, shadow) register
Simple words: a register whose new value takes effect later, not at the moment you write it. Analogy: "the new temperature applies from the next baking cycle". Precise: a register with a preload copy that software writes and an active copy that the hardware uses; the preload is transferred to the active copy at a defined event (for a timer, the update event), so that changes never take effect in the middle of a period. D3 R1
Update event
Simple words: the moment a timer restarts its count and takes on new settings. Analogy: the start of a new baking cycle. Precise: in the teaching chip's TIM2 (and many real timers), the event generated when the counter wraps or when software sets the update-generation bit; it reloads buffered registers and sets the update flag. R1

Layer 1 — the kid explanation

A microcontroller has hundreds of little switches and dials, called registers. Nobody remembers them all. The reference manual is a big book that lists every one: where it is, what each tiny part of it does, and what it is set to when the chip starts.

The trick is not to read the book from the start. You look up the part you want, like a timer, in the table of contents. Every part has a chapter that looks the same: first what it can do, then how it works, then a list of its registers. Inside, a few small sentences decide whether your program works: "this value is used only after the next restart" or "to clear this flag, write 1". Good engineers read those sentences slowly, twice.

Layer 2 — the student explanation

The document set

Analogy first: leaflet, service manual and "known issues". Precisely: for a Cortex-M microcontroller you typically need the datasheet of your exact part (pins, alternate functions, electrical limits; F1-79), the reference manual of its family (peripherals and registers), the core's manuals from Arm (exceptions, interrupt controller, SysTick, debug: what F1-77 used), the errata sheet for your silicon revision, and the board's user guide and schematic. D1 D2 D3 Vendors also publish machine-readable register descriptions (CMSIS-SVD files), from which headers and debugger register views are generated; they are convenient but can contain mistakes, so the reference manual remains the authority. D4

Navigating a reference manual

A reference manual is long (often well over a thousand pages for a mid-range family), but it is regular. D1 Learn its fixed parts:

  1. Memory map: a table of base addresses for every peripheral, as you saw from the emulator's side in F1-73 and F1-74.
  2. Reset and clock control: clock sources, the PLL, bus prescalers, and the enable bit of every peripheral (F1-75). Almost every "the peripheral does nothing" bug is answered here.
  3. One chapter per peripheral, each with: introduction and main features; functional description (the behaviour in prose and timing diagrams, often with a recommended configuration sequence); interrupts and flags; and the register descriptions, ending in a register-map table. D1 D3

Reading a register description


For each register, read the parts in Figure 2's order: name and offset (address = base from the memory map + offset), reset value, then each field with its bit positions, access type and meaning. D3 Access types deserve the most care, because they change what a write does: rw (read/write), r (read-only: writes ignored), w (write-only: reads return something meaningless, here 0), w1c (write 1 to clear), and on other chips read-to-clear or "set by hardware, cleared by software" forms. D3 R1 Then read the functional description for the field's timing: when does a write take effect? The teaching manual's section 14.2 says TIM2_PSC is buffered and only takes effect at the next update event; this one sentence is the forensic lab.



From requirement to register writes


Exam P asks for a timer configured "from the reference manual alone". A method that works on any manual:


    

  1. Write the requirement as numbers: "update event every 1 s from TIM2CLK = 72 MHz".
    2. 

  2. Find the formula in the functional description and cite it: CK_CNT = TIM2CLK / (PSC + 1) (14.2); period = ARR + 1 counts (14.1).
    3. 

  3. Solve with the register widths in mind: 72,000,000 counts per second do not fit 16 bits; choose PSC = 7199 → CK_CNT = 10 kHz; ARR = 9999 → 10,000 counts = 1 s.
    4. 

  4. Find the configuration sequence and follow it, citing a section for each write: clock enable (7.6, 14.5 step 1), PSC and ARR (14.5 step 2), UG to load the buffered PSC, then clear UIF by writing 1 (14.2, 14.4.4, 14.5 step 3), enable the counter (14.5 step 4).
    5. 

  5. Verify: here on the model; on a real chip by reading registers back in the debugger and measuring.
    6.

Layer 3 — the engineer's depth


Sentences that bite


Experienced embedded engineers read for a short list of traps, because they cause most "it should work" bugs: D2 D3


    

  • Buffered registers and the event that loads them (this chapter's forensic lab).
    • 

  • Flag-clearing rules (w1c, read-to-clear, clear by reading one register then another): writing the "obvious" value can do nothing.
    • 

  • Order requirements: "configure while disabled", "enable the clock first", "wait for the ready flag".
    • 

  • Register access width: some registers must be accessed as 16 or 32 bits; the teaching manual says "accessed as 32-bit words" (14.4).
    • 

  • Reserved bits: written with the documented value, never with whatever happened to be in a variable.
    • 

  • Clock domain delays: a peripheral on a slow bus may need a few cycles before a write is visible; manuals note when a read-back is required.
    • 

  • Errata for your revision: check before believing any of the above.
    • 




Headers, SVD files and your own definitions


In real projects you rarely type addresses: vendor headers (CMSIS device headers) define a struct per peripheral whose members are laid out at the documented offsets, and macros for bit positions. D4 They save typing but not reading: a header tells you that EGR exists, not that you must write it before enabling the counter. When you write your own definitions, as this course does, check every offset against the register-map table, and add a compile-time check (static_assert(offsetof(...) == 0x10)) for each one, so a misplaced member is a build error. D5



When the manual is wrong


Manuals have mistakes, and silicon has defects. If your careful reading does not match the hardware's behaviour, check in this order: your reading (again, slowly), the errata sheet for your chip revision (marked on the package or readable from a device-ID register), the manual's revision history, then the vendor's community or support channels. Record what you found as a measurement on your chip and revision, with the document you compared against. D1 C1

How the hardware actually does it


A buffered register is two registers: software's writes go to the preload register; the active register, which feeds the counter's comparator or the prescaler's divider, is loaded from it by a load-enable signal driven by the update event. D6 This is the reason buffering exists: the prescaler's divider is itself a counter, and changing its limit in the middle of a count could produce one very short or very long count. A w1c flag is a flip-flop with a set input from the hardware event and a clear input from "write strobe AND data bit = 1" (F1-17); because only 1-bits clear, software can clear flag A without touching flag B even if B was set between the read and the write. D6 D3 Listing 1 models both: lines 39 and 81 for the prescaler preload and its transfer, line 34 for w1c.

Where the analogy breaks


    

  • An oven's manual is written for a user; a reference manual is written for someone who already knows the field. It assumes you know what a prescaler or an update event is, and rarely explains why. The chapters before this one supply that background.
    • 

  • An oven forgives a wrong button; a register does not. A write with the wrong value is silently accepted, and the symptom can appear seconds later in a different place.
    • 

  • The oven leaflet is enough to cook something; the datasheet is not enough to program anything. For firmware, the reference manual is the primary document. D1
    • 




Common mistakes and debugging


    

  • Symptom: first period much shorter than expected, then correct. Cause: buffered prescaler not loaded before start. Fix: force an update event (UG) before enabling.
    • 

  • Symptom: after the first event, the "wait for flag" loop never waits. Cause: flag cleared the wrong way (wrote 0 to a w1c bit). How to find it: read the status register after your clear in the debugger. Fix: follow the access type.
    • 

  • Symptom: a register reads back 0 after you wrote it. Cause: peripheral clock not enabled, or the register is write-only. Fix: check the enable bit and the access type.
    • 

  • Symptom: code copied from another chip of the "same family" misbehaves. Cause: different base addresses, bit positions or rules. Fix: check every register against your part's manual and errata.
    • 

  • Symptom: a field seems to be in the wrong place. Cause: bit numbering misread (bit 0 is the least significant bit; fields are written high:low, as in "bits 6:4"). Fix: compute the mask by hand: bits 6:4 = 0x70, value 110 shifted by 4 = 0x60.
    •

Forensic lab answer key


Root cause. Two manual rules were not applied. (1) Section 14.2: TIM2_PSC is buffered. Without a UG write (14.5 step 3), the active prescaler is still its reset value 0, so the counter runs at the full 72 MHz and the first update event comes after 10,000 cycles = 0.139 ms instead of 1 s. (2) Section 14.4.4: UIF is w1c; writing 0 has no effect. After the first event, UIF stays set, so every later "wait for UIF" returns at once: toggles 0.000 ms apart, and the final read shows TIM2_SR = 0x1. The LED toggles as fast as the loop runs, which looks "half-lit".


Evidence. First toggle at 0.139 ms; following toggles 0.000 ms after the previous; read TIM2_SR -> 0x1 after four clears with 0.


Fix. Add write TIM2_EGR 1 and write TIM2_SR 1 before write TIM2_CR1 1, and clear with 1 in the loop (blink 4 1). Expected: toggles at 1,000 ms intervals, as in the reference run.
