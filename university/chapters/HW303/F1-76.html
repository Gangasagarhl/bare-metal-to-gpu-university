Story hook

The take-away stand has a lamp over the order window. When an order is ready, the cook switches it on; when the customer has taken it, off. Simple. But at night the owner wants the lamp dimmer, to save power and not dazzle anyone. The lamp has no dimmer switch. Amara has an idea: she flicks it on and off so fast that the eye sees only an average. On for a quarter of each moment, off for the rest: a quarter of the light.

Flicking by hand is tiring, and her rhythm wobbles whenever a customer asks a question. So she uses the kitchen timer. It rings at a steady beat, and at each ring she knows exactly what to do. Later the owner buys a lamp controller that does the flicking by itself; Amara only tells it "how long per cycle" and "how long on".

A microcontroller does all three things in this chapter: switch a pin on and off (GPIO), keep a steady beat (a timer), and flick a pin with a chosen on-time per cycle (PWM), first by software at the timer's beat, then by the timer's own hardware.

What you will be able to do

  • Explain what a GPIO pin is electrically and logically: direction, output data, input data, pulls, push-pull and open-drain.
  • Configure a hardware timer from its registers and use its flag to make a steady tick, on an emulated microcontroller with your own start-up code.
  • Blink an LED and produce software PWM from a timer tick, and prove it with the emulator's trace of every LED write.
  • Compute PWM frequency and duty cycle from a timer's clock, prescaler, reload and compare values, and solve the reverse problem.
  • Diagnose PWM signals that are slightly off in frequency and never reach 100 % from the register values alone.
Jargon box
GPIO (general-purpose input/output)
Simple words: a pin the program can switch on and off, or read as on or off. Analogy: the lamp switch over the order window, and the bell button customers press. Precise: a pin whose direction, output level and input sampling are controlled by software through the GPIO peripheral's registers (direction or mode, output data, input data, and often pull-up/pull-down and output-type settings). D1 D2
Push-pull and open-drain
Simple words: two ways a pin can drive a wire: actively high and low, or only pulling low. Analogy: a door you can push and pull, versus one you can only pull shut while a spring opens it. Precise: a push-pull output has transistors to both supply and ground and drives either level; an open-drain output has only the transistor to ground, so the high level must come from a pull-up resistor, which lets several outputs share one wire (as I2C does). D3 D1
Pull-up / pull-down
Simple words: a weak connection that keeps an unconnected input at a defined level. Analogy: a spring that holds a door shut until someone pushes. Precise: a resistor (internal, enabled by a GPIO register, or external on the board) from an input to the supply or to ground, so that the input reads a known value when nothing drives it. D3
Timer (counter/timer peripheral)
Simple words: a counter that counts clock ticks by itself and raises a flag when it reaches a set value. Analogy: the kitchen timer that rings at a steady beat. Precise: a peripheral with a counter register clocked by a (prescaled) peripheral clock, a reload or compare value that defines its period, a status flag set at each period, and usually an interrupt request and compare/capture channels. D1 D4
Reload (auto-reload, period) register
Simple words: the number the timer counts to (or from) before starting again. Analogy: how many seconds the kitchen timer is set to. Precise: the register whose value defines the counter's period; for a counter running 0…N or N…0 the period is N + 1 counter clocks. D1 R2
PWM (pulse-width modulation)
Simple words: switching a pin on and off very fast with a chosen fraction of "on" time. Analogy: flicking the lamp so fast it looks dimmer. Precise: a periodic digital signal whose period is fixed and whose high time (pulse width) encodes a value; the ratio of high time to period is the duty cycle. D4 D3
Duty cycle
Simple words: how much of each cycle the signal is on, in percent. Analogy: a quarter of each moment on = 25 %. Precise: high time divided by period; for an edge-aligned PWM with compare value C and period N + 1 counts, duty = C / (N + 1). R1
Compare channel
Simple words: a second number the timer watches, used to switch an output in the middle of each period. Analogy: a mark on the kitchen timer's dial: "switch the lamp off here". Precise: a register compared with the counter on every count; the comparison drives an output pin in PWM modes or raises an event flag. D1

Layer 1 — the kid explanation

A GPIO pin is a tiny switch the program controls. Write 1 and the pin goes to the supply voltage, so an LED connected to it lights. Write 0 and it goes to ground. Turn the pin around and it becomes a reader: the program asks "is this pin high or low?", for example to know if a button is pressed.

A timer is a counter that counts by itself, very fast and very steadily. When it reaches its target, it raises a flag and starts again. The program can wait for the flag, or let the flag ring a doorbell (an interrupt). Either way, the program now has a steady beat.

PWM means switching a pin on and off very fast and choosing how long it stays on. An LED switched on for a quarter of the time looks about a quarter as bright. A motor gets a quarter of its push. The timer can do the switching by itself, so the program only sets two numbers: how long a cycle is, and how long the "on" part is.

Layer 2 — the student explanation

GPIO: registers and pins

Analogy first: a lamp switch and a doorbell button. Precisely: a GPIO port groups several pins (often 16 or 32, per the chip's manual) and controls them through registers: a mode or direction register selects input, output, alternate function (the pin belongs to a peripheral such as a UART) or analog; an output data register sets output levels; an input data register returns the sampled pin levels; further registers choose pull-ups or pull-downs, push-pull or open-drain, and drive speed. D1 D2 Many chips add set/reset registers that change single bits of the output atomically, so an interrupt handler and the main loop cannot undo each other's changes with a read-modify-write race. D1

Electrically, an output pin can supply or absorb only a limited current, given in the datasheet; an LED therefore always needs a series resistor sized with Ohm's law (F1-02, F1-06), and larger loads such as motors need a driver transistor or chip (F1-70). D3 F1-79 does that calculation from a schematic.

Watch out

On QEMU's mps2-an385 board the CMSDK GPIO blocks are not modelled (they appear as prio -1000 placeholders in F1-73's memory tree). The board's user LEDs are bits in the modelled mps2-fpgaio block instead, and that is the "LED" of this chapter's lab. The behaviour of a real GPIO port is therefore not exercised here. R3

Timers: a counter with a period

A timer peripheral counts pulses of its input clock, optionally divided by a prescaler. When the counter reaches the end of its range (zero for a down-counter, the reload value for an up-counter) it restarts and sets a flag; if enabled, the flag requests an interrupt. D1 D4 Two conventions decide every "off by one": the prescaler usually divides by its register value plus one, and a counter that runs 0…N (or N…0) has a period of N + 1 counts. D1 The teaching timer of Listing 1 uses both conventions and says so in its header comment. R1

PWM in software and in hardware


Software PWM uses a timer only as a beat: at each tick the program decides whether the pin is on or off. Listing 2's PWM has a period of 10 ticks and switches the LED on for the first duty ticks of each period; its UART output draws the result:




Software PWM is easy and works on any pin, but its edges move whenever the program is busy elsewhere, and it costs a lot of processor time at high frequencies. D4 Hardware PWM uses a timer's compare channel: the counter runs continuously, the compare register sets the pulse width, and the timer itself drives the pin (Figure 2). The processor only writes new compare values. D1 D4 For edge-aligned PWM on an up-counter with prescaler P, reload N and compare C:

    •

  • duty = C / (N + 1), with C = 0 meaning always low and C > N meaning always high. R1

Layer 3 — the engineer's depth


Frequency, resolution and the prescaler trade-off


The number of distinct duty values is N + 1: with N = 9 you get steps of 10 %, with N = 35,999 steps of 1/36,000. For a fixed PWM frequency, a smaller prescaler gives a larger N and therefore finer duty steps, until N would exceed the counter's width. D4 That is the search Listing 1's solve performs: for 1 kHz from 72 MHz, P = 0 would need N + 1 = 72,000, which does not fit 16 bits; P = 1 gives fcnt = 36 MHz and N = 35,999, the finest resolution available. For a 50 Hz servo-style signal the first prescaler that fits is 21, giving a period of 20,000.139 µs instead of exactly 20,000 µs, because 72,000,000 / 22 / 50 is not an integer. R1 Whether that 0.0007 % matters depends on the device you drive; the method is what counts: compute, then check the residual error.



Changing PWM values safely


If software changes the compare value while the counter is between the old and the new value, one period can get an extra or a missing edge (a glitch). Timers therefore usually buffer the reload and compare registers ("preload" or "shadow" registers) and copy them into the active registers only at an update event, at the start of a period. D1 D4 The same buffering surprises beginners when a newly written prescaler seems to be ignored until the first overflow; F1-78's forensic lab is built on that rule of the teaching chip's manual.



Other timer functions


The same counter hardware serves several jobs, chosen by mode bits: periodic interrupts (a system tick), one-pulse mode, input capture (store the counter value when an input edge arrives, to measure a pulse width or frequency, used for encoders in F1-66), center-aligned PWM (counting up and down, which places pulses symmetrically and is used for motor control), and complementary outputs with dead time for half-bridges (F1-70). D1 D4 Every Armv7-M core also has a simple timer of its own, SysTick, used in F1-77. D5

How the hardware actually does it


A push-pull output stage is a pair of complementary transistors, one to the supply and one to ground; the output data bit turns one of them on. An open-drain stage omits the upper transistor. The input path is a buffer with hysteresis (a Schmitt trigger) that converts the pin voltage into a clean 0 or 1, followed by synchronising flip-flops in the peripheral's clock domain, so a reading is delayed by a clock or two. D3 D1 A timer is a binary counter (F1-17) with a comparator: each counter clock, the counter increments; a digital comparator checks equality with the reload register and resets the counter; a second comparator against the compare register sets or clears an output flip-flop, whose output, through the pin multiplexer, is the PWM signal. D4 An LED driven by PWM really switches fully on and off; its apparent brightness is the eye's averaging, while a motor's winding inductance averages the current. D3

Where the analogy breaks


    

  • A hand flicking a lamp makes soft, uneven edges; a timer's PWM edges are exact to one counter clock. That precision is why PWM can control motors and power converters, not only lamps. D4
    • 

  • "Dimmer" suggests the voltage goes down. It does not: the pin is always fully on or fully off. Something else (the eye, a motor's inductance, an RC filter) does the averaging. Measured with a fast instrument, a 25 % PWM is a full-height pulse a quarter of the time. D3
    • 

  • A kitchen timer rings for anyone in the room; a timer flag is noticed only if someone looks. If the program does not poll the flag or enable the interrupt, the timer keeps counting and the event is lost, or merged with the next one.
    • 




Common mistakes and debugging


    

  • Symptom: PWM frequency slightly low (for example 985 Hz instead of 1 kHz). Cause: P or N set to the divisor instead of divisor − 1. How to find it: compute from the registers with the +1 rules (Listing 1). Fix: P = divisor − 1, N = counts − 1. (Forensic lab.)
    • 

  • Symptom: "100 %" still shows a short low pulse each period. Cause: C = N instead of C ≥ N + 1. Fix: use C = N + 1 for always-high.
    • 

  • Symptom: the tick loop runs at full speed after the first tick. Cause: the flag is never cleared (wrong value written to a write-1-to-clear bit, or the clear is missing). How to find it: read the status register in the debugger after the clear. Fix: clear as the manual says.
    • 

  • Symptom: LED glows faintly when it should be off, or a button reads randomly. Cause: pin left as an input without pull (floating), or wrong pin mode. Fix: configure mode and pull explicitly; check the schematic (F1-79).
    • 

  • Symptom: a duty change causes a visible flicker. Cause: compare value changed mid-period without preload. Fix: enable the compare preload so changes take effect at the update event.
    •

Answers to Check yourself


    

  1. Push-pull drives the pin actively high and low; open-drain only pulls it low and lets it float otherwise. You need a pull-up whenever nothing else drives the high level: open-drain outputs and shared lines (I2C), and inputs that would otherwise float (a button to ground).
    2. 

  2. Counter clock = 16 MHz / 16 = 1 MHz; period = 1,000 counts = 1 ms (1 kHz update events). Common wrong answer: 999 µs, forgetting that N = 999 means 1,000 counts.
    3.

Forensic lab answer key


Root cause. Two off-by-one errors. (1) PSC = 72 divides by 73, not 72: counter clock 986,301.4 Hz instead of 1 MHz. (2) ARR = 1000 gives 1,001 counts per period, not 1,000. Together: 72,000,000 / 73 / 1,001 = 985.316 Hz (model output), matching the measured "about 985 Hz". For full speed he set CCR = ARR = 1000, which is high for 1,000 of 1,001 counts: 99.90 %, with a low pulse of one count (about 1.01 µs at 986 kHz) each period, exactly the "drops low for about a microsecond".


Evidence. Model lines "counter 986301.4 Hz, PWM 985.316 Hz" and "high 1013.889 us" of a 1014.903 µs period, "duty 99.90 %".


Fix. PSC = 71 (72 MHz / 72 = 1 MHz), ARR = 999 (1,000 counts → 1 kHz); full speed CCR = 1000 (≥ ARR + 1: always high); half speed CCR = 500. Verify with show fixed 72000000 71 999 1000 and ... 500.
