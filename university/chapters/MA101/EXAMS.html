  11. M11 (5 points · F0-13 · Understand 5) Multiple choice: 1/3 + 1/6 = (a) 2/9 (b) 1/2 (c) 2/6 (d) 1/9. Explain in one sentence why the correct one is right.

  13. M13 (6 points · F0-14 · Apply 6) Work out −6 + 4, 3 − 8 and 2 − (−5). For the last one, describe the move on a number line.
  14. M14 (4 points · F0-14 · Understand 4) Two mornings: −7 degrees and −3 degrees. Which was colder? Explain with the number line.
  15. M15 (4 points · F0-14 · Apply 4) Mei's lift goes from floor −3 to floor 2. How many floors does it travel? Write the subtraction you used.
  16. M16 (4 points · F0-14 · Analyse 4) A program worked out 3 − 6 and printed 4294967293. What kind of number type was it using, and why should the programmer be suspicious of that result? What type should be used instead?
  17. M17 (3 points · F0-15 · Remember 3) Multiple choice: 24 = (a) 8 (b) 16 (c) 6 (d) 24.
  18. M18 (6 points · F0-15 · Apply 6) How many on/off patterns can 7 light switches make? What is log2(64)? Write 105 as an ordinary number.

Practical (P) — 50 %

Task: "How many helpers for how many jobs." A school fair needs 300 leaflets folded; helpers come in teams of 32, and each helper folds at most one leaflet. Plan the work on paper, complete a small C++ program that does the same plan, run it, and diagnose a broken plan. (These are exercise values; later courses use the same plan with blocks of 256 threads.)

Time limit: 60 minutes. Allowed documentation: the nine MA101 chapters (printed or on screen), your own notes, and the compiler's own messages. Not allowed: other people, the internet, and any program other than the compiler and a text editor. Engineers use documentation; you may too.

Starting files — candidates receive only these three (ruling B7): helpers_exam_start.cpp, the program with three marked TODO lines; helpers_exam_start.in, the exam input 300 32; and plan_bug.out, the evidence for Part C (its text is also printed in Part C). They live in university/labs/MA101-P/ together with the reference solution and the evidence programs, which are shown in full after this section for markers and are not handed to candidates. The build command is written at the top of the starting file and is the one used in every MA101 lab.

Part A — the plan on paper (40 points)

  1. (8) Teams: work out the number of teams with the rounding-up formula of F0-12, showing the division and the remainder, and say why one fewer team is not enough.
  2. (4) Helpers and idle helpers: how many helpers come, and how many have no leaflet?
  3. (8) Tickets: write the ticket formula of F0-16 with the names used in this task (team, seat, team size), and work out the tickets of team 0 seat 0, team 1 seat 0 and team 9 seat 11.
  4. (8) Allowed range: write the allowed range of tickets with two inequality signs, draw it on a number line with the right filled and empty dots (F0-19), and say how many whole numbers it holds.
  5. (6) Bounds check: write the check each helper must do, in words and in symbols. Which is the last ticket that works, and which is the first idle ticket? Give the team and seat of each.
  6. (6) One more leaflet: Part B also plans 320 leaflets (an exact fit for teams of 32). If 321 leaflets arrive instead of 320, what happens to the number of teams and the idle helpers? Explain with the staircase of F0-18.

Part B — the program (40 points)

  1. (24) Complete the three TODO lines of helpers_exam_start.cpp: the rounded-up number of teams, the ticket formula and the bounds check. Do not change any other line.
  2. (8) Build it with the command at the top of the file (it must build with no warnings, because the flags turn warnings into errors) and run it with helpers_exam_start.in. Write the six lines it printed on your answer sheet.
  3. (8) Change the input to 320 32 and run again. Compare both runs with your Part A answers and write one sentence about each difference you see (there should be none for 300; say what changed for 320).

Part C — diagnose a broken plan (20 points)

teams: 10, helpers: 320
working: 301, idle: 19

last working ticket: 300 (team 9, seat 12)

  1. (4) Which printed numbers are impossible for 300 leaflets? Quote them.
  2. (8) Which of the three plan ideas (rounding up, ticket formula, bounds check) is broken? Prove it from the evidence: which ticket is the first wrong one, and what does that tell you about the comparison used?
  3. (4) Write the wrong line and the corrected line.
  4. (4) In a program that writes into a list of 300 items, what could this mistake have done? Name the tool every MA101 listing is built with that would report it.

How the practical is marked

100 points: Part A 40, Part B 40, Part C 20. Part A and Part C are marked against the key with the points shown per item; a wrong number with correct working keeps half the item's points. Part B is marked on the real run: the three completed lines (8 each; a line is right when the program prints the key's numbers for both inputs), a clean build (8: no warnings or errors; 4 if it needed one fix after a compiler message), and the comparison sentences (8). A program that does not build gets the points for any TODO line that is correct on paper. Reference solution and real runs: university/labs/MA101-P/ (helpers_exam.cpp, helpers_exam.out, helpers_case2.out, helpers_case3.out), run by the Lab Engineer with run_lab.sh; the key quotes them. Pass mark 50; a candidate who scores below 50 may retake Part B and Part C once with a different input. The mark is returned with written, encouraging feedback per part (B6).

Course project — 30 %

Goal. A poster (paper or one HTML page, no scripts, no external assets) that explains powers of two with real examples from computers, each example sourced. The F0-15 mini-project is its starter; the F0-19 mini-project (the helpers plan) supplies one example.

Requirements

  • Functional. At least eight examples of a power of two, each written both ways (28 = 256) and each with a one-sentence meaning. At least one example of each kind: a calculation you did yourself (switch patterns, folds, halvings); a program run you made yourself (Listing 1 or 2 of F0-15, or helpers_plan.cpp of F0-19, with its output and the date); a number read from a real device's own label, settings screen or documentation (write exactly where you read it and when). One example must show the difference between 210 and 103 (and, for L1 learners, between 220 and 106). One example must be the helpers plan: jobs, team size 256, teams, idle helpers.
  • Quality. A drawing of a row of eight switches with place values (F0-15 Figure 1 style). A clear title, readable from two metres on paper. A source list: every number points to its source; a number without a source is removed, not guessed (AH-21). No URL unless you opened it yourself and wrote the date.
  • Honesty. Numbers measured on your own computer are labelled "measured on my computer" with the date. The poster does not claim that a byte has 8 bits everywhere; it says what your run printed (F0-15, Listing 2).

Constraints

No hardware beyond a home computer with the course compiler (optional: a device with a settings screen or label to read). About 6 hours of work spread over the second half of the course. Paper poster: at most two A3 sheets. HTML page: one file, inline styles only, no script, no images from the internet (a drawing you made, as an inline SVG or a photo you took, is fine).

Deliverables

  1. The poster or HTML file.
  2. A one-page source list: for each example, the calculation, the program run (source file name, output, date) or the document or screen it came from.
  3. A check sheet: for every power of two on the poster, the halving count back to 1 (its log2) or the run that printed it, so that every number is checked twice.
  4. A five-minute show-and-tell to a family member or classmate; they ask one question, and you write down the question and your answer.

Milestones

  1. After F0-15: the starter from the F0-15 mini-project: four examples with sources (that mini-project's 4-point rubric is the gate).
  2. After F0-17: eight examples, the 210 versus 103 example, the switch drawing, and the first source list.
  3. After F0-19: the helpers-plan example added (from helpers_plan.cpp or by hand), the check sheet complete, the poster finished and shown.
