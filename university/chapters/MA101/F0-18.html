Story hook

Analogy

Priya and Daniel want to know when a toy robot will bump into the fridge. The robot rolls across the kitchen floor in a straight line, at a steady speed. They do not have a real robot yet, so they use the university's tiny toy-robot simulator, a small program that pretends to be one.

Every second, the simulator prints how far the robot is from the kitchen door. Daniel copies the numbers into a table. Priya draws a dot on squared paper for each row. The dots line up perfectly, like beads on a string.

"Look," says Priya, laying a ruler along the dots. "We don't need to wait. The line tells us where it will be at any time." Daniel points at the fridge mark on the paper. "And when it gets there."

A rule that turns each time into one distance is a function. A picture of it is a graph. This chapter teaches both.

What you will be able to do

  • Explain what a function is: a rule that gives exactly one output for each input.
  • Make a table of values from a rule such as d = 10 + 15t, and plot it as points (t, d) on a graph.
  • Read a straight-line graph: its starting value and its slope (change per step).
  • Predict from a graph or rule, forwards ("where at t = 7?") and backwards ("when at 130 cm?").
  • Recognise a staircase graph, such as "teams needed for this many jobs".
Jargon box
Function
Simple words: a rule that takes a number in and gives exactly one number out. Analogy: a kitchen gadget that always does the same thing: put the same thing in, get the same thing out. Precise: a rule f that assigns to every allowed input x exactly one output f(x); for example f(x) = 3x − 2. Not the same as a function in a program (KID102 F0-34), which is a named piece of code. D1
Input and output
Simple words: what goes into the rule, and what comes out. Analogy: the time you ask about, and the distance the simulator tells you. Precise: for y = f(x), x is the input (independent variable) and y is the output (dependent variable). D1
Coordinates
Simple words: a pair of numbers that says where a point is: across first, then up. Analogy: "third tile from the door, fifth tile from the wall". Precise: an ordered pair (x, y): x is the position along the horizontal axis, y along the vertical axis. D1
Axis
Simple words: one of the two number lines at the edge of a graph. Analogy: the edge of the kitchen floor where you count tiles. Precise: a number line used to measure one coordinate; the horizontal axis (usually the input) and the vertical axis (usually the output) cross at (0, 0). D1
Graph
Simple words: a picture of a function made of all its points. Analogy: Priya's dots on squared paper. Precise: the set of points (x, f(x)) for all allowed inputs x, drawn on a pair of axes. D1
Slope
Simple words: how much the output changes when the input goes up by 1. Analogy: how many centimetres the robot moves each second. Precise: for a straight-line function y = mx + c, the number m; between two points it is (change in y) ÷ (change in x). D1R2

Layer 1 — the kid explanation

A function is a rule that turns one number into another. Think of it as a machine, as in Figure 1. You drop a number in, the machine follows its rule, and one number comes out.

The number you put in is the input. The number that comes out is the output. A function is fair and boring in a useful way. The same input always gives the same output. Put in 4 seconds today or next week: the robot rule always says 70 cm.

Tables of values

The robot simulator uses the rule d = 10 + 15t. Here t is the time in seconds and d is the distance from the door in centimetres. At t = 0 the robot is already 10 cm from the door. Each second it moves 15 cm more.

A table shows some inputs and their outputs side by side. For t = 0, 1, 2, 3 the distances are 10, 25, 40, 55. The code walk-through shows the simulator's full table, up to t = 8.

From table to graph

A graph turns the table into a picture. Draw two number lines at right angles. Each is called an axis. The flat one, across the bottom, is for the input: time. The upright one, on the left, is for the output: distance.

Each row of the table becomes one dot. The pair (4, 70) means "go across to 4, then up to 70". Such a pair is called the dot's coordinates. Across first, then up. Swapping them puts the dot in the wrong place.

For the robot, all the dots lie on one straight line (Figure 2). The line crosses the upright axis at 10, the starting distance. And it climbs by 15 for every step across. That climb per step is called the slope.

Predicting with a graph

Now you can predict. Where is the robot at t = 7? Use the rule: 10 + 15 × 7 = 115 cm. Or find 7 on the time axis, go up to the line, then across to read 115.

You can also predict backwards. The fridge is 130 cm from the door. When does the robot reach it? Find 130 on the distance axis, go across to the line, then down: t = 8. With the rule, that is the equation 10 + 15t = 130 from F0-17. Take 10 from both sides: 15t = 120. Divide by 15: t = 8.

Not every graph is a straight line

Remember the helpers formula from F0-12. Teams of 4 helpers, and some number of jobs. How many teams? For 1 to 4 jobs, one team. For 5 to 8 jobs, two teams. For 9 to 12, three.

That is a function too: jobs in, teams out. But its graph is a staircase (Figure 3). It stays flat, then jumps up by a whole team. You cannot have 2.25 teams. One extra job can cost a whole new team.

Layer 2 — the student explanation

A function f assigns to each allowed input x exactly one output, written f(x). The set of allowed inputs matters: the robot rule only makes sense for t from 0 up to the moment it reaches the fridge, and the teams function only for whole numbers of jobs. F0-19 writes such allowed ranges with inequalities. D1

Functions of the form y = mx + c have straight-line graphs. The number c is the output when x = 0, where the line crosses the vertical axis. The number m is the slope: between any two points, (change in y) ÷ (change in x). For the robot, between t = 2 and t = 5: (85 − 40) ÷ (5 − 2) = 45 ÷ 3 = 15 cm per second, the same everywhere on the line. D1R2

A slope can be negative. For y = 20 − 4x, the outputs for x = 0, 1, 2 are 20, 16, 12: the line goes down 4 for each step right, so the slope is −4, and y reaches 0 at x = 5. A robot driving towards the door instead of away from it would have a graph like this. D1R2

Not all functions are straight. The doubling function of F0-15, y = 2x, curves upwards ever more steeply (F0-15 Figure 2). The teams function, teams = (jobs + 4 − 1) ÷ 4 with whole-number division, is a step function. D1R2

Layer 3 — the engineer's depth

Note

For the curious. Nothing here is needed for the quiz.

Listing 1 contains a C++ function, distanceAt. It behaves like a maths function: same input, same output. But C++ functions in general need not. A C++ function may print, read input or change stored values, and then two calls with the same input can give different results. Engineers prize functions that behave like maths functions, because they are easy to test. KID102 (F0-34) teaches C++ functions. R1B2

In this university's GPU courses, the number of blocks for n elements is exactly this staircase function with a block size of 256: 1,000 elements need 4 blocks and 1,025 need 5. Robotics courses use straight-line functions as "the line a robot should follow". U1R2

How the hardware actually does it

A computer works out a function only at the inputs it is given, one at a time. Listing 1 asks for t = 0, 1, … , 8 and gets nine numbers; it knows nothing about t = 2.5 unless asked. The straight line in Figure 2 is drawn by us, assuming the speed is steady between the dots. When you meet robots in F9, keep this in mind: a program only knows the values it has actually computed or been given. R1

Where the analogy breaks


    

  • Real machines can jam; functions cannot. A real kitchen gadget may give a different result on a bad day. A function gives the same output for the same input, every time.
    • 

  • Real robots do not keep a perfect speed. Wheels slip, floors differ, batteries run down. The simulator's rule is perfect because it is only a rule. A real robot's graph would wobble; that is why F9 measures instead of assuming.
    • 

  • The line between dots is a guess. The simulator computes whole seconds only. Joining the dots assumes nothing strange happened in between.
    • 

  • A graph of time never runs backwards. The function machine accepts any number, but t = −3 seconds has no meaning for this robot. The allowed inputs are part of the function (F0-19).
    •

Lab


Goal


Graph a robot's distance over time from a table, find its starting value and slope, and make two predictions you then check with the rule.


Hardware and software needed


Squared paper, a pencil, a ruler. The table from Listing 1 (printed above), or a computer with a C++ compiler to run the simulator yourself; this build used g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0. No real robot is needed. Optional extension: a stopwatch and a tape measure.


Safety


None beyond normal care. For the optional walking extension, use a clear, flat floor and walk slowly.


Steps


    

  1. Draw a time axis from 0 to 8 (one big square per second) and a distance axis from 0 to 140 (one big square per 20 cm). Label both with units.
    2. 

  2. Copy the simulator's table. Plot one dot per row: across to t, up to d.
    3. 

  3. Lay a ruler along the dots and draw the line.
    4. 

  4. Read off the starting distance (where the line meets the upright axis) and the slope (pick two dots far apart).
    5. 

  5. Predict d at t = 6.5 from the graph. Then compute it with the rule.
    6. 

  6. Predict when d = 100 from the graph. Then solve 10 + 15t = 100.
    7. 

  7. Optional: change speed to 10 in Listing 1, predict the new table, run it, and plot the new line on the same axes.
    8. 



Expected observations


All nine dots lie on one straight line, crossing the upright axis at 10, with slope 15 cm per second, as in run R1. Step 5 gives 10 + 15 × 6.5 = 107.5 cm; step 6 gives t = 6 s. With speed 10, the new line starts at the same place and is less steep.


Verification


Your graph readings agree with the rule to within half a small square. Every table row lies exactly on your line.


Troubleshooting


    

  • Dots do not line up → an axis scale is uneven or a dot is swapped → check each axis's numbers are equally spaced; check "across, then up".
    • 

  • The line misses the upright axis at 10 → the line was drawn from (0, 0) → a rule with a starting value does not pass through (0, 0).
    • 

  • The program's table differs from yours → you changed start or speed → compare lines 7–8 with Listing 1.
    • 



Extension


Measure yourself instead of the simulator. Walk slowly and steadily past marks on the floor while a partner calls out each second and notes your mark. Make your own table and graph. Write your own numbers: they are your measurement, and they will not lie perfectly on a line. Why not?

Summary


    

  • A function gives exactly one output for each allowed input; the same input always gives the same output.
    • 

  • A table lists inputs and outputs; a graph draws them as points (x, y), across then up.
    • 

  • A straight-line function y = mx + c starts at c (when x = 0) and changes by the slope m per step.
    • 

  • Slope = change in output ÷ change in input, using two points.
    • 

  • Predict forwards by substituting, backwards by solving an equation or reading the graph.
    • 

  • Some functions are staircases (teams needed) or curves (doubling).
    • 

  • A computer computes a function only at the inputs it is given.
    •
