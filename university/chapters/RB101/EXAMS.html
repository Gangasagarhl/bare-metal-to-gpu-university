Exams and course project of RB101 "Robots for kids: sense, think, act" (chapters F9-01 to F9-07; level L0–L1; 3 credits). Written in the exam pass of 2026-10-10 under owner ruling B4 and guide sections 11.3–11.5. Every question can be answered from the seven chapters; every output quoted below is copied exactly from a real run on the build machine (g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0, Linux x86_64, course flags). All distances, speeds, gains, thresholds, squares and step limits are the course's own simulator values (owner ruling A4), never real-part numbers. Answer keys are in the "Answer keys" appendix.

Note

Weights. RB101 is an L0–L1 course, so it uses the L0 option of guide 11.4 (owner ruling B6): quizzes 20 %, practical 50 %, course project 30 % (an exercise value, ruling A4), with encouraging written feedback. RB101 has 3 credits, so it has no midterm; the midterm's weight moves to the final (guide 11.4), and the final itself is an ungraded practice paper under ruling B6. Candidates receive only the practical's starting files (ruling B7).

Safety

Every paper and the practical use only a computer: the course card's practical is "program the simulated robot through a course", and the course project is a line follower in simulation. No real robot moves in any RB101 exam. The optional supervised kit session of F9-07 Part B is not examined; if a teacher or parent offers it, the six safety rules of F9-07 apply unchanged (simulator first, adult supervision, clear zone, physical emergency stop within reach and tested, speed limit set low, the kit maker's battery rules; no LiPo, no mains), and it remains untested on hardware in this build (owner ruling C3).

Quizzes (Q) — 20 %

Each chapter's "Check yourself" is quiz Q of that chapter (graded variant: the same questions, answered in writing before the chapter's "Answers to Check yourself" section is read). Each of the seven quizzes is worth one seventh of 20 % (about 2.9 %) of the course mark; marking uses the chapter's own answers, with the generic rubric of guide 11.4 for the "explain in your own words" and "apply to a new case" questions.   16. F16 — forensic question (20 points; Apply 2, Analyse 12, Evaluate 6).

    Scenario. Priya built the course project in the simulator: a line follower with gain 0.5 (F9-05), a speed limit of 3 and a latched emergency stop (F9-07). To test the stop she made the program press it at step 2. "Something is wrong," she says. "The robot moved 4 units in the first step although the limit is 3. And after the stop it stood still for one step and then carried on by itself. The simulator must be broken."

    Evidence 1 — the source, labs/RB101-P/forensic_follower.cpp, copied exactly:

    // Evidence for the RB101 final exam (forensic question): Priya's line follower.
// Priya says: "I used gain 0.5 like F9-05, a speed limit of 3 and a latched stop like F9-07.
// I pressed the stop at step 2 to test it. But the robot moved 4 units in one step although
// the limit is 3, and after the stop it stopped for one step and then carried on."
#include <algorithm>
#include <cmath>
#include <iomanip>
#include <iostream>
#include <string>

int main()
{
    const double gain = 0.5;         // how strongly the robot corrects (F9-05)
    const double speedLimit = 3.0;   // the biggest sideways move allowed per step (F9-07)
    const int stopPressedAt = 2;     // in this test, someone presses the stop at step 2
    double distance = 8.0;           // start 8 units to the right of the line
    bool stopped = false;

    std::cout << "step  distance    steer  allowed  stop?      -10.......0.......+10\n";
    for (int step = 0; step <= 12; ++step) {
        stopped = (step == stopPressedAt);                 // the stop is pressed at this step

        double error = distance;                           // SENSE
        double steer = -gain * error;                      // COMPARE: how far to move back
        double allowed = std::clamp(steer, -speedLimit, speedLimit);   // obey the speed limit
        if (stopped) {
            allowed = 0.0;                                 // the stop beats everything else
        }

        std::string row(21, ' ');
        row[10] = '|';
        long column = 10 + std::lround(distance);
        if (column >= 0 && column <= 20) {
            row[static_cast<std::size_t>(column)] = '*';
        }
        std::cout << std::setw(4) << step << std::fixed << std::setprecision(2)
                  << std::setw(10) << distance << std::setw(9) << steer << std::setw(9)
                  << allowed << std::setw(7) << (stopped ? "yes" : "no") << "      " << row
                  << '\n';

        distance = distance + steer;                       // CORRECT: the robot moves
    }
    return 0;
}

Course project — 30 %

Goal. A line-following robot in simulation, explained to a friend (the course card). It must use what the course taught: a sense–compare–correct loop with a gentle gain (F9-05), a speed limit and a latched emergency stop inside the loop (F9-07), a log you can read line by line (F9-04), a run that is the same every time (F9-06), and a safety page with the six rules (F9-07). It is started in the F9-05 mini-project (the one-page explanation) and finished in the F9-07 mini-project.

Requirements.

  • Functional: a C++ text simulator in the course style (start from steer.cpp of F9-05 and safe_drive.cpp of F9-07) in which the robot starts off the line, steers with the rule steer = − gain × error with a gain below 1, obeys a speed limit on every command, and obeys a latched stop that is checked at the start of every round; it prints one log row per step (step, distance, allowed command, stop state, and the text plot) and a final line with the distance, how many times the line was crossed and whether the stop was pressed. The run must read a scripted list of "pushes" (sideways nudges, one per step, standing for bends and bumps) from an input file so that the robot has something to correct.
  • Quality: builds with the course command with no warnings; the steering rule lives in one place (a function or one clearly marked block); every simulator number is labelled as a simulator value in a comment; a hand-worked check of the rule for at least four cases (far off on one side, a little off on the other side, on the line, stop pressed) is printed before the run and reports 0 failures.
  • Explanation: a one-page explanation for a friend who has never programmed (F9-05 mini-project): the sense–compare–correct loop in the friend's words, one gentle run and one zig-zag run copied from real runs with their gains, and how the gain was chosen; plus a safety page (F9-07 mini-project) with the six rules and which two of them the program itself follows, and which ones software cannot replace.

Constraints. No hardware: the simulator version is the whole project. (A supervised kit session is optional, outside the project, only under F9-07's Part B rules, and untested on hardware in this build, ruling C3.) About 6 hours of work spread over the course, after F9-05. One source file of at most about 100 lines is enough.

Deliverables. (1) the one-page explanation from the F9-05 mini-project; (2) the source file; (3) the build log made with the course flags; (4) one recorded run with its input file (.in) and output (.out) that can be repeated line for line, showing the self-check, at least one push on each side of the line, and the stop pressed near the end; (5) the safety page; (6) a half-page report in the learner's own words: the gain chosen and why, one push traced by hand for one step, one mistake found and how (log, trace or self-check); (7) a five-minute demo to a friend and the examiner: run the self-check, run the scripted run, explain one log row, and let the friend say why "steer harder" can be worse.

Milestones. (M1, after F9-05) the one-page explanation with a gentle run and a zig-zag run from real runs. (M2, after F9-06) the simulator builds, reads pushes from a file, and the self-check reports 0 failures. (M3, after F9-07) speed limit and latched stop in the log; the safety page. (M4, end of course) recorded run, report and demo.
