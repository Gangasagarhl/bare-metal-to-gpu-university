Story hook

Analogy

Most kitchens are built once: the stove is bolted down, the sink is plumbed in, and changing the layout means builders and months of work. The restaurant's event hall has something different: a kitchen of movable stations on wheels, each with a small answer card that says what the station does today, and a floor full of sockets so that any station can be connected to any other.

On Monday the hall is set up as a bakery. On Tuesday Ana loads a new floor plan, the stations are re-labelled and re-connected, and it is a noodle bar. Nothing was built; everything was configured.

That is a field-programmable gate array, an FPGA: a chip full of small, identical logic blocks and programmable wiring, which becomes whatever circuit you describe, and can be changed again. In this chapter you see the building block, a lookup table, run it as a program, watch a synthesis tool map your counter onto lookup tables, and investigate a counter that grew eight times larger than needed.

What you will be able to do

  • Explain what an FPGA is made of: lookup tables, flip-flops, programmable routing, I/O blocks and block memories.
  • Show how a 4-input lookup table becomes any 4-input logic function by choosing its 16 configuration bits.
  • Read a synthesis report that maps a design onto lookup tables and flip-flops.
  • Describe the FPGA design flow from HDL to a configured board.
  • Diagnose a design that uses many more flip-flops than it needs (the forensic lab).
  • Optionally, put a counter on a real board, with the safety rules for doing so.
Jargon box
FPGA (field-programmable gate array)
Simple words: a chip whose circuit you can choose, and change, after it is made. Analogy: the event-hall kitchen of movable stations. Precise: an integrated circuit made of an array of configurable logic blocks, programmable interconnect and I/O blocks, whose function is set by loading configuration data. D5 “FPGAs: Field Programmable Gate Arrays”, “General FPGA Layout” D6 ch. 1
Lookup table (LUT)
Simple words: a tiny memory that stores the answer for every input pattern. Analogy: the station's answer card: find your inputs' line and read the answer. Precise: a k-input LUT is a 2k-bit memory addressed by its k inputs; its contents are configuration bits, so it implements any Boolean function of k inputs. D7 “Look-Up Table” D5 “LE: Logic Element”
Configurable logic block
Simple words: one repeated tile of the FPGA, with lookup tables and flip-flops. Analogy: one movable station. Precise: the basic logic tile of an FPGA, usually grouping LUTs, flip-flops, multiplexers and carry logic; names and contents differ by vendor. D7 “CLB Overview” D5 “LE: Logic Element”
Programmable interconnect
Simple words: wires with switches that can be set to connect any block to others. Analogy: the floor sockets and cables between stations. Precise: routing channels and switch boxes whose connections are set by configuration bits. D5 “FPGAs: Field Programmable Gate Arrays” D6 ch. 1
Bitstream
Simple words: the file that tells the FPGA what to become. Analogy: the full setup sheet for the hall: every answer card and every cable. Precise: the configuration data, produced by the vendor toolchain, that sets every LUT, flip-flop option and routing switch of a specific device. D6 ch. 1
Place and route
Simple words: deciding which block does which job and which wires connect them. Analogy: deciding where each station stands and which cables to run. Precise: the tool steps that assign netlist cells to physical sites on the device and choose routing resources, followed by timing analysis. D5 “FPGA Design Flow” D11 §2
Block RAM
Simple words: ready-made memory blocks inside the FPGA. Analogy: built-in pantry shelves in the hall. Precise: dedicated SRAM blocks in the FPGA fabric, usually with synchronous (clocked) read ports. D8 RAMB18E1
Constraints file
Simple words: a file that says which pin is which and how fast the clock is. Analogy: the list of which hall door is the delivery door. Precise: a toolchain input mapping top-level ports to package pins and stating clock periods and I/O standards; its format is vendor-specific. (Not checked against a vendor manual in this course: see the box in Layer 3.)

The idea in pictures

Layer 1 — the kid explanation

Most chips do one job forever. The chip in a calculator is always a calculator.

An FPGA is a chip that can become many different circuits. Inside it are thousands of tiny, identical blocks. Each block has a little answer card: "if the inputs are this, answer that". There are also many wires with switches, so any block can be connected to others.

You write a description of the circuit you want, like the Verilog in the last chapters. A program on your computer works out what each answer card should say and which switches to close. It sends that setup to the chip, and the chip becomes your circuit: a counter, a traffic light, even a small computer.

If you want something else tomorrow, you send a new setup. Nothing is soldered and nothing is thrown away.

Layer 2 — the student explanation

Any function from a memory

A truth table with 4 inputs has 16 rows. If you store the 16 output bits in a 16-bit memory and use the 4 inputs as the address, reading the memory is evaluating the function D5 “Logic with Memory Arrays”. That is a lookup table. Since there are 216 = 65,536 ways to fill 16 bits, one 4-input LUT can implement any of the 65,536 Boolean functions of 4 inputs W1. Listing 1 does this in software: it fills a LUT from a function by trying all 16 inputs, then checks that the LUT gives the same answer as the function for every input R1.

Logic blocks, routing and the rest

A LUT followed by a flip-flop can be one bit of any synchronous design: the LUT computes the next-state logic for that bit, the flip-flop stores it D5 “LE: Logic Element” D7 “CLB Overview”. An FPGA repeats this tile many times and adds programmable routing between tiles, I/O blocks for the pins, block RAMs for memories (F1-20), and usually dedicated arithmetic and clock-distribution resources (F1-18) D5 “FPGAs: Field Programmable Gate Arrays” D7 “CLB Overview” D10 §2.2.3.

The design flow

  1. Describe the design in an HDL and test it in simulation (F1-21).
  2. Synthesise: turn it into a netlist of LUTs and flip-flops D2 synth. Listing 2's run does this step with Yosys for 4-input LUTs.
  3. Place and route onto a specific device, then check timing: does every path fit within the clock period you constrained D5 “FPGA Design Flow” D11 §2?
  4. Generate the bitstream and load it into the device through one of its configuration interfaces; the JTAG interface, for example, is always available on one vendor's device family D6 ch. 1. How your board connects that interface to your computer is in the board's documentation.

Steps 3 and 4 need the toolchain for your exact device, so this build could not run them (see the unverified box). Steps 1 and 2 are the same for every device and run in the lab.

Layer 3 — the engineer's depth

Why FPGAs matter. There is no manufacturing step: a new design is a new bitstream, loaded into the configuration memory of the same chip D6 ch. 1. The price of this flexibility, and where FPGAs are used, are discussed in textbooks that were not opened in the verification pass (see the box below). The accelerator courses come back to the trade-off between flexible and specialised hardware.

Reading a LUT netlist. In Listing 2's mapped netlist, each LUT is written as a constant shifted by its inputs, for example 16'h7f80 >> count: a 16-bit configuration indexed by a 4-bit address R2. That is exactly Listing 1's (config_ >> address) & 1, and the constant matches: Listing 1 computed 0x7F80 for "bit 3 of count + 1", and the synthesis tool chose the same 16 bits for the next value of count[3] R1 R2.

Resources are counted, not free. Every FPGA has a fixed number of LUTs, flip-flops and block RAMs. Synthesis reports tell you how much of that budget a design uses; the forensic lab shows how a careless declaration can multiply it.

To check the open points, read the vendor manual of the chosen board's FPGA family (architecture, configuration and constraints chapters) and a textbook chapter on FPGAs, and record the sections in the dossier.

How the hardware actually does it

Each LUT's bits and each routing switch are set by configuration data. In one vendor's family, the configuration is held in volatile memory inside the chip, so it is lost when the power goes off, and the device loads its bitstream again after power-up, for example from an external non-volatile memory chip D6 ch. 1. Other families keep their configuration in on-chip flash memory, which keeps it without power D9. Clocks reach the flip-flops through dedicated global, low-skew clock routing, so that the clock edge reaches every flip-flop at nearly the same time (F1-18); FPGA design guides recommend PLL outputs as the source of internally generated clocks D10 §2.2.3. What a development board's USB connection provides (power, programming, a serial port) depends on the board; read its documentation.

Worked example

Problem: compute by hand the 16 configuration bits of a 4-input LUT for the full adder's sum a ⊕ b ⊕ c (input d unused), as Listing 1 numbers the addresses (a is bit 0, b bit 1, c bit 2, d bit 3).

  1. For addresses 0–7 (d = 0), the sum is 1 when an odd number of a, b, c are 1: addresses 1, 2, 4, 7 W1.
  2. Bits 7…0 are then 1 0 0 1 0 1 1 0 = 0x96.
  3. For addresses 8–15, d = 1 but d is unused, so the pattern repeats: 0x96 again.
  4. Configuration: 0x9696 W1. Listing 1's run computes the same value and checks all 16 inputs: config = 0x9696 checked 16 inputs, 0 wrong R1.
  5. For the 4-input AND, only address 15 gives 1: bit 15 set, 0x8000, as in Figure 2.

Where the analogy breaks


    

  • Movable stations can be anything; LUTs cannot. A LUT computes one function of at most k inputs D7 “Look-Up Table”. Bigger functions need several LUTs chained, as the counters of Listing 2 and the forensic lab show R2 R4.
    • 

  • Rearranging the hall moves furniture; reconfiguring moves only data. A new circuit is a new bitstream loaded into the chip's configuration memory D6 ch. 1. The values the old circuit had stored in its flip-flops are not part of the new bitstream, so save anything you need before reconfiguring.
    • 

  • The hall's cables are free; FPGA routing is not. Routes through programmable interconnect add delay to a path, and the timing analysis after place and route checks every path against the clock period, as in F1-18 D11 §2.

Safety
Learners at levels L0–L2 do Part B only with an adult supervising. Use only a board powered from USB (low voltage); never connect anything to mains electricity. Summary


    

  • An FPGA is an array of LUT-plus-flip-flop blocks, programmable routing, I/O, block RAM and clock resources, configured by a bitstream.
    • 

  • A k-input LUT is a 2k-bit memory addressed by its inputs: any function of k inputs.
    • 

  • Flow: HDL and simulation → synthesis to LUTs and flip-flops → place and route with timing → bitstream → device.
    • 

  • Synthesis reports count resources; check them against your intent.
    • 

  • Declarations decide flip-flop counts: an integer is 32 bits.
    • 

  • Board work needs the board's own documentation and, at L0–L2, adult supervision.
    •

Forensic lab answer key


Observation: both counters print the same digits and pass R3; the classmate's uses 4 flip-flops and 6 LUTs, Omar's 32 flip-flops and 64 LUTs, eight times the flip-flops R4. A counter to 9 needs ⌈log2 10⌉ = 4 bits W1. Hypotheses: (1) the tool is bad: ruled out, because the same tool maps the classmate's counter to the minimum; (2) Omar's description asks for more storage: confirmed. Root cause: integer n; (line 9 of decade_big.v): the tools treat a Verilog integer as a 32-bit variable: Yosys made 32 flip-flops from it R4. (The standard's definition of integer, in D4, was not opened.) The tool cannot remove the upper 28 bits, because the description reads them: n == 9 compares all 32 bits and n + 1 computes all 32 bits. The tool does not know that n never exceeds 9; proving that is not part of normal synthesis. Fix: reg [3:0] n;, or keep the output register as in decade.v. Prevention: read the resource report after every synthesis and compare flip-flop counts with the widths you intended; reserve integer for testbenches and loop indices. How the evidence was made: the classmate's counter rewritten with an integer state variable. Wrong answers: "simulation would have shown it" (it cannot: the values are the same); "it's the testbench" (resource use does not depend on the testbench). Note that board_top.v's 32-bit ticks has the same cost; Lab step 5 asks you to size it.
