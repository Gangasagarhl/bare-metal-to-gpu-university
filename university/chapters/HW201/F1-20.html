Story hook

Analogy

The kitchen keeps two kinds of notes. On the wall by the pass hang little flip signs, one per table: "waiting" or "served". A flip sign stays exactly where you flipped it for as long as the lights are on. It is quick to read and quick to change, but each sign takes a lot of wall.

In the pantry the kitchen keeps far more information in a cheaper way: rows of small jars, where a full jar means 1 and an empty jar means 0. Thousands fit on one shelf. The catch is that the jars slowly evaporate. So Sam, the kitchen porter, walks along the shelves all day, one row at a time, and tops up every jar that is still more than half full. A jar that Sam forgets for too long becomes "empty", and its 1 is gone.

The flip signs are SRAM; the jars are DRAM; Sam's endless walk is refresh. In this chapter you build both kinds of cell in models you can run, a small RAM in the logic simulator, and you investigate a refresh walk that forgot half the shelf.

What you will be able to do

  • Describe how an SRAM cell holds a bit with two inverters in a loop, and how it is read and written through access switches.
  • Describe how a DRAM cell holds a bit as charge on a capacitor, and why it needs refresh and loses its value when read.
  • Explain how a memory array uses an address decoder, word lines and bit lines.
  • Build and test a 16 × 8 RAM in the logic simulator.
  • Compare SRAM and DRAM in density, speed and refresh, and say where each is used.
  • Diagnose a refresh counter that is too narrow (the forensic lab).
Jargon box
Memory cell
Simple words: the smallest part of a memory: it stores one bit. Analogy: one flip sign, or one jar. Precise: a circuit storing one bit that can be selected for reading and writing by a word line and connected to one or two bit lines. D1
SRAM (static RAM)
Simple words: memory whose cells hold their bit for as long as the power is on. Analogy: the flip signs. Precise: random-access memory whose cell is a bistable loop of two cross-coupled inverters plus access transistors (six transistors in the common design); "static" means no refresh is needed. D1 D2
DRAM (dynamic RAM)
Simple words: memory that stores each bit as a tiny electric charge, which leaks away and must be topped up. Analogy: the evaporating jars. Precise: random-access memory whose cell is one access transistor and one capacitor; the charge leaks, so the cells must be refreshed periodically, and reading disturbs the charge, so a read must be followed by a write-back. D1 D2
Refresh
Simple words: reading each row and writing it back before its charge leaks too far. Analogy: Sam topping up the jars, row by row. Precise: periodic read-and-restore of every DRAM row within a maximum interval set by the part's specification. D1
Word line
Simple words: the wire that picks one row of cells. Analogy: the shelf label Sam reads to pick a row. Precise: the row-select line, driven by the address decoder, that turns on the access transistors of every cell in one row. D1
Bit line
Simple words: the wire that carries one bit into or out of the selected cell. Analogy: the hatch through which a jar's level is passed out. Precise: a column line shared by all cells in a column; SRAM uses a pair (bit line and its complement), DRAM one line per cell column. D1
Sense amplifier
Simple words: a circuit that notices a very small change on a bit line and turns it into a clear 0 or 1. Analogy: Sam's practised eye for "more or less than half full". Precise: a differential amplifier on each bit line that resolves the small voltage change caused by a cell into a full logic level (and, in DRAM, restores the cell). D1
Memory array
Simple words: cells arranged in rows and columns. Analogy: the pantry shelves. Precise: a two-dimensional grid of cells with a row decoder driving word lines and column circuits on the bit lines. D1
Volatile memory
Simple words: memory that forgets when the power goes off. Analogy: the signs fall when the lights go out; the jars dry out. Precise: memory that loses its contents without power; SRAM and DRAM are both volatile. D1

The idea in pictures

Layer 1 — the kid explanation

A computer's memory is made of billions of tiny places that each keep one bit. There are two popular ways to build such a place.

The first way is a little loop of two NOT gates. Each one says the opposite of the other, so they hold each other steady: one says 1, the other says 0, and they stay that way. This is SRAM. It is fast and it never needs help, but it uses quite a few parts per bit.

The second way is a tiny bucket for electric charge, called a capacitor, with a little gate in front. A full bucket is 1, an empty bucket is 0. This is DRAM. It needs only two parts per bit, so many more bits fit on a chip. But the buckets leak. So the memory has a helper that reads every row and fills it up again, over and over, all the time. That is called refresh.

Both kinds forget everything when the power goes off. That is why a computer must load its programs again after you switch it on.

Layer 2 — the student explanation

The SRAM cell

Two inverters in a loop (Figure 1, left) have two stable states: q = 1, q̄ = 0 or q = 0, q̄ = 1. This is the same feedback idea as the latch of F1-16, without the set and reset gates D1. Two access switches, controlled by the word line, connect q and q̄ to a pair of bit lines D1.

  • Write: strong drivers put the value on BL and its opposite on BL̄; the word line goes to 1; the drivers are stronger than the cell's inverters and force the loop into the new state D1.
  • Hold: the word line is 0; the loop keeps itself, for as long as the power is on.
  • Read: the bit lines are prepared (in real chips, precharged) and left undriven; the word line goes to 1; the cell pulls one bit line towards its value, and a sense amplifier decides D1.

Listing 1 models exactly this in Verilog with strengths: the cell's inverters are declared weak, the testbench's write drivers strong, so the simulator resolves the fight the way the circuit does D3 R1.

The DRAM cell

A DRAM cell is one access transistor and one capacitor (Figure 1, right) D1 D2. A charged capacitor is 1, an empty one 0 (F1-05 explained capacitors). Three facts follow:

  1. It leaks. The charge slowly drains away, so every row must be refreshed (read and written back) before it falls below what the sense amplifier can still recognise D1.
  2. Reading destroys. The cell's capacitor is tiny compared with the bit line; connecting them shares the charge, leaving a very small change on the bit line and the cell drained. The sense amplifier amplifies the change and writes the full value back D1.
  3. It is dense. Two parts per bit instead of about six, so far more bits per chip, at lower cost per bit D1 D2.

Listing 5 is a numeric model of these facts. Each "tick", every cell keeps 95 % of its charge (an exercise value, not a property of any real part). A stored 1 starts at 1.0 and reads as 1 while above 0.5. Since 0.9513 ≈ 0.513 and 0.9514 ≈ 0.488 W1, an unrefreshed 1 is lost at tick 14, which is exactly what the run shows R3. If each of the 8 rows is refreshed once every 8 ticks, the lowest charge any 1 reaches is 0.958 ≈ 0.663, safely above the threshold W1.

Arrays and the RAM interface

Cells are arranged in rows and columns (Figure 2). The address is split: the row part goes to a decoder (F1-12) that turns on one word line; the column part chooses which bit lines go to the output, through multiplexers D1. From the outside, a RAM looks like Listing 3: an address, data in, data out, and a write enable. The lab builds that interface from Verilog registers (a register file, F1-17), which is how small memories inside processors are often described in HDL D1.

Layer 3 — the engineer's depth

Why both exist. SRAM is fast and needs no refresh, but uses more area per bit; DRAM is dense and cheap per bit, but slower to access, needs refresh, and is made in a process tuned for its capacitors D1 D2. That is why processors keep SRAM on the chip for registers and caches, and DRAM on separate chips as main memory: the memory hierarchy of HW203 (F1-32, F1-33) D2.

Rows and the row buffer. In DRAM, opening a row moves the whole row into the sense amplifiers; reading further columns of the same open row is faster than opening a new row D1. Memory controllers schedule requests around this, and refresh competes with normal accesses for time (F1-39).

Synchronous memories. Memories inside FPGAs and processors usually register the address or the output, so data appears one clock edge after the address; Listing 3 instead reads asynchronously (dout follows addr at once) to keep the first model simple D1. F1-22 meets such block memories.

Disturbance. Because DRAM cells are tiny and close together, heavy activity on one row can disturb charge in neighbouring rows; controllers and chips include measures against this D2. This matters for security as well as reliability, and returns in later security courses.

Not verified — check before relying on this

This build opened no DRAM or SRAM specification or data sheet. The structure "six transistors per SRAM cell" and "one transistor and one capacitor per DRAM cell" is the common textbook description D1; real products may use other cell designs. Refresh intervals, retention times, row sizes, timing parameters and protections against row disturbance are set by the memory standards (published by JEDEC) and by each part's data sheet; this chapter gives no numbers for them on purpose. The 95 % per tick, the 0.5 threshold and the 8 rows of Listing 5 are exercise values.

How the hardware actually does it

A real SRAM cell is six transistors: two inverters of two transistors each, plus two access transistors (F1-09 showed the transistor as a switch) D1. The transistors are sized so that the bit-line drivers win a write and the cell is not upset by a read D1. A DRAM chip contains many arrays (banks), row and column decoders, sense amplifiers, and control logic that accepts commands such as "open row", "read column", "write column" and "refresh" from a memory controller D1 D2. The memory controller, today usually part of the processor chip, is a large state machine of the kind F1-19 introduced: it issues refresh commands on schedule and orders requests around open rows D2. Firmware that starts a computer must configure this controller before main memory can be used at all, a topic of the boot courses.

Worked example

Problem: in the model of Listing 5 (keep 95 % per tick, threshold 0.5), what is the longest gap between two refreshes of a row that never loses a 1? With 8 rows and one refresh per tick in turn, is the data safe? What if only 4 of the rows are ever refreshed?

  1. After k ticks without refresh a 1 holds 0.95k W1.
  2. 0.9513 ≈ 0.513 > 0.5 but 0.9514 ≈ 0.488 < 0.5. So a row must be refreshed at least every 13 ticks W1. Run A confirms: the charge is printed as 0.513 at tick 13 and 0.488 at tick 14 R3.
  3. Round-robin over 8 rows: each row is refreshed every 8 ticks; 8 ≤ 13, so the data is safe; the lowest charge is 0.958 ≈ 0.663 W1. Run B: 0 rows lost after 40 ticks R3.
  4. If 4 rows are never refreshed, their gap is infinite: after 40 ticks a 1 holds 0.9540 ≈ 0.129, far below 0.5, and those rows read as 0 W1. (The forensic lab shows how this can happen.)
  5. General rule: rows × (time per refresh step) must not exceed the retention time, with margin. Real devices state their own limits (see the unverified box).

Where the analogy breaks


    

  • Sam can glance at a jar without touching it. Reading a DRAM cell drains it; the value survives only because the sense amplifier writes it back. In the analogy, every look would empty the jar into Sam's hands.
    • 

  • Jars evaporate slowly and evenly. Real cells differ from each other, and leakage depends on temperature; specifications set refresh intervals with margin for the worst cell (see the unverified box). The model's even 95 % is a simplification.
    • 

  • Flip signs stay up in a blackout. SRAM does not: without power, the loop stops and the bit is lost. Both SRAM and DRAM are volatile.

Transition box

Where you came from: F1-16 stored one bit in a feedback loop, F1-17 grouped flip-flops into registers, and F1-19 showed controllers as state machines. What carries over: the SRAM cell is that same feedback loop, a memory array is decoders and multiplexers from F1-12 around many cells, and a refresh controller is a counter driving an FSM D1. What changes: to store many bits cheaply, cells give up the full flip-flop: SRAM drops the clock and edge logic, DRAM even drops the feedback and keeps the bit as leaking charge, so correctness now depends on refresh timing. What comes next: F1-21 teaches you to read the Verilog you have been running, including how a tool turns it into flip-flops and gates.

Summary


    

  • SRAM: a loop of two inverters plus two access switches; holds while powered; fast; larger per bit.
    • 

  • DRAM: one transistor plus one capacitor; dense and cheap per bit; leaks, so needs refresh; reads destroy and must restore.
    • 

  • Arrays use a row decoder for word lines, bit lines for data, and sense amplifiers.
    • 

  • A RAM's interface: address, data in, data out, write enable, and a clock for writes.
    • 

  • Every row must be refreshed within the retention time; a refresh counter must reach every row.
    • 

  • Both SRAM and DRAM are volatile.

Forensic lab answer key


Observation: the log shows rows 0, 1, 2, 3, 0, 1, 2, 3, …; rows 4–7 never appear. Rows 4–7 read as 0x00 R4. Hypotheses: (1) upper rows leak faster: ruled out, because leak() applies the same factor to every cell and the model is identical to Listing 5, where all rows survive R3; (2) upper rows are never refreshed: confirmed by the log. Root cause: line 84, row = (row + 1) & 0x3u;, keeps the refresh counter in 2 bits, which can count only 0–3. With 8 rows the counter needs 3 bits (& 0x7u, or % kRows as in Listing 5). Unrefreshed for 40 ticks, a 1 holds 0.9540 ≈ 0.129 < 0.5 W1, so every bit reads as 0, hence 0x00. Fix: derive the counter width from the number of rows. Prevention: a test that checks that every row is refreshed within its interval (refresh coverage), not only that data survives a short test; a test long enough to exceed the retention time. Why it is hard in real hardware: real cells often keep their charge far longer than the specified minimum, so a missed row may survive in a short test at room temperature and fail only later, warmer, or on another chip. How the evidence was made: Listing 5 with the refresh counter changed to a 2-bit mask. Wrong answers: "the threshold is too high" (rows 0–3 pass with the same threshold); "the write is wrong" (rows 4–7 would also fail immediately, but they are written exactly like rows 0–3).
