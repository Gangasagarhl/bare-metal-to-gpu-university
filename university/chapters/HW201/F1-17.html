Story hook

Analogy

At the restaurant door stands a "take a number" machine. Each guest pulls a ticket, and a display over the counter shows whose turn it is. Every time the kitchen's bell rings and a table is free, the display moves on by one: 7, 8, 9.

Inside, the ticket rail has grown. It no longer holds one slip but a row of four clips, and all four are swapped together when the bell rings. Along the pass, finished plates sit on a short conveyor. At every ring, each plate slides one place towards the dining room, and a new plate enters at the kitchen end.

Kofi, the new waiter, asks: "Why does everything move at the bell, and never in between?" Because then nobody ever sees a half-changed display, a half-swapped row, or two plates in one place. In this chapter you build all three machines from flip-flops: the row of clips (a register), the number display (a counter) and the conveyor (a shift register).

What you will be able to do

  • Build a register with load and reset from D flip-flops, and say which input wins when several are active.
  • Design a synchronous counter as "a register plus an adder that feeds it", with enable and wrap-around.
  • Explain why a ripple counter passes through wrong values, using a real simulation trace.
  • Trace a shift register bit by bit.
  • Diagnose "the counter skips" from a timing diagram (the course's forensic lab).
Jargon box
Register (hardware)
Simple words: a row of flip-flops that store one number together. Analogy: a row of ticket clips on the rail, all swapped at the same ring of the bell. Precise: n D flip-flops sharing one clock, storing an n-bit value; extra inputs (load or enable, reset) decide whether a clock edge stores new data, clears, or keeps the value. The CPU registers named by instructions (HW202, "Register (CPU)") are built this way. D5 “Registers” D2 §3.2.2
Load (enable)
Simple words: the input that says "store the new value at the next edge". Analogy: the cook's nod that says "yes, swap my ticket at this ring". Precise: a control input of a register: at a clock edge, if load = 1 the register takes its data input, otherwise it keeps its value. D5 “Enabled Flip-Flops”
Reset (synchronous and asynchronous)
Simple words: the input that clears a register to a known value, usually 0. Analogy: wiping the rail clean before service. Precise: a synchronous reset acts only at a clock edge; an asynchronous reset acts at once, without waiting for the clock. D5 “Resettable Flip-Flops” D8 Description
Counter
Simple words: a register that adds 1 to itself at each clock edge. Analogy: the "take a number" display at the door. Precise: a sequential circuit whose state steps through a fixed sequence, usually binary 0, 1, 2, ..., 2n − 1 and then wraps to 0. D7 “Counters”
Synchronous counter
Simple words: a counter in which all bits change at the same clock edge. Analogy: all digits of the display flip at the same ring. Precise: a counter whose flip-flops share one clock; the next value is computed by combinational logic (an incrementer) from the current value. D8 Description D2 §3.2.4
Ripple counter
Simple words: a counter in which each bit's change triggers the next bit, one after another. Analogy: a line of cooks who each start only when the neighbour has finished. Precise: a counter in which only the lowest flip-flop is clocked by the clock and each other flip-flop is clocked by the output of the one before it; the bits change at different times. D9 §1, §4 D11 §1.2.2.3
Wrap-around
Simple words: after the biggest number, the counter goes back to 0. Analogy: the display after 99 shows 00. Precise: arithmetic modulo 2n: in 4 bits, 15 + 1 = 0 (see MA102). W1
Shift register
Simple words: a register whose bits move one place at each clock edge. Analogy: the plate conveyor on the pass. Precise: a chain of flip-flops in which each flip-flop's input is the previous one's output; a serial input enters at one end at each edge. D7 “Shift Registers” D10 §1
Glitch
Simple words: a short wrong value that appears while signals are changing. Analogy: the display flashing a wrong number for a blink before it settles. Precise: a brief unintended value on a signal, caused by inputs or bits that change at slightly different times. D8 Description

The idea in pictures

Figure 1 shows a 4-bit register. It is nothing more than four D flip-flops from F1-16, side by side, all connected to the same clock. A small selector in front of each one chooses what it stores: the new data, zero, or its own old value.

Figure 2 compares two ways to count. On the left, a synchronous counter: a register whose input is its own output plus one, computed by an incrementer (the adder of F1-14 with one input fixed at 1). On the right, a ripple counter: a chain in which each bit is clocked by the bit before it.

Layer 1 — the kid explanation

One flip-flop remembers one bit. A number needs several bits, so you put several flip-flops in a row and connect them all to the same clock. That row is a register. At each clock edge, every flip-flop in the row stores its new bit at the same moment, so the number changes in one clean step.

Sometimes you want the register to keep its number. So each flip-flop gets a small chooser in front: "new number" or "my old number". A wire called load controls the chooser. Another wire called reset forces everything to zero, so the register never starts as a mystery.

Now feed the register's output into an adder that adds 1, and feed the adder's answer back into the register. At every clock edge the number grows by one: 0, 1, 2, 3. That is a counter, like the "take a number" display. When it reaches the biggest number its bits can hold, it wraps around to 0.

A shift register is a row of flip-flops where each one copies its neighbour. At each edge every bit moves one place, like plates sliding along the conveyor.

Layer 2 — the student explanation

Registers with load and reset

A register of n bits is n D flip-flops sharing a clock D5 “Registers” D2 §3.2.2. On its own, a D flip-flop stores something at every edge. To make "keep" possible, a 2-input multiplexer (F1-12) in front of each flip-flop selects D or the flip-flop's own Q, controlled by load D2 §3.2.2. A synchronous reset adds one more choice, the constant 0, and is checked first. Listing 1 writes all of this in five lines; the order of the if statements is the priority: reset, then load, then keep R1.

An asynchronous reset clears the flip-flop immediately, without waiting for an edge D5 “Resettable Flip-Flops” D9 §1. In Verilog you write it by adding the reset to the event list: always @(posedge clk or posedge reset), as the ripple counter of Listing 4 does. Both kinds exist in real designs; within one design, pick one style and use it consistently.

Synchronous counters

A synchronous counter is a register plus an incrementer: next = count + 1 D2 §3.2.4. Every flip-flop sees the same clock, so all bits change together, one flip-flop delay after the edge. Between edges the incrementer has a whole clock period to compute the next value. That is the time budget studied in F1-18.

Two extras make counters useful. An enable input lets the counter pause (enable = 0 means "keep"). A wrap output (Listing 2, line 11) is 1 during the cycle in which the next edge will take the counter from 15 back to 0; a second counter can use it as its own enable, which is how a two-digit display counts 00 to 99 D8 Description. In 4 bits, 15 + 1 wraps to 0 because only the lowest four bits of 16 (binary 10000) are kept W1.

Ripple counters

A cheaper design uses no adder at all. Bit 0 toggles at every clock edge. Bit 1 toggles whenever bit 0 falls from 1 to 0, bit 2 whenever bit 1 falls, and so on D9 §1, §4. This counts correctly, but slowly and untidily: when the count goes from 7 (0111) to 8 (1000), bit 0 falls first, which then makes bit 1 fall, which makes bit 2 fall, which makes bit 3 rise. With a flip-flop delay of 1 time unit, the real run of Listing 4 passes through 6, 4 and 0 before it reaches 8 R2. Those short wrong values are glitches. Any circuit that reads the counter at the wrong moment, or decodes "count = 0", can be fooled. That is why designs that must be read reliably use synchronous counters.

Shift registers

In a shift register, flip-flop k takes the output of flip-flop k − 1 at each edge, and a serial input enters at bit 0 D10 §1 D7 “Shift Registers”. Listing 3 writes this as q <= {q[2:0], serial_in}: keep the lower three bits, move them up, and put the new bit at the bottom. After four edges, four bits that arrived one at a time sit side by side. This is how a serial line (one wire, one bit per clock) becomes a parallel number; HW204 meets it again in input and output devices.

Layer 3 — the engineer's depth

Why "one clock" is a design rule. In a synchronous design, every flip-flop is clocked by the same clock, and all logic between flip-flops is combinational. Then the behaviour can be reasoned about one cycle at a time: at each edge, every register takes the value its input logic computed during the previous cycle D5 “Synchronous Sequential Logic”. The testbench in Listing 5 relies on exactly this: its models (lines 39–41) compute the next state from the current state, once per edge, and the hardware must agree R1. Clocking a flip-flop from another flip-flop's output, as the ripple counter does, breaks this rule; synthesis and timing tools then treat each such output as a separate clock, and analysis gets harder D11 §1.2.2.3.

Counters are the smallest finite state machines. A counter's state is its value; its next-state logic is "+1". F1-19 generalises this: any next-state logic, any outputs.

Edge or level? In Verilog, the event list of an always block decides what kind of storage you describe. @(posedge clk) describes edge-triggered flip-flops; a list of levels such as @(clk) or @(en or d) describes something that reacts to every change D6 “always Statement”, “D Flip-Flop”. The forensic lab of this chapter is about exactly that difference.

Not verified — check before relying on this

How long the in-between values of a real ripple counter last depends on the flip-flop delays of the actual part or chip, which this build cannot measure: it has no hardware. The 1-time-unit delay in Listing 4 is an exercise value. A ripple-counter data sheet lists the delay from each stage's output to the next stage (for example the 74HC393 data sheet, D9 §10), but this chapter copies no value from it. To check the in-between values on real hardware you would need a ripple-counter chip on a low-voltage breadboard, a logic analyser or oscilloscope fast enough for the part's delays, and its data sheet; record the measured values in the dossier as a measurement (AH-23).

How the hardware actually does it

The program counter of a processor is a register with load, increment and reset, exactly the kind of circuit in this chapter; F1-21 reads one, and the course project builds it for HW202 D2 §3.2.4. The processor's registers (the ones instructions name) are registers in this sense too, grouped into a register file with read and write ports D7 “Multi-ported Memories”. Counters appear wherever hardware must count: the textbook's slides name digital clocks and program counters as uses D7 “Counters”, and F1-42 builds a timer from one. Shift registers sit behind serial links, where bits arrive one at a time and are collected into bytes: a shift register is a serial-to-parallel converter D7 “Shift Registers”.

Worked example

Following the register, the counter and the shift register

Listing 5 drives the three parts with the inputs in its table below. Predict each row before you read the output.

  1. Cycle 0: reset = 1. The register and the counter become 0 at the edge. The shift register has no reset: it shifts in the first serial bit, 1, so q_shift = xxx1 (three unknown bits remain).
  2. Cycle 2: load = 1 and d = 9, so the register becomes 9 (1001). The counter, enabled, goes 1 → 2.
  3. Cycles 4 and 5: enable = 0, so the counter stays at 3. The register keeps 9 because load = 0.
  4. Cycle 6: load = 1, d = 6: the register becomes 6.
  5. Shift register: the serial bits are 1, 0, 1, 1, 0, 0, 1, 0 (the binary number 10110010, left bit first). After cycle 3 the register shows the first four bits in order: 1011. After cycle 7 it shows the next four: 0010.
  6. Cycle 17: count = 15 with enable = 1, so wrap = 1. At the next edge (cycle 18) the count wraps to 0 W1.

Every prediction appears in the recorded output, and the testbench's own models agree at all 20 cycles R1.

The ripple counter from 7 to 8

Start: count = 0111. Rising clock edge at t = 150; each flip-flop takes 1 time unit.

  1. t = 151: bit 0 toggles 1 → 0. Count = 0110 = 6. Bit 0 fell, so bit 1 is triggered.
  2. t = 152: bit 1 toggles 1 → 0. Count = 0100 = 4. Bit 2 is triggered.
  3. t = 153: bit 2 toggles 1 → 0. Count = 0000 = 0. Bit 3 is triggered.
  4. t = 154: bit 3 toggles 0 → 1. Count = 1000 = 8. Done, 4 time units after the edge.

The run prints exactly the lines t = 151, 152, 153, 154 with counts 6, 4, 0, 8 R2. A synchronous counter would go from 7 straight to 8.

Where the analogy breaks


    

  • The "take a number" display could skip if the staff wanted; a counter cannot choose. A counter follows its next-state logic exactly. When it skips, the logic or the clocking is wrong (forensic lab), never a decision.
    • 

  • Plates on a conveyor are not copied; bits in a shift register are. At each edge each flip-flop copies its neighbour's old value. The last bit falls off the end and is lost unless something stores it.
    • 

  • A row of ticket clips can be swapped one clip at a time; a register's bits change together. In a synchronous design all bits change at the same edge. Only the ripple counter, which breaks that rule, shows bits changing one after another R2.
    •

Transition box

Where you came from: F1-16 built single flip-flops; F1-14 built adders. What carries over: the flip-flop's rule (store at the edge, hold otherwise) and the adder, unchanged; a counter is literally an adder feeding a register D2 §3.2.4. What changes: you now reason in clock cycles, one row per edge, instead of in gate delays; and the order of control inputs (reset, load, enable) becomes part of the design. What comes next: F1-18 asks how fast the clock may tick before the adder in the loop cannot keep up.

Summary


    

  • A register is n flip-flops on one clock; load chooses "new value" or "keep", reset forces a known value.

Forensic lab answer key


Observation: from edge 3 on, the display grows by 2 per edge (3, 5, 7, ..., 15, then 1), and the testbench reports 8 of 8 checked edges wrong R4. In the timing diagram count changes every 5 time units, at the rising edges (15, 25, ...) and also at the falling edges (20, 30, ...): two changes per 10-unit clock period. Hypotheses: (1) the adder adds 2: ruled out, because the diagram shows single steps of 1 (1, 2, 3, 4, ...); (2) the display reads twice per edge: ruled out, because the log has exactly one line per edge and the diagram, which records the counter itself, shows the extra changes; (3) the counter is triggered by both clock edges: confirmed by the diagram. Root cause: Listing 7, line 13, always @(clk): the block runs at every change of clk's level, rising and falling, so the counter adds 1 twice per period. The edge condition posedge is missing. Fix: always @(posedge clk), as in Listing 2; the same testbench then passes, one step per edge R3. Prevention: a self-checking testbench that compares each value with the previous one (as display_tb.v does); a coding rule "every clocked block has posedge clk"; reading a timing diagram, not only values at edges. How the evidence was made: counter4.v with posedge removed from line 13, simulated in this build. Wrong answers: "the clock is too fast" (the counter steps cleanly on every half period; it is not missing values, it is making extra ones); "the display is broken" (the diagram records the counter, not the display).
