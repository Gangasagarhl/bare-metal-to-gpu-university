Story hook

A school that has worked with one friendly supplier (virtio, F4-05) now signs a contract with a big old logistics company. The company has rules for everything. Its loading dock has 32 numbered bays; every order goes on a printed form of exactly 20 bytes, filed in the bay's folder together with a list of shelves to fill; the dock clerk has a book where he writes, in the company's own format, what happened; and before the first delivery somebody must walk down the access road to every one of the company's six gates and shout to see whether anyone answers.

That last rule is the subject of this course's forensic case. A boot-trace summary shows one storage driver taking five seconds while every other driver takes milliseconds. By the end of this chapter you will have written an AHCI driver for SATA disks, checked it with the same random test as virtio-blk, broken a command on purpose and recovered from it, and you will be able to point at the exact hardware step that cost those five seconds.

What you will be able to do

  • Find an AHCI controller by its class code and read its capabilities from the ABAR.
  • Bring up a port in the order the specification prescribes: stop, reset the link, give it a command list and a received-FIS area, enable FIS receive, then start.
  • Build a command: a host-to-device register FIS, a command header, a command table and physical region descriptors.
  • Identify a disk with IDENTIFY DEVICE and decode its strings and capacity.
  • Recover from a failed command with a port stop and start, and explain when a COMRESET is needed.
  • Diagnose a slow boot from a driver-timing table by connecting the slow driver to the hardware step it waits for.
Jargon box
AHCI (Advanced Host Controller Interface)
Simple words: the standard way a computer talks to the chip that runs its SATA ports. Analogy: the logistics company's rule book for its loading dock. Precise: a register-level interface for SATA host bus adapters, found on PCI with class code 01h, subclass 06h, programming interface 01h; registers in a memory BAR (ABAR, BAR5), commands passed through per-port command lists in memory. D1
HBA (host bus adapter)
Simple words: the controller chip between the computer's bus and its disks. Analogy: the loading dock itself. Precise: the AHCI controller: global registers (CAP, GHC, IS, PI, VS) and up to 32 ports, each with its own register block. D1
FIS (frame information structure)
Simple words: a packet on the SATA cable. Analogy: the company's printed forms. Precise: a typed frame exchanged between host and device; the driver builds register host-to-device FISes (type 27h) for commands and reads device-to-host FISes the HBA copies into the received-FIS area. D1 D3
Command list and command slot
Simple words: a table of up to 32 commands a port can work on. Analogy: the 32 numbered bays. Precise: a 1 KiB-aligned array of 32-byte command headers at PxCLB; slot n is issued by setting bit n of PxCI and is finished when the HBA clears it. D1
PRD (physical region descriptor)
Simple words: one "put this many bytes here" entry for a command's data. Analogy: one shelf on the order's shelf list. Precise: a 16-byte entry of the command table's PRD table: data base address and a byte count minus one (bit 0 must give an even count); a command's data is the concatenation of its PRDs. D1
COMRESET
Simple words: resetting the SATA link and waiting for the disk to answer. Analogy: walking to a gate and shouting. Precise: an out-of-band reset signal the HBA sends when PxSCTL.DET is set to 1 and cleared again; a present device answers and the link comes up (PxSSTS.DET = 3); on an empty port nothing answers and only a timeout ends the wait. D1 D3
IDENTIFY DEVICE
Simple words: the command that asks a disk to describe itself. Analogy: asking the visitor for an identity card. Precise: ATA command ECh, returning 256 16-bit words: serial number (words 10–19), firmware revision (23–26), model (27–46), the 48-bit sector count (100–103), and feature flags. D2

Layer 1 — the kid explanation

A SATA disk is connected through a controller chip with several plugs. To use a disk, the computer writes an order on a form in memory ("read sector 1000 into this box"), puts it in one of 32 numbered trays, and tells the controller "tray 0 is ready". The controller sends the order down the cable, the disk answers, and the controller puts the data straight into the box. Before all that, the computer must find out which plugs have a disk. If it shouts down every empty plug and waits a whole second each time for an answer that never comes, starting the computer takes much longer than it needs to.

Layer 2 — the student explanation

An AHCI controller appears on PCI as class 01h (mass storage), subclass 06h (SATA), interface 01h (AHCI). Its registers are in BAR5, called the ABAR: global registers first (CAP says how many ports and command slots exist, PI which ports are implemented, GHC holds reset, interrupt enable and "AHCI mode"), then one 128-byte block per port starting at offset 100h. D1 R2

Each port needs two areas of memory from the driver: a command list (32 command headers) and a received-FIS area where the HBA copies the disk's answers. A command is a 20-byte register FIS in a command table, plus a list of PRDs for the data. The driver points a command header at the table and sets the slot's bit in PxCI; when the bit clears, the command is done, and PxTFD holds the disk's status and error registers. D1

The disk itself speaks ATA. IDENTIFY DEVICE (ECh) returns 512 bytes describing it; READ DMA EXT (25h) and WRITE DMA EXT (35h) move data with 48-bit sector numbers. Milestone C5 asks for "HBA reset and enable, port start/stop, command slots, PRD tables, interrupt handling, error recovery for at least a port reset", and its acceptance tests compare IDENTIFY with QEMU's configuration, rerun F4-05's random test on AHCI, and log the throughput next to virtio-blk's. D2 D7

Layer 3 — the engineer's depth

HBA initialisation

The driver enables memory decoding and bus mastering, sets GHC.HR (HBA reset) and waits until the HBA clears it, then sets GHC.AE (AHCI enable). It reads CAP: in R2, 0xc0141f05 decodes as NP = 5 (6 ports), NCS = 1Fh (32 command slots), S64A (64-bit addressing) and SNCQ (native command queuing) set. PI = 0x3f: ports 0–5 implemented. D1 R2

Port start and stop

Two DMA engines run per port: the FIS receive engine (enabled by PxCMD.FRE, running when PxCMD.FR is set) and the command engine (PxCMD.ST, running while PxCMD.CR is set). The specification's "Software Manipulation of Port DMA Engines" gives the order: to stop, clear ST and wait for CR to clear, then clear FRE and wait for FR to clear; PxCLB and PxFB may be changed only while both are stopped; to start, set FRE first, wait until the device is not busy (PxTFD.STS.BSY and DRQ clear), then set ST. An early version of the lab's driver set ST before FRE and waited on PxTFD before FRE was set; the HBA then had not received the device's first FIS, PxSIG read 0xffffffff, and every port start waited the full timeout. The order in Listing 2 fixed both. D1 R4

The link and the signature

PxSSTS reports the link: DET (bits 3:0) = 3 means a device is present and communication is established; R2's 0x113 also reports speed (bits 7:4 = 1, Gen 1) and power state (bits 11:8 = 1, active). A COMRESET is requested by writing PxSCTL.DET = 1, holding it at least 1 ms, and writing 0; the link renegotiates. After the device's first device-to-host FIS, PxSIG holds its signature: 0x00000101 for an ATA disk, 0xEB140101 for ATAPI (optical drives). D1 D3

They are confirmed only by QEMU 8.2.2's ICH9 AHCI model behaving as expected and by QEMU's own trace naming the registers the driver wrote (R4). Building a command

The register host-to-device FIS is 20 bytes (5 dwords): byte 0 type 27h, byte 1 bit 7 "C" (this FIS carries a command), byte 2 the command, bytes 4–6 and 8–10 the 48-bit LBA, byte 7 the device register (bit 6 = LBA mode), bytes 12–13 the sector count. The command header gives the FIS length in dwords (5), a "write" bit (data flows to the device), the number of PRD entries and the command table's address (128-byte aligned). Each PRD's byte count is stored minus one. D1 D2

The lab's driver uses one slot and waits for each command, so the random test runs at queue depth 1 only. Native command queuing (FPDMA QUEUED commands, PxSACT, up to 32 commands in flight) is the mini-project; until then, "the same 1 GiB random I/O test as C4" is only half done on AHCI: C4's test also runs at depth 32. D7

Interrupts, and a flaw R2 exposes

The driver enables PxIE for device-to-host FIS and task-file errors, sets GHC.IE and installs a handler on the PCI interrupt line (line 10 through the PIC in R2). The handler reads the global IS to find ports, and clears PxIS and IS by writing back the bits it read, since both are write-1-to-clear (F4-01). R2 counts 4003 interrupts: one per command of the random test (4000) and of the error test (2), plus one more: IDENTIFY ran before interrupts were enabled, but its completion bits stayed set in PxIS, so setting GHC.IE raised an interrupt at once. The last lines of R4 show exactly that: GHC.IE written, then the handler clearing PxIS (0x3) and IS (0x1). D1 R2

But the issuing code also polls PxCI and PxIS. R2's error line shows PxIS=0x00000000 for a command that failed: the interrupt handler had already cleared the error bit before the polling code looked. The driver still detected the failure, through PxTFD's error bit, but two pieces of code consuming the same write-1-to-clear register is a design flaw. A correct driver either polls with interrupts masked, or lets the handler record the status in memory for the waiting code. Fixing it is lab step 4.

Errors and recovery

The lab reads LBA 2097152 on a disk of 2097152 sectors: one past the end. R2 shows PxTFD = 0x441: status byte 41h (DRDY and ERR) and error register 04h, which in ATA is ABRT (command aborted). After an error the port's command engine stops processing; the recovery used here is the AHCI one for a non-fatal error: stop the port (clear ST, wait for CR), clear PxSERR and PxIS, and start it again. If the device stays busy (BSY or DRQ set), the next step would be a COMRESET. R2: the bad read returned −5 (−E_IO) and the following read of LBA 0 succeeded. D1 D2 R2

The ATA status and error bit meanings (DRDY 40h, ERR 01h, ABRT 04h) and the IDENTIFY word numbers are from memory of D2. The IDENTIFY words are indirectly confirmed: the model, serial and capacity the driver decoded match QEMU's command line and the 1 GiB image exactly (R2). A real disk would probably report a read past the end differently (an "ID not found" error rather than an abort); that is an expectation, not a tested fact. The recovery sequence is from memory of D1's error-handling chapter and was tested only for this one error in QEMU.

How the hardware actually does it

On a PC the AHCI HBA is usually a function of the chipset (on the test machine of DRIVERS.html, an AMD SATA controller handled by amdsata; Microsoft's generic driver for the same interface is storahci). The SATA link is a serial connection with its own physical layer: a COMRESET is an out-of-band signal pattern, the device answers with COMINIT, and the two sides then negotiate speed before any FIS can flow. The disk on the other end runs its own firmware, which interprets the ATA commands, manages its cache and media, and decides how fast it reports "ready" after a reset. D3 D6

The DMA itself is done by the HBA: it fetches the command header and table from memory, sends the FIS, and moves data between the disk's FISes and the buffers the PRDs name. In QEMU the "HBA" is QEMU's ich9-ahci model; the trace in R4 is the HBA's own view of the driver's register writes. D8 R4

Not verified — check before relying on this

The out-of-band signalling names (COMRESET, COMINIT) and the description of link negotiation are from memory of the Serial ATA specification (D3). How long real disks take to answer a COMRESET, and how long real controllers wait on empty ports, were not measured: no physical hardware was used in this build.

Worked example

Decoding CAP. 0xc0141f05: bits 4:0 = 00101b = 5, so 6 ports; bits 12:8 = 11111b = 31, so 32 slots; bit 31 (S64A) and bit 30 (SNCQ) set; bits 23:20 = 1 (interface speed Gen 1 in the author's memory of D1). Version register 0x00010000: AHCI 1.0. R2

A read command in bytes. Block 1000 (4 KiB) is LBA 8000 = 0x1F40, count 8. CFIS: 27 80 25 00 | 40 1F 00 40 | 00 00 00 00 | 08 00 00 00 | 00 00 00 00 (byte 4 = 40h is LBA bits 7:0 = 0x40, byte 5 = 1Fh, byte 7 = 40h the device register). Header: flags = 5 (no write bit), PRDTL = 1, CTBA = the table's address. PRD: address of the 4 KiB buffer, byte count 4095. D1 D2

IDENTIFY strings. ATA strings put the first character of each pair in the high byte of a 16-bit word. In memory (little-endian), the model "DR301 SATA DISK" appears as "RD03 1ASAT DIKS" until the driver swaps each pair (Listing 2, ata_string). The sector count at words 100–103 gives 2097152 × 512 = 1 GiB, the size of the image. All three values the acceptance test names match QEMU's configuration: model "DR301 SATA DISK", serial "DR301SATA0001" (both from -device ide-hd,model=…,serial=…) and the capacity. R2

Reading the trace. R4, kernel part: GHC 0x80000001 (AE + HR: reset), then 0x80000000 (AE). Port 0: PxCMD written twice with 0x6 (stop: ST clear, then FRE clear), SCTL 1 then 0 (the COMRESET), CLB and FB set, SERR and IS cleared, PxCMD 0x16 (FRE on) then 0x4017 (ST on; bit 14, FR, read back as running and written back unchanged), then PxCI = 1 (the IDENTIFY). Ports 1–5: only the stop writes, no COMRESET, because their SSTS.DET was not 3. R4

Where the analogy breaks


    

  • The bays are in the school's own building. The command list and tables are in the computer's memory, written by the driver; the "dock" (HBA) only reads them. A real loading dock owns its own paperwork.
    • 

  • Shouting at an empty gate is not foolish in principle. A COMRESET on an empty port is sometimes needed (hot-plug, a link the firmware did not train). The analogy makes the slow probe look silly; the real lesson is that the firmware has often already done the work and the driver can read the result.
    • 

  • Forms in a foreign language. The register FIS carries ATA's old register layout (LBA split across bytes, a "device" register with an LBA bit). The analogy hides that AHCI is a modern wrapper around a decades-old command set.
    • 




Common mistakes and debugging


    

  • Starting ST before FRE, or changing PxCLB while the engines run. Symptom: PxSIG reads all ones, commands never complete, or the HBA reads a stale list. Follow the stop and start order exactly.
    • 

  • Forgetting that PxIS and IS are write-1-to-clear. Symptom: interrupt storms (bits never cleared) or lost events (cleared by someone else, as in R2's error line).
    • 

  • PRD byte count not minus one. Symptom: one byte too many per PRD; on a write, the disk receives garbage at the end of the sector or the command fails.
    • 

  • Using LBA28 commands on large disks. Symptom: works on small images, wraps around above 128 GiB. Use the EXT commands.
    • 

  • Not checking the signature. Symptom: an optical drive receives disk commands and aborts them.
    • 

  • Resetting every port with a fixed long timeout. Symptom: a boot that is seconds slower with every empty port (forensic lab).
    • 

  • Polling and interrupt handling sharing status registers. Symptom: errors seen only some of the time.
    • 




Transition box

Where you came from: F4-05's descriptors, DMA and random test; F4-03's interrupt handling and write-1-to-clear status; F4-02's class-code matching. What carries over: memory structures that the device reads, publication order (structures before the "go" write), the random test and the host's image check. What changes: a fixed, older format with strict start and stop rules, two layers of protocol (AHCI for the HBA, ATA for the disk), a link that must be brought up, and real error reporting that the driver must recover from. Next: F4-07's NVMe drops the ATA layer and the link handshake: queues of 64-byte commands in memory, doorbells, and completion entries with a phase bit, designed for flash from the start.

Run university/labs/run_lab.sh university/labs/F4-06 from the repository root (about half a minute; the slow boot alone takes five emulated seconds).


Safety
"Expect that a bad driver can corrupt disks (wrong LBA, wrong DMA address)... Disconnect disks you care about while testing storage drivers on real hardware." (curriculum safety box). This lab writes 4000 random blocks across a 1 GiB image file; on a spare PC the same code would write across the first gigabyte of whatever disk is on port 0. Never run it on a machine with a disk you want to keep, and physically disconnect other disks.

Summary


    

  • An AHCI HBA is class 010601h with registers in BAR5: global registers, then 32 possible ports.
    • 

  • Each port needs a command list and a received-FIS area; stop and start follow a fixed order (ST/CR, FRE/FR).
    • 

  • A command is a 20-byte register FIS plus PRDs, in slot n, issued by PxCI bit n; errors appear in PxIS.TFES and PxTFD.
    • 

  • IDENTIFY gives model, serial, firmware and capacity; ATA strings swap bytes in each word.
    • 

  • Recovery from a command error: stop, clear errors, start; COMRESET if the device stays busy.
    • 

  • Probing empty ports with a full COMRESET and a fixed timeout costs about a second each; reading the link state first costs nothing.
