Story hook

Analogy

The head chef, Ji-woo, never carries ingredients around the kitchen. She carries small paper notes. "Shelf 4410" means the saffron. When a cook needs saffron, Ji-woo does not hand over the jar; she copies the note and hands over the copy. Two cooks with the same note can both walk to the same jar.

The notes are wonderfully light. A note for a huge sack of flour is as small as a note for a pinch of salt. You can pass a note to someone across the kitchen, keep a stack of notes, even write "the next shelf after this one" on a new note.

One evening a new cook, Samuel, is handed a blank note. He walks to "shelf nothing" and stands there, confused. Later he is handed a note for a shelf that was cleared at lunch and refilled with fish. He walks there, reaches in, and puts fish into the dessert. The notes never complained. That evening the whole kitchen learns the two rules of this chapter: a note is only as good as the shelf it names, and nobody checks it but you.

What you will be able to do

  • Explain what a pointer is, how & makes one and how * and -> follow one.
  • Write functions that change the caller's objects through pointers, and decide when a reference is the better tool.
  • Compute pointer arithmetic inside an array, in elements and in bytes, including the one-past-the-end pointer.
  • Use nullptr to mean "no object", and check for it.
  • Diagnose a null-pointer crash from a sanitizer report.
Jargon box
Pointer
Simple words: a variable that holds the address of something else. Analogy: a note with a shelf number written on it. Precise: an object of type T* whose value is the address of an object of type T, the address one past the end of an array of T, or the null pointer value. D1 D2
Address-of operator (&)
Simple words: "where is this?" Analogy: writing a shelf's number on a new note. Precise: the unary operator & applied to an lvalue of type T yields a pointer of type T* to that object. Not the same symbol use as the reference declarator T& (F2-12). D1
Dereference (*, ->)
Simple words: "go to that place and use what is there." Analogy: walking to the shelf on the note. Precise: the unary * applied to a pointer yields the object it points to (an lvalue); p->m means (*p).m. Dereferencing a pointer that does not point to a live object is undefined behaviour. D1
Null pointer (nullptr)
Simple words: a pointer that deliberately points to nothing. Analogy: a blank note. Precise: the null pointer value of a pointer type, compares unequal to the address of every object; nullptr is the literal that converts to it. Dereferencing it is undefined behaviour. D1
Pointer arithmetic
Simple words: moving a pointer forward or back by whole elements. Analogy: "four sacks further along the shelf". Precise: adding an integer n to a pointer into an array gives a pointer n elements further; subtracting two pointers into the same array gives the number of elements between them (type std::ptrdiff_t); results outside the array, except one past its end, are undefined. D1
One-past-the-end pointer
Simple words: a pointer just after the last element, used as a finish line. Analogy: the line painted after the last slot of your section. Precise: for an array of N elements, &a[0] + N; it may be computed and compared but not dereferenced. Standard iterators' end() follows the same rule (F2-15). D1
Dangling pointer
Simple words: a pointer to something that is gone. Analogy: a note for a shelf that was cleared and refilled. Precise: a pointer whose value was the address of an object whose lifetime has ended; using it to access memory is undefined behaviour (F2-23). D1

Layer 1 — the kid explanation

In F2-18 every box of memory got a number. A pointer is a variable whose job is to hold one of those numbers. It is a note that says "the thing you want is in box 4410".D2

Two little symbols do all the work. &portions asks "where is portions?" and gives you the note. *p says "go to the box on note p", and there you can read or change what is inside.D1 If you change *p, you change portions itself, because they are the same box.R1

A note can also be blank on purpose. In C++ the blank note is nullptr. It means "no box". It is useful for answers like "I looked for table 9 and found nothing". But you must never walk to a blank note's box. The program does not stop you; it crashes, or worse, keeps going with nonsense. You will read such a crash in this chapter's forensic lab.

Layer 2 — the student explanation

Making and following pointers

For any object x of type T, &x is a value of type T*, "pointer to T". Storing it in a variable, T* p = &x;, gives you an object (8 bytes on this build's machine) whose value is x's address.D1 R1 The expression *p then is x: reading it reads x, assigning to it assigns to x. For a pointer to a structure, p->member is short for (*p).member.D1 The type matters: the compiler uses T to know how many bytes to read at that address and how to interpret them (F2-18).

Pointers as parameters

C++ passes arguments by value: a function receives copies.D1 Listing 2's swapCopies swaps its own copies and the caller sees nothing. swapThrough receives two addresses and swaps the objects they point to, so the caller's variables change.R2 SP102 (F2-12) gave you a second way to do this: references. Prefer a reference (int&) when the argument must always refer to an object; use a pointer when "no object" (nullptr) is a meaningful value, or when the function must walk through memory.D4 The C++ Core Guidelines state exactly this preference.D4

The null pointer

nullptr converts to the null pointer value of any pointer type; it compares unequal to the address of every object.D1 It is the honest return value of a search that found nothing, which is what Listing 3's findOrder returns for table 9. The pointer is not the problem; the caller that follows it without checking is. Dereferencing the null pointer is undefined behaviour: the standard says nothing about what happens next (F2-23).D1 On this build's machine, the sanitizer build reported the bad member access and the program was then stopped by a segmentation fault.R3

Pointer arithmetic

Inside an array, p + n points n elements further, not n bytes: the compiler multiplies by sizeof(T) for you. q - p for two pointers into the same array is the number of elements between them.D1 Listing 1 prints "2 elements, 8 bytes" for q = &shelf[0] + 2 on an int array.R1 Array indexing is defined in terms of this arithmetic: a[i] means *(a + i).D1 A pointer may legally point at any element or one past the last element; computing anything outside that range is already undefined, even if you never dereference it.D1 The one-past-the-end pointer is the finish line of loops such as the lab's largest(first, last), exactly like a container's end() in F2-15.

Pointers and const

Two different things can be constant. const int* p is a pointer through which you may not change the int (you may make p point elsewhere). int* const p is a pointer that always points to the same place (you may change the int). Read the declaration from right to left: "p is a const pointer to int".D1 D2 Listing 3 uses const Order* because the search must not change the orders; the lab uses int* const begin because the start of the array never moves.

Layer 3 — the engineer's depth

A pointer is more than a number. Two pointers can hold the same address and still not be interchangeable in the language's eyes: pointer arithmetic is defined only within one array object, and the compiler may assume a pointer derived from one object does not reach another.D1 Optimisers use that assumption; it is one reason why "it is just an address, I can compute it" leads to undefined behaviour in C++ and why kernels that really need address arithmetic do it on std::uintptr_t values and convert back at well-defined points (curriculum 1.1, strong types for addresses).S1

Not verified — check before relying on this

The C++ standard's treatment of pointer "provenance" (which object a pointer value is allowed to reach) and of integer-to-pointer conversion has been discussed by the committee for several years. This chapter only states the conservative rule (arithmetic stays inside one array, plus one past the end). Check the current working draft's clauses on pointer values, the additive operators and reinterpret_cast, and any committee paper on provenance the Source Researcher finds, before teaching more.

Null is not necessarily address zero. The language says what the null pointer does (compares unequal to every object's address; may not be dereferenced), not which bit pattern it has. On the platforms of this course it is all-zero bits, which is why the sanitizer says "address points to the zero page" and why the faulting address 0x10 in the forensic evidence is a small number: a null pointer plus a small offset into the object.D1 R3 A kernel can map memory at address zero; in your own operating system (track B) a null dereference does not crash unless you deliberately leave the first page unmapped, which is exactly what operating systems do to catch these bugs.D3

Uninitialised pointers. A local int* p; without an initialiser has an indeterminate value; using it is undefined behaviour.D1 GCC, with the course's warnings turned into errors, refused to compile wild.cpp, which writes through such a pointer; the compiler's message is in the mistakes section.R5 The compiler cannot catch every case (a pointer set on some paths only, or stored in a structure), so the habit is: initialise every pointer, to an object or to nullptr.D4

Raw pointers and ownership. A raw pointer says where; it says nothing about who is responsible for the object's lifetime. In modern C++ a raw T* is used as a non-owning observer, while ownership is expressed with containers and smart pointers (F2-21, F2-22).D4 Every listing in this chapter follows that rule: the pointers observe objects that something else owns.

How the hardware actually does it

At the machine level a pointer is an address in a 64-bit register, and dereferencing is a load or store instruction whose address operand is that register (plus a constant offset for p->member, plus an index times a scale for p[i]).D3 The processor has no idea whether the address belongs to a live object. It only checks, through the page tables, whether the page is mapped with the right permissions; if not, it raises a page fault, which Linux turns into the SIGSEGV signal that ended Listing 3's run.D3 R3 This is why a dangling pointer into still-mapped memory does not crash: the page is valid, the bytes are just wrong (F2-23's forensic lab). HW202 (F1-24) showed the load and store instructions; F1-38 shows the page-table check.

Worked example

An array int tips[6] = {4, 9, 2, 9, 7, 1}; starts at a made-up address 0x5000, with sizeof(int) == 4. Let begin = &tips[0] and end = begin + 6.

  1. end = 0x5000 + 6 × 4 = 0x5000 + 24 = 0x5018. It points one past the last element; it may be compared but never dereferenced.
  2. begin + 3 = 0x5000 + 12 = 0x500c, and *(begin + 3) = tips[3] = 9.
  3. Walking p from begin to end and keeping the first largest value: 4 → 9 (index 1); the second 9 is not greater, so best stays at index 1. best - begin = 1.
  4. After *best = 0, the array is 4, 0, 2, 9, 7, 1, and the walk finds 9 at index 3.

The lab program ptr_lab.cpp computes steps 3 and 4; its output (Listing 4, in the lab) prints "largest tip 9 at index 1" and then "largest tip 9 at index 3".R4 The lab's reference solution continues from step 4.R6

Where the analogy breaks


    

  1. Nobody checks the note. In a kitchen, a cook who walks to a refilled shelf might notice fish where saffron should be. A program never notices: a dangling pointer into memory that was reused reads or writes the new contents silently (the registered "where it breaks" of this mapping, guide 8.1).D1
    2. 

  2. Notes are not just numbers. On paper, "shelf 4410 + 8" is always shelf 4418. In C++, arithmetic that leaves the array is undefined even if the resulting number looks fine, and the compiler may optimise on that assumption (Layer 3).D1
    3. 

  3. A blank note is harmless paper. Following nullptr is not a polite "nothing there": it is undefined behaviour, which on this build ended in a crash.R3

Where you came from: F2-18 numbered every byte; SP102 (F2-12) gave you references, which also refer to an existing object. Summary


    

  • A pointer is an object holding an address; & makes one, * and -> follow it.
    • 

  • Changing *p changes the object itself.
    • 

  • Pass a pointer when "no object" is meaningful; otherwise prefer a reference.
    • 

  • nullptr means "no object"; following it is undefined behaviour (on this build: a sanitizer report and SIGSEGV).
    • 

  • Pointer arithmetic counts elements and is defined only inside one array plus one past the end.
