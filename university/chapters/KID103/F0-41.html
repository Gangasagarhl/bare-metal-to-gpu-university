Story hook

Analogy

In Priya's home there are two kinds of switches. The hallway light has a switch that stays where you put it. Flip it down and the light stays on. Flip it up and it stays off.

The doorbell is different. It rings only while you hold the button. When you let go, a spring pushes the button back up, and the ringing stops.

Priya's little cousin wants a "secret" lamp. It should light only if he presses two buttons at the same time. Priya wonders: how do you wire that? And how would you make one button that turns a lamp on with one press and off with the next? This chapter answers both questions.

What you will be able to do

  • Explain the difference between a switch that stays and a push button that springs back.
  • Predict when an LED lights with two switches in series (AND) or in parallel (OR).
  • Read a truth table produced by the course simulator.
  • Explain why a "toggle" light must remember the button's last state.
  • Wire and explain a button-controlled LED, in the simulator and (supervised) with the kit.
Jargon box
Switch
Simple words: a part that opens or closes a gap in a circuit. Analogy: a tap on a pipe: open lets water through, closed stops it (careful: for electricity, a "closed" switch lets current through). Precise: a component with contacts that connect (closed) or disconnect (open) a conducting path. D4 ch. 6 D7 §9.1
Push button
Simple words: a switch that is on only while you press it. Analogy: a doorbell button. Precise: a momentary switch: it connects only while it is pressed and goes back to its rest position when released. D3 (see the unverified box in "How the hardware actually does it")
Series
Simple words: parts placed one after the other in the same loop. Analogy: two taps on the same pipe: water passes only if both are open. Precise: a connection in which the same current passes through each part in turn. D7 §10.2 D4 ch. 6
Parallel
Simple words: parts placed side by side, each giving the current its own path. Analogy: two pipes joined side by side: water passes if either tap is open. Precise: a connection in which the parts share the same two connection points, so current can take either path. D7 §10.2 D4 ch. 6
Truth table
Simple words: a table that lists every combination of inputs and the result. Analogy: a chart on the fridge: "if this and that, then …". Precise: a table giving the output of a logic function for every combination of its inputs. D4 ch. 6
Toggle
Simple words: change to the other state: on becomes off, off becomes on. Analogy: pressing the light switch in the hallway once more. Precise: an operation that inverts a two-state value; here it happens once per new button press. R1

Layer 1 — the kid explanation

A switch makes a gap in the loop, or closes it. Closed means connected. Open means there is a gap. You met the gap idea in F0-39: one gap stops the current everywhere.D4 ch. 6 D7 §9.1

Be careful with the words. A closed water tap stops water. A closed switch lets current through. The words go the other way round. Say it slowly: closed switch, closed loop, current flows.

Some switches stay where you put them. A push button does not. A small spring pushes it back when you let go. Like the doorbell, it only connects while you press.D3

Now take two switches. Put them one after the other in the loop. That is called series. The current must pass through A and then through B. If either one is open, there is a gap. So the LED lights only when A and B are both closed. That is Priya's cousin's secret lamp.

Put them side by side instead. That is called parallel. Now the current has two roads. If A is closed, it can use A. If B is closed, it can use B. So the LED lights when A or B is closed, or both.

A truth table lists every case. With two switches there are four cases. Figure 1 and the program below show all four.D4 ch. 6

Layer 2 — the student explanation

Write "closed" as 1 and "open" as 0. Write "LED on" as 1 and "LED off" as 0. Then series switches behave like AND: the output is 1 only when both inputs are 1. Parallel switches behave like OR: the output is 1 when at least one input is 1. MA102 chapter F0-26 builds these truth tables with the same two light switches.D4 ch. 6

The LED still needs its resistor, in both circuits. The switches decide whether the loop is closed. The resistor decides how much current flows when it is.D7 §9.4

The second idea is the toggle light. One press turns it on. The next press turns it off. A plain wire cannot do that. Something has to remember. In the next chapter a microcontroller does the remembering. Here, our simulator does it.

A program reads a button again and again. Each reading is one "tick". If the program toggled the light at every tick where the button is down, a long press would flip it many times. So the program must remember the previous tick. It toggles only when the button was up last tick and is down now. That moment is the start of a new press.R2 D6

Layer 3 — the engineer's depth

Note

For the curious. When the metal contacts inside a real button close, they can bounce: they touch, part and touch again several times in a very short moment. A fast program could see one press as several. Programs handle this by ignoring changes for a short time after the first one; this is called debouncing.D5 D6 How long that time should be depends on the button, so it comes from its datasheet or a measurement, not from this chapter. Our simulator's button does not bounce: each tick is clean.

How the hardware actually does it

A switch has metal contacts. When they touch, the gap is closed and current can flow. When they are apart, there is a gap.D4 ch. 6 Real metal contacts do not always close cleanly: they can bounce (Layer 3).D5

Not verified — check before relying on this

Inside a push button there are two metal contacts and a spring. Pressing pushes a metal piece across the contacts, which closes the gap. Releasing lets the spring lift it away again. A toggle switch has a lever that holds the metal piece in one of two positions until you move it. No document opened in the verification pass describes the inside of a push button or a toggle switch. Check it in the datasheet of the buttons and switches in your kit (D3).

Worked example

Part 1: series or parallel?

Switch A is closed (1). Switch B is open (0).

  1. Series: the current must pass A and B. B is open, so there is a gap. LED off. In logic: 1 AND 0 = 0.
  2. Parallel: the current can pass through A. LED on. In logic: 1 OR 0 = 1.

Part 2: the toggle light, tick by tick

The button readings are: up, down, down, down, up. The light starts off. Remember the last reading each time.

  1. Tick 0: up. Not a new press. Light stays off.
  2. Tick 1: down, and it was up before. New press! Toggle: light on.
  3. Tick 2: down, but it was down before. Not new. Light stays on.
  4. Tick 3: down, was down. Light stays on.
  5. Tick 4: up. Light stays on. It will go off at the next new press.

Where the analogy breaks


    

  1. The words "open" and "closed" swap. An open tap lets water flow. An open switch stops current. If you carry the tap picture too far, you will say the opposite of what you mean.D4 ch. 6
    2. 

  2. An open switch has the push across it. Close a tap and the pipe is still full of still water. Open a switch and the battery's whole voltage appears across the gap, as F0-40's forensic lab showed. Pipes give no hint of that.D7 §9.4
    3. 

  3. Taps do not bounce. Turning a tap is smooth. Real button contacts can bounce, which a fast program can notice (Layer 3).D5

Summary


    

  • A switch closes or opens a gap; closed means connected.
    • 

  • A push button connects only while pressed; a spring returns it.
    • 

  • Series switches: LED on only if A AND B are closed.
    • 

  • Parallel switches: LED on if A OR B (or both) is closed.
    • 

  • A toggle light needs memory: toggle only on a new press (up before, down now).
    • 

  • Real buttons can bounce; programs can ignore changes for a short time.

Forensic lab answer key


Observation: in Jun's log the light changes at ticks 1, 2, 3, 6, 9 and 10 — at every "down" tick. New presses are only at ticks 1, 6 and 9. Hypotheses: (1) the button bounces; (2) the program toggles on every down tick. The simulator's button cannot bounce (each tick is a clean scripted reading), and the program has no memory of the last tick, so (2) is proven. Fix: add int wasPressed = 0;, change the condition to pressed == 1 && wasPressed == 0, and add wasPressed = pressed; after it — exactly Listing 2.
