Exams and course project of KID103 "Make it move: circuits, LEDs and a simulated robot" (chapters F0-39 to F0-46; level L0–L1; 3 credits). Written in the exam pass of 2026-10-10 under owner ruling B4 and guide sections 11.3–11.5. Every question can be answered from the eight chapters; every output quoted below is copied exactly from a real run on the build machine (g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0, Linux x86_64, course flags). All LED, battery, pin, motor and sensor numbers are the course's pretend exercise values (owner ruling A4), never real-part values. Answer keys are in the "Answer keys" appendix.

Note

Weights. KID103 is an L0–L1 course, so it uses the L0 option of guide 11.4 (owner ruling B6): quizzes 20 %, practical 50 %, course project 30 % (an exercise value, ruling A4), with encouraging written feedback. KID103 has 3 credits, so it has no midterm; the midterm's weight moves to the final (guide 11.4), and the final itself is an ungraded practice paper under ruling B6. Candidates receive only the practical's starting file (ruling B7).

Safety

Every written paper and the simulator part of the practical use only a computer. The kit part of the practical (Part B) is done only with an adult examiner present the whole time, only with the battery-powered reference kit chosen for this course, battery pack disconnected while wiring; no mains electricity, no LiPo batteries, no propellers (faculty rule, F0-46). The kit part was not performed in this build (untested on hardware, owner ruling C3).

  16. F16 — forensic question (20 points; Apply 2, Analyse 12, Evaluate 6).

    Scenario. Priya built the course project, a night-light, in the simulator. She used two thresholds, as F0-43 teaches, and chose her resistor with the F0-40 sum: (6 − 2) ÷ 0.02 = 200 Ω. "It flickers more than Tomás's one-threshold light did," she says, "and the program shouts that my LED is over the maximum, although my sum said 20 mA. The simulator must be broken."

    Evidence 1 — the source, labs/KID103-P/forensic_nightlight.cpp, copied exactly:

    // Evidence for the KID103 final exam (forensic question): Priya's night-light.
// Priya says: "I used two thresholds like F0-43 and it flickers MORE than before,
// and the simulator says my LED is over the maximum although my sum said 20 mA."
// Pretend datasheet numbers (exercise values): LED forward 2 V, maximum 20 mA; battery 6 V.
#include <iostream>

int main()
{
    const double batteryVolts = 6.0;         // "pretend the battery pack gives 6 V"
    const double pretendForwardVolts = 2.0;  // "pretend the datasheet says 2 V"
    const double pretendMaxMilliamps = 20.0; // "pretend the datasheet says 20 mA"
    const double resistorOhms = 200.0;       // Priya's sum: (6 - 2) / 0.02 = 200

    const int turnOnBelow = 34;  // lamp on when it gets dark
    const int turnOffAbove = 26; // lamp off when it gets bright again

    const double milliamps = batteryVolts * 1000.0 / resistorOhms;
    std::cout << "pretend datasheet: forward voltage " << pretendForwardVolts << " V, maximum "
              << pretendMaxMilliamps << " mA; battery " << batteryVolts << " V; resistor "
              << resistorOhms << " ohms\n";
    std::cout << "LED current when lit: " << milliamps << " mA";
    if (milliamps > pretendMaxMilliamps) {
        std::cout << "  ABOVE the pretend maximum of " << pretendMaxMilliamps << " mA!";
    }
    std::cout << "\n";

    int minute = 0;
    int light = 0;
    int switches = 0;
    bool lampOn = false;
    while (std::cin >> minute >> light) {
        if (!lampOn && light < turnOnBelow) {
            lampOn = true;
            ++switches;
        } else if (lampOn && light > turnOffAbove) {
            lampOn = false;
            ++switches;
        }
        std::cout << "minute " << minute << "  light " << light << "  lamp "
                  << (lampOn ? "ON" : "off") << "\n";
    }
    std::cout << "lamp changed " << switches << " times\n";
    return 0;
}

Course project — 30 %

Goal. A night-light that turns on in the dark (the course card): a light sensor, two thresholds, an LED loop and a simple program, simulator first. It must use what the course taught: a sensor reading turned into a decision with two thresholds (F0-43), an LED loop whose resistor is chosen with the F0-40 sum, a log you can trace line by line (F0-41, F0-42) and the safety checklist of F0-46 before any kit step.

Requirements.

  • Functional: a C++ text simulator in the course style that reads a scripted table of readings for a whole evening (one line per minute, light in simulator units 0–100), decides with two thresholds and a dead zone, prints one log line per minute with the reading and the LED state, prints how many times the lamp changed and for how many minutes the LED was lit; the LED loop's current is computed from the pretend datasheet values (forward voltage 2 V, maximum 20 mA; battery 6 V) and the program refuses to run the evening if the current is above the maximum.
  • Quality: builds with the course command with no warnings; every pretend number labelled as pretend in a comment; good names; a hand-worked check of the decision rule for at least four readings (clearly dark, dead zone from off, dead zone from on, clearly bright), run before the evening.
  • Safety: the project's own checklist (the F0-46 mini-project, at least eight questions with reasons) is written and run; the optional kit build happens only after the checklist says "All checks passed", with an adult, battery disconnected while wiring, and real datasheet values copied by the adult.

Constraints. No hardware is required: the simulator version is the project. The kit version is optional and supervised, with the reference kit only; it is untested in this build (owner ruling C3) and the reference kit does not yet name a light sensor, LED or resistor (F0-43, F0-40). About 6 hours of work spread over the course, after F0-43. One source file of at most about 80 lines is enough.

Deliverables. (1) the plan on paper from the F0-43 mini-project (sensor, two thresholds, LED loop sum, a scripted table for one evening that tests the dead zone); (2) the source file; (3) the build log made with the course flags; (4) one recorded run with its input file (.in) and output (.out) that can be repeated; (5) the safety checklist with its recorded run, signed by the adult; (6) a half-page report in the learner's own words: the two thresholds and why there is a gap, the resistor sum, one mistake found and how (log, trace or hand check); (7) a five-minute demo: run the hand check, run one evening, explain one line of the log; if a kit build was made, show it to the examiner unpowered first.

Milestones. (M1, after F0-43) the paper plan: thresholds, table, LED sum. (M2, after F0-44) the simulator builds and runs on the table; the hand check reports 0 failures. (M3, after F0-46) the checklist runs with all yes; the optional kit build is made with the adult. (M4, end of course) recorded run, report and demo.
