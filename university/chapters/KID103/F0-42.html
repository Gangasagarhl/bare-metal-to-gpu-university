Story hook

Analogy

Diego is helping his aunt bake bread. The recipe card says: "Knead for one minute. Rest for one minute. Repeat." His aunt sets a kitchen timer. Knead, beep. Rest, beep. Knead again.

Diego notices that the card never says "stop". His aunt laughs. "I stop when the dough is ready. The card would go on forever."

That evening Diego sees a tiny green light blinking on the internet box at home. On, off, on, off. "Is there a recipe card inside that box too?" he asks. Yes, there is. A small computer is following a recipe like his: turn on, wait, turn off, wait, repeat. In this chapter you write that recipe and run it in our simulator. Then, with an adult, you may try it on a real board.

What you will be able to do

  • Explain what a microcontroller is, using the recipe picture and precise words.
  • Describe the shape of a blink program: set up a pin, then loop forever (on, wait, off, wait).
  • Run the course's blink simulator and change the timing to make a new rhythm.
  • Calculate how many blinks happen in a given time.
  • Find the missing line in a blink program from its log.
  • Follow the supervised steps for a real board, checked against the kit's own instructions.
Jargon box
Microcontroller
Simple words: a very small computer on one chip, made to control things like lights and motors. Analogy: a cook who only knows one short recipe card and repeats it all day. Precise: an integrated circuit that contains a processor, memory for the program and data, and input/output pins on one chip. D5
Pin (input/output)
Simple words: a little metal leg of the chip that the program can switch on or off, or read. Analogy: a light switch the cook can flip, or a doorbell the cook can listen to. Precise: a terminal connected to the chip's input/output circuits; as a digital output the program drives it high or low, as an input the program reads its level. D6 D5
High and low
Simple words: "on" and "off" for a pin. Analogy: the light switch up or down (KID101 F0-02). Precise: the two voltage levels of a digital signal; the actual voltages are given in the microcontroller's datasheet. D5 D3
Program loop
Simple words: steps that repeat again and again. Analogy: "knead, rest, repeat" on the recipe card. Precise: a sequence of instructions that the processor carries out again and again; the main loop of a blink program has no end condition. D6
Millisecond (ms)
Simple words: a very short time: one second cut into a thousand parts. Analogy: a tiny tick of the kitchen timer. Precise: one thousandth of a second; 1,000 ms = 1 s. D6
Firmware
Simple words: the program that lives inside a small device. Analogy: the recipe card glued inside the cook's cupboard. Precise: software stored in a device's own program memory (on many microcontrollers, flash memory on the chip) that runs when the device is powered or reset. D5 D6

Layer 1 — the kid explanation

A microcontroller is a tiny computer on one chip. It is much smaller than a laptop. It does not have a screen or a keyboard. It has little metal legs called pins instead.D5

A program can switch a pin on or off. On is called high. Off is called low. If an LED and its resistor are connected to the pin, the LED follows the pin. Pin high, LED on. Pin low, LED off.D6

To blink the LED, the program follows a recipe. Turn the LED on. Wait a little. Turn it off. Wait a little. Do it again. Like Diego's bread, the recipe never says stop. It is a loop that runs as long as the board has power.D6

The waiting matters. Computers are very fast. Without a wait, the LED would change far too quickly for anyone to see. We measure the wait in milliseconds. A thousand milliseconds make one second.

In this chapter you run the blink recipe in our simulator first. It prints what the LED would do and when. Then, with an adult, you may try a real board from the kit.

Layer 2 — the student explanation

Every blink program has the same shape, whatever the board. First, a setup step runs once. It tells the chip that the LED pin is an output. Then the main loop runs forever: set the pin high, wait, set it low, wait.D6

Here is that shape as pseudocode. Pseudocode is a recipe written in plain words that looks a bit like code.

Watch out

Pseudocode — not buildable, not for any real board. The real names of the "make output", "set pin" and "wait" instructions depend on the board, its library and its toolchain. They come from the documentation of the board in the reference kit, the BBC micro:bit V2 (K1, D3), which was not opened for this chapter. Do not type this into a board's tools.

SETUP (runs once):
    make the LED pin an OUTPUT
LOOP (runs forever):
    set the LED pin HIGH      -- LED on
    wait ON_TIME milliseconds
    set the LED pin LOW       -- LED off
    wait OFF_TIME milliseconds

The simulator in Listing 1 does the same steps in ordinary C++. Instead of a real pin, it prints "LED ON" or "LED off". Instead of really waiting, it adds the wait to a pretend clock. So the run is instant, and it prints the exact time of every change.R1

One full blink takes ON_TIME + OFF_TIME. With 500 ms + 500 ms, one blink takes 1,000 ms, which is one second. The program built for a real board is called firmware. The kit's tools copy it onto the board, where it starts every time the board gets power.D6 D5

Layer 3 — the engineer's depth

Note

For the curious. A "wait" on a real microcontroller can be done in two ways. The program can count clock ticks and do nothing else until enough have passed (a busy wait). Or it can set up a hardware timer and do other work until the timer says the time is up.D5 A busy wait is the easy way to blink. It has a cost: while waiting, the program cannot read a button.D6 Robots need the second way. RB101 and the firmware courses of F3 come back to this.

How the hardware actually does it

Inside the chip, each pin has a small output circuit. When the program sets the pin high, the output circuit connects the pin to the chip's supply voltage. When it sets the pin low, the pin is connected to the chip's ground (its − side). The LED and resistor between the pin and ground then form a closed loop only when the pin is high.D6 D5 The pin can only give a small current; the largest allowed value is in the microcontroller's datasheet (D3). The example datasheet D5 states such a limit for each pin and for all pins together.D5 F0-44 shows why that matters for motors.

Worked example

The timing numbers below are our own exercise choices. They are not taken from any board.

How long is one blink?

ON_TIME = 500 ms, OFF_TIME = 500 ms. One blink = 500 + 500 = 1,000 ms = 1 s.

How many blinks in ten seconds?

Ten seconds = 10 × 1,000 = 10,000 ms. Blinks = 10,000 ÷ 1,000 = 10 blinks.

A faster rhythm

You want two blinks every second, with equal on and off times. One blink must take 1,000 ÷ 2 = 500 ms. Split it equally: ON_TIME = 250 ms, OFF_TIME = 250 ms.

When does the LED switch?

With 500/500 and three blinks, the LED turns on at 0, 1,000 and 2,000 ms, and off at 500, 1,500 and 2,500 ms. The total simulated time is 3,000 ms. Listing 1's real output prints these exact times.R1

Where the analogy breaks


    

  1. A cook notices problems; a microcontroller does not. Diego's aunt stops kneading when the dough is ready. The chip keeps blinking forever, even if the LED is missing or broken. It does exactly what the recipe says.D6
    2. 

  2. The waits are far shorter, and their accuracy is written down. A kitchen timer is "about a minute". A microcontroller counts the ticks of its clock. How exact its timing is depends on that clock, and the datasheet states it (D3); the example datasheet D5 gives a tolerance for its built-in clock. The kitchen picture hides that the error can be looked up.D5
    3. 

  3. A cook can do two things at once. Diego's aunt can listen to the radio while the dough rests. A busy-waiting program cannot do anything else while it waits (Layer 3).D6

Forensic lab answer key


Observation: the log has only "LED ON" lines, at 0, 1,000 and 2,000 ms; there is no "LED off" line, but the total time is still 3,000 ms. Hypotheses: (1) wiring: the LED is connected straight to the battery, so the pin cannot turn it off; (2) program: the off step is missing. The simulator has no wiring at all and still never turns the LED off, so the program is at fault (hypothesis 2 proven; hypothesis 1 is not needed to explain the evidence, though Nadia's adult may still check it). Root cause: the line that prints "LED off" (set the pin low) is missing between the two waits. Fix: insert it after clockMs += onMs;, as on line 15 of Listing 1. Verification: the fixed program prints the same log as Listing 1 (R1). Prevention: read the program against the pseudocode, one step per line. How the evidence was made: blink_broken.cpp is Listing 1 with line 15 removed, run in this build (R1).
