Story hook

Analogy

Zainab has just moved into River Street, house 15. When her neighbour at number 77 has a parcel for her, he walks over and puts it in the mailbox with "Zainab" painted on it. When Zainab writes to her friend Pedro in the mountain town, she does not walk anywhere: she takes the letter to River Street's post office at number 1, and the post office takes it from there.

How does Zainab decide between walking and the post office? She looks at the address. "River Street, anything" is her own street: walk. Any other street: post office. And when she needs to walk to number 77 but has never met the people there, she stands at her door and calls out: "Who lives at number 77?" Someone answers: "We do, ours is the blue mailbox." Next time she remembers.

Every computer on a network makes exactly these decisions, thousands of times a second, with two kinds of address: a name on the mailbox for this street only, and a full postal address that works anywhere.

What you will be able to do

  • Read an Ethernet header and a MAC address, including the broadcast address and the "locally administered" and "group" bits.
  • Compute the mask, network address, broadcast address and host range of an IPv4 address with a prefix length, by hand and in C++.
  • Decide, as a host does, whether a destination is on-link or must go through a router, and pick a route by longest-prefix match.
  • Explain ARP and build an ARP request that tshark decodes.
  • Diagnose a host whose wrong prefix length makes some destinations unreachable.
Jargon box
MAC address
Simple words: the 48-bit address of a network interface on its local link. Analogy: the name painted on a mailbox; it means something only on that street. Precise: a 48-bit link-layer address, written as six hex bytes; one bit of the first byte marks group (multicast and broadcast) versus individual addresses, another marks locally administered versus globally unique ones (HW205 introduced it). D5 R3
Broadcast (Ethernet)
Simple words: a frame for every machine on the link. Analogy: calling out along the whole street. Precise: a frame whose destination MAC address is all ones, ff:ff:ff:ff:ff:ff; every interface on the link accepts it. D5 R3
IPv4 address
Simple words: a 32-bit number that identifies an interface across the whole internet, written as four numbers 0–255 with dots. Analogy: the full postal address: street and house. Precise: a 32-bit value carried in the IPv4 header; in dotted-decimal notation each of the four bytes, most significant first, is written in decimal. D2 R1
Prefix length and subnet mask
Simple words: how many leading bits of an address name the network; the rest name the host. Analogy: the rule saying which part of the address is "the street". Precise: a prefix length n (written /n) means the first n bits are the network part; the subnet mask is the 32-bit value with n ones followed by 32 − n zeros, so that address AND mask = network address. D6 R1
Subnet
Simple words: a group of addresses that share the same network part and sit on the same link. Analogy: one street. Precise: the set of addresses with a given prefix; hosts in the same subnet reach each other directly at the link layer, without a router. D1
Default gateway
Simple words: the router a host sends everything to that is not on its own subnet. Analogy: the street's post office. Precise: the next hop of the route 0.0.0.0/0, the least specific route, used when no more specific route matches. D1 R2
Longest-prefix match
Simple words: when several routes fit a destination, use the most specific one. Analogy: "River Street, house 15" beats "River Street" beats "anywhere". Precise: the IPv4 forwarding rule that selects, among table entries whose prefix matches the destination, the entry with the largest prefix length. D6 R2
ARP (Address Resolution Protocol)
Simple words: the way a host finds the MAC address that belongs to an IPv4 address on its own link. Analogy: calling out "who lives at number 77?" and getting an answer. Precise: a protocol carried directly in Ethernet frames (its own EtherType): a broadcast request "who has address X? tell Y" and a unicast reply "X is at MAC M"; hosts cache the answers. D3 R3

Layer 1 — the kid explanation

Every network card has a MAC address, like a name painted on a mailbox. It only helps on your own street, your own cable or Wi-Fi network: the card listens for frames with its own name on them and ignores the others. D5

To reach a computer anywhere, you need its IP address, like a full postal address. The first part of an IP address names the street (the network), the last part names the house (the host). A number after a slash, like /24, says how long the street part is. D2 D6

Before sending, a computer asks: is this address on my street? If yes, it sends straight there. If no, it sends to the street's post office, the router, which passes it on. To send straight to a neighbour, it needs the neighbour's mailbox name, so it calls out to everyone on the street: "who has this IP address?" That call is ARP. D3

Layer 2 — the student explanation

Ethernet frames and MAC addresses

An Ethernet header is 14 bytes: 6-byte destination MAC address, 6-byte source MAC address, 2-byte EtherType (F5-02). D5 MAC addresses are written as six hex bytes. Two bits of the first byte have meanings that tshark decodes for you: the lowest bit (I/G) marks a group address, and the next bit (U/L or "LG") marks a locally administered address rather than one assigned by the manufacturer; Listing 1's laptop address 02:00:00:41:00:15 has the second bit set, as tshark showed in F5-02. R3 D5 The all-ones address ff:ff:ff:ff:ff:ff is the broadcast address: every interface on the link accepts such a frame. D5

IPv4 addresses, prefixes and masks

An IPv4 address is 32 bits; dotted-decimal notation writes each byte in decimal, most significant first. D2 A prefix length /n splits it into an n-bit network part and a (32 − n)-bit host part. The mask has n ones followed by zeros; with it, three formulas give everything (Listing 1, lines 49–51): D6 R1

  • network address = address AND mask;
  • broadcast address of the subnet = network OR (NOT mask), all host bits set to one;
  • usable host addresses: from network + 1 to broadcast − 1, that is 232 − n − 2 of them, because the all-zeros and all-ones host values are reserved for the network and its broadcast.

Before prefixes of any length were allowed, addresses were divided into fixed "classes"; classless inter-domain routing (CIDR) replaced that scheme, and the /n notation comes from it. D6 On this build's machine, a fresh network namespace contains exactly one IPv4 address: 127.0.0.1/8 on the loopback interface (Listing 4). R5

The sending decision and the routing table

For every outgoing datagram, a host looks up the destination in its routing table and takes the matching entry with the longest prefix. An entry is either on-link (the destination is on that link: deliver directly) or has a gateway (deliver to that router, which must itself be on-link). The entry 0.0.0.0/0 matches everything and is the default route. D1 D7 Listing 2 implements this for a table with four entries: 10.8.3.9 matches both 10.8.0.0/16 and 10.8.3.0/24, and the /24 wins. R2 Note what does not change when a packet goes to a gateway: the IP header still carries the final destination's address; only the Ethernet frame is addressed to the router's MAC. That is the layering of F5-02 at work.

ARP: from IP address to MAC address

To build the Ethernet frame the host needs the next hop's MAC address. ARP asks for it: the host broadcasts a request carrying its own MAC and IPv4 addresses and the target IPv4 address with an all-zero target MAC; the owner of the target address answers with a unicast reply containing its MAC; both cache the result. D3 Listing 3 builds a request byte by byte; tshark decodes it as "Who has 192.168.41.1? Tell 192.168.41.15", with hardware type Ethernet (1), protocol type IPv4 (0x0800), sizes 6 and 4, opcode request (1). R3 ARP frames have their own EtherType, so ARP sits beside IP at the bottom of the internet layer, not inside it.

Layer 3 — the engineer's depth

Special addresses. Some IPv4 ranges have fixed meanings: 127.0.0.0/8 for loopback (shown by Listing 4 in this build), ranges set aside for private networks that are not routed on the public internet, and ranges reserved for documentation, from which this course takes its example addresses (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24). R5 D8 The private ranges and the special cases of /31 and /32 prefixes are in the unverified box: they matter in practice, and their exact values must come from the documents, not from this chapter's memory.

Not verified — check before relying on this

Not checked against the documents in this build: (1) the private address ranges (RFC 1918, "Address Allocation for Private Internets"); (2) the documentation ranges listed above (RFC 5737, "IPv4 Address Blocks Reserved for Documentation"); (3) the rules for /31 point-to-point links (RFC 3021) and /32 host routes; (4) whether every operating system treats the network and broadcast addresses of a subnet as unusable for hosts. Check those documents before using these values in a configuration.

Forwarding at scale. A router's table can hold a very large number of prefixes, and a lookup must finish for every packet; routers therefore use data structures such as tries keyed by address bits, or special memories that compare against all entries at once. Listing 2's linear search is the definition, not an implementation for a router. D1

ARP is unauthenticated. Any machine on the link can answer an ARP request, or send an unsolicited reply, and hosts tend to believe it; an attacker on the same link can redirect traffic this way. Switch features and static entries mitigate it; F11 covers the attack. D1

IPv6 in one paragraph. IPv6 (RFC 8200) uses 128-bit addresses, written in hex groups separated by colons, with the same prefix idea; ARP is replaced by Neighbor Discovery (RFC 4861), which uses ICMPv6 messages sent to multicast addresses instead of Ethernet broadcast. D9 The build container has IPv6 disabled, so no IPv6 listing was run in this course; curriculum milestone C9 adds IPv6 after IPv4. S1

How the hardware actually does it

An Ethernet NIC compares the destination MAC of every frame it receives with its own address, the broadcast address and a list of multicast addresses it was told to accept, and drops the rest in hardware; capture tools ask the driver to switch this filter off ("promiscuous mode") to see everything. D5 D1 An Ethernet switch learns, from the source address of each frame, which of its ports leads to which MAC address, forwards frames only to the right port, and floods broadcasts and unknown destinations to all ports; that is why an ARP request reaches every host on the link and the reply normally reaches only the asker. D1 HW205 showed where a NIC keeps its own MAC address and how the driver reads it.

Worked example

Take 10.1.200.9/20 and compute everything by hand, then compare with Listing 1.

  1. Only the third byte is cut by a /20 (16 bits in the first two bytes, 4 more in the third). 200 in binary is 1100 1000.
  2. Mask: 16 ones, then 4 ones, then 12 zeros. Third byte of the mask: 1111 0000 = 240. Mask = 255.255.240.0.
  3. Network: third byte 1100 1000 AND 1111 0000 = 1100 0000 = 192; fourth byte 9 AND 0 = 0. Network = 10.1.192.0.
  4. Broadcast: set the 12 host bits to one: third byte 1100 1111 = 207, fourth byte 255. Broadcast = 10.1.207.255.
  5. Hosts: 212 − 2 = 4094, from 10.1.192.1 to 10.1.207.254.
  6. Listing 1 printed the same four values and "4094 usable addresses". R1
  7. Same subnet? Is 10.1.207.100 on-link for this host? 207 AND 240 = 192 = the host's own third byte AND 240, and the first two bytes match: yes. Is 10.1.208.1? 208 = 1101 0000, AND 240 = 208 ≠ 192: no, it goes to the gateway.

Where the analogy breaks


    

  1. Streets do not move; addresses do. A house keeps its address. A laptop gets a different IP address on every network it joins (F5-06, DHCP), and one interface can hold several addresses at once. D1
    2. 

  2. The street boundary is a number you choose. On a real street everyone agrees where it ends. Each host decides from its own prefix length; two hosts on the same cable with different prefix lengths disagree about who is "on the street" — the forensic lab's whole problem.
    3. 

  3. Neighbours who answer may be lying. Calling out on a street, you can see who answers. ARP replies are not authenticated, and anyone on the link can claim any address (Layer 3). D1
    4.

Summary


    

  • Ethernet frames carry 48-bit MAC addresses; ff:ff:ff:ff:ff:ff is broadcast; tshark decodes the group and local bits.

  • An IPv4 address is 32 bits; /n says how many leading bits are the network part; mask = n ones then zeros.
    • 

  • network = address AND mask; broadcast = network OR NOT mask; usable hosts = 232−n − 2.
    • 

  • A host sends on-link if the destination is in its own subnet, otherwise to a gateway; the routing table is searched by longest-prefix match.
    • 

  • ARP finds the next hop's MAC: broadcast request, unicast reply, cached answer.
    • 

  • The IP header keeps the final destination; only the frame is addressed to the next hop.
    • 

  • A wrong prefix length breaks some destinations and not others.

Observation: Zainab (192.168.41.15/24) asks "Who has 192.168.41.1?" — the router — and gets a reply 0.3 ms later. Pedro (192.168.41.16/16) asks "Who has 192.168.40.20?" — the printer itself — three times, one second apart, with no reply. R4 Analysis: printer 192.168.40.20 AND 255.255.255.0 = 192.168.40.0 ≠ 192.168.41.0 (Zainab's network): via gateway, correct. With Pedro's /16 mask 255.255.0.0: 192.168.40.20 AND mask = 192.168.0.0 = 192.168.41.16 AND mask: Pedro believes the printer is on his own link and broadcasts an ARP request there; the printer is on the other link, broadcasts do not cross the router, so nobody answers. Why the rest works for Pedro: 203.0.113.9 is outside 192.168.0.0/16, so it goes to the gateway as it should; 192.168.41.77 is really on his link. Only addresses inside 192.168.0.0/16 but outside 192.168.41.0/24 fail — exactly the printer's subnet. Alternative wrong answers: "the printer is off" — Zainab prints fine; "the router is broken" — Zainab's traffic uses it; "ARP is blocked" — Zainab's ARP works. Fix: set Pedro's prefix length to /24 (better: let DHCP configure it, F5-06). Check: compare the prefix and gateway of every machine with the network plan; or capture ARP for one minute and look for requests about addresses outside the local subnet. How the evidence was made: printer_case.cpp applies the sending rule to each configuration and writes the ARP frames it implies, plus the router's reply to Zainab, into a capture file with made-up timestamps; tshark summarised it (R4).
