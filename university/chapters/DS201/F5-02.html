Story hook

Analogy

Rafael writes a letter to Amara's little brother, Kofi. He folds it into an envelope marked "for Kofi". His town's post office does not deliver to people; it delivers to houses, so the envelope goes into a bag labelled with Amara's street and house number. The bag rides on a van, and the van only goes as far as the next sorting office, so the van has its own label: "to the sorting office at the bridge".

At the bridge, a clerk unloads the van, throws away the van's label, reads the house address on the bag and loads it onto another van with a new label: "to the river-town office". Nobody on the way opens the envelope. At the end, the postman reads the house address and drops the bag at Amara's door; the family opens it and reads the name on the envelope: Kofi.

Each label is written for one helper and is read only by that helper's counterpart at the other end. That simple idea, labels inside labels, is how every computer network is organised. It has a name: layering.

What you will be able to do

  • Name the four layers of the Internet architecture, the job of each and the header each adds.
  • Explain encapsulation and demultiplexing, and follow the EtherType, protocol and port fields from the wire to a program.
  • Build an Ethernet frame containing IPv4, UDP and application data by hand in C++, and verify it with tshark.
  • Explain why a router looks only at the lower layers, and what changes in a packet at each hop.
  • Diagnose a hand-built packet that a decoder marks as faulty, and name the layer at fault.
Jargon box
Layer (protocol layer)
Simple words: one job of the network, done by one protocol, using only the job below it. Analogy: the van driver, the post office, the family at the door: each handles only its own label. Precise: a level in a protocol architecture; a layer offers a service to the layer above and uses the service of the layer below, and talks to its peer layer on the other machine through its own header. D1 D2
Encapsulation
Simple words: putting one layer's packet, header and all, inside the next layer's packet as its payload. Analogy: the envelope goes into the bag, the bag onto the van. Precise: the process in which each layer on the sending side prepends its header (and sometimes appends a trailer) to the data unit it received from the layer above. D1
Demultiplexing
Simple words: on arrival, choosing who gets the packet next by reading one field of the current header. Analogy: the family reads the name on the envelope to decide who opens it. Precise: the receiving side's use of a field in each header — EtherType, then the IP protocol number, then the destination port — to select the next protocol or the receiving socket. D1 R3
Frame (link layer)
Simple words: the name for a packet at the link layer, the one that travels on one wire. Analogy: the van with its label. Precise: the link-layer data unit; for Ethernet, destination and source MAC addresses, an EtherType and the payload (on the wire also a preamble and a frame check sequence that captures usually omit). D5 D1
Port (transport)
Simple words: a 16-bit number that says which program on a computer a packet is for. Analogy: the name of the person in the house. Precise: a 16-bit field in the UDP and TCP headers; the destination port, together with the address and protocol, selects the receiving socket. Not the same as a Verilog port (HW201) or an x86 I/O port (HW204). D3 D4
Pseudo-header
Simple words: a few fields borrowed from the IP header and included in the UDP or TCP checksum, but never sent as part of the UDP or TCP header. Analogy: Kofi's family checks that the house address on the bag matches their house before trusting the envelope. Precise: source address, destination address, protocol number and transport length, prepended only for the checksum computation, so that a datagram delivered to the wrong address fails the check. D3 R1
Checksum offload
Simple words: letting the network card compute a checksum instead of the CPU. Analogy: the van driver adds the count at the bottom, so the copy kept at the office has a blank. Precise: a feature where the operating system leaves a checksum incomplete and the network interface finishes it while sending; captures taken on the sending host then show a value that is not the final one. D1 R4

Layer 1 — the kid explanation

Sending a message across a network is too big a job for one program, so it is split into jobs that sit on top of each other, called layers. Each layer does one job and trusts the layer below to do its job. D1

The bottom layer moves bytes across one cable or one radio link, to the next box only. The layer above it gets a packet across many such links, from one computer to another far away. The layer above that delivers the packet to the right program on that computer. The top layer is the program itself, with its own message. D1

Each layer writes its own label, a header, in front of what it was given: that is encapsulation. The receiving computer peels the labels off in reverse order, and each label tells it who should look next. Boxes in the middle of the network, the routers, only peel the bottom labels, as the sorting office only reads the bag and never opens the envelope. D1 D2

Layer 2 — the student explanation

The four layers of the Internet architecture

The host requirements for the Internet describe four layers. Link layer: carries frames over one physical network (Ethernet, Wi-Fi); addresses are link addresses such as 48-bit MAC addresses (F5-03). Internet layer: IP carries datagrams from a source host to a destination host across many links; addresses are IP addresses; routers work at this layer. Transport layer: UDP and TCP deliver data from one program to another; ports select the program; TCP adds reliability and ordering (F5-04). Application layer: the program's own protocol, such as DNS (F5-06) or your project's chat protocol. D6 D1

You will also meet the seven-layer OSI reference model (physical, data link, network, transport, session, presentation, application). It is a vocabulary that many documents use ("a layer 2 switch", "a layer 7 load balancer"); the Internet protocols were not designed to it, and the four-layer description is the one used in this course. D7 D1

Encapsulation in bytes

Listing 1 builds a frame from the top down, exactly as a sender's stack does. udpLayer prepends an 8-byte UDP header (source port, destination port, length, checksum) to the 13 bytes of text: 21 bytes. ipLayer prepends a 20-byte IPv4 header (version and header length, total length, identification, flags, time to live, protocol, header checksum, source and destination addresses): 41 bytes. ethernetLayer prepends a 14-byte Ethernet header (destination MAC, source MAC, EtherType): 55 bytes. D2 D3 R1 tshark, Wireshark's command-line tool, decoded the file it wrote, found every field where the specifications put it, and called both checksums "correct". R2 A decoder written by other people agreeing with your bytes is strong evidence; it is not a proof (decoders have bugs too), which is why the course also compares against frames built by the Linux kernel (Layer 3).

Demultiplexing: one field per layer

On arrival each layer must decide who handles its payload. Ethernet's EtherType says which internet-layer protocol is inside (0x0800 was decoded as IPv4); IPv4's protocol field says which transport is inside (17 was decoded as UDP); UDP's destination port selects the socket of the receiving program (5000). R3 D2 A packet whose destination port has no socket is dropped by the receiving host, which may answer with an ICMP error; F5-04 captures that happening. D3

Where layers touch

Layering is not perfectly clean. The UDP checksum covers a pseudo-header made of IP-layer fields (both addresses, the protocol number and the UDP length), lines 46–52 of Listing 1, so a datagram delivered to the wrong host fails the check. D3 The IPv4 total length must agree with the UDP length, and with the bytes that really arrived. When one layer's field is computed from another layer's data, one mistake shows up as an error in a layer that is not to blame, as the forensic lab shows.

Layer 3 — the engineer's depth

Comparing with the kernel's own frame. F5-01 captured the frame the Linux kernel built for the same 13 bytes. Its decoding (below, in the code walk-through) differs from Listing 1's in exactly the places you would predict: on the loopback interface both MAC addresses are zero, because there is no real link; the identification field is a different number; the addresses are 127.0.0.1. The layout, the lengths and the protocol numbers are identical. R4 R2

A checksum that looks wrong but is right. tshark reports the kernel's UDP checksum as matching only a "partial (pseudo header) checksum", and suggests "UDP checksum offload". R4 The kernel left the checksum for a later stage to finish, as it does for NICs that compute checksums in hardware; on loopback the data never leaves memory, so the receiver can be told the data needs no check. D1 The lesson for engineers: a capture on the sending machine shows the packet before the last steps; do not file a bug for a bad checksum until you have looked at the packet on the wire or on the receiving side.

Not verified — check before relying on this

The exact mechanism by which the Linux kernel marks loopback packets so that the receiver skips checksum verification (the socket buffer's checksum state) was not checked in this build. Check the Linux kernel documentation on checksum offloads ("Checksum Offloads" in the networking documentation) for the kernel version recorded in the run logs before relying on the details.

Layer violations are sometimes deliberate. Network address translation rewrites addresses and ports, so it must recompute transport checksums; firewalls read port numbers; load balancers read application headers. Each such middle box makes the network less "end to end" and harder to change, which is a recurring design argument in networking. D1 In curriculum milestone C9 you will implement these layers as separate modules of your own kernel's stack, with the demultiplexing fields as the only coupling. S1

How the hardware actually does it

The physical part of the link layer is in hardware. An Ethernet PHY turns bits into signals; the MAC part of the NIC adds a preamble before the frame and a 32-bit frame check sequence (a CRC) after it when sending, and checks and strips them when receiving, so the operating system and captures normally see neither. D5 Many NICs also take over pieces of higher layers: checksum offload (above) and segmentation offload, in which the kernel hands the NIC one large TCP segment and the NIC cuts it into wire-sized ones with copied headers. D1 HW205 showed the descriptor rings through which the NIC fetches the bytes Listing 1's kind of code prepares.

Worked example

Compute the IPv4 header checksum of Listing 1's frame by hand, with the method of F5-01. The 20 header bytes (frame bytes 14–33) as 16-bit words, checksum field zero:

4500 0029 0001 4000 4011 0000 c000 0201 c000 0202

  1. 0x4500 + 0x0029 = 0x4529; + 0x0001 = 0x452A; + 0x4000 = 0x852A; + 0x4011 = 0xC53B.
  2. + 0xC000 = 0x1853B, fold the carry: 0x853C. + 0x0201 = 0x873D.
  3. + 0xC000 = 0x1473D, fold: 0x473E. + 0x0202 = 0x4940.
  4. Complement: 0xFFFF − 0x4940 = 0xB6BF. tshark: "Header Checksum: 0xb6bf [correct]". R2

Then the lengths, top-down: UDP length = 8 + 13 = 21 = 0x0015; IPv4 total length = 20 + 21 = 41 = 0x0029; frame = 14 + 41 = 55 bytes, all as printed by Listing 1 and decoded by tshark. R1

Where the analogy breaks


    

  1. Postal labels are written once; IP headers change on the way. Each router decrements the time to live and recomputes the IPv4 header checksum; a post office does not rewrite the house address. Network address translators even rewrite addresses and ports. D2 D1
    2. 

  2. The layers are not independent people. The family never checks the bag's address; UDP's checksum does include IP addresses (the pseudo-header), and one layer's wrong length makes another layer's decoding fail. D3
    3. 

  3. One sending computer is all the helpers at once. In the story different people handle each label. On a host, one kernel implements link, internet and transport layers in the same code path, and a NIC may do parts of several layers (checksums, segmentation). D1
    4.

Summary


    

  • The Internet architecture has four layers: link, internet (IP), transport (UDP, TCP) and application.
    • 

  • Sending, each layer prepends its header to what it got from above (encapsulation); receiving, each layer removes its header and reads one field to choose the next handler (demultiplexing).
    • 

  • EtherType → IP protocol number → destination port: the path from the wire to a socket.
    • 

  • Routers work at the internet and link layers; transport and application headers are end to end.
    • 

  • Layers touch: the UDP checksum covers IP addresses through a pseudo-header; lengths must agree across layers.
    • 

  • A decoder such as tshark is a strong check for hand-built packets; captures on the sender may show offloaded, unfinished checksums.
    •
