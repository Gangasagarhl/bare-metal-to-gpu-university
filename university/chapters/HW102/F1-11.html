Story hook

Analogy

Zofia has been asked to equip a small kitchen with a very tight budget. The supplier offers only one kind of tool: a good knife. "One knife?" says her friend. "How will you peel, slice, chop and spread?"

Zofia thinks about it. A knife can peel, if you hold it one way. It can slice and chop. It can even spread butter. Each job needs a different way of holding it, and some jobs need two or three knife moves. But nothing on the menu is impossible.

Digital designers face the same puzzle with gates. Suppose a factory makes only NAND gates. Can you still build every circuit? In this chapter you prove that you can, and you count how many NANDs each job costs.

What you will be able to do

  • Build NOT, AND, OR, NOR, XOR and XNOR from two-input NAND gates only, and state how many NANDs each needs.
  • Use De Morgan's laws to explain why the NAND constructions are correct.
  • Explain what "functionally complete" (universal) means and why NAND alone is enough.
  • Write gates as structural Verilog using only nand primitives and test them exhaustively.
  • Read a synthesis tool's gate count and compare it with a hand design.
  • Locate a wrongly connected wire inside a four-NAND XOR from its inside-wire values (the forensic lab).
Jargon box
Functionally complete (universal gate)
Simple words: a set of gates is complete if you can build every logic function from it; a gate that is complete on its own is called universal. Analogy: Zofia's one knife that can do every kitchen job, with enough moves. Precise: a set of Boolean operations is functionally complete if every Boolean function can be expressed using only operations from the set; {NAND} and {NOR} are each functionally complete. D1 D2
XOR (exclusive OR)
Simple words: "one or the other, but not both": the output is 1 when the inputs differ. Analogy: a light on a staircase with a switch at the top and one at the bottom: flipping either switch changes the light. Precise: y = a XOR b = (a AND NOT b) OR (NOT a AND b); its truth table is 0, 1, 1, 0 for inputs 00, 01, 10, 11. Defined in F0-26. W1
XNOR
Simple words: the opposite of XOR: 1 when the inputs are equal. Analogy: a "same?" checker for two switches. Precise: y = NOT (a XOR b); truth table 1, 0, 0, 1. W1
Structural description
Simple words: describing a circuit by listing its parts and how they are wired, not by writing a formula. Analogy: a floor plan showing every pipe and tap, instead of a sentence saying "the sink fills when…". Precise: an HDL description built from instances of gates or modules connected by named wires; the opposite style, describing what the output should be, is called behavioural. D2 D5
Synthesis tool
Simple words: a program that turns a circuit description into a list of gates. Analogy: a head chef who reads "make soup for twelve" and writes the exact steps and tools. Precise: software that translates an HDL description into a netlist of cells from a target library (here, NAND and NOT cells), usually trying to reduce some cost. D6 D2
Netlist
Simple words: the list of every gate in a circuit and the wires that join them. Analogy: the plumber's parts list with every pipe connection written down. Precise: a description of a circuit as instances (cells) and the nets (wires) connecting their pins. D6

Layer 1 — the kid explanation

A NAND gate answers 0 only when both inputs are 1. Join its two inputs together, and you feed it the same signal twice. Then it answers 0 only when that one signal is 1. That is a NOT gate, made from one NAND.

Now you have NOT. A NAND followed by a NOT gives AND, because the two "nots" cancel. That costs two NANDs.

OR is the clever one. Flip both inputs first, then NAND them. The NAND says 0 only when both flipped inputs are 1, which means both real inputs were 0. So the answer is 1 whenever a or b is 1. That is OR, with three NANDs.

Once you have NOT, AND and OR, you can build any truth table. So NAND alone is enough for every circuit in a computer. Engineers call it a universal gate.

Layer 2 — the student explanation

Why NAND is enough

Any truth table can be written as an OR of AND terms, one AND term for each row whose output is 1, each term using inputs or their NOTs. This is the sum-of-products form from Boolean algebra. So {AND, OR, NOT} is functionally complete. If NAND can build all three, NAND alone is complete too. D2 D1

The three constructions, with the algebra that proves them:

  • NOT a = NAND(a, a), because NOT (a AND a) = NOT a. One NAND. W1
  • a AND b = NOT (NAND(a, b)). Two NANDs: the second is used as an inverter. W1
  • a OR b = NAND(NOT a, NOT b), because by De Morgan's law NOT ((NOT a) AND (NOT b)) = a OR b. Three NANDs. W1

From these, NOR is OR followed by NOT: 3 + 1 = 4 NANDs. XNOR is XOR followed by NOT. The same argument works with NOR as the only gate, swapping the roles of AND and OR. W1 D2

XOR with four NANDs

Building XOR from the formula (a AND NOT b) OR (NOT a AND b) with the pieces above costs many NANDs. Figure 2 does it with four. The trick is the shared wire t = NAND(a, b). Then u = NAND(a, t) and v = NAND(b, t), and y = NAND(u, v). The Worked example checks all four rows by hand, and Listing 3 checks them in the simulator. W1 R2

Structural Verilog and counting gates

Listing 1 is a structural description: every gate is an instance of Verilog's built-in nand primitive, and every wire has a name. Modules can contain other modules: nor_n is built from an or_n and a not_n. Because nothing else is used, the run of Listing 2 proves each function is reachable from NAND alone. R1 D5

A synthesis tool can do the same job automatically. We gave Yosys the one-line XOR assign y = a ^ b; and asked it to use only NAND cells. Its report counts 3 NAND and 2 NOT cells. A NOT costs one NAND, so that is 5 NAND-equivalents, one more than the hand design. The tool's goal is not "fewest NANDs", so its answer can differ. For OR it reports 1 NAND and 2 NOT cells: exactly Figure 1. R3 R4 D6

Layer 3 — the engineer's depth

NAND-only design is a teaching tool and a real constraint in some technologies, but real chips mix many cell types. A synthesis tool picks cells from a library to meet goals for area, delay and power, and its internal cost model decides between them. Counting "NAND-equivalents", as we do, is a rough measure of size: it ignores that a NOT is smaller than a NAND in CMOS (2 transistors versus 4, F1-10) and that some cells are faster than others. D2 D6

Functional completeness also has a precise meaning for single gates: among the two-input gates, only NAND and NOR are complete on their own. AND and OR alone cannot build NOT, because with all inputs at 0 they can only output 0. D2 W1

How the hardware actually does it

In CMOS a NAND gate is 4 transistors and a NOT is 2 (F1-10). So "AND = 2 NANDs" is 8 transistors in our NAND-only style, but only 6 as NAND + NOT. Real chips use the cheaper mix. The NAND-only discipline is kept in this course because it lets you build a whole computer from one well-understood part, which is exactly the path the course book D1 takes. D1 W1

Where the analogy breaks


    

  • A knife used to spread butter is still one knife; a NAND used as NOT is a whole gate. Every "move" in the analogy is a separate physical gate on the chip, with its own transistors and its own delay. D2
    • 

  • A cook can choose a better tool when one is available; a NAND-only design cannot. Real chips are not limited to NAND: they use whatever cells are cheapest (Layer 3), so "one knife" is a teaching rule, not how hardware is made.
    • 

  • The order of knife moves matters in a kitchen; the gates of Figure 1 work all at once. All gates react to their inputs in parallel; there is no step-by-step order, only signals passing through (time returns in F1-15).

Transition box

Where you came from: F1-10 built NOT, NAND and NOR from transistors. What carries over: truth tables, exhaustive testbenches, and the fact that a gate is a real physical part. What changes: you stop drawing transistors and treat the NAND gate as the single building block; correctness is now proved with Boolean algebra (De Morgan) plus simulation; you also meet a synthesis tool that chooses gates for you. What comes next: F1-12 combines gates into the first useful building blocks: multiplexers that choose a signal and decoders that select one line. D1

Summary


    

  • NAND alone is functionally complete: NOT, AND and OR can all be built from it, and they can build any truth table.
    • 

  • NOT = 1 NAND, AND = 2, OR = 3 (De Morgan), NOR = 4, XOR = 4 (shared wire t), XNOR = 5.
    • 

  • NOR is universal too, by the mirror argument.
    • 

  • Structural Verilog lists gates and wires; behavioural Verilog says what the output is.
    • 

  • A synthesis tool turns behaviour into a netlist; its gate count need not match a hand design.
    • 

  • Printing inside wires is how you localise a wrong connection.

Forensic lab answer key


Observation: rows 01 and 11 are wrong (y = 0 for 01, y = 1 for 11; FAIL 2 of 4, R5). Comparing inside wires with the Worked example: t and u match in every row; v differs in rows 01 (1 instead of 0) and 11 (0 instead of 1). Hypotheses: (1) g4 is miswired; (2) g3 is miswired. In rows 00 and 10, u and v match the table and y is right, and g4's inputs are u and v as designed, which rules out (1). Root cause: Listing 5, line 6: nand g3(v, b, a); takes a instead of t, so v = NAND(a, b) = t. Why rows 00 and 10 survive: in those rows NAND(b, a) happens to equal NAND(b, t) (both 1, because b = 0). Fix: nand g3(v, b, t);; rerun gives ALL PASS (R2). Prevention: print inside wires in testbenches of small blocks and compare with a hand table. How the evidence was made: Listing 1's XOR with g3's second input changed from t to a, run with Listing 3 in this build. Wrong answers: "the simulator rounds" (logic values are exact 0/1; the run is repeatable); "g2 is wrong" (u matches the table in every row).
