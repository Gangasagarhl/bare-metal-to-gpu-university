Story hook

Analogy

Mateo runs the pass, the counter between the kitchen and the dining room. Four stations put plates on it: grill, soup, salad and dessert. Only one plate can go through the hatch at a time. Mateo looks at the order number on the ticket and slides that station's plate through.

Above the stations hangs a ticket board with four lamps. When a new order arrives, the board lights exactly one lamp, the one for the station that must cook it. The other three stay dark.

Mateo is doing two jobs that every computer does billions of times: choosing one of several inputs by a number, and turning a number into "this one, and no other". In hardware these jobs have names: the multiplexer and the decoder.

What you will be able to do

  • Explain what a multiplexer and a decoder do, with their truth tables and symbols.
  • Build a 2-to-1 multiplexer from four NAND gates, and a 4-to-1 multiplexer as a tree of 2-to-1 multiplexers.
  • Build a 2-to-4 decoder with an enable input from NOT and AND gates.
  • Design a combinational circuit from a word description, via its truth table.
  • Write a one-hot probe testbench, and use it to find swapped select lines (the forensic lab).
Jargon box
Combinational circuit
Simple words: a circuit whose outputs depend only on its inputs right now, with no memory. Analogy: the pass: what goes through depends only on the plates and the ticket in front of Mateo, not on yesterday's orders. Precise: a digital circuit without feedback or storage, whose outputs are a Boolean function of its current inputs (after the outputs settle, F1-15). Circuits with memory are sequential (HW201). D2 ch.2 summary D8 §7.7
Multiplexer (mux)
Simple words: a circuit that chooses one of several inputs and passes it to the output. Analogy: Mateo sliding one station's plate through the hatch. Precise: a combinational circuit with 2n data inputs, n select inputs and one output, whose output equals the data input whose index is the binary number on the select inputs. D1 §1.2.2, §1.2.4 D8 §7.8.1
Select input
Simple words: the input that says which choice to make, written as a binary number. Analogy: the order number on the ticket. Precise: the control inputs of a multiplexer or decoder; with n select bits there are 2n choices. D1 §1.2.4 D8 §7.8.1
Decoder
Simple words: a circuit that turns a binary number into one active line out of many. Analogy: the ticket board lighting exactly one station lamp. Precise: a combinational circuit with n inputs and 2n outputs, of which exactly the output whose index equals the input number is 1 (when enabled). D8 §7.8.3.1
Enable
Simple words: an on/off input that lets a circuit work or keeps all its outputs off. Analogy: the main switch of the ticket board: when it is off, no lamp lights. Precise: an input that, when inactive, forces a decoder's outputs to their inactive value (here 0) regardless of the other inputs. W1 R1
One-hot
Simple words: a group of wires where exactly one is 1. Analogy: one lit lamp on the ticket board. Precise: an encoding in which exactly one bit of a group is 1; a decoder's outputs are one-hot when enabled. D8 §7.8.3.1

Layer 1 — the kid explanation

A multiplexer is a chooser. It has several data inputs and one output. A small number, the select, says which input to pass on. With one select wire you can choose between two inputs. With two select wires you can count 00, 01, 10, 11, so you can choose between four.

A decoder works the other way round. It takes a small number and lights exactly one of its outputs. With two input wires it has four outputs. Input 10 is the number two, so output number two lights up.

Both are made of gates you already know. A decoder output is an AND gate that only says 1 for its own number. A multiplexer is a set of AND-like gates, one per input, with an OR to collect the one that was let through.

These two parts are everywhere inside a computer. A computer's memory uses a decoder to find the one box an address points to. Its calculator uses a multiplexer to choose which answer to keep.

Layer 2 — the student explanation

Combinational design from a description

A combinational circuit has no memory: its outputs are a function of its present inputs. Designing one follows a fixed recipe: write the truth table from the word description, write a sum-of-products formula (one AND term per row with output 1), simplify if you can, then build it from gates. Multiplexers and decoders are the first useful products of this recipe. D2 ch.2 summary D8 §7.6

The multiplexer

A 2-to-1 multiplexer has data inputs d0, d1, a select input s and output y. Its description is "y = d0 when s = 0, y = d1 when s = 1". The sum-of-products formula is y = (d0 AND NOT s) OR (d1 AND s). Each AND term is a gate that lets one input through only when it is selected; the OR collects them. D8 §7.8.1 W1

Turning AND-OR into NAND-NAND is De Morgan's law again: (x AND y) OR (z AND w) = NAND(NAND(x, y), NAND(z, w)). So the mux is g2 = NAND(d0, ns), g3 = NAND(d1, s), and y = NAND(g2, g3), plus g1 to make ns = NOT s: four NANDs, Figure 1. W1 R1

Bigger multiplexers come from smaller ones. A 4-to-1 mux needs two select bits s1 s0. In the tree of Figure 2, the first level uses s0 to choose within each pair (d0 or d1, d2 or d3), and the second level uses s1 to choose between the pairs. The select number s1 s0 is read as a binary number, so 10 chooses d2. That costs 3 × 4 = 12 NANDs. W1 R2

The decoder

A 2-to-4 decoder has two inputs s1 s0 and four outputs y0 to y3. Output yk is 1 exactly when s1 s0 is the binary number k. Each output is one AND term of the truth table: y2 = s1 AND NOT s0, for example. With an enable input en, each AND gets a third input en, so all outputs are 0 when en = 0. The outputs are one-hot when enabled: exactly one is 1. D8 §7.8.3.1 R1

Decoders and multiplexers are close relatives. A multiplexer can be built from a decoder whose outputs gate each data input, followed by an OR. Conversely, the AND terms inside a multiplexer are a decoder. W1

Layer 3 — the engineer's depth

Two properties make multiplexers important in design. First, any Boolean function of n inputs can be built from a 2n-to-1 multiplexer: put the function's truth-table outputs on the data inputs as constants and the function's inputs on the select lines. Second, a multiplexer is how hardware implements "choose", the hardware version of if and switch; in F1-14 the ALU chooses its result with one. D8 §7.8.2 W1

The tree in Figure 2 is not the only structure. A wide AND-OR (one AND term per input, as in the formula) has fewer levels of gates, which matters for speed (F1-15); a tree reuses one small tested block. Choosing between them is an early example of the size-versus-speed trade-offs of real design. D8 §7.7 W1

How the hardware actually does it

Inside a memory, combinational logic uses the address to select one register out of many, the job of a decoder; inside a processor, select signals choose which register values go to the ALU, the job of multiplexers. D1 §3.2.3, §3.3 D8 §14.2.2.1 You will meet both again: the register file and memory in HW201, and the datapath in HW202. Real chips may build multiplexers from transmission gates (pairs of transistors used as pass switches) instead of NANDs; that is a transistor-level choice the logic function does not see. D7 L1

Worked example

From a description to a circuit

Description: "A buzzer at the pass sounds when the selected station's plate is ready. There are two stations, the select s picks one, and r0, r1 are 1 when that station's plate is ready." Truth table rows with output 1:

sr1r0buzzAND term
0011NOT s AND NOT r1 AND r0
0111NOT s AND r1 AND r0
1101s AND r1 AND NOT r0
1111s AND r1 AND r0

The first two terms combine to (NOT s AND r0), because r1 can be either value. The last two combine to (s AND r1). So buzz = (r0 AND NOT s) OR (r1 AND s): exactly a 2-to-1 multiplexer with d0 = r0 and d1 = r1. A description that says "choose by a number" usually becomes a multiplexer. W1

Trace the tree

Inputs d = d3 d2 d1 d0 = 0 1 0 0 (only d2 is 1), select s1 s0 = 10. m0 uses s0 = 0 and passes d0 = 0 (lo = 0). m1 uses s0 = 0 and passes d2 = 1 (hi = 1). m2 uses s1 = 1 and passes hi = 1. Output y = 1 = d2. The probe run of Listing 3 prints "d2" in the row for select 1 0. W1 R2

Where the analogy breaks


    

  • Mateo moves a plate; a multiplexer copies a value. The unselected inputs keep their values and the selected one is not "used up". Many multiplexers can read the same input at once. D8 §7.8.1 W1
    • 

  • Mateo takes time to read the ticket and can be distracted; a mux has no attention. It responds to every change of any input, selected or not, after a gate delay. It never "waits for the ticket". D8 §7.7
    • 

  • The ticket board could light no lamp by mistake and a cook would notice; a decoder with a fault is silent. Only a test (like Listing 2's 8 rows) finds an output that never lights.

Transition box

Where you came from: F1-11 built every single gate from NAND. What carries over: NAND-NAND form via De Morgan, structural Verilog, exhaustive testbenches. What changes: you now design blocks with many inputs from a word description (truth table → sum of products → gates), use buses, and build big blocks from small tested ones; tests now report which input is connected (probes), not only pass/fail. What comes next: F1-13 applies the same recipe to arithmetic: the half adder and the full adder. D8 §7.6 D1 ch.2 §2.2.1

Summary


    

  • Combinational circuits have no memory; design them via truth table → sum of products → gates.
    • 

  • A 2n-to-1 multiplexer chooses one data input by an n-bit select number.
    • 

  • A 2-to-1 mux is (d0 AND NOT s) OR (d1 AND s): four NANDs.
    • 

  • Bigger muxes are trees of smaller ones; the low select bit goes to the first level.
    • 

  • An n-to-2n decoder makes one output 1 (one-hot) for each input number; an enable can turn all outputs off.

  • A one-hot probe maps which input is really connected for each select value.

Forensic lab answer key


Observation: select 0 1 gives d2 and select 1 0 gives d1; selects 0 0 and 1 1 are correct (FAIL 4 of 16 probes, R3). Hypotheses: (1) data inputs d1 and d2 are swapped (a "mislabelled file"); (2) the select bits are swapped. Under (1), the one-hot probe would still show each select value picking one input, and swapping the data would also be fixed by relabelling; but the wrong rows are exactly those whose two select bits differ (01 and 10), the signature of swapped select bits. The source decides it: data wiring in Listing 4 lines 4–5 matches Listing 1. Root cause: Listing 4, lines 4–6: m0 and m1 use s[1] and m2 uses s[0]; the levels' select bits are swapped. Why 00 and 11 survive: swapping two equal bits changes nothing. Fix: m0 and m1 use s[0], m2 uses s[1], as Listing 1; the probe then prints the diagonal and ALL PASS (R2). Prevention: a one-hot probe or an exhaustive test with d[s] as the reference. How the evidence was made: Listing 1's mux4 with the select bits of the two levels exchanged, run with Listing 3 in this build. Wrong answers: "the sound files are mislabelled" (relabelling would only hide the fault; the data wiring is correct); "mux2 is broken" (it passes its own 8-row test in R1).
