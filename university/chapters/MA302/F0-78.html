Story hook

Analogy

Two things can go wrong when Laila carries a full cup of tea to the table. The table may be wobbly: lean on it with one finger and the cup on it tips. Or her way of carrying may be careless: she swings her arm, and tea spills on a perfectly steady floor. A wobbly table is a property of the table; the careless swing is a property of how she carries. A careful carrier cannot fix a wobbly table, and a steady table does not save a careless carrier.

Numerical work has the same two questions. Is the problem sensitive, so that tiny changes in its data change the answer a lot? That is its conditioning. Is the algorithm careless, adding error the problem never asked for? That is its stability. This chapter teaches you to tell them apart, with a solver that is careful on a hopelessly wobbly table, two careless algorithms on steady tables, and a robot whose position jumps by half a metre near a wall although nothing in its code is wrong.

What you will be able to do

  • Define the condition number of a problem and compute it for subtraction, a sum, a function value and a linear system.
  • Distinguish forward error from backward error, and a stable algorithm from a well-conditioned problem.
  • Apply the rule of thumb "forward error ≲ condition number × backward error" to predict how many digits a result can have.
  • Replace unstable formulas with stable ones (the small root of a quadratic, a series with alternating signs).
  • Diagnose an error that comes from the problem's geometry, not from the code (this chapter's forensic lab).
Jargon box
Condition number (of a problem)
Simple words: how much a problem magnifies small changes in its input. Analogy: how far the cup tips per gram of finger pressure on the table. Precise: the relative condition number of y = f(x) is the limit of (relative change of y)/(relative change of x) for small changes; for differentiable scalar f, κ = |x f′(x)/f(x)|. It belongs to the problem, whatever algorithm is used. B1B2
Condition number of a matrix
Simple words: the condition number of solving Ax = b. Analogy: the wobble factor of a table built from the matrix. Precise: κ(A) = ‖A‖ ‖A−1‖ in a chosen norm (κ∞, κ2); κ2 = σmax/σmin, the ratio of the largest to the smallest singular value. κ ≥ 1, and κ = ∞ for a singular matrix. B2
Forward error and backward error
Simple words: how wrong the answer is, and how much you would have to change the question for the answer to be exactly right. Analogy: how far the cup is from where it should be, and how much the table would have to move for that to be its right place. Precise: for computed ŷ ≈ f(x): forward error |ŷ − f(x)|/|f(x)|; backward error the smallest |Δx|/|x| with ŷ = f(x + Δx). B1
Stable algorithm (backward stable)
Simple words: an algorithm that adds no more error than rounding the input would. Analogy: a careful carrier. Precise: an algorithm is backward stable if its result is the exact answer for an input changed by a relative amount of order the unit roundoff u; then forward error ≲ κ × u. B1B2
Ill-conditioned problem
Simple words: a problem whose answer is very sensitive to its data. Analogy: the wobbly table. Precise: a problem with κ large compared with 1/(required relative accuracy); with κ ≈ 10k, expect to lose about k decimal digits of the input's accuracy, whatever the algorithm. B1

Layer 1 — the kid explanation

Some questions are touchy. If you ask "where are the two lines crossing?" and the lines are almost parallel, a tiny wiggle of one line moves the crossing point far along. No calculator, however good, can fix that: the question itself magnifies the wiggle. That magnifying power is the question's condition number.

Other times the question is calm but the way you compute it is clumsy. You subtract two nearly equal big numbers when you did not need to, and lose the digits that mattered. A better recipe gives the right answer on the same computer.

So when an answer is wrong, ask two questions. Is the question touchy? Then get better data or ask a different question. Is the recipe clumsy? Then change the recipe. Fixing the wrong one wastes your time.

Layer 2 — the student explanation

Condition numbers you have already met

  • Subtraction a − b: κ = (|a| + |b|)/|a − b|. Large when a ≈ b: this is catastrophic cancellation (F0-74) seen as a property of the problem. D1B1
  • A sum Σxi: κ = Σ|xi|/|Σxi|, the condition number of a sum from F0-75 (5,617 for the mixed data there).
  • A function value f(x): κ = |x f′(x)/f(x)|. For ex, κ = |x|: computing e−20 is well conditioned (κ = 20). For √x, κ = 1/2. D1
  • A linear system Ax = b: κ(A) = ‖A‖ ‖A−1‖, and if b changes by a relative amount ε, x can change by up to κ(A) ε. B2

The rule of thumb

If an algorithm is backward stable, its answer is the exact answer to a problem changed by about u. The problem then magnifies that change by κ. So forward error ≲ κ × backward error ≈ κ u. With u ≈ 1.1 × 10−16 in double, κ = 108 leaves about 8 correct digits; κ = 1016 leaves none. In float (u ≈ 6 × 10−8), κ = 106 already leaves about one. B1D1

Figure 2 tests the rule. The Hilbert matrix hij = 1/(i + j − 1) becomes ill-conditioned fast: κ∞ = 27 for n = 2, 3.5 × 1013 for n = 10, 4.6 × 1017 for n = 13 (run R1). Gaussian elimination with partial pivoting (F0-77) keeps the relative residual between 3 × 10−17 and 2.3 × 10−16 for every n: the algorithm is doing its job. The relative error grows from 7 × 10−16 to 4.2 and stays below κu throughout. At n = 13 not a single digit of x is right, and nothing in the residual warns you. R1

Unstable algorithms on calm problems

The small root of x2 − bx + 1 = 0 is about 1/b: a well-conditioned problem. The textbook formula (b − √(b2 − 4))/2 subtracts two nearly equal numbers. Run R2: at b = 108 it returns 7.45 × 10−9 instead of 1.0 × 10−8, and at b = 1010 it returns 0 (b2 − 4 rounds to b2). Multiplying by the conjugate gives the algebraically identical 2/(b + √(b2 − 4)), which adds two positive numbers and is accurate to the last digit printed. R2S2

e−20 from its Taylor series sums terms that alternate in sign and reach 2020/20! ≈ 4.3 × 107 before shrinking. Each rounding of a partial sum near that size is about 4.3 × 107 × 1.1 × 10−16 ≈ 5 × 10−9, already larger than the answer 2.06 × 10−9. Run R2 prints 6.15 × 10−9: wrong by a factor of three. Computing 1/e20 with the same series (all terms positive) gives 2.061153622438557 × 10−9, matching the library to 15 digits. The problem (κ = 20) was never the trouble. R2D1

Watch out

A small residual or a passing round-trip test checks backward error. It cannot detect an ill-conditioned problem: run R1 at n = 13 has a residual of 2 × 10−16 and an error of 4.2. When accuracy matters, estimate κ as well.

Layer 3 — the engineer's depth

The perturbation bound. If (A + ΔA)(x + Δx) = b + Δb with ‖A−1‖‖ΔA‖ < 1, then ‖Δx‖/‖x‖ ≤ κ(A)/(1 − κ(A)‖ΔA‖/‖A‖) × (‖ΔA‖/‖A‖ + ‖Δb‖/‖b‖). For a stable solver both relative perturbations are of order u, which gives the rule of thumb with a constant. The bound is attained for some perturbations, so it is a true worst case, not a pessimistic guess. B1B2

Estimating κ cheaply. Listing 1 forms A−1 to compute κ, which costs as much as several solves and is fine for teaching. Libraries estimate ‖A−1‖ from the LU factors in O(n2) extra work; the estimate is usually within a small factor. κ2 exactly needs the singular value decomposition (SVD), which also shows which directions of x are poorly determined: the singular vectors of the smallest singular values. B2

Least squares and the normal equations. Fitting a model to more measurements than unknowns leads to min ‖Ax − b‖. Solving the normal equations ATA x = ATb squares the condition number (κ2(ATA) = κ2(A)2), so a fit with κ = 106 becomes a system with κ = 1012. QR factorisation solves the same problem working with A directly. This matters for calibration and polynomial fits in RB and DN courses. B2

Mixed precision. The rule of thumb tells you which precision a problem needs: with data accurate to 10−3 and κ = 102, the answer cannot be better than 10−1 relative in any precision, and float is plenty; with exact data and κ = 1010, float is useless and double leaves six digits. F0-80 applies this to FP16, BF16 and FP8. D1

How the hardware actually does it

Hardware has no notion of conditioning: every IEEE 754 operation is correctly rounded, and the floating-point unit does not know whether the problem it serves is touchy. What the hardware choice changes is u. Moving a computation from double to float multiplies u by 229 ≈ 5 × 108, so the same κ costs about 8.7 more decimal digits. On GPUs and accelerators, where float and lower precisions are much faster (HW301), the condition number of the problem decides whether the faster precision is acceptable, and that decision must be written down with its numbers. S1D1

Sensors bring their own conditioning. A robot that locates itself from beacon bearings, ranges or camera features solves a small linear (or linearised) system each time; the geometry of the landmarks sets that system's κ, which is why where you mount beacons matters as much as how good the sensor is. R5

Worked example

A nearly singular 2 × 2 system. A = [[1, 1], [1, 1.0001]], b = (2, 2.0001).

  1. Solve: det A = 1.0001 − 1 = 0.0001. By Cramer's rule x1 = (2 × 1.0001 − 1 × 2.0001)/0.0001 = 1, x2 = (1 × 2.0001 − 1 × 2)/0.0001 = 1. So x = (1, 1).
  2. Change b a little: b = (2, 2.0002), a relative change ‖Δb‖∞/‖b‖∞ = 0.0001/2.0001 ≈ 5 × 10−5. Now x1 = (2.0002 − 2.0002)/0.0001 = 0, x2 = (2.0002 − 2)/0.0001 = 2. So x = (0, 2): a relative change of 1, that is 100 %.
  3. Condition number: ‖A‖∞ = max(1 + 1, 1 + 1.0001) = 2.0001. A−1 = (1/0.0001)[[1.0001, −1], [−1, 1]], so ‖A−1‖∞ = 10,000 × 2.0001 = 20,001. κ∞ = 2.0001 × 20,001 ≈ 40,004.
  4. Check the bound: κ × 5 × 10−5 ≈ 2.0 ≥ 1, the change observed. The bound holds and is nearly attained.
  5. Meaning: the two equations describe two almost parallel lines; a measurement error of 10−4 in b2 moves their crossing from (1, 1) to (0, 2). No algorithm can do better: if b2 is known only to ±10−4, x is not known at all. D1

Where the analogy breaks


    

  • You can see a wobbly table; you cannot see κ. It must be computed or estimated, and its value depends on the norm and on which inputs you allow to change. B2
    • 

  • A table wobbles the same way for everyone. A problem can be well conditioned for one kind of change (relative changes of each entry) and badly for another (changes in a combined norm). B1
    • 

  • Laila can steady a table with a folded napkin. Some ill-conditioned problems can be reformulated into well-conditioned ones (more beacons, a different basis for a polynomial fit); some cannot, and then the honest output is a large uncertainty. R5
    • 

  • Careless carrying spills a little each time. An unstable algorithm can be perfect on most inputs and catastrophic on a few (the quadratic formula is fine for b = 3). Testing must include the bad inputs. R2
    •

Method hints


The system is s da − t db = B − A with unit direction vectors da, db. When the two directions are nearly opposite, the matrix [da, −db] has nearly parallel columns. A 0.2° bearing error at 5 m moves a sight line sideways by about 5 × 0.0035 = 0.017 m.

Summary


    

  • Conditioning belongs to the problem (κ); stability belongs to the algorithm (backward error).
    • 

  • Forward error ≲ κ × backward error; for a stable algorithm about κu: log10 κ digits are lost.
    • 

  • For linear systems κ(A) = ‖A‖‖A−1‖; GEPP is stable, so its residual stays tiny even when its answer is meaningless (run R1).
    • 

  • Unstable algorithms on calm problems are fixed by rearranging: the stable quadratic root, summing without huge cancelling terms (run R2).

  • Geometry is conditioning: beacons almost in line with the robot give κ = 16.7 and a long sliver of possible positions (run R5).
