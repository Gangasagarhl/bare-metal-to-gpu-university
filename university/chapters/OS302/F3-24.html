Story hook

In the old school building every classroom had a wire running to a single bell board in the office, with eight lamps and a second board chained to the first for the newer wing. It worked, but only for one office, and the lamp numbers were fixed by how the electrician wired them decades ago.

The new building has a switchboard. Every doorbell in the school is wired to it, and the switchboard has a programmable table: "doorbell 1, ring the principal's desk, with tone 48". Each staff desk has its own small receiver that queues calls by importance. The caretaker leaves a booklet in the office describing the wiring: how many desks, where the switchboard is, and which doorbells were moved when the building was extended ("the old bell 0 now arrives on line 2").

There is one rule the new principal forgets on her first day: after answering a call, press "done" on the desk receiver. She answers the first doorbell, never presses "done", and wonders why the desk goes quiet for the rest of the morning.

This chapter reads the caretaker's booklet (the ACPI tables), switches off the old bell board (the 8259 PIC), programs the switchboard (the IOAPIC) and the desk receiver (the local APIC), and takes the first real device interrupts: the keyboard and the serial port.

What you will be able to do

  • Find the ACPI RSDP, walk the RSDT or XSDT, and validate every table's checksum; reject a damaged table.
  • Parse the MADT: processors, IOAPICs, interrupt source overrides and NMI entries, and decode override flags.
  • Retire the 8259 PICs safely: remap them away from the exception vectors, then mask every line.
  • Program the local APIC in xAPIC (MMIO) or x2APIC (MSR) mode and the IOAPIC's redirection table.
  • Route ISA IRQ 1 (keyboard) and IRQ 4 (serial) to vectors of your choice, and acknowledge them correctly.
  • Read the local APIC's ISR, IRR and PPR in a QEMU monitor dump and explain a missing interrupt.
Jargon box
ACPI
Simple words: tables in memory in which the firmware describes the machine's devices and wiring. Analogy: the caretaker's booklet. Precise: the Advanced Configuration and Power Interface; here only its static tables: a Root System Description Pointer, a root table (RSDT with 32-bit or XSDT with 64-bit entries), and description tables each starting with a 36-byte header with signature, length and checksum. D1
RSDP
Simple words: the small signpost that tells you where the ACPI tables are. Analogy: the note on the office door saying "booklet in drawer 3". Precise: the Root System Description Pointer, a structure with the signature "RSD PTR " found on a 16-byte boundary in the first KiB of the EBDA or in 0xE0000–0xFFFFF on legacy boots (UEFI passes it in the configuration table). D1
MADT
Simple words: the ACPI table that lists the interrupt hardware. Analogy: the booklet's page about doorbells and desks. Precise: the Multiple APIC Description Table (signature "APIC"): local APIC address, flags (PCAT_COMPAT), then variable-length entries for processor local APICs, I/O APICs, interrupt source overrides, NMI sources and their x2APIC variants. D1
Local APIC
Simple words: each CPU's own interrupt receiver. Analogy: the receiver on a staff desk. Precise: the per-processor Advanced Programmable Interrupt Controller: it accepts interrupts, prioritises them by vector (in-service, request and priority registers), delivers them to the core, and has its own timer and local vector table; accessed as memory (xAPIC) or MSRs (x2APIC). D2
IOAPIC
Simple words: the chip that turns device interrupt wires into messages to CPUs. Analogy: the switchboard. Precise: an I/O APIC with a redirection table of one 64-bit entry per input pin (vector, delivery mode, polarity, trigger mode, mask, destination), programmed through an index register and a data window. D3
8259 PIC
Simple words: the old interrupt controller of the original PC. Analogy: the old bell board with eight lamps. Precise: a pair of cascaded 8259A Programmable Interrupt Controllers providing ISA IRQs 0–15; still emulated, and by default delivering on vectors that collide with CPU exceptions, so it must be remapped and masked. D4
GSI (global system interrupt)
Simple words: ACPI's number for an interrupt input, counted across all IOAPICs. Analogy: the switchboard's line number. Precise: a flat numbering of IOAPIC inputs; an IOAPIC with first GSI g serves g to g + pins − 1. D1
Interrupt source override
Simple words: a note that an old IRQ number arrives on a different line, or with different electrical settings. Analogy: "the old bell 0 now arrives on line 2". Precise: a MADT entry mapping an ISA IRQ to a GSI, with flags for polarity (bits 1:0) and trigger mode (bits 3:2), where 0 means "conforms to the bus" (ISA: edge, active high). D1
EOI (end of interrupt)
Simple words: telling the interrupt controller "I have finished with that interrupt". Analogy: pressing "done" on the desk receiver. Precise: a write to the local APIC's EOI register that clears the highest-priority bit in the in-service register, allowing interrupts of equal or lower priority to be delivered again. D2
x2APIC
Simple words: the newer mode of the local APIC, used through special CPU registers instead of memory. Analogy: a desk receiver with a direct line instead of a shared cable. Precise: an extension of the local APIC architecture with 32-bit APIC IDs, register access through MSRs 0x800–0x8FF, and a single 64-bit ICR; enabled by bit 10 of IA32_APIC_BASE. D2

As in the whole course, "kernel" means the operating-system kernel; the "kernel (GPU)" of F6 is a function launched on a GPU.

Layer 1 — the kid explanation

When you press a key, the keyboard needs to tell the CPU "something happened". It does this by ringing a doorbell: an interrupt. In old PCs all doorbells went to one small chip with sixteen lamps. Modern PCs have a switchboard that can send each doorbell to any CPU with any number the kernel picks, and each CPU has its own receiver that sorts the calls by importance.

The kernel cannot guess how the switchboard is wired, so it reads a booklet the firmware left in memory: the ACPI tables. Each page of the booklet has a checksum, so a damaged page can be spotted and ignored. And after answering each doorbell, the kernel must press "done", or the receiver stops passing on calls.

Analogy

Doorbells are devices, the switchboard is the IOAPIC, the desk receiver is the local APIC, the booklet is ACPI, and "done" is the EOI. The old bell board (the 8259) is still on the wall, so the kernel disconnects it before using the switchboard.

Layer 2 — the student explanation

Finding and checking the tables

On a legacy (BIOS) boot the RSDP is found by scanning: first the first KiB of the Extended BIOS Data Area (its segment is the 16-bit word at physical 0x40E), then 0xE0000–0xFFFFF, on 16-byte boundaries, for "RSD PTR " with a valid checksum over the first 20 bytes D1. Revision 0 means ACPI 1.0: only a 32-bit RSDT. Revision 2 adds a length, an extended checksum and a 64-bit XSDT, which the kernel prefers. QEMU 8.2.2 with SeaBIOS gives revision 0, RSDP at 0xf52b0, RSDT at 0x07fe1c23 R1.

Every description table starts with the same 36-byte header; all length bytes must add up to 0 modulo 256. The kernel checks every table and keeps only valid ones. The DSDT is not in the root table: its address is in the FADT (signature "FACP"). QEMU's tables: FACP, DSDT (6,807 bytes of AML, which this course does not interpret), APIC (the MADT), HPET (F3-25) and WAET.

What the MADT says

After the header come the local APIC address (32 bits) and flags; bit 0, PCAT_COMPAT, says 8259 PICs are present and must be disabled. Then entries, each starting with a type and a length byte. The kernel uses types 0 (processor local APIC), 1 (IOAPIC), 2 (interrupt source override), 4 (local APIC NMI), 5 (64-bit local APIC address), 9 (processor local x2APIC) and 0x0A (x2APIC NMI) D1. A length that runs past the table is a reason to reject the table: trusting it would read past the end.

QEMU's MADT has one CPU, one IOAPIC at 0xfec00000 with first GSI 0, and five overrides. The famous one: ISA IRQ 0 (the PIT timer) arrives on GSI 2, because on these chipsets IOAPIC pin 2 is wired to the PIT output. IRQs 5, 9, 10 and 11 are level-triggered, active high (flags 0x000d: polarity 1, trigger 3); IRQ 9 is the ACPI system control interrupt.

Retiring the 8259

The 8259 pair's power-on vectors overlap the CPU's exception vectors, so even a stray interrupt would look like an exception. The kernel reinitialises both chips (ICW1–ICW4) with bases 0x20 and 0x28, and then masks all 16 lines D4. Remapping first matters: a masked PIC can still deliver a spurious IRQ 7 or 15, which now lands on 0x27 or 0x2F, not on #DF or #GP. The run reads back masks ff ff.

The local APIC

The IA32_APIC_BASE MSR (0x1B) holds the register page's physical address, a "boot CPU" bit (8), an x2APIC enable bit (10) and a global enable bit (11). The run reads 00000000fee00900: base 0xfee00000, boot CPU, enabled R1. The kernel maps the page uncached in a device window (0xffffe80000000000), then sets: task priority 0 (accept everything), the timer and LINT0 masked, LINT1 as NMI, an error vector (0xFE), and the spurious-interrupt vector register to 0x1FF (software enable plus vector 0xFF). The local APIC reports version 0x14 and 6 LVT entries.

In x2APIC mode the same registers are MSRs: register offset o becomes MSR 0x800 + o/16, so EOI (0xB0) is MSR 0x80B. The kernel's read_lapic and write_lapic hide the difference; the only other differences it handles are the ID's position (bits 31:24 in xAPIC, all 32 bits in x2APIC) and that nothing needs mapping.

The IOAPIC and routing

The IOAPIC has two registers in its 4 KiB page: IOREGSEL at offset 0 (which register) and IOWIN at offset 0x10 (its value). Register 1 is the version: bits 23:16 hold the highest redirection entry index, so pins = that + 1 = 24 in QEMU. Redirection entry n is registers 0x10 + 2n (low half: vector bits 7:0, delivery mode, destination mode, polarity bit 13, trigger bit 15, mask bit 16) and 0x11 + 2n (destination APIC ID in bits 63:56) D3. The kernel masks all pins first, then for each ISA IRQ: looks up the override (or identity, edge, active high), allocates the next free vector from 0x30, installs the handler, writes the high half, and finally the low half with the mask bit clear.

The run: IRQ 1 → GSI 1 → vector 0x30 (redirection 0000000000000030); IRQ 4 → GSI 4 → vector 0x31. Three "transmitter empty" serial interrupts arrive at 0x31, and the four scancodes of "a" and "b" (press 1e, release 9e, press 30, release b0) at 0x30, with 0 spurious interrupts R1.

Layer 3 — the engineer's depth

Priority, ISR, IRR and why EOI matters

The local APIC keeps three 256-bit registers: IRR (requested, not yet delivered), ISR (delivered, handler not finished) and TMR (trigger mode). A vector's priority class is its upper four bits. The processor priority (PPR) is the larger of the task priority and the class of the highest ISR bit; the local APIC delivers an IRR vector only if its class is higher than the PPR D2. So while vector 0x30 is in service, 0x30–0x3F wait, and a higher class (0x40 and up: the timer of F3-25) can interrupt the handler if interrupts are enabled. The EOI write clears the highest ISR bit. That is why vector numbers are priorities: the course gives device vectors from 0x30 up and the timer 0x40.

Spurious interrupts (vector 0xFF here) arrive when an interrupt is withdrawn between request and delivery; they set no ISR bit and must not be acknowledged with EOI. The kernel counts them and the run shows 0.

Edge and level, polarity, and acknowledging the device

The EOI acknowledges the local APIC. The device needs its own acknowledgement, or a level-triggered line stays asserted and the interrupt fires again at once. The keyboard handler reads port 0x60 (the scancode), which empties the controller's output buffer; the serial handler reads the IIR (cause 1, "transmitter holding register empty": IIR value c2, with the FIFO bits) and clears the interrupt enable register so that the next interrupt happens only when the test asks for it. For a level-triggered IOAPIC input, the local APIC's EOI is broadcast to the IOAPIC, which then re-samples the line; an edge-triggered input needs no such step D3. Getting the polarity or trigger mode wrong is a classic source of interrupt storms or silence; the MADT overrides exist exactly to get them right.

Rejecting a damaged table

The milestone asks for "a deliberately corrupted table (via a test patch)". The tables live in RAM that the kernel's direct map makes read-only, so the test kernel (-DB7_CORRUPT) maps the MADT's page a second time, writable, at 0xffffc00000000000, flips bit 6 of the OEM revision field (byte 24: 01 → 41) without fixing the checksum, and rescans. The rescan logs APIC … checksum BAD: table rejected at level Error, find("APIC") returns nothing, and the kernel refuses to program the APICs R3. The host test also builds a table whose checksum is valid but whose last entry claims 40 bytes past the end, and checks that the parser refuses it R2: a checksum proves the table was not damaged in transit, not that its author was right.

x2APIC on and off: what the lab can and cannot show

The third acceptance test asks that the same kernel works with QEMU's x2APIC CPU flag on and off. The lab runs both. With the flag off, CPUID reports no x2APIC and the kernel uses xAPIC: pass. With the flag on, QEMU 8.2.2 under TCG prints "warning: TCG doesn't support requested feature: CPUID.01H:ECX.x2apic [bit 21]", CPUID still reports no x2APIC, and the kernel again uses xAPIC: pass, but the x2APIC code path did not run R4. The x2APIC branch (MSR access, enable bit 10, 32-bit ID) is therefore untested in this build. It needs KVM on a host whose CPU has x2APIC, or a QEMU version whose TCG implements it; recording that is part of the honest result.

Not verified — check before relying on this

From memory, pending D1–D4: the RSDP layout and search areas; the FADT's DSDT field at offset 40; MADT entry types and field offsets (especially types 5, 9 and 0x0A) and the override flag encoding; the IA32_APIC_BASE bits; the local APIC register offsets (ID 0x20, version 0x30, TPR 0x80, EOI 0xB0, SVR 0xF0, ESR 0x280, LVT 0x320–0x370) and the x2APIC MSR mapping 0x800 + offset/16; the IOAPIC register numbers and redirection-entry bits; the 8259 initialisation words. The x2APIC path has never run (see above). The XSDT path of acpi::init has not run either: QEMU's pc and q35 machines with SeaBIOS both gave revision-0 RSDPs in this build.

How the hardware actually does it

Inside a modern PC the IOAPIC is part of the chipset (the platform controller hub), and "wires" from devices are often virtual: a PCI device may assert a legacy INTx line that the chipset routes to an IOAPIC pin, or it may send a message-signalled interrupt (MSI or MSI-X) that writes directly to the local APIC's address range and bypasses the IOAPIC completely D2. The PS/2 keyboard and the COM port are often emulated by a super-I/O chip or by firmware on machines without the physical ports. On real hardware the MADT may list many CPUs, some disabled, several IOAPICs with different GSI bases, and overrides beyond IRQ 0.

Under KVM the local APIC is usually emulated in the host kernel, and x2APIC is normally offered: the untested path matters as soon as the course moves to KVM or to real hardware. Firmware may already have switched the CPU to x2APIC mode before the kernel runs; switching back to xAPIC is not allowed directly, so a kernel must handle "already in x2APIC mode" D2.

Watch out

Untested on hardware. On a real machine with UEFI, the RSDP comes from the UEFI configuration table (or the bootloader), not from a memory scan, and the tables may be above 4 GiB: the direct map must cover them.

Worked example

Decode the redirection entry for GSI 1 and the override for IRQ 9, then check the MADT's length.

  1. GSI 1 entry 0000000000000030: bits 7:0 = 0x30 (vector); bits 10:8 = 0 (fixed delivery); bit 11 = 0 (physical destination); bit 13 = 0 (active high); bit 15 = 0 (edge); bit 16 = 0 (unmasked); bits 63:56 = 0 (APIC ID 0). The kernel's line agrees: "vector 30, edge, active high, unmasked, destination 0".
  2. GSI 2 entry 0000000000010000: bit 16 = 1, masked. The PIT's IRQ 0 arrives here (override 0 → 2), still unused until F3-25.
  3. Override for IRQ 9, flags 0x000d = binary 1101: polarity bits 1:0 = 01 (active high), trigger bits 3:2 = 11 (level). The redirection entry would have bit 15 set and bit 13 clear.
  4. MADT size: 36 (header) + 4 (LAPIC address) + 4 (flags) + 8 (CPU) + 12 (IOAPIC) + 5 × 10 (overrides) + 6 (NMI) = 120 bytes, the length the kernel printed R1.

Where the analogy breaks


    

  • A switchboard rings a desk; the IOAPIC sends a message that the local APIC can delay, merge (two edges of the same vector before delivery become one) or reorder by priority.
    • 

  • Pressing "done" ends one call. EOI clears the highest-priority in-service vector, whichever that is: an EOI from the wrong handler acknowledges someone else's interrupt.
    • 

  • The caretaker's booklet is written once; ACPI tables can contain code (AML in the DSDT) that a full kernel must interpret, which this course does not do.
    • 




Common mistakes and debugging


    

  • Masking the 8259 without remapping it: a spurious IRQ 7 arrives as vector 7 (#NM).
    • 

  • Mapping APIC registers cached: writes stay in the cache; nothing happens, or happens late.
    • 

  • Forgetting the IRQ 0 → GSI 2 override: the timer never fires (F3-25).
    • 

  • Ignoring polarity and trigger flags: an interrupt storm or silence on level-triggered lines.
    • 

  • No EOI, or EOI for a spurious interrupt: the forensic lab; or a lost real interrupt.
    • 

  • Not acknowledging the device: reading port 0x60, reading IIR; otherwise the device does not raise the next edge.
    • 

  • Using vectors below 0x20 for devices: collisions with exceptions.
    • 

  • Debugging: QEMU's monitor info lapic shows ISR, IRR and PPR; info irq counts raises per line; info pic shows the 8259s and the IOAPIC.
    •

Summary


    

  • RSDP by scanning (legacy) → RSDT or XSDT → tables with a common 36-byte header; every checksum checked, damaged tables rejected.
    • 

  • The MADT lists CPUs, IOAPICs, overrides and NMI sources; overrides move ISA IRQs (IRQ 0 → GSI 2) and set polarity and trigger.
    • 

  • The 8259 is remapped to 0x20–0x2F, then fully masked.
    • 

  • The local APIC: base MSR, uncached page or x2APIC MSRs, TPR 0, LVTs, SVR enable with a spurious vector.
    • 

  • The IOAPIC's redirection entries choose vector, polarity, trigger, mask and destination; unmask last.
    •

Forensic lab answer key


Observation. The kernel logged one keyboard interrupt (scancode 1e, the press of "a"). QEMU counted 3 raises of IRQ 1 for the four scancodes sent; once the kernel stops reading port 0x60, later scancodes wait inside QEMU's keyboard model, so the exact count depends on that model and is not needed for the diagnosis. info lapic: ISR 48 and IRR 48, i.e. vector 0x30 is in service and another 0x30 is requested; PPR 0x30.


Hypotheses. QEMU's keyboard is fine: it raised IRQ 1 three times. The IOAPIC entry is not masked: the request reached the local APIC (IRR). The local APIC holds it back because the processor priority (0x30, from the in-service vector) is not lower than the request's class (3).


Root cause and fix. The keyboard handler never writes EOI (B7_NO_EOI removes apic::eoi(), lines 34–36). The ISR bit for 0x30 is never cleared; every later 0x30 waits in the IRR. Fix: send EOI at the end of every non-spurious interrupt handler, preferably in the common dispatch code so a handler cannot forget it.


Prevention. The whole class 0x30–0x3F was blocked, including the serial port's 0x31 (the serial tests ran before the first key, so they passed). Detectors: after each handler, check that the vector's ISR bit is clear (the mini-project), or count interrupts per vector and alarm when a device's count stops while QEMU's info irq grows. QEMU also counted 4 raises of IRQ 4 for 3 logged serial interrupts; this build does not explain the extra one (an open question for the owner, not needed for the diagnosis).
