Story hook

At six in the morning, before any guest arrives, Daniel walks Yuki through the empty kitchen. "Follow one ticket," he says. "It always takes the same path." He points: the ticket rail, where the next ticket is taken down. The pass, where someone reads it and calls out what each station must do. The cutting boards beside the stove, where the ingredients for this dish are laid out. The stove itself, where something is combined or cooked. The hatch to the pantry, used only when the ticket needs something stored or fetched. And finally the shelf by the stove where the result is put down, ready for the next ticket that needs it.

"Every ticket walks this road," Daniel says. "Some skip the pantry hatch. Some only move the clip on the rail. But the road is always the same." Yuki draws the road on the back of a menu. It is the same drawing you will make in this chapter, with one change of words: the kitchen becomes a datapath.

What you will be able to do

  • Name the parts of a single-cycle datapath (program counter, instruction memory, register file, sign extension, ALU, data memory, multiplexers) and what each does.
  • Trace any U16 instruction through the datapath, writing down the value on every important wire.
  • Explain why a single-cycle design needs a clock period long enough for the slowest instruction.
  • Run a program you wrote in U16 machine language on the simulated CPU and read its trace.
  • Diagnose a program whose result is always zero from a datapath trace.
Jargon box
Datapath
Simple words: the parts of the processor that hold, move and change data, connected by wires. Analogy: the road one ticket takes through the kitchen: rail, cutting boards, stove, pantry hatch, shelf. Precise: the collection of functional units (ALU, register file, memories, adders, multiplexers) and the connections between them that carry out instructions, steered by control signals. D1 D2
Register file
Simple words: the block that holds all the registers, with doors to read two of them and write one. Analogy: the row of cutting boards beside the stove, each with a number. Precise: an array of registers with (here) two read ports, addressed by register numbers from the instruction, and one write port enabled by a control signal. D1 R1
ALU (arithmetic logic unit)
Simple words: the calculator part: it adds, subtracts, compares and combines bits. Analogy: the stove, where ingredients are combined. Precise: a combinational circuit that computes one of several operations on two inputs, chosen by its operation input (built in F1-14). D2
Multiplexer (mux)
Simple words: a switch that picks one of several inputs to pass on. Analogy: the cook choosing whether the stove gets an ingredient from the board or a measured spoonful written on the ticket. Precise: a combinational selector whose select input, driven by a control signal, chooses which data input reaches the output (F1-12). D2
Sign extension
Simple words: making a short signed number longer without changing its value. Analogy: writing "−1" on a big label instead of a small one: same value, bigger space. Precise: copying the sign bit of an n-bit two's-complement value into all higher bits of a wider word; U16 extends its 6-bit immediate to 16 bits. D1 R1
Single-cycle processor
Simple words: a processor that does a whole instruction in one tick of the clock. Analogy: one cook who walks every ticket along the entire road before taking the next ticket. Precise: a design in which every instruction completes in one clock cycle, so the clock period must cover the longest path through the datapath. D1 D2
Critical path
Simple words: the slowest route signals must travel before the result is ready. Analogy: the longest walk any ticket needs. Precise: the longest combinational delay between two clocked elements; it sets the minimum clock period (F1-15, F1-18). D2

The idea in pictures

Figure 1 is the U16 single-cycle datapath. It is drawn from left to right in five regions that the next chapters will turn into pipeline stages: instruction fetch (IF), instruction decode and register read (ID), execute (EX), memory access (MEM) and write back (WB). Solid lines carry data; dashed lines carry control signals from the control unit (F1-25).

Layer 1 — the kid explanation

Every instruction goes through the same few steps. First the processor fetches it: it looks at the program counter, the bookmark that says which instruction is next, and reads that instruction from memory. Then it decodes it: it splits the bits into the command and the register numbers, and reads the registers the command needs.

Next it executes: the ALU, the processor's calculator, adds or subtracts or compares. If the instruction is a load or a store, the processor then goes to data memory, the pantry, to fetch or put away a value. Last, it writes back the answer into a register, like putting a finished dish on the shelf.

Some instructions skip steps. An add never visits data memory. A store does not write a register. A branch only decides where the bookmark goes next. But the road is always the same, and little switches called multiplexers decide which turnings an instruction takes.

In the simplest processor, all of this happens in one tick of the clock. That is easy to understand, but slow: the tick must be long enough for the longest trip, even when the instruction is short.

Layer 2 — the student explanation

The parts and the wires

The textbook way to build a processor is to first collect the parts each instruction needs, then join them with wires and multiplexers so that every instruction can share them. D1 D2 For U16 the parts are:

  • PC, a 16-bit register (F1-17) holding the address of the current instruction, and an adder that computes PC + 1 (U16 addresses count whole instructions, not bytes). R1
  • Instruction memory: given the PC, it outputs the 16-bit instruction word. D1
  • Register file with two read ports and one write port. Read port A is always addressed by field rs. Read port B is addressed by rt for R-type instructions and by rd for sw, beq, bne and out, which read the register named in that field; a multiplexer controlled by ReadRdAsB chooses. R1
  • Sign extension of the 6-bit immediate to 16 bits. D1
  • ALU with operations add, sub, and, or and slt. A multiplexer controlled by AluSrcImm chooses whether the second ALU input is register B or the immediate. R1
  • Data memory: the ALU result is the address; register B is the data to store. R1
  • Write-back multiplexer controlled by MemToReg: the value written to rd is either the ALU result or the word read from memory; RegWrite decides whether anything is written at all. D1 R1
  • Next-PC logic: for beq/bne the ALU subtracts the two registers; if the zero test matches the branch type, the next PC is PC + 1 + imm, otherwise PC + 1. R1

R1

The column B in the trace may show a value even for addi. That is not a bug: the register file always reads both ports, because it cannot know in advance whether the value will be needed; the AluSrcImm multiplexer then ignores it. Real datapaths behave the same way: reading is cheap and done in parallel, and multiplexers throw away what is not needed. D1 R1

Why "single-cycle" is slow

In a single-cycle design, all state (PC, registers, data memory) is updated at one clock edge, and between two edges the signals must ripple all the way from the PC through instruction memory, register file, ALU and data memory to the write-back multiplexer. The clock period must therefore be at least the delay of the slowest instruction's path, the load in a typical design, even though an add or a branch finishes earlier. D1 D2 Every instruction pays for the worst one. F1-26 fixes this by cutting the road into stages.

Layer 3 — the engineer's depth

  • Harvard versus unified memory. U16 has separate instruction and data memories, so one cycle can fetch an instruction and access data at once. With one shared memory, a single-cycle design would need two memory accesses in the same cycle for a load; textbook designs avoid this by assuming separate instruction and data memories (in real processors: separate instruction and data caches in front of one main memory, F1-33). D1 D2
  • Register file timing. The register file is read combinationally during the cycle and written at the clock edge. That is why the instruction can read r3 and write r3 in the same instruction (add r3, r3, r4): it reads the old value during the cycle and the new value appears after the edge (F1-16). D2
  • Word addressing. U16 counts addresses in 16-bit words, so the next instruction is at PC + 1. Byte-addressed ISAs add the instruction size instead; the real RISC-V output in F1-23 shows instructions at byte offsets 0, 2, 6, 8 and so on. R2
  • Multi-cycle alternative. Between single-cycle and pipelined designs lies the multi-cycle design: one instruction at a time, but split into several shorter cycles, so a short instruction uses fewer cycles. It reuses one ALU and one memory across cycles. This course skips it and goes straight to pipelining; D1 and D2 treat it. D1 D2

How the hardware actually does it

Everything in Figure 1 is built from parts you met in HW102 and HW201. The PC and the registers are banks of D flip-flops (F1-16, F1-17) that change only at a clock edge (F1-18). The register file's read ports are multiplexers that pick one register's outputs by number; its write port is a decoder that enables exactly one register. The memories are arrays of storage cells (F1-20). The ALU is the circuit of F1-14, and the adders are ripple-carry or faster adders. Between two clock edges nothing is "stepped": all these circuits compute at once, and the slowest chain of gates sets how soon the next edge may come (F1-15). D2 D3 The simulator steps through the regions in order only because C++ runs line by line; the hardware does them as one wave of signals.

Worked example

Task. Trace bne r2, r0, -5 at address 7 when r2 = 4 (cycle 8 of the trace).

  1. IF. PC = 7. Instruction memory outputs 0xA43B. PC + 1 = 8.
  2. ID. op = 10 (bne), rd = 2, rs = 0, imm = −5. Control sets ReadRdAsB = 1, so read port B uses rd = r2. Port A reads r0 = 0, port B reads r2 = 4. Sign extension turns 111011 into 1111 1111 1111 1011 = −5.
  3. EX. ALU op = sub (control, F1-25). A − B = 0 − 4 = −4. Not zero. Branch adder: 8 + (−5) = 3.
  4. MEM. MemRead = MemWrite = 0: nothing happens.
  5. WB. RegWrite = 0: no register changes.
  6. Next PC. BranchNe = 1 and the ALU result is not zero, so the next PC is the branch target, 3.

The trace line for cycle 8 shows A = 0, B = 4, ALU = −4, next PC 3, "(branch taken)", matching every step. R1 The order of subtraction (A − B = r0 − r2) does not matter for equality, which is all bne needs.

Where the analogy breaks


    

  • The kitchen road is walked; the datapath is not. A ticket moves from station to station over time. In a single-cycle datapath, all regions work at the same moment on the same instruction, as one wave of electrical signals settling. D2
    • 

  • Cooks look at what they need; the register file reads everything it is pointed at. Port B reads a register even for addi, and the multiplexer discards it (column B in the trace). Nothing in hardware "decides not to look". R1
    • 

  • A shelf keeps whatever you put on it; register r0 does not. Writes to r0 are discarded, by design (forensic lab). R3
    • 




Common mistakes and debugging


    

  • Symptom: a result stays 0. Cause: destination r0. How to find it: the trace's write-back column shows "-" for an instruction that should write. Fix: use r1–r7. (Forensic lab.)
    • 

  • Symptom: a load returns the wrong element. Cause: the address register was not advanced, or advanced before the load. How to find it: compare the "read [n]" addresses in the trace with the intended ones. Fix: order lw and addi correctly.
    • 

  • Symptom: confusion about why B is non-zero for addi. Cause: reading the B column as "used". How to find it: check AluSrcImm in the control table of F1-25. Fix: remember that multiplexers choose; the register file always reads.
    • 

  • Symptom: "pc ... is outside the program" fault. Cause: a missing halt, so execution runs off the end. How to find it: the last trace line's next PC equals the program length. Fix: end every program with halt.
    •

  • A datapath is the set of units and wires that carry out instructions; control signals steer it.

Forensic lab answer key


Root cause. add r0, r0, r5 uses r0 as the counter. In U16, r0 always reads 0 and writes to it are discarded (line 327 of u16.h: write back only if rd != 0). The count is computed and thrown away every time, and out r0 prints 0.


Evidence. slt works: cycles 5, 11, 17, 23 show ALU = 1, 0, 1, 0 and "r5 = 1", "r5 = 0"… (3 < 5, 8 < 5 false, 1 < 5, 6 < 5 false). The add r0, r0, r5 lines show ALU = 1 in cycles 6 and 18 but the write-back column is "-". The final register dump shows r0 = 0; r3, which Kofi probably meant, was never used.


Fix. Initialise a real counter (addi r3, r0, 0) before the loop, use add r3, r3, r5 and out r3. Verified pattern: this is the structure of the F1-27 forensic program, whose real runs output the correct count.


How the fault was made. The Lab Engineer wrote the correct program with r3 as the counter and replaced r3 by r0 in the add and out lines (and removed the counter's initialisation).


Wrong answers and why. "slt is broken": its results are right in the trace. "The limit is wrong": r6 = 5 in cycle 3. Prevention: the assembler could warn when an instruction with RegWrite names r0 as its destination.
