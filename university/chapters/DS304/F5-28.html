Story hook

Analogy

Amara and Kenji live in two towns joined by one bridge. Each town has its own library. When Amara needs a book from her own library she walks round the corner; when the book sits in Kenji's library it must cross the bridge, and on busy days the bridge has a queue. Both towns share one catalogue, so any friend can borrow any book, and nobody is ever told "no". They are only told "later". The friends' reading club works fastest when each member's books live in the member's own town, and slowest when a newcomer's whole shelf was, by accident, put in the other town.

A modern server is two (or more) of those towns. Each processor socket has its own memory, attached through its own memory channels; the sockets are joined by an interconnect; and every core can read every byte, some faster than others. This is non-uniform memory access, NUMA, which you met in F1-39 from the hardware side. This chapter looks at it the way a data-centre engineer and an operating system meet it: the firmware describes the towns in ACPI tables (SRAT and SLIT) and the inventory in SMBIOS, the OS reads those tables, and placement decisions that ignore them make a server mysteriously slow. You will build a UEFI program that reads those tables on a two-socket virtual server, check every line against the QEMU command line, and then diagnose a server whose second town has no library at all.

What you will be able to do

  • Explain the anatomy of a multi-socket server: sockets, cores, memory controllers and channels, the inter-socket interconnect, I/O attached to sockets, and the management controller beside them.
  • Read the firmware's description of a server's NUMA layout: the SRAT (which processors and memory ranges belong to which proximity domain) and the SLIT (relative distances), plus the SMBIOS processor and memory-device inventory.
  • Verify those tables against an independent source of truth, and explain what differs and why (the legacy hole in node 0).
  • Compute the mean relative distance of a thread's memory accesses for a given page placement, and say what the number does and does not mean.
  • Diagnose a NUMA misconfiguration (a node with processors but no memory) from table dumps.
Jargon box
Socket (processor package)
Simple words: the place on a server's main board where one processor chip sits; a "two-socket server" has two processors. Analogy: one town. Precise: a physical processor package with its cores, caches, memory controllers and links; SMBIOS describes each populated or empty socket with one processor information structure (type 4). D1 D3
NUMA node (proximity domain)
Simple words: a group of processors and the memory that is nearest to them. Analogy: a town with its own library. Precise: a set of processors, memory ranges (and possibly devices) that the firmware declares to be close to each other; ACPI calls it a proximity domain and numbers it in the SRAT; the OS turns proximity domains into its NUMA nodes. D2 D4 Not to be confused with a "node" in distributed systems (F5-08), which is a whole machine.
SRAT
Simple words: the firmware table that says which processors and which memory belong to which NUMA node. Analogy: the town register: who lives where, which library holds which shelves. Precise: the ACPI System Resource Affinity Table (signature "SRAT"): after the common header, a list of affinity structures, among them processor local APIC affinity (APIC ID → proximity domain) and memory affinity (base, length → proximity domain, with an "enabled" flag). D2 R2
SLIT
Simple words: the firmware table that says how far apart the NUMA nodes are. Analogy: the travel-time signs on the roads between towns. Precise: the ACPI System Locality Information Table (signature "SLIT"): a count n of localities followed by an n × n matrix of one-byte relative distances, where the distance of a locality to itself is normalised to 10. D2 R2
Interconnect (inter-socket link)
Simple words: the wires and protocol that join the processors so they can reach each other's memory and keep caches consistent. Analogy: the bridge between the towns. Precise: point-to-point links between sockets that carry remote memory requests, responses and cache-coherence traffic; their names and properties are vendor-specific and come from the vendor's documentation for a named processor (AH-21). D1
Memory-less node
Simple words: a NUMA node that has processors but no memory of its own. Analogy: a town with houses but no library: every book comes over the bridge. Precise: a proximity domain to which the SRAT assigns processors but no enabled memory range; every memory access from its processors is remote. D2 R6

Terms from earlier chapters used here: NUMA, memory channel, memory controller and first-touch policy (F1-39); ACPI, MADT and SMBIOS (F3-12).

Layer 1 — the kid explanation

A big server is several computers' worth of processors glued into one machine. Each processor chip has its own memory next to it. Any processor can use any memory, but memory next to a different chip takes a trip across a bridge. The machine still looks like one computer to your program. Nobody tells your program which memory is near and which is far, unless the operating system asks the firmware and then places things carefully.

So a server has a map: which processors live in which "town", which memory belongs to which town, and how long the trip between towns is. The firmware writes that map when the machine starts. In this chapter you read the map yourself and check that it is true.

Layer 2 — the student explanation

Anatomy, from the outside in

Analogy first: the towns, the libraries and the bridge. A rack-mounted server holds one or more processor packages in sockets, memory modules (DIMMs) in slots grouped into channels, storage and network devices on PCI Express, power supplies, fans, and a baseboard management controller (BMC) that runs whenever the server has standby power. D1 D6 Inside each package are cores with private caches, a shared last-level cache, one or more memory controllers and the links to other packages and to I/O. D1 Since the memory controller is in the package, each socket owns the DIMMs on its channels; a core that needs a line from the other socket's DIMMs sends the request over the interconnect, and the other socket's controller answers. D1 That is the hardware reason for NUMA (F1-39).

Channels matter twice. They add bandwidth when they work in parallel, and they decide how much memory a node has. A socket whose channels are empty has no local memory, however many cores it has. D1 Which slots must be filled, in which order, and with which module types is a rule of the specific main board and processor; it comes from the board vendor's manual, not from general principles (see the unverified box in "How the hardware actually does it").

How the OS learns the layout

The OS cannot discover NUMA by itself in a general way; the firmware describes it. On ACPI systems that description is two tables you have not decoded before. D2 S1

  • The SRAT lists affinity structures. A processor local APIC affinity structure says "the processor with this APIC ID belongs to proximity domain d"; a memory affinity structure says "this physical range belongs to proximity domain d", with flags (bit 0: enabled). D2
  • The SLIT is a square matrix of relative distances. Entry (i, j) is the relative cost for locality i to reach memory of locality j; the diagonal is 10. A value of 21 means "about 2.1 times the local cost" only in the loose sense the specification gives it: the numbers are relative and unitless, not nanoseconds. D2

The MADT (from F3-12) still lists the processors; the SRAT adds where they live. SMBIOS adds inventory for humans and management tools: one type 4 structure per processor socket and one type 17 structure per memory device. D3 If there is no SRAT, an OS treats the machine as one node; the lab's second boot shows exactly that case. D4 R3

What the OS does with it

Linux turns proximity domains into NUMA nodes and shows them in sysfs, one directory per node, with the node's CPU list, its memory counters and its row of the distance table; by default it allocates a page on the node of the CPU that first touches it (F1-39, first-touch policy), and it offers memory policies and CPU affinity so that programs and administrators can bind threads and memory to nodes. D4 Listing 1 reads those sysfs files on the build container: it is a virtual machine with one node, four CPUs in one package, and a distance row of "10". R1

Layer 3 — the engineer's depth

The SRAT and SLIT byte by byte

Both tables start with the 36-byte ACPI header you checksum in F3-12. In Listing 2 the SRAT body is walked from offset 48 (the header plus 12 reserved bytes), entry by entry using each entry's length byte, and the SLIT's locality count is read as a 64-bit value at offset 36 with the matrix following at offset 44. D2 These offsets were written from memory of the ACPI Specification; what supports them in this build is that the checksums pass and every decoded value equals the QEMU configuration (R4). That is evidence the parser agrees with QEMU's table generator, not proof that both agree with the specification; the Source Researcher must confirm the section "System Resource Affinity Table" and "System Locality Distance Information Table" in the specification. R4

Three details from the run are worth reading closely:

  1. The proximity domain of a processor entry is split. The low 8 bits sit at byte 2 of the entry and the upper 24 bits at bytes 9–11 (a later extension of an older 8-bit field), so Listing 2 assembles them. D2
  2. Node 0 has two ranges and a gap. Node 0's memory is reported as 640 KiB at 0 and 261,120 KiB from 1 MiB, 384 KiB short of the 256 MiB backend. The missing range is the legacy area between 640 KiB and 1 MiB that PCs reserve for video memory and option ROMs; it is in no node. R2 D6 The check in R4 therefore tests node 1 for exactly 262,144 KiB and reports node 0's difference instead of hiding it.
  3. A disabled entry. The last memory affinity entry has flags 0 and length 0. The specification lets firmware include entries that are not enabled (for example, reserved for hot-plug); an OS must skip them, and Listing 2 does. D2 R2 Why QEMU emits this one was not investigated (QEMU source hw/i386/acpi-build.c would answer it; not opened).

What SRAT and SLIT do not say

A SLIT value is one number per pair of nodes. It does not separate latency from bandwidth, reads from writes, or idle from loaded. For that, newer ACPI versions define a Heterogeneous Memory Attribute Table (HMAT), and QEMU's own help lists matching -numa hmat-lb and hmat-cache options (run R7). D2 R7 Real latency and bandwidth between nodes are measured with a benchmark on the named machine and recorded as a measurement (AH-23); this chapter has no such machine and quotes no such number.

Devices have locality too. A network card or NVMe drive attached to socket 1's PCI Express links is closer to node 1; DMA from it into node 0 memory crosses the interconnect. Linux reports a PCI device's node in sysfs, and ACPI can attach proximity information to devices. D4 D2 In practice this decides which cores should run a NIC's interrupt handlers and the threads that consume its data: the topic returns with GPUs and RDMA NICs in DS401 and F8.

Placement trade-offs

There are three standard policies, and each fits a different workload. D4 D1

  • Local (bind or first touch): threads and their data on one node. Best mean distance (10); the node's channels limit bandwidth, and one node's memory limits capacity.
  • Interleave: pages spread round-robin over nodes. Every thread sees the same mean distance (15.5 in the worked example), and all channels of all sockets are used; it suits shared data that every thread reads.
  • Accidental remote: data first touched by an initialisation thread on the wrong node, or a node without memory (the forensic lab). Mean distance 21 for every access, and the interconnect carries all of it.

Hypervisors face the same choice for whole virtual machines; F5-32 places VMs so that each fits in one node.

How the hardware actually does it

A request from a core first misses in its private caches and the shared cache; the package's logic then decides, from the physical address, which memory controller owns the line. If it is local, the controller schedules DRAM commands on the right channel (F1-39). If it is remote, the request travels over the interconnect, the other package's controller reads DRAM, and the data comes back the same way, while the coherence protocol makes sure no cache anywhere holds a newer copy (F1-36). D1 The extra hops are the physical meaning of the SLIT's larger number. The firmware learns the topology while it trains memory and brings up the links during early boot (PEI phase, F3-11), and it writes SRAT and SLIT for the OS during DXE. D6 In QEMU, none of this hardware exists: QEMU's ACPI generator writes the tables from the command line, which is exactly why the command line is a good source of truth for the lab.

Not verified — check before relying on this

Everything product-specific is outside this build: the number of memory channels per socket, the number of DIMM slots per channel, the slot population order and module mixing rules, the name and speed of the inter-socket links (vendor names exist for Intel and AMD links), the real SLIT values a given server reports, and its measured local and remote latency and bandwidth. Take them from the processor vendor's datasheet and the board vendor's manual for the exact model, and from your own measurement on that machine; record the document and section in the dossier (AH-21 to AH-23).

Worked example

Use the SLIT the lab printed: 10 on the diagonal, 21 between nodes. A thread runs on a CPU of node 0. What is the mean relative distance of its memory accesses for four placements? Weight each node's distance by the share of accesses that go to it:

mean distance = Σj sharej × SLIT[cpu node][j]

  1. All local: 1.00 × 10 = 10.00, which is 1.00 times the all-local value.
  2. Interleaved over both nodes: 0.5 × 10 + 0.5 × 21 = 5 + 10.5 = 15.50, or 1.55 times.
  3. Everything on the other node (the data was first touched by a thread on node 1): 1.00 × 21 = 21.00, or 2.10 times.
  4. A thread on node 1 with 90 % of its accesses local: 0.1 × 21 + 0.9 × 10 = 2.1 + 9 = 11.10, or 1.11 times.

Listing 3 computes the same four cases from placement.in (output below it). Read the results carefully: they are ratios of SLIT numbers, which the specification defines as relative. They do not predict that the program will run 2.1 times slower; caches hide some remote accesses, bandwidth limits may dominate instead of distance, and the hardware may not match its own table exactly. Use the number to rank placements; measure to know the cost. D2 R5

Where the analogy breaks


    

  1. Libraries hand out the only copy; memory systems copy. A remote line, once read, can sit in the local caches, so repeated remote reads may cost little; but a write by one socket must invalidate copies in the other socket's caches, a cost the towns do not have.
    2. 

  2. The bridge is not the only shared road. Bandwidth is limited inside a town too: all threads of one node share that node's channels. A placement with perfect locality can still be slow if every thread is in one town and the other town's channels sit idle.
    3. 

  3. The travel-time sign is not a clock. A SLIT value is a relative number written by firmware; the analogy's "travel time" suggests a measured duration, which it is not.
    4.

Summary


    

  • A server is sockets with their own memory controllers and channels, joined by an interconnect, with I/O attached to sockets and a BMC beside them.
    • 

  • The memory of one socket forms one NUMA node; remote accesses cross the interconnect.
    • 

  • The firmware describes the layout in the ACPI SRAT (who belongs to which proximity domain) and SLIT (relative distances, 10 = local), and the inventory in SMBIOS types 4 and 17.
    • 

  • Check tables against an independent source: in the lab every value matched QEMU's options, and node 0's 384 KiB difference is the legacy hole.
    • 

  • Mean SLIT distance ranks placements (10, 15.5, 21 for local, interleaved, all-remote); measurements, not SLIT values, give costs.
    • 

  • A node with CPUs and no memory makes every access of its CPUs remote: a configuration fault that SMBIOS alone may not reveal.

  1. Server B: "MEM 0x000100000 + 0x01ff00000 (523264 KiB) -> node 0", two disabled memory entries instead of one, no memory line for node 1, and the summary "node 0: 2 CPUs, 523904 KiB" and "node 1: 2 CPUs, 0 KiB of memory". SMBIOS, MADT, the processor affinity lines and the SLIT are identical.

  2. Hypothesis 1: node 1 has no local memory, so threads on CPUs 2–3 make only remote accesses. Hypothesis 2: CPUs 2–3 are slower themselves (a throttled socket, a firmware power setting). The SRAT supports 1 directly; to separate them, run a compute-only test without memory traffic on CPUs 2–3 (hypothesis 2 predicts slowness, 1 does not), or bind the job's memory to node 0 explicitly and compare CPUs 0–1 with 2–3.
