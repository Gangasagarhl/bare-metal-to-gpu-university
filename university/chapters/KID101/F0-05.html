Story hook

Analogy

Elif's aunt runs a small restaurant. One Saturday, Elif is allowed to watch the kitchen from a stool in the corner.

The head chef stands at the stove. She works with her hands on a small cutting board. On shelves near the stove are the things she uses most: salt, oil, a few onions. Down the corridor is a big pantry full of jars and boxes. Every morning a van brings sacks of flour and rice from a warehouse across town.

An order slip comes in through the order window. The chef reads it, fetches what she needs, cooks, and passes a plate out through the serving hatch.

Elif thinks: "It is like a machine." She is right, in a way. A computer has a part like each of these. This chapter opens the box and shows you the kitchen inside.

What you will be able to do

  • Name the main parts inside a computer: CPU, registers, cache, main memory, storage, bus, and input and output.
  • Match each part to its place in the kitchen map.
  • Explain why the closest storage places are the smallest and the fastest to reach.
  • Trace a tiny "load, add, store" recipe step by step on paper.
  • Find the step in the wrong order when a toy computer gives a wrong answer.
Jargon box
CPU (central processing unit)
Simple words: the part that carries out the program's steps. Analogy: the head chef. Precise: the processor: the circuit that fetches instructions from memory and carries them out, one after another, working on data. A CPU can contain one or more cores; each core is like one head chef. D1 §5.1.4 D3 §1.4.1, §1.9.1
Register
Simple words: a tiny place inside the CPU that holds a number it is working on right now. Analogy: the chef's hands and the cutting board. Precise: a small, very fast storage place inside the processor that holds one value; instructions work on values in registers. D1 §5.1.4, §5.1.5 D3 §1.4.1
Cache
Simple words: a small, fast store near the CPU for things used often. Analogy: shelves near the stove. Precise: a small, fast memory between the processor and main memory that keeps copies of recently used data, so it can be reached sooner. D6 §10.1 D3 §1.5
Main memory
Simple words: the big workspace that holds the program and its data while it runs. Analogy: the big pantry down the corridor. Precise: the computer's large working memory (built from DRAM chips, dynamic random-access memory), where running programs and their data are kept; its contents are lost when the power goes off. D3 §1.4.1 D5 §6.1.1
Storage
Simple words: where files and programs are kept, even when the computer is off. Analogy: the warehouse across town. Precise: a device such as an SSD (solid-state drive) or a hard disk that keeps data without power; it is larger and slower to reach than main memory. D5 §6.1.1 D3 §1.4.1, §1.6
Bus
Simple words: the paths that carry information between the parts. Analogy: corridors and service lifts. Precise: a set of connections that carries information, as bytes, back and forth between the processor, memory and devices. D3 §1.4.1
Input and output (I/O)
Simple words: information coming into the computer, and results going out. Analogy: order slips through the order window; plates out through the serving hatch. Precise: the transfer of data between the computer and the outside world through devices such as a keyboard (input) or a screen (output). D3 §1.4.1

Layer 1 — the kid explanation

Every computer, from a phone to a laptop, has the same main parts. Let us walk through the kitchen.

The head chef: the CPU

The CPU is the head chef. It carries out the program's steps, one after another. It is very fast, but it can only work on what it is holding right now. D1 §5.1.4

The chef's hands: registers

What the chef is holding goes in her hands and on her cutting board. In the CPU, these are the registers. There are only a few. They hold the numbers being worked on this very moment. D1 §5.1.4 D3 §1.4.1

Shelves near the stove: the cache

The chef keeps salt and oil on shelves right next to the stove. She uses them all the time, so she does not walk to the pantry each time. The CPU has the same trick, called a cache. It keeps copies of things used often, close by. D6 §10.1 D3 §1.5

The big pantry: main memory

Down the corridor is the big pantry. It holds everything needed for today's cooking. That is main memory. While a program runs, the program and its data live here. But this pantry has a strange rule. When the power goes off, it forgets everything. D5 §6.1.1

The warehouse: storage

Across town is the warehouse. It is huge, and it keeps things safe even at night. That is storage. Your photos, games and documents stay there when the computer is off. Before a program runs, it is brought from storage into main memory. D3 §1.4.2

Corridors, window and hatch

Things move between all these places along the bus, like corridors and service lifts. New information arrives as input, like order slips at the window: a key you press, a mouse click. Results leave as output, like plates through the hatch: letters on the screen, a sound from the speaker. D3 §1.4.1

The big rule of the kitchen

Look at Figure 1 again. The closer a place is to the chef, the smaller it is. And the faster it is to reach. Hands are tiny but instant. The warehouse is huge but slow. Good programs try to keep what they need close to the chef. D3 §1.5, §1.6

Layer 2 — the student explanation

Note

For the curious. Main memory is a long row of numbered boxes. Each box has an address, like a house number. To fetch a number, the CPU sends the address along the bus, and the memory sends back what is in that box. Instructions are stored in memory as numbers too, so the CPU fetches them the same way. D1 §5.1.1, §5.1.3 D3 §1.4.1 A cache works by itself: the chef does not decide what goes on the shelves; the hardware does. D6 §10.1

Layer 3 — the engineer's depth

At this level, the depth waits for HW102 and the F1 faculty, where the same kitchen map is used again with more detail: several levels of cache, how memory is organised, and how real processors read and run their instructions. Real sizes and speeds are only quoted there from the datasheet of a named product. D3 §1.5, §1.6

How the hardware actually does it

All these parts are made of electronic circuits that store and move bits, as in F0-02. The registers are part of the CPU itself, and the caches are built close to it. Main memory is made of separate memory chips. Storage is another device. The bus is made of wires and connections on the board that joins them. D3 §1.4.1, §1.5

Not verified — check before relying on this

How many registers a CPU has, how large its caches are, and how much faster a register is than main memory or storage are different for every product. This chapter gives no such numbers on purpose. To find real ones, use the datasheet or manual of a named processor and memory part (guide rule AH-21), or ask a grown-up to show you the system information of your own computer and write your own numbers here: ____.

Worked example

Let us cook "7 + 5" in a toy kitchen. The pantry has three boxes. Box 0 holds 7, box 1 holds 5, and box 2 is empty (0). The chef has two hands. Here is the recipe.

StepRecipe lineLeft handRight handPantry boxes 0, 1, 2
start—007, 5, 0
1LOAD_LEFT 0: fetch box 0 into the left hand707, 5, 0
2LOAD_RIGHT 1: fetch box 1 into the right hand757, 5, 0
3ADD: left = left + right1257, 5, 0
4STORE_LEFT 2: put the left hand's number in box 21257, 5, 12

The answer, 12, ends up in box 2 of the pantry. Notice that the chef never adds things in the pantry. She brings them to her hands first. The simple model of a processor in the textbook D3 works in the same "load, work, store" way, with registers as the hands. (Each real processor has its own exact rules; you meet them in HW102.) Where the analogy breaks


    

  • The chef chooses what goes on her shelves; a CPU does not. A cache fills and empties by itself, following fixed rules in the hardware. D6 §10.1
    • 

  • "Down the corridor" is about time, not metres. Main memory is not far away in distance. It takes longer to reach because of how it works, not because the CPU walks there. D3 §1.5 D5 §6.1.1
    • 

  • A real chef understands food. The CPU does not understand anything. It only follows its instructions very fast, as in F0-01.
    • 

  • A pantry does not empty itself at night. Main memory loses everything when the power is off. Only storage keeps it. D5 §6.1.1
    •

Lab


Be the kitchen


Goal: act out the toy kitchen with people and paper, and get the right answer for 7 + 5 and for a sum of your own.


You need: three paper cups labelled box 0, box 1, box 2; small slips of paper; a pencil; two or three people. No computer is needed.


Safety
None beyond normal paper and pencil work.


    

  1. One person is the head chef, with two hands. Another is the pantry keeper, with the three cups. A third person, if you have one, reads the recipe aloud.
    2. 

  2. Write 7 on a slip in box 0, 5 in box 1, and 0 in box 2.
    3. 

  3. The reader reads one line at a time: LOAD_LEFT 0, LOAD_RIGHT 1, ADD, STORE_LEFT 2.
    4. 

  4. For LOAD, the chef walks to the pantry keeper, copies the number onto a slip, and holds it in that hand. For ADD, the chef adds in her head and writes the new number on the left-hand slip. For STORE, the chef walks back and puts a copy into the box.
    5. 

  5. After every line, write the hands and the boxes in a table like the worked example.
    6. 

  6. Change the numbers and run it again.
    7. 



What you should see: the chef walks to the pantry for every LOAD and STORE, but not for ADD. That walking is the slow part.


Check you succeeded: your table matches the Listing 1 output for 7 + 5, and box 2 ends with the right sum for your own numbers.


If something goes wrong: box 2 has the wrong number → STORE came too early → check the order. A hand has an old number → a LOAD was skipped → reload. The chef adds in the pantry → remind her: work happens only in the hands.


Extension: write a recipe for 7 + 5 + 4, using a fourth box. How few lines can you use?

Forensic lab answer key


Observation: box 2 changes at the third line, STORE_LEFT 2, and gets 7. The ADD comes last and makes the left hand 12, but nothing stores it afterwards.


Root cause: STORE_LEFT 2 and ADD are in the wrong order. The store copied the left hand before the addition.


Evidence: in the bad run, the line "STORE_LEFT 2 → hands: 7, 5, pantry boxes: 7, 5, 7" comes before "ADD 0 → hands: 12, 5". In Listing 1's run, ADD comes first and box 2 gets 12.


Fix: the order LOAD_LEFT 0, LOAD_RIGHT 1, ADD, STORE_LEFT 2. Run again and check that box 2 holds 12.


Why no complaint: every step was a valid step. The computer did exactly what was written, as in F0-01; only the order was wrong.


How the fault was made: the Lab Engineer swapped the last two recipe lines (line 20) of Listing 1.


Wrong answers and why: "ADD is broken": the trace shows ADD made 12. "The pantry lost the number": box 2 holds exactly what the left hand held at the store. Prevention: trace hands and boxes after every step before trusting the answer.
