Story hook

Analogy

Jun and his cousin Priya share a secret code. A is 1, B is 2, C is 3, and so on. Priya leaves a note on the fridge: 8, 9. Jun counts on his fingers. H, I. "Hi!"

The next week, Priya's friend finds a note: 8, 9. She has no idea what it means. Is it two shoe sizes? A phone number? Without the code, the numbers are only numbers.

That is the whole secret of this chapter. A computer can only store numbers made of bits. To store a letter, a colour or a sound, everyone must agree on a code first. Then numbers become messages.

What you will be able to do

  • Explain that letters, colours and sounds are stored as numbers, using an agreed code.
  • Encode a short word as bytes, using a real letter table printed by a computer.
  • Decode bytes back into a word.
  • Describe a colour as three numbers: how much red, green and blue.
  • Find the cause of a scrambled message.
Jargon box
Code (for information)
Simple words: an agreement about which number stands for which thing. Analogy: Jun and Priya's "A is 1, B is 2" note on the fridge. Precise: a fixed rule that matches each symbol (a letter, a colour, a sound level) with a pattern of bits, so both writer and reader get the same meaning. Not the same as "code" meaning a program's text. D1
Character code
Simple words: a table that gives every letter, digit and sign its own number. Analogy: the fridge note, but agreed by the whole world. Precise: a mapping from characters to numbers. ASCII (American Standard Code for Information Interchange) is an early example; Unicode is a larger one for the writing systems of the world. D1
Pixel
Simple words: one tiny dot of a picture. Analogy: one tile in a mosaic on a kitchen wall. Precise: a picture element: one point of an image, stored as numbers that describe its colour. D1
Sample (of a sound)
Simple words: one measurement of a sound at one moment. Analogy: one frame of a flip book. Precise: a number that records the level of a sound wave at one instant; a recording is a long list of samples taken at regular times. D1

Layer 1 — the kid explanation

In F0-02 you learned that a computer stores numbers as rows of switches. But computers also show words, photos and music. How?

The answer is a code. A code is an agreement: "this number means that thing". The computer stores only the number. A program uses the code to turn the number back into a letter, a colour or a sound. D1

Letters

For letters, people agreed on tables called character codes. Each letter, digit and sign gets its own number. We asked a computer in this build which number it uses for each capital letter. It printed A = 65, B = 66, and so on up to Z = 90. R1

So the word "HI" is stored as 72, 73. Each number fits in one byte. In switches, H is 01001000. Check it with your bit board: 64 + 8 = 72.

Small letters have different numbers from capitals. The space between words has a number too. In our run, a space was 32 and "!" was 33. R1

Colours

A picture on a screen is made of tiny dots called pixels. Each dot has one colour. A common way to describe a colour is with three numbers: how much red, how much green and how much blue light to mix. D1

In this chapter we use our own paper code. Each of the three amounts goes from 0 (none) to 255 (full), so each fits in one byte. Red 255, green 0, blue 0 is bright red. All three at 0 is black. All three at 255 is white.

Sounds

Sound is air that wobbles very fast. A microphone turns the wobble into a changing signal. The computer measures that signal again and again, at equal steps in time. Each measurement is a number, called a sample. A song is a very long list of samples. D1

To play the song, the computer sends the numbers to a speaker, in order and at the same speed. The speaker wobbles the air again, and you hear the sound.

Not verified — check before relying on this

How many samples per second real recordings use, and how many bytes real image files use per pixel, depend on the file format and device. This chapter gives no such numbers. Check: D1 (sections on sound and pictures), or the specification of the named file format, before quoting any.

Layer 2 — the student explanation

Note

For the curious. One byte has 256 patterns, which is plenty for English capital and small letters, digits and signs. But the world has many writing systems with thousands of characters. Unicode gives each of them its own number, and some numbers need more than one byte. D1 Also, the same byte can mean different things: 72 can be the letter H, the number 72, or a dark shade of red. Only the program knows which code to use.

Layer 3 — the engineer's depth

At this level, Layer 3 waits for later courses. MA102 covers bytes, units and hexadecimal colour numbers. KID102 uses char and std::string for text. The key idea to keep: bits never carry their own meaning; the code is an agreement between the writer and the reader. D1

How the hardware actually does it

Memory stores only bits. It does not know if a byte is a letter or a colour. When you press a key, the keyboard sends a number to the computer. A program looks up which character that is, and finds which dots on the screen to light to draw its shape. Every step is numbers and agreed codes. D1

Worked example

Encode the word "HI"

  1. Look up H in the letter table from Listing 3: H = 72.
  2. Turn 72 into switches. Is 72 at least 128? No: 0. At least 64? Yes: 1, and 72 − 64 = 8 is left. 32? No: 0. 16? No: 0. 8? Yes: 1, nothing left. 4, 2, 1: all 0. So H is 01001000.
  3. I = 73. That is 72 + 1, so the same pattern with the last switch on: 01001001.
  4. The message is 01001000 01001001.

Decode a message

Decode 01001100. The switches that are on are worth 64, 8 and 4. 64 + 8 + 4 = 76. The table says 76 is L. Listing 2 decoded the same byte as L in its real run. R1

Mix a colour

Using our paper code, orange is red 255, green 128, blue 0. In bits, 255 is 11111111, 128 is 10000000 and 0 is 00000000. So one orange dot takes three bytes in our code: 11111111 10000000 00000000.

Where the analogy breaks


    

  • A fridge-note code is private; computer codes are shared. Jun and Priya made up their own code. Computers must use the same agreed tables, or a message from one computer turns into nonsense on another. D1
    • 

  • Jun's code used A = 1; the computer's does not. In our run, A is 65. Do not mix the two codes. R1
    • 

  • A mosaic tile is a solid object. A pixel on a screen is light, and its colour is only numbers until the screen shows it. Our paper code of three numbers from 0 to 255 is a teaching code; real file formats have their own exact rules.

Lab


Secret bit messages


Goal: send a short word to a friend as bytes and have them decode it.


You need: paper, a pencil, your bit board from F0-02, the letter table (the output of Listing 3). No computer is needed.


Safety
None beyond normal paper and pencil work.


    

  1. Choose a word of three to five capital letters.
    2. 

  2. Look up each letter's number in the table.
    3. 

  3. Turn each number into eight bits. Write them in groups of eight with a gap between groups.
    4. 

  4. Give the bits, and only the bits, to your friend.
    5. 

  5. Your friend decodes each group and writes the word.
    6. 

  6. Compare. If it is wrong, find which group went wrong and why.
    7. 



What you should see: every capital letter starts with 010 in its eight bits, because they are all between 64 and 95. Look for that pattern in your message.


Check you succeeded: your friend reads the word correctly with no hints.


If something goes wrong: a group gives a number below 65 → a switch was dropped → count to eight. A letter is one off → adding slip → add again. A group gives a huge number → read from the wrong end → put 128 on the left.


Extension: design a colour message: three bytes for one dot, using our paper code. Can your friend say the colour?

Forensic lab answer key


Root cause: in the friend's decoder, line 7 lists the place values smallest first, so each group is read from the wrong end.


Evidence: 01001000 read with values 1, 2, 4, …, 128 from the left: the 1s are in the 2nd and 5th places, worth 2 and 16, so 18. That is exactly what the bad run printed. The good run printed 72 for the same bits. The only different line is line 7.


Why both L's became "2": L is 01001100 in both places; read backwards it is 2 + 16 + 32 = 50, and 50 is the digit "2" in the character code. Same input, same wrong rule, same wrong answer.


Fix: change line 7 back to {128, 64, 32, 16, 8, 4, 2, 1}; run again and check that the message is "HELLO".


How the fault was made: the Lab Engineer copied Listing 2 and reversed the list on line 7, then ran both with the same input file.


Wrong answers and why: "Zainab sent the wrong bits": the good decoder read the same bits as HELLO. "The letter table is wrong": 72 is H in the Listing 3 table. Prevention: test a decoder on a known message first, such as one letter you can check by hand.
