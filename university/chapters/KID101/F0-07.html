Story hook

Analogy

Sofia is making hot chocolate with her dad. The recipe card says: "Stir 20 times." She counts out loud: one, two, three… all the way to twenty. Then she stops.

Next, the card says: "Add milk, one spoon at a time, until the cup is full." Sofia does not know how many spoons that will be. So she adds one, looks, adds another, looks again. When the cup is full, she stops.

Last line: "If it is too hot, wait one minute." Sofia touches the cup. It is warm, not hot. So she skips the waiting and drinks.

That one small recipe had three big ideas: repeat a number of times, repeat until something is true, and choose what to do. Every computer program is built from these ideas. You can learn them with no computer at all.

What you will be able to do

  • Write a decision as an "if … then … otherwise …" step with a yes-or-no question.
  • Write a loop that repeats a fixed number of times, and one that repeats until something is true.
  • Explain why a loop that never changes its question runs forever.
  • Add two small binary numbers on paper by following written rules (the paper computer).
  • Find the cause of a loop that never ends from its output.
Jargon box
Condition
Simple words: a question whose answer is yes or no. Analogy: "Is the cup full?" Precise: an expression that is either true or false, used to decide which step comes next. D1
Decision
Simple words: a step that chooses what to do, using a yes-or-no question. Analogy: "If it is too hot, wait one minute." Precise: a branch in an algorithm: if the condition is true, one set of steps runs; otherwise another set (or nothing) runs. In C++ it is written with if and else. D1 D3
Loop
Simple words: steps that are repeated. Analogy: "Stir 20 times." Precise: a part of an algorithm that runs again and again, either a set number of times or while a condition stays true. In C++, for and while make loops. D1 D3
Infinite loop
Simple words: a loop that never stops. Analogy: "Add milk until the cup is full", but nobody ever adds milk. Precise: a loop whose condition never becomes false, usually because nothing inside the loop changes what the condition tests. D1
Carry
Simple words: the extra 1 you pass to the next column when a column adds up to too much. Analogy: when 9 + 3 = 12, you write 2 and "carry the 1". Precise: the value moved into the next place when the sum of one place is at least the base (10 in decimal, 2 in binary). D2

Layer 1 — the kid explanation

In F0-01, every algorithm went straight from the first step to the last. Real recipes are not always like that. Sometimes you repeat. Sometimes you choose. A computer can do both, as long as you write exactly how.

Decisions: if, otherwise

A decision is a step that chooses. It always starts with a yes-or-no question, called a condition. "If it is raining, take an umbrella. Otherwise, take a cap." The question is "Is it raining?" The answer picks one path. D1

The question must have a clear yes or no. "Is it cold?" is unclear: cold for whom? "Is the temperature below 10?" is clear. You saw this in the night light of F0-06: "Is the light level less than 30?"

Loops: repeat a number of times

A loop repeats steps. "Stir 20 times" is the simplest kind. You know before you start how many times. You count each one and stop at 20. D1

Loops: repeat until something is true

"Add milk until the cup is full" is a different kind. You do not know how many spoons. So each time round, you ask a question: "Is the cup full?" If no, add a spoon and ask again. If yes, stop. Figure 1 draws this loop.

Look at the question in Figure 1. Each time you add a spoon, the answer gets closer to "yes". That is what makes the loop end. D1

The loop that never ends

Now imagine a helper who asks "Is the cup full?" but never adds any milk. The answer is always "no". The helper asks forever. That is an infinite loop. A person would notice and stop. A computer does not notice. It keeps asking until someone stops the program. D1 R1

Here is the rule for every "until" loop. Something inside the loop must change what the question looks at.

Layer 2 — the student explanation

Note

For the curious. With three tools, steps in order, decisions and loops, you can already write a great many algorithms. Inside the computer, both decisions and loops are made from one kind of instruction: "jump to another step if a condition is true". A loop is a jump backwards. A decision is a jump forwards over steps you skip. D2 You will write if, for and while yourself in F0-32 and F0-33.

Layer 3 — the engineer's depth

At this level, the depth waits for KID102 (writing loops and decisions in C++) and HW102 (the jump instructions and the adder circuits that do what our paper computer does). Keep this habit: for every loop, say what makes it end. D2

How the hardware actually does it

The CPU answers a condition by comparing two numbers, such as "spoons" and 4, and remembering the yes-or-no result. A following "jump if" instruction then goes either back to the top of the loop or on to the next step. Adding binary numbers is done by circuits that follow rules like the ones in our worked example, column by column, with a carry. D2

Where the analogy breaks


    

  • A cook would stop. If Sofia added no milk, she would notice after a few tries. A computer running a loop that forgets to change its condition keeps going until someone stops the program. R1
    • 

  • "Full" is a feeling for a person. Sofia looks at the cup and judges. A computer needs an exact test, such as "spoons is 4 or more". If the test is fuzzy, it cannot be written at all.
    • 

  • People skip pointless steps. If the cup was already full, Sofia would not even ask. A computer asks the question every time, exactly as written.
    •

Summary


    

  • A condition is a yes-or-no question; a decision uses it to choose what to do.
    • 

  • A loop repeats steps: a set number of times, or until something is true.
    • 

  • Something inside an "until" loop must change what the question looks at, or the loop never ends.
    • 

  • Decisions and loops are jumps: forwards to skip, backwards to repeat.
    • 

  • The paper computer adds binary numbers with a loop over columns and four rules.
    • 

  • A machine can add correctly by following rules, without understanding.

Forensic lab answer key


Observation: every "still not full" line says "cup has 0". "cup is full" never printed. The run record says exit code 124: the program was stopped by the time limit, not finished.


Root cause: the loop has no step that adds a spoon. spoons stays 0, so spoons < full is always true and the loop never ends.


Evidence: Listing 1 has spoons = spoons + 1; inside its loop (line 12) and its output counts 1, 2, 3, 4. Musa's loop has only the print and a short wait.


Fix and check: add spoons = spoons + 1; inside the loop. The run should then print the cup filling to 4, print "cup is full", and end with exit code 0.


How the fault was made: the Lab Engineer wrote the loop without the adding step. The short wait (line 12 of Musa's file) slows the printing so the evidence stays short.


Wrong answers and why: "The computer is too slow": in 3 seconds it printed the same value many times, so it was running, only never changing. "The limit 4 is too big": even a limit of 1 would never be reached from 0 without adding. Prevention: for every "until" loop, point to the line that moves it towards the end.
