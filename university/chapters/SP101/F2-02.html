Story hook

Analogy

In the restaurant kitchen every ingredient lives in a container of the right shape. Eggs go in an egg box with whole places only: you cannot store half an egg there. Soup goes in a measuring jug with marks for fractions of a litre. Spices go in tiny jars with a single letter on the lid.

One evening Priya pours 2.9 litres of soup into a rack that holds only whole bottles. Two bottles fill up, and the rest is gone. Nobody hears a sound. Later, Kwame counts the eggs: 12 in the box, but the cooks used 14. He subtracts on a counter that cannot show a minus sign, and the counter rolls round to an enormous number. "We have more eggs than ever!" he says. They have none.

Containers in C++ are called types. Today you learn their shapes, what happens when you pour a value from one shape into another, and how to make the compiler warn you before something spills.

What you will be able to do

  • Choose a fitting type (int, double, char, bool, std::size_t) for a value, and print its size and limits on your machine.
  • Predict the result of integer division, % and mixed int/double arithmetic.
  • Convert between types on purpose with static_cast, and explain what is lost.
  • Use brace initialization and -Wconversion to catch conversions that lose information.
  • Explain signed overflow and unsigned wrap-around, and recognise both in a program's output.
Jargon box
Value
Simple words: The actual thing stored, such as 7, 2.9, 'A' or true. Analogy: What is inside the container. Precise: The meaning of the bits of an object, interpreted according to the object's type. D2, D1
sizeof
Simple words: An operator that tells you how many bytes a type uses. Analogy: Reading the container's capacity printed on its side. Precise: sizeof(T) gives the number of bytes of an object of type T as a std::size_t; sizeof(char) is 1 by definition. D2, R1
std::size_t
Simple words: A whole-number type with no minus sign, used for sizes and counts. Analogy: A counter that can only count up from zero. Precise: The unsigned integer type of the result of sizeof, declared in <cstddef>; 8 bytes in this build. D2, R1
Conversion
Simple words: Turning a value of one type into a value of another type. Analogy: Pouring from one container into another shape. Precise: Producing a value of a target type from a value of a source type; implicit when the compiler does it by itself (for example int to double in 7.0 / 2), explicit when you ask for it. D2, R2
static_cast
Simple words: The way to say "convert this, I mean it". Analogy: Pouring on purpose, with your name on the label. Precise: An explicit conversion expression, static_cast<T>(e), for conversions the language defines, such as double to int (which drops the fraction). D1, R2
Narrowing conversion
Simple words: A conversion that can lose part of the value. Analogy: Pouring 2.9 litres into a rack of whole bottles. Precise: A conversion such as double to int, or to a type that cannot represent the value; forbidden inside brace initialization { }, where g++ reports "narrowing conversion". D2, R4
Truncation
Simple words: Cutting off the fraction instead of rounding. Analogy: Throwing away whatever does not fill a whole bottle. Precise: The double-to-integer conversion discards the fractional part, moving towards zero: 2.9 becomes 2 and −2.9 becomes −2 in this build. D2, R2
Signed overflow
Simple words: A calculation with int whose true answer is too big (or too small) for int. Analogy: Pouring more into a jug than it can hold. Precise: An arithmetic result of a signed integer type that is outside its range; it is undefined behaviour, and UndefinedBehaviorSanitizer reported it in this build. D2, R6
Undefined behaviour
Simple words: Something the C++ rules do not allow, where the program may then do anything. Analogy: A recipe step the kitchen rules forbid; nobody promises what happens if a cook does it anyway. Precise: Behaviour for which the standard imposes no requirements; the program may seem to work, give wrong answers or crash. D2
Unsigned wrap-around
Simple words: Going below zero (or above the top) on an unsigned type jumps to the other end. Analogy: A counter with no minus sign that rolls round. Precise: Unsigned arithmetic is done modulo 2n for an n-bit type, so 12 − 14 gives 264 − 2 = 18,446,744,073,709,551,614 for the 64-bit std::size_t of this build. D2, R7

Words you already know: type, int, double, bool, char and integer division from F0-31; byte, two's complement and overflow from MA102.

Layer 1 — the kid explanation

Every value in a program sits in a container with a fixed shape. The shape is called the type. An int holds whole numbers. A double holds numbers with a fraction. A char holds one letter. A bool holds only true or false.

Each container has a fixed size. On this build machine an int took 4 bytes, and the largest number it could hold was 2,147,483,647. That is big, but it is not endless. R1

Sometimes you pour a value from one container into another. Pouring an int into a double is safe: 7 becomes 7.0. Pouring a double into an int is not: 2.9 becomes 2, and the 0.9 disappears. The program does not round, and it does not warn you unless you ask. R2, R3

Some containers cannot show a minus sign. If you take 14 eggs from a box of 12 on such a counter, it rolls round to a huge number instead of −2. Your program then believes nonsense. This chapter teaches you to spot these spills, and to ask the compiler to help. R7

Layer 2 — the student explanation

Types, sizes and limits

Listing 1 asks the compiler for the size of each type with sizeof and for the limits of int with std::numeric_limits. On this machine it printed: char and bool 1 byte, int 4 bytes, long long, double and std::size_t 8 bytes. The range of int was −2,147,483,648 to 2,147,483,647. R1

These numbers fit what you learned in MA102: 4 bytes are 32 bits, and a 32-bit two's-complement number runs from −231 to 231 − 1. You can check it: 231 = 2,147,483,648. The largest std::size_t, 18,446,744,073,709,551,615, is 264 − 1, the largest 64-bit number with no sign. R1, D4

Not verified — check before relying on this

The sizes above were measured on one machine with one compiler. The C++ standard promises only minimum ranges and some relations between the types (for example, sizeof(char) is 1); exact sizes on other machines and compilers can differ. Check the clause on fundamental types in ISO/IEC 14882 (D2) and run Listing 1 on your own machine; write your numbers here: int ___ bytes, std::size_t ___ bytes.

Arithmetic decides the type

When both operands are int, the result is an int: 7 / 2 printed 3, and 7 % 2 printed the remainder 1. When one operand is a double, the other is converted to double first: 7.0 / 2 printed 3.5. This is an implicit conversion. R2, D2

Explicit conversions

static_cast<int>(2.9) gave 2 and static_cast<int>(-2.9) gave −2: the fraction is dropped towards zero (truncation). To round to the nearest whole number, use std::lround from <cmath>, which gave 3 for 2.9. R2, D1

A char is a small integer that is printed as a character. In this build, 'A' converted to int printed 65, and 66 converted to char printed B. Converting a number to bool gives false for 0 and true for anything else. R2, D2

Catching lost information

Listing 3 writes int cups = 2.5;. It compiled with all the course warnings turned on and printed cups = 2. The conversion is legal, so the default warnings stay quiet. R3

Two tools catch it. First, brace initialization: int cups{2.5}; is an error, "narrowing conversion of '2.5e+0' from 'double' to 'int'" (Listing 4). Second, the extra warning option -Wconversion, which turned Listing 3 into an error: "conversion from 'double' to 'int' changes value from '2.5e+0' to '2'". Prefer braces for new variables, and write static_cast when you really want the conversion. R4, R5, D3, D5

Overflow and wrap-around

Listing 5 adds 1 to 2,147,483,646 twice. The second addition has no int answer. That is signed overflow, which the standard calls undefined behaviour: the rules no longer say what happens. Our sanitizer caught it and printed "runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'". The program then printed −2,147,483,648, but you must not rely on that value. R6, D2

Unsigned types such as std::size_t behave differently. They never overflow in that sense; they wrap round modulo 2n. That is well defined, so no sanitizer complains, and that is exactly why the forensic lab's bug went unnoticed. R7, D2

Decimal fractions are approximate

0.1 + 0.2 printed 0.30000000000000004 with 17 digits, and 0.1 + 0.2 == 0.3 was false. A double stores a binary fraction, and 0.1 has no exact binary form, just as 1/3 has no exact decimal form. Never compare computed double values with ==; compare with a small tolerance (you will do this in F2-08). R2, D6

Layer 3 — the engineer's depth

Note

For the curious. Small integer types such as char and bool are first converted to int before arithmetic ("integral promotion"); and when a signed and an unsigned operand of the same size meet, the signed one is converted to unsigned. That is why mixing int and std::size_t in comparisons can surprise you; GCC's -Wsign-compare (part of -Wall for C++) warns about such comparisons; F2-05 shows it stopping a real build. D2, D3 Systems code cares deeply about these rules: the curriculum lists signed overflow among the kinds of undefined behaviour that "bite kernels" (curriculum 1.1). Object representation in detail (size, alignment, padding) is F2-24.

How the hardware actually does it

Memory is a long row of bytes, and a variable is a few neighbouring bytes. The processor has separate instructions for whole numbers and for floating-point numbers, so the type decides which instructions the compiler chooses. Integer addition works on fixed-width registers; when the result needs one more bit than the register has, that bit is lost, which is how an int can end up at −2,147,483,648 in practice even though C++ calls it undefined. A double is stored as a sign, an exponent and a binary fraction, following the IEEE 754 format. D4, D6 The bits themselves have no type: the same 8 bytes could be a double, a long long or eight chars. Only the program's types give them meaning (the F0 analogy registry says the same: "meaning is decided by the program, not by the switches"). D4

Worked example

A soup recipe makes 2.9 litres. Bottles hold 1 litre. How many full bottles, and how much is left over? Work it out, then check against the real runs.

  1. Full bottles. We want the whole part of 2.9. static_cast<int>(2.9) gives 2 (truncation). Real run: 2. R2
  2. Rounded bottles for a shopping list. std::lround(2.9) gives 3. Real run: 3. Choose the function that matches the question: "full bottles" truncates; "nearest number" rounds.
  3. Sharing 7 bowls between 2 tables with int: 7 / 2 is 3 bowls each, and 7 % 2 is 1 bowl left over. Check: 3 × 2 + 1 = 7. Real run: 3 and 1. R2
  4. Eggs left with std::size_t: 12 − 14. The true answer is −2, which does not exist in an unsigned type, so the result wraps round to 264 − 2. Compute: 18,446,744,073,709,551,616 − 2 = 18,446,744,073,709,551,614. Real run: exactly that. R7
  5. Fixed version with long long: 12 − 14 = −2, and the program can test eggs_left < 0. Real run: "Eggs left: -2". R8

Where the analogy breaks


    

  • A kitchen container spills in a visible way. In C++ a lost fraction or a wrapped counter leaves no trace: the value is simply different (R3, R7). Only warnings, braces, sanitizers and tests make the spill visible. R3, R7
    • 

  • An overfilled jug always overflows the same way. Signed overflow in C++ is undefined behaviour: the language makes no promise at all, and an optimising compiler may produce a program that behaves differently from the −2,147,483,648 seen here. D2, R6
    • 

  • A measuring jug shows 0.1 litres exactly. A double cannot store 0.1 exactly; it stores the nearest binary fraction (R2). R2, D6
    •

Summary


    

  • A type is a container shape: it fixes the size, the range and the operations of a value.
    • 

  • Sizes and limits are machine-specific; measure them with sizeof and std::numeric_limits.
    • 

  • int divided by int gives an int; a double operand makes the result a double.
    • 

  • double to int truncates towards zero; use std::lround to round.
    • 

  • Braces refuse narrowing; -Wconversion reports silent conversions.
    • 

  • Signed overflow is undefined behaviour; unsigned arithmetic wraps round.
    • 

  • Most decimal fractions are approximate in a double; do not compare them with ==.

  • Observation: "Eggs left: 18446744073709551614" after 12 in stock and 14 used, then "Enough eggs for tomorrow." R7
    • 

  • Hypotheses: (1) "the input was read wrongly" — ruled out: the program printed 12 and 14 back correctly. (2) "the subtraction 12 − 14 went wrong" — confirmed: all three variables are std::size_t.

  • Root cause: unsigned arithmetic wraps modulo 264 on this machine: 12 − 14 = 264 − 2 = 18,446,744,073,709,551,616 − 2 = 18,446,744,073,709,551,614. That number is not less than 6, so the "order more" branch was skipped. R7, D2

  • Why no warning: the subtraction is legal and well defined for unsigned types, so neither the compiler nor UndefinedBehaviorSanitizer had anything to report.

  • Fix: use a signed type for a difference that may be negative and handle the negative case (the fixed program pantry_fixed.cpp printed "Eggs left: -2" and a warning, R8), or check eggs_used > eggs_in_stock before subtracting. R8
    • 

  • Prevention: a test with "used more than in stock" as an edge case; the rule "use unsigned types for sizes and indexes, signed types for differences".
    • 

  • How the evidence was made: a correct program that used signed numbers was changed to std::size_t; the output is the real run R7.
