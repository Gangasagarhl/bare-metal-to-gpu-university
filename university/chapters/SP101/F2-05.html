Story hook

Analogy

Three things hold the evening together in the kitchen. Above the pass hangs a spike for order slips. Waiters push new slips onto it all evening, and it takes as many as they bring. Next to the oven stands a muffin tin with exactly six cups: never five, never seven. And every slip carries a line of handwriting, such as "table 7: 2 soups", which the cooks read letter by letter.

Ana, the new cook, counts the slips on the spike: "one, two, three, four". The head chef counts them differently: "zero, one, two, three". Both see four slips. But when Ana asks the spike for "slip number four", the head chef's spike has no such slip. Ana reaches past the last one into empty air.

In C++ the spike is a std::vector, the tin is a std::array, and the handwriting is a std::string. Today you use all three, and you learn what happens when a program reaches past the last slip.

What you will be able to do

  • Create, grow, shrink and loop over a std::vector, with indexes and with range-for.
  • Choose between [] and at(), and explain what each does with a bad index.
  • Use std::string operations: size, +, +=, find, substr, std::stoi, std::to_string, comparison.
  • Use std::array for a collection whose size never changes.
  • Read an AddressSanitizer report of an out-of-bounds read and find the faulty line.
Jargon box
Container
Simple words: An object that holds many values of one type. Analogy: The spike of slips, the muffin tin, the line of handwriting. Precise: A standard-library class that stores a collection of elements and gives access to them, such as std::vector<T>, std::array<T, N> and (for characters) std::string. D1, D2
push_back
Simple words: Add one element at the end of a vector. Analogy: Pushing one more slip onto the spike. Precise: The std::vector member function that appends a copy of its argument, increasing size() by one; pop_back() removes the last element. D2, R1
size()
Simple words: How many elements a container holds right now. Analogy: Counting the slips on the spike. Precise: A member function returning the number of elements as an unsigned type (std::size_t-like); valid indexes are 0 to size() - 1. D2, R1
at()
Simple words: Get an element by index, but check the index first. Analogy: A cook who counts the slips before reaching for one. Precise: A member function that returns the element at an index and throws std::out_of_range if the index is not less than size(); operator[] does no such check. D2, D1
std::string::npos
Simple words: The special answer "not found" from find. Analogy: "There is no tea on this slip." Precise: A constant equal to the largest value of std::string::size_type, returned by search functions such as find when there is no match. D2, R2
substr
Simple words: Copy a piece of a string. Analogy: Copying only the words "table 7" from the slip. Precise: s.substr(pos, count) returns a new string with up to count characters starting at index pos; without count, everything to the end. D2, R2
Out-of-bounds access
Simple words: Using an index that is not inside the container. Analogy: Reaching past the last slip into empty air. Precise: Accessing an element with an index ≥ size() (or negative) through []; undefined behaviour, detected in this build by AddressSanitizer as a "heap-buffer-overflow". D2, R6
AddressSanitizer
Simple words: A checker built into the program that stops it when it touches memory it should not. Analogy: A kitchen inspector who stops service the moment a cook reaches into the wrong shelf. Precise: A compiler instrumentation (-fsanitize=address) that adds checks around memory accesses and prints a report (kind of error, address, stack of calls, where the memory was allocated) before aborting. D3, R6

Words you already know: std::vector, std::array, std::string, element, index, range-based for loop, out of range (KID102); std::size_t and const reference (F2-02, F2-04).

Layer 1 — the kid explanation

You met std::vector in F0-35: a list that can grow. Now you will use it every day, together with two relatives. A std::string is a list of characters with extra tools for text. A std::array is a list whose length is part of its type and never changes, like a muffin tin.

All three count from 0. A vector with 4 elements has the indexes 0, 1, 2 and 3. Index 4 does not exist. Many bugs come from forgetting this. They are called off-by-one errors. R1, R6

There are two ways to ask for an element. Square brackets, menu[1], are fast and trust you completely. menu.at(1) first checks that 1 is a real index and stops the program with an error if it is not. When you are not sure, use at, or better, use a range-for loop, which never goes past the end. D2, R1

What if you use square brackets with a bad index? Then the program reads memory that does not belong to the vector. Our course flags switch on a checker, AddressSanitizer, that caught exactly this in the forensic lab. Without the checker, the program might just print a strange number. R6

Layer 2 — the student explanation

std::vector

Listing 1 starts with two dishes, appends two with push_back, and prints size() (4), front() ("soup") and back() ("salad"). The index loop uses std::size_t i from 0 while i < menu.size(). Then pop_back() removes "salad", and menu.at(1) = "fried noodles" replaces element 1 after checking the index. R1, D2

Why std::size_t and not int for i? size() returns an unsigned type. Comparing it with a signed int made g++ report "comparison of integer expressions of different signedness", and our -Werror stopped the build (Listing 5). The range-for loop avoids the question entirely. R5, D3

In the range-for of Listing 1, the loop variable is const std::string& dish: each element is read in place, without a copy, exactly the const& idea of F2-04. To pass a whole vector to a function that only reads it, use const std::vector<T>&. R1, D1

std::string

Listing 2 takes apart the order "table 7: 2 soups" (16 characters). find(':') returns the index of the first colon, 7. substr(0, 7) copies the 7 characters before it, "table 7"; substr(colon + 2) copies everything from index 9, "2 soups". std::stoi reads the number at the start of a text, 2. std::to_string goes the other way, and + and += join strings. R2, D2

When find finds nothing, it returns std::string::npos; Listing 2 tests for it to print "No tea in this order." Strings compare letter by letter, by the characters' codes, so "apple" < "banana" is true. R2, D2

std::array

std::array<int, 6> muffin_tin{}; creates six ints, all 0 because of the empty braces. The 6 is part of the type: it cannot grow, and size() is always 6. Giving four values to a std::array<int, 3> did not compile: "too many initializers for 'std::array<int, 3>'" (Listing 4). Use std::array when the number of elements is fixed by the problem (six cups, seven days, three sizes). R3, R4, D1

Layer 3 — the engineer's depth

Note

For the curious. A std::vector keeps its elements next to each other in one block of memory that it allocates itself. It usually allocates room for more elements than it holds; capacity() tells you how many fit before a new, larger block is needed. When push_back needs a new block, the elements are moved there, and references to the old elements become invalid. D2, D1 The AddressSanitizer report in the forensic lab shows this allocation: the 4 ints live in a "16-byte region" obtained through operator new inside the vector's constructor. R6 A std::array allocates nothing: its elements are stored inside the object itself. Memory, the heap and allocation are the subject of SP201, and bounds-checked views (std::span) appear in F2-25.

How the hardware actually does it

Memory is a long row of numbered bytes. A vector's elements sit side by side in that row: element i of a std::vector<int> is found by starting at the first element and moving i × 4 bytes further on a machine where an int takes 4 bytes (F2-02 measured 4 in this build). D4 The processor does this address arithmetic in one or two instructions and does not know where the vector ends. That is why [] is fast and unchecked: reading index 4 of a 4-element vector simply reads the next 4 bytes, whatever they belong to. AddressSanitizer works by surrounding allocations with forbidden "red zones" and checking each access against a map of them (the shadow bytes in the report). D3, R6

Where the analogy breaks


    

  • A cook reaching past the last slip feels empty air at once. A program reaching past the end with [] reads whatever bytes come next and gets no signal at all, unless a checker such as AddressSanitizer is built in. R6, D2
    • 

  • A spike holds slips in a pile; a vector keeps its elements side by side in one block of memory, and when it grows it may move all of them to a new block. D2
    • 

  • Handwriting has letters; a std::string has bytes. For plain English letters these are the same, but for many other characters one character needs several bytes, and size() counts bytes. Text encodings are taught later; until then, do not assume size() counts letters in every language. D2

Summary


    

  • std::vector grows and shrinks; std::array has a fixed size in its type; std::string holds text.
    • 

  • Valid indexes are 0 to size() - 1; size() is unsigned.
    • 

  • [] is unchecked; at() checks and throws std::out_of_range.
    • 

  • Range-for with const& visits every element safely and without copies.
    • 

  • find returns a position or std::string::npos; substr copies a piece.
    • 

  • AddressSanitizer reports an out-of-bounds read with the kind, the place and where the memory came from.
    • 

  • Buffered output can be lost when a program is stopped; do not read too much into missing lines.

Forensic lab answer key


    

  • Observation: "ERROR: AddressSanitizer: heap-buffer-overflow", "READ of size 4", #0 … in main evidence/last_order.cpp:10, "located 0 bytes after 16-byte region", allocated in the vector's constructor at line 7. Exit code 1. R6
    • 

  • Hypotheses: (1) "the vector is empty or broken" — ruled out by Evidence 3, which shows tables 4, 7, 2 and 9 served correctly. (2) "the loop reads one element too many" — confirmed.
    • 

  • Root cause: the condition i <= tables_waiting.size() lets i reach 4. The region holds 16 bytes = 4 ints of 4 bytes (F2-02); "0 bytes after" the region is exactly where element [4] would start, and "READ of size 4" is one int. Evidence 3 shows the fifth "Serving table " line starting, then the report. R6, R7
    • 

  • Why no "Serving" lines in Evidence 2: the output was written to a file, so it was collected in a buffer; AddressSanitizer stopped the program before the buffer was written out. With std::unitbuf every output is sent at once, and the four lines appear. Missing output is not proof that code did not run.
    • 

  • Fix: i < tables_waiting.size(); or better, for (int table : tables_waiting), which cannot go past the end; at(i) would turn the silent read into a clear exception.
    • 

  • Prevention: always build and test with the sanitizers on; prefer range-for; review every <= next to a size().
    • 

  • How the evidence was made: the correct condition < was changed to <=; the outputs are the real runs R6 and R7, with machine-specific numbers replaced by placeholders by run.sh.
