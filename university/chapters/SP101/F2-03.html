Story hook

Analogy

At the pass, where finished dishes leave the kitchen, Chef Amara has pinned a card with her rules. "Take the next order slip. If it says q, the kitchen closes. If it says s, ladle a soup. If it says n or N, cook noodles. For anything else, ask the waiter. Then take the next slip."

The rules decide which step happens next. Some steps happen only in some cases. Some steps repeat until there are no slips left. One word, "closes", stops the repeating even if slips are still waiting.

New cooks make two classic mistakes with such cards. One cook checks "warm" before "hot", so nothing is ever called hot. Another cook forgets to stop after one step and also does the next one. Programs make the same mistakes. Today you learn the rules of control flow, and how the compiler and a careful eye catch those mistakes.

What you will be able to do

  • Write if/else if/else chains and order the tests correctly.
  • Use switch with case labels, break and default, and explain fallthrough.
  • Choose between for, while, do-while and range-for, and use break and continue.
  • Use the short-circuit rule of && and || to guard a risky operation.
  • Read a loop that reads input until it ends: while (std::cin >> code).
Jargon box
Control flow
Simple words: The order in which a program's statements run. Analogy: The rules card at the pass that says which step comes next. Precise: The sequence of executed statements, changed by selection statements (if, switch), iteration statements (for, while, do) and jump statements (break, continue, return). D2, D1
else if chain
Simple words: A list of tests where the first true one wins. Analogy: Reading the rules card from the top and following the first rule that fits. Precise: Nested if/else statements written as if (a) … else if (b) … else …; the conditions are tested in order and only the first true branch runs. D1, R5
switch statement
Simple words: A way to pick one of many actions by comparing one value with fixed choices. Analogy: Sorting order slips by the letter written on them. Precise: switch (expr) { case c1: … } jumps to the case label whose constant equals the value of the integer or character expression, or to default if none does. D2, R1
Fallthrough
Simple words: When the program runs on into the next case because nothing stopped it. Analogy: A cook who finishes the soup and carries on making noodles too. Precise: Execution continuing past the end of one case's statements into the next label; with -Wextra g++ warns "this statement may fall through" (an error under -Werror). R4, D3
break
Simple words: "Stop this loop or this switch now." Analogy: "The kitchen closes": stop taking slips. Precise: A jump statement that ends the innermost enclosing loop or switch; inside a switch in a loop it leaves only the switch. D2, R1
continue
Simple words: "Skip the rest of this round and start the next one." Analogy: Table 3 is closed tonight: skip it and set the next table. Precise: A jump statement that ends the current iteration of the innermost loop; in a for loop the increment still runs. D2, R2
do-while loop
Simple words: A loop that runs its body first and checks the condition afterwards. Analogy: Taste the soup, then decide whether to taste again. Precise: do statement while (condition); executes the statement at least once, then repeats while the condition is true. D2, R2
Short-circuit evaluation
Simple words: && and || stop as soon as the answer is known. Analogy: "If guests have arrived and each eats a lot" — if no guests arrived, you do not even think about how much they eat. Precise: The right operand of && is not evaluated if the left is false; the right operand of || is not evaluated if the left is true. D2, R1

Words you already know: if statement, condition, comparison operator, logical operator, while loop, for loop, range-based for loop, block (KID102) and truth table (MA102).

Layer 1 — the kid explanation

A program normally runs its lines from top to bottom. Control flow is everything that changes that order. A decision skips some lines. A loop goes back up and repeats lines.

You already know if, else, while and for from KID102. This chapter adds three tools. A switch picks one of many actions by looking at one value, like sorting slips by their letter. break means "stop now". continue means "skip the rest of this round".

Order matters in a list of tests. The computer follows the first rule that fits and ignores the rest. If "warmer than 60 degrees" comes before "warmer than 75 degrees", every hot dish is already caught by the first rule. The second rule can never win. R5

The compiler watches some mistakes for you. With our course flags, it refused a switch that forgot a break, and an if that used = instead of ==. It did not notice the wrong order of the temperature rules. That one you must catch yourself, with tests. R3, R4, R5

Layer 2 — the student explanation

if, else if, else

In if (a) X else if (b) Y else Z the conditions are checked from the top. The first true one runs its block, and the rest are skipped. Z runs only if all conditions are false. So put the most specific test first: temperature > 75 before temperature > 60. Listing 6 does that and correctly calls 82 and 90 "hot". D1, R6

switch

A switch compares one integer or character value with constant case labels and jumps to the matching one; default catches every other value. A case is only a label, a place to jump to. Execution continues downward from there until a break. Two labels in a row, like case 'n': case 'N':, share one action on purpose. D2, R1

Forgetting break after statements is a classic bug: the program falls through into the next case. In Listing 4 the size 'S' would first set 200 grams and then run on into case 'L' and set 400. With -Wextra, g++ warned "this statement may fall through", and -Werror made it an error. If you ever want fallthrough, C++ has a way to say so ([[fallthrough]];), which silences the warning. R4, D3, D2

Four loops

for fits counting: for (int table = 1; table <= 5; ++table). while fits "repeat while something holds", and may run zero times. do … while runs its body once before checking. Range-for visits every element of a container without an index. Listing 2 uses all four; its output shows that the do-while tasted once although its condition tastes < 1 was false after the first taste. R2, D1

continue skipped table 3 in Listing 2, and the loop went on with table 4. break leaves the innermost loop or switch. In Listing 1 the break on line 14 leaves the while, but the breaks inside the switch leave only the switch. That is why the check for 'q' is an if placed before the switch. R1, R2, D2

Reading until the input ends

while (std::cin >> code) reads one value per round. The expression std::cin >> code is true while reading works and false at the end of the input, so the loop ends by itself. Listing 1 counted 3 soups, 2 noodles and 1 unknown code, and ignored the two s after q. R1, D1

Short-circuit guards

In guests_per_table > 0 && (soups + noodles) / guests_per_table > 2, the division runs only if the left side is true. With 0 guests the left side is false, so the program never divides by zero, and it printed "Quiet evening at 3 tables." Swap the two sides and the division by zero would come first. R1, D2

= is not ==

if (guests = 0) assigns 0 and then tests the value 0, which is false. It is legal C++, so it is easy to miss. With -Wall, g++ said "suggest parentheses around assignment used as truth value", and -Werror stopped the build (Listing 3). R3, D3

Layer 3 — the engineer's depth

Note

For the curious. A switch over many dense values can be compiled into a "jump table": the value is used as an index into a table of addresses, so the program jumps straight to the right case instead of testing each one. Whether the compiler does this depends on the values and the optimisation level; you can check by reading the assembly with g++ -S (F2-01) or later with the tools of F2-32. D4 C++ also allows an initializer inside if and switch (an "init-statement"), as in if (int n = count(); n > 0), which keeps n local to the decision. D2

How the hardware actually does it

The processor has no if and no while. It has compare instructions and jump instructions. You saw them in F2-01: cmpl $1, -4(%rbp) followed by jne .L2 ("jump if not equal"). An if becomes "compare, then jump over the block if the condition is false". A loop becomes "compare, then jump back to the top if the condition is true". break and continue are plain jumps to the end or to the start of the loop. D4 How a processor guesses which way a jump will go before it knows, to keep busy, is the subject of branch prediction in F1-28.

Where the analogy breaks


    

  • A cook reading "if warm … else if hot" would notice that the second rule can never apply. The compiler did not warn about Listing 5's unreachable branch; it only checks what its warning options cover. R5
    • 

  • A cook told "stop" stops everything. break stops only the innermost loop or switch it is in (Figure 1). D2, R1
    • 

  • A case on a rules card is a separate rule; in C++ a case is only a label to jump to, and execution keeps going down until something stops it (fallthrough). D2, R4
