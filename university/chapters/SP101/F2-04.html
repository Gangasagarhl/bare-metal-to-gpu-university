Story hook

Analogy

The kitchen has stations. Ravi runs the sauce station, Sofia the tasting station, and Jonas plates the desserts. The head chef sends work to a station in one of three ways.

Sometimes she hands over a photocopy of an order slip. Ravi can scribble on his copy as much as he likes; the original stays clean. Sometimes she hands over the real pot of soup. Whatever Ravi adds goes into the soup the guests will eat. And sometimes she lets Sofia taste the real pot, with one rule: "taste, but do not add anything".

There are also two stations with the same sign, "portions". One expects a number of guests; the other expects kilograms of rice. A waiter picks the station by looking at what is written on the slip. If he reads "3" and not "3.0", he may walk to the wrong one. This chapter is about these three ways of handing things over, and about stations that share a name.

What you will be able to do

  • Pass arguments by value, by reference (&) and by const reference (const &), and choose the right one.
  • Predict whether a function can change the caller's variable.
  • Write overloaded functions and default arguments, and predict which overload a call picks.
  • Separate a function's declaration from its definition.
  • Diagnose a wrong overload choice from a program's output.
Jargon box
Pass by value
Simple words: The function gets its own copy of the argument. Analogy: A photocopy of the order slip. Precise: A parameter of a non-reference type is initialized as a copy of the argument; changes to it do not affect the caller (R1: the pot was unchanged after add_salt_to_copy). D1, R1
Reference
Simple words: Another name for an existing variable. Analogy: Handing over the real pot instead of a copy. Precise: A reference (T&) is an alias bound to an object when it is initialized; every use of the reference uses that object. D1, D2, R1
Pass by reference
Simple words: The function works on the caller's own variable. Analogy: The sauce station adds salt straight into the real pot. Precise: A parameter of type T& binds to the argument, so changes through it change the caller's object; the argument must be a modifiable variable. D1, R1
Const reference
Simple words: A reference that may be read but not used to change anything. Analogy: "Taste the real pot, but do not add anything." Precise: A parameter of type const T&: no copy is made, and assigning through it is a compile error ("assignment of read-only reference"). D1, R3
Overloading
Simple words: Several functions with the same name but different parameter lists. Analogy: Two stations with the same sign, chosen by what is written on the slip. Precise: Functions in the same scope with one name and different parameter types or counts; for each call the compiler selects the best match by the argument types (overload resolution). D2, R2
Default argument
Simple words: A value a parameter takes when the caller leaves it out. Analogy: "Unless told otherwise, 0.1 kg of rice per portion." Precise: An initializer written in a function declaration, such as double kilograms_per_portion = 0.1; the compiler inserts it at each call that omits the argument. D2, R2
Scope
Simple words: The part of the program where a name can be used. Analogy: A station's own notepad: other stations cannot read it. Precise: The region of program text in which a declaration is visible; a parameter or local variable is visible from its declaration to the end of its block. D2, D1

Words you already know: function, parameter, argument, return value, void (F0-34); declaration and name mangling (F2-01).

Layer 1 — the kid explanation

In F0-34 you learned that a function gets a copy of what you give it. If the function changes its copy, your variable stays the same. That is safe, but sometimes you want the function to change your variable. And sometimes a copy is wasteful, like photocopying a whole recipe book just so someone can read one line.

C++ lets you choose. A plain parameter is a copy. A parameter with & is the real thing under another name: changes go straight into your variable. A parameter with const and & is the real thing, but read only.

Functions can also share a name if their parameters differ. portions(4) and portions(2.0) call two different functions. The compiler picks one by looking at the types of what you pass. That is handy, but it can surprise you: 3 is an int, and 3.0 is a double. R2, R4

Layer 2 — the student explanation

Three ways to pass

By value (std::string soup): the parameter is a new object initialized from the argument. In R1, add_salt_to_copy printed "tomato soup + salt" inside, but main still saw "tomato soup" afterwards. R1, D1

By reference (std::string& soup): the parameter is bound to the caller's object, so it is that object under a second name. After add_salt(pot), main printed "tomato soup + salt". swap_plates(int& left, int& right) uses two references to exchange the caller's values: a and b became 2 and 1. R1, D1

By const reference (const std::string& soup): bound to the caller's object, but read only. taste printed the soup and its size, 18 characters, without copying it. Listing 3 tries to assign to a const reference and g++ refused: "assignment of read-only reference 'spoons_of_salt'". R1, R3, D1

Which one to choose

A simple guideline: pass small, cheap types such as int, double and char by value. Pass larger objects such as std::string and std::vector that the function only reads by const&. Use a plain & only when changing the caller's object is the function's job, and make that clear in its name (add_salt, swap_plates). For results, prefer returning a value. D4, D1

Declaration and definition

Listing 2 declares its functions above main and defines them below. A declaration gives the name, the return type and the parameter types; a definition adds the body. The compiler needs a declaration before each call (F2-01); the definition may come later, or live in another file (F2-07). D1, R2

Overloading and default arguments

Listing 2 has three functions named portions: one with an int, one with two ints, and one with two doubles. For each call the compiler compares the argument types with each parameter list and picks the best match. portions(4) chose the int version and returned 4; portions(4, 3) returned 12. R2, D2

The third portions has a default argument, kilograms_per_portion = 0.1, written in the declaration. portions(2.0) used it and printed 20; portions(2.0, 0.25) printed 8. In the object file there is only one function for both calls, portions(double, double): the compiler wrote the 0.1 into the call itself. R2, R5, D2

Overloads are different functions for the linker too. nm showed three symbols, _Z8portionsi, _Z8portionsii and _Z8portionsdd: the parameter types are part of the mangled names (F2-01). R5, D5

Scope

A parameter or local variable exists only inside its function, from its declaration to the closing brace. Two functions can both have a parameter called soup; they are unrelated. Each call gets fresh parameters (F0-34). D2, R1

Layer 3 — the engineer's depth

Note

For the curious. Overload resolution ranks conversions: an exact match beats a promotion, which beats a standard conversion such as int to double. If two candidates rank equally the call is ambiguous and does not compile. That ranking is why print_price(3) in the forensic lab picks the int overload without any warning: it is an exact match. D2 A reference must be bound when it is created and cannot be re-bound later; returning a reference to a local variable leaves it bound to an object that no longer exists (a dangling reference). References, const and object lifetimes are deepened in F2-12 and F2-23. D1, D2

How the hardware actually does it

A call is a jump that remembers where to come back to (F0-34). Arguments travel in agreed places, mostly processor registers, according to the platform's calling convention; on Linux x86-64 that convention is the System V AMD64 ABI, which the curriculum lists among the foundations (curriculum 1.2). D6, D3 In the assembly of F2-01, dish_price found its int argument in the register %edi (movl %edi, -4(%rbp)). Passing by value copies the value itself into such a place. Passing by reference typically passes the address of the caller's object instead, which is why the function can change it; how compilers implement references is not fixed by the standard. D3, D2 Addresses are the topic of SP201.

Worked example

Predict every line of Listing 1, then compare with R1.

  1. add_salt_to_copy(pot): soup is a copy of "tomato soup". It becomes "tomato soup + salt" and is printed inside the function. When the function ends, the copy is gone. main prints "after add_salt_to_copy: tomato soup".
  2. add_salt(pot): soup is pot. Adding " + salt" changes pot. main prints "tomato soup + salt".
  3. taste(pot): reads pot. Its size: "tomato soup" has 11 characters, " + salt" has 7 (space, plus, space, s, a, l, t), total 18.
  4. swap_plates(a, b) with a = 1, b = 2: held = 1; left (that is, a) = 2; right (b) = 1. main prints "a = 2, b = 1".

The real output R1 matches every prediction, including the 18 characters. R1 Now Listing 2: portions(2.0) uses the default 0.1, so 2.0 / 0.1 = 20; portions(2.0, 0.25) gives 2.0 / 0.25 = 8. Where the analogy breaks


    

  • A photocopy is cheap. Copying a large std::string or std::vector by value copies every character or element, which can cost real time; the analogy hides that cost. D4
    • 

  • "Taste but do not add" is a polite rule a cook might break. const& is enforced by the compiler: breaking it does not build (R3). R3
    • 

  • A waiter who sees "3" for a rice order would ask "three what?". The compiler never asks: 3 is an exact match for an int parameter, so it silently picks that overload (forensic lab). R4, D2

Forensic lab answer key


    

  • Observation: soup printed 0.03 instead of 3.00: too small by a factor of 100. Tea (2.50) and bread (1.50) are right. R4
    • 

  • Hypotheses: (1) "the cents arithmetic is wrong" — ruled out: bread uses the same print_price(int) and prints 150 cents correctly as 1.50. (2) "the soup call reaches the wrong overload" — confirmed.
    • 

  • Root cause: print_price(3) passes the int literal 3. The int overload is an exact match, so it wins over the double overload (which would need a conversion). The function treats 3 as 3 cents. The intent ("3 coins") exists only in the comment.
    • 

  • Why no warning: choosing an exact match is ordinary, correct overload resolution; nothing is suspicious from the compiler's point of view. D2
    • 

  • Fix: do not overload one name for two different units; use names that carry the unit (print_cents, print_amount). The fixed program printed 3.00, 2.50 and 1.50. R6 (A later course shows a stronger fix: a separate type for money, so that the compiler can tell units apart.)
