Story hook

Analogy

Ana wants her grandfather to make her favourite pancakes. She writes the recipe on a card in her neat handwriting. But her grandfather reads only one language, and it is not the one Ana writes.

So Ana asks her cousin Tomás for help. Tomás reads the card very carefully. If a step makes no sense, he hands the card back and says exactly which line is wrong. If every step makes sense, he copies the recipe into the language her grandfather reads.

Now her grandfather follows the new card, word for word. The pancakes appear. Ana never had to learn her grandfather's language at all.

Writing a computer program works the same way. You write the recipe. A helper program checks it and rewrites it. Then the computer follows it exactly. In this chapter you will do all three steps yourself, for the first time.

What you will be able to do

  • Explain, with the recipe story, the three steps from source code to a running program: write, compile, run.
  • Build and run a C++ program that prints text, using the course's build command.
  • Check which toolchain you have by asking the compiler for its version, and write that version down.
  • Change the text a program prints, predict the new output, run it and compare.
  • Find a missing \n and steps in the wrong order by reading a program's output and its source.
Jargon box
Program
Simple words: A list of exact steps that a computer follows. Analogy: A recipe that the cook follows word for word. Precise: A set of instructions for a computer; in this course it starts as C++ source code and is turned by a compiler into an executable that the operating system can run. R1, D1
Source code
Simple words: The text of a program, written by a person in a programming language. Analogy: The recipe written in your own handwriting on a card. Precise: The human-readable text of a program, stored in files such as hello.cpp; the compiler reads it and either reports errors or produces an executable. R1, D1
Compiler
Simple words: A program that turns the text you wrote into a program the computer can run. Analogy: A helper who rewrites your recipe in the only language the cook can read, and refuses if the recipe makes no sense. Precise: A program (here g++) that checks C++ source code against the rules of the language and translates it into machine instructions stored in an executable file; it reports errors and warnings when it cannot. R4, D2
Executable
Simple words: The finished program file that the computer can start. Analogy: The recipe after it was rewritten for the cook: ready to use, but no longer easy for you to read. Precise: A file of machine instructions and data produced by the compiler; on the Linux build machine of this course the file tool describes it as an ELF 64-bit executable, and its first bytes are 7f 45 4c 46. R4, D3
Toolchain
Simple words: The set of programs you use to turn source code into a running program. Analogy: Your kitchen tools: the same recipe needs the right pots and an oven. Precise: The compiler and the programs that work with it (and, in F0-37, the debugger). This course records the exact versions the tools print, for example "g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0". R4, D2
main function
Simple words: The place where every C++ program starts. Analogy: The first line of the recipe: "start here". Precise: The function named main, which the program runs first; the value it returns (0 here) becomes the exit code that the run log records. R1, D1
Statement
Simple words: One instruction in a program. In C++ most statements end with a semicolon. Analogy: One step of the recipe. Precise: A single instruction inside a function body, such as std::cout << "Hello"; statements run one after another, from top to bottom, unless a statement such as if or a loop changes the order. R2, D1
std::cout
Simple words: The name C++ uses for "print this on the screen". Analogy: The cook calling out loud what is happening. Precise: The standard output stream from the header <iostream>; the operator << sends text and numbers to it, and the run log captures what it printed. R1, D1
String literal
Simple words: Text written inside double quotes in your program. Analogy: Words copied exactly onto a label. Precise: A sequence of characters between double quotes in source code, such as "Hello, world!\n"; the program uses it exactly as written. R1, D1
Newline
Simple words: The invisible character that says "start a new line here". Analogy: Pressing the Enter key on a typewriter or keyboard. Precise: The character written '\n' in C++; without it, the next output continues on the same line (R3 shows two messages glued together). R3, D1
Exit code
Simple words: A number a program gives back when it ends. 0 means "all went well". Analogy: The cook saying "done, no problems" or "something went wrong" at the end. Precise: The value returned by main (or set when a program is stopped); run_lab.sh records it in each .log file, for example "exit code: 0". R1

The idea in pictures

Figure 1 shows the whole journey of a program. You write text. The compiler checks it and turns it into an executable. The computer runs the executable, and you see the output.

Layer 1 — the kid explanation

A computer follows steps exactly. You learned that in KID101 with recipes and robots. Now you will write steps that a real computer follows.

You write your steps as text in a file. The file is like Ana's recipe card. People can read it. The computer cannot follow it yet. We call this text source code.

Next, a helper program reads your text. This helper is called the compiler. It checks every line against the rules of the language. If something is wrong, it stops and tells you where. If all is well, it writes a new file. That new file is the program the computer can run.

Then you run the new file. The computer follows the steps, one after another, from top to bottom. Our first program has one main step: show the words "Hello, world!" on the screen.

"Hello, world" is a small program. But it proves that the whole chain works: your text, the compiler, and the computer.

Three ideas matter most today. First, the computer does exactly what you wrote, not what you meant. Second, the compiler is your helper, not your judge. Third, every run leaves a record, so you can compare what you expected with what really happened.

Layer 2 — the student explanation

A C++ program is one or more text files whose names end in .cpp. Our first one is hello.cpp. It contains a main function: the place where the program starts. Inside main there are statements. Each statement is one instruction and ends with a semicolon. R1, D1

To print, the program sends text to std::cout with the << sign. The text is a string literal: characters between double quotes. The two characters \n inside it mean "start a new line". They are one invisible character, the newline. R1, R3, D1

The last statement, return 0;, ends main. The number 0 goes back to the system as the program's exit code. Zero means "everything went well". Our lab runner writes it into a log file after every run. R1

You build the program with the compiler g++. The course runner uses this exact command:

g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror -g -fsanitize=address,undefined hello.cpp -o hello

That is long, so here is what each part does. -std=c++20 picks the version of the C++ rules. -Wall -Wextra -Wpedantic turn on many warnings. -Werror turns every warning into an error, so nothing suspicious slips through. -g keeps information for the debugger (F0-37). -fsanitize=address,undefined adds extra checks while the program runs. -o hello names the output file. R4, D2

The compiler can also be called the short way, g++ hello.cpp -o hello. We tried that too, and it worked: the transcript is in the Lab section below. The course uses the long form because it catches more mistakes early. R4

Layer 3 — the engineer's depth

Note

For the curious. "Compiling" is really several jobs in a row. g++ first prepares the text (it pulls in the contents of headers such as <iostream>), then translates C++ into machine instructions, and finally joins your code with ready-made library code into one executable. That last job is called linking. You will study each job in SP101 (chapter F2-01). D1, D2

The file our compiler made is not text any more. The tool file described it as an "ELF 64-bit LSB pie executable, x86-64". ELF is the name of the file format on this Linux machine. Its first four bytes, shown by od, are 7f 45 4c 46. When od shows the same four bytes as characters, the last three appear as the letters E, L and F. R4

How the hardware actually does it

Inside the computer, the processor cannot read C++. It reads machine instructions: numbers that stand for tiny steps such as "add" or "copy". That is why the compiler is needed. The executable is a long list of such numbers, plus the text "Hello, world!" stored as bytes. When you run it, the operating system loads the file into memory, and the processor follows the instructions one by one. You met the processor and memory as the kitchen's cook and pantry in F0-05. R4, D3

Worked example

Let us predict the output of Listing 2 before running it. We read the program like the computer does: from top to bottom, one statement at a time.

  1. Line 5 prints Sandwich recipe, then \n. So the next text starts on a new line.
  2. Line 6 prints Step 1: take two slices of bread and a newline.
  3. Lines 7 and 8 print steps 2 and 3 the same way, each on its own line.
  4. Line 9 prints Done. Enjoy! and a newline.
  5. Line 10 returns 0, so the exit code should be 0.

Prediction: five lines of text, in the same order as in the source, and exit code 0. The real run below matches this. If you swap lines 7 and 8, step 3 will be printed before step 2. The computer does not know that the numbers are out of order. It follows the order of the statements, not the meaning of the words. R2

Where the analogy breaks


    

  • Tomás, the helper, would fix a small spelling mistake himself. The compiler never guesses what you meant. It stops and reports, and you fix it. (It may suggest a fix, as F0-36 shows, but it does not apply it.) R4, D2
    • 

  • Ana's grandfather could notice that "step 3" comes before "step 2" and fix the order. The computer cannot. It runs statements in the order written, whatever the words say (the forensic lab shows this). R3
    • 

  • A rewritten recipe card is still a card someone could read. The executable is a file of numbers. You read your program in the source file, never in the executable. R4
    •
