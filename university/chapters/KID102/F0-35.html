Story hook

Analogy

Before the big family dinner, Aiko writes a shopping list: rice, beans, onions. Her brother shouts from the other room, "Add lemons!" She writes "lemons" at the bottom. One list, four items, in order.

Imagine keeping the list as separate jars instead: item1, item2, item3. Then the fourth item needs a new jar with a new name, and every part of the program must learn about it. That would be silly.

In the pantry there is a long shelf of identical jars with numbers painted on them. The first jar has the number 0. Aiko's grandmother says, "Bring me jar 2." Aiko counts: 0, 1, 2. That is the third jar.

And then there is the egg box. It always has exactly six places, no more, no fewer. In this chapter you will meet both kinds of list: the growing shelf, called std::vector, and the fixed box, called std::array.

What you will be able to do

  • Create a std::vector, read its elements by index, ask for its size and add elements with push_back.
  • Visit every element with a counting loop and with a range-based for loop.
  • Compute a total, a count and a best value from a list.
  • Use std::array for a list whose length never changes.
  • Explain what "out of range" means, and find a loop that skips the last element.
Jargon box
std::vector
Simple words: A list of values of the same type that can grow. Analogy: A row of numbered jars on a shelf, and you can add more jars at the end. Precise: The standard library container from <vector> that stores elements in order; size() gives the number of elements and push_back adds one at the end (R1). R1, D1 §12.2, D4 §22.2.3
std::array
Simple words: A list with a fixed number of values. Analogy: An egg box: always the same number of places. Precise: The standard library container from <array> whose size is part of its type, for example std::array<std::string, 3> (R3). R3, D4 §22.3.7.1
Element
Simple words: One value inside a list. Analogy: One jar in the row. Precise: One of the values stored in a container such as std::vector. R1, D1 §12.2
Index
Simple words: The position number of an element. Counting starts at 0. Analogy: The number painted on a jar: jar 0, jar 1, jar 2. Precise: The position of an element in a container, from 0 up to size() − 1; list[0] is the first element (R1). R1, D1 §12.2
Range-based for loop
Simple words: A for loop that visits every element of a list, one by one, without an index. Analogy: Walking along the shelf and looking into each jar in turn. Precise: for (int score : scores) { ... } runs the block once for each element, with the loop variable holding that element (R2). R2, D1 §12.2, D4 §8.6.4
Out of range
Simple words: Asking for a list position that does not exist. Analogy: Reaching for jar 3 on a shelf that has only jars 0, 1 and 2. Precise: Using an index that is not less than size(); the member function at() checks and throws std::out_of_range, which stopped the program in R4 with exit code 134 (an exception that nobody catches makes the program call std::terminate, which by default calls abort()). R4, D1 §12.2.2, D4 §22.2.3, §14.6.1, §17.9.4.1

Layer 1 — the kid explanation

So far, each jar held one value. But many things come in lists: shopping items, scores in a game, guests at a party. A list keeps many values of the same kind together, in order, under one name.

Each value in the list has a position number. Programmers count positions from 0, not from 1. So the first item is at position 0, the second at position 1, and so on. It feels strange at first. Think of the numbers painted on the pantry jars, starting with 0.

A std::vector is a list that can grow. You can ask how many items it holds, and you can add a new item at the end. A std::array is a list with a fixed length, like an egg box.

Lists and loops are best friends. A loop can visit every item, one after another: add them up, find the biggest, print them all. That works for 3 items or for 3,000.

There is one danger. If you ask for a position that does not exist, like jar 3 on a shelf of three jars (0, 1, 2), something must go wrong. You will see what the computer does in that case.

Layer 2 — the student explanation

A vector is declared with the type of its elements in angle brackets: std::vector<std::string> list = {"rice", "beans", "onions"};. You need #include <vector>. Each value in it is an element. list.size() gives the number of elements: 3 here. R1, D1 §12.2

You read an element by its index in square brackets: list[0] is "rice". Valid indexes go from 0 to size() - 1. list.push_back("lemons") adds a new element at the end; afterwards the size was 4 and "lemons" had index 3. R1, D1 §12.2, D4 §22.2.3

To visit every element, you can count through the indexes: for (std::size_t i = 0; i < list.size(); ++i). The type std::size_t is a whole-number type made for sizes: it has no negative values, and it is big enough for the size of any object. Note the <: the last index used is size() - 1. R1, D4 §17.2.4

If you do not need the index, a range-based for loop is shorter and cannot go out of range: for (int score : scores) runs once per element, with score holding a copy of that element. Listing 2 uses it to compute a total, a count and the best score. R2, D1 §12.2, D4 §8.6.4

A std::array has its length in its type: std::array<std::string, 3> meals always holds exactly 3 strings. It has size() and can be visited with the same loops, but it has no push_back. R3, D4 §22.3.7.1, §22.2.3

Square brackets do not check the index. The member function at() does: eggs_per_box.at(3) on a vector of size 3 stopped the program with the message "vector::_M_range_check: __n (which is 3) >= this->size() (which is 3)" and exit code 134. R4, D1 §12.2.2, D4 §22.2.3

Layer 3 — the engineer's depth

Note

For the curious. Look closely at the run of Listing 4: the line "Box 0 has 6 eggs" is missing from the output, although that statement ran before the crash. The program collected its output in a waiting area (a buffer) to print it later, and the crash came first. When the same program used std::endl, which empties the buffer at once, the line appeared. So when a program crashes, its last printed lines may be missing: the crash may have happened later than the output suggests. R4, R5, D4 §29.7.5.4

What about square brackets with a bad index? The C++ rules do not promise any particular result: the program might print a strange value, crash, or seem to work. That is why this course uses at() when an index could be wrong, and why our build uses AddressSanitizer (-fsanitize=address), a tool that watches memory use while the program runs. D1 §12.2.2, D2 §3.12

In for (const std::string& meal : meals) (Listing 3), the & lets the loop look at each string in place, without copying it, and const promises not to change it. You will learn this properly in SP101. D4 §8.6.4, §9.4.3, §7.2.1

How the hardware actually does it

A vector keeps its elements next to each other in memory, like jars side by side on one shelf. To find element i, the program starts at the address of element 0 and moves forward i element-widths. That is why counting starts at 0: element 0 is zero steps from the start. When a vector grows beyond the space it has, it moves its elements to a bigger shelf; you do not see this happen. D1 §12.2, D4 §22.2.3, §22.3.11.1, §22.3.11.5

Where the analogy breaks


    

  • Real shelves are numbered from 1 by most people. C++ indexes start at 0, so "jar 3" is the fourth jar. Many bugs come from this difference. R1
    • 

  • A shopping list can hold rice and a phone number at the same time. A vector holds elements of one type only: std::vector<int> holds only whole numbers. D1 §12.2
    • 

  • Reaching for a jar that is not there, you would feel the empty shelf and stop. In C++, square brackets do not check; only at() checks, and it stops the program when the index is bad. R4, D1 §12.2.2
    • 

  • Adding a jar to a real shelf never moves the other jars. A growing vector may move all its elements to a new place in memory, which matters in later courses. D4 §22.3.11.5
    •

Where you came from: F0-33 (loops) and F0-34 (functions): one jar per value. Summary


    

  • A std::vector holds many elements of one type, in order, and can grow with push_back.
    • 

  • Indexes start at 0; the last valid index is size() - 1.
    • 

  • Count through indexes with std::size_t i = 0; i < v.size(), or use a range-based for loop.
    • 

  • Totals, counts and "best so far" are loop patterns over a list.
