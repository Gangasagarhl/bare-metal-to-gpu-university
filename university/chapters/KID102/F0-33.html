Story hook

Analogy

Grandma Ama's soup recipe says: "Stir 20 times." It does not say "stir, stir, stir, stir…" twenty times on the card. One short line is enough, because everybody understands "repeat this".

The egg timer works in a different way. Nobody says "wait 5 seconds" five times. You say: "While the timer is above zero, wait one more second." When it reaches zero, it rings, and you stop.

Then there is Kofi's job: "Fill the bowl with 20 spoons of flour, 3 spoons at a time." Kofi counts: 3, 6, 9, 12, 15, 18, 21… Wait! Kofi is a person, so he notices that he went past 20 and stops. A computer would not notice. It would keep spooning flour forever, and the kitchen would disappear under a white mountain.

This chapter is about repeating steps. You will learn the two main loops of C++, and how to make sure they stop.

What you will be able to do

  • Write while and for loops that repeat a block a counted number of times or until a condition changes.
  • Trace a loop by hand in a table, iteration by iteration, and predict its output.
  • Use a counter and a running total inside a loop.
  • Explain how a loop ends, and recognise one that runs zero times or one time too many.
  • Diagnose a loop that never ends from its output and its source.
Jargon box
Loop
Simple words: A part of a program that repeats. Analogy: "Stir 20 times." Precise: A statement (while, for) that runs its block again and again as long as its condition is true. R1, D1
while loop
Simple words: A loop that checks its condition before every round, and stops when it is false. Analogy: "While the timer is above zero, wait one more second." Precise: while (condition) { ... } evaluates the condition before each iteration and runs the block only while it is true (R2). R2, D1
for loop
Simple words: A loop with a counter built in: start, keep going while, and step. Analogy: Counting your stirs out loud: "one, two, three…" up to five. Precise: for (start; condition; step) { ... } runs start once, then checks the condition before each iteration and runs step after each one (R1). R1, D1
Iteration
Simple words: One round of a loop. Analogy: One stir of the spoon. Precise: A single execution of a loop's block. R1, D1
Counter
Simple words: A variable that counts how many times something happened. Analogy: Counting stirs on your fingers. Precise: A variable, usually an int, that is increased (for example with ++day) on each iteration and often used in the loop's condition. R1, D1
Infinite loop
Simple words: A loop that never stops by itself. Analogy: A cook told "stir until the soup is purple" who keeps stirring forever. Precise: A loop whose condition never becomes false; in R4 the time limit stopped the program and the log recorded exit code 124. R4

The idea in pictures

Figure 1 shows the path the computer takes through a for loop. The arrow back to the condition is the "repeat". The only way out is a false condition.

Layer 1 — the kid explanation

A loop repeats some steps. Instead of writing the same line twenty times, you write it once and say how often to repeat it, or until when.

A while loop is like the egg timer. Before each round, it asks a question: "Is the timer still above zero?" If yes, it does the steps inside once more. If no, it stops and the program carries on below the loop.

A for loop is like counting your stirs out loud. It has three parts in one line: where to start counting, when to keep going, and how to count up. "Start at 1. Keep going while the count is 5 or less. Add 1 each time."

Every loop needs a way out. Something inside the loop must change, so that one day the question gets the answer "no". If nothing changes, or if the change jumps over the stopping point, the loop never ends. Kofi's flour is a famous kitchen example, and you will investigate it in the forensic lab.

Layer 2 — the student explanation

A while loop has the form while (condition) { block }. The condition is checked before every iteration. If it is true, the block runs, and then the condition is checked again. In Listing 2, seconds starts at 5 and the block subtracts 1 each time; when it reaches 0, seconds > 0 is false, and the loop ends after 5 iterations. R2, D1

A for loop packs the three loop parts into one line: for (start; condition; step). The start runs once. Then, as long as the condition is true, the block runs and then the step runs. Listing 1 uses int stir = 1, stir <= 5 and stir = stir + 1. R1, D1

Programmers usually write the step stir = stir + 1 more shortly as ++stir; Listing 3 uses that form with ++day. Both add 1 to the counter. R3, D1

Because the condition is checked first, a loop can run zero times. When Listing 2 started with seconds = 0, the program printed only the "Ding!" line. R6

A loop whose condition never becomes false is an infinite loop. With while (spoons != 20) and steps of 3, spoons goes 18, 21, 24… and is never exactly 20. Our lab runner stops any program after a time limit; for that program the log recorded exit code 124. R4

Layer 3 — the engineer's depth

Note

For the curious. Choosing between while and for is about clarity, not power: any for loop can be rewritten as a while loop with the start before it and the step at the end of its block. Use for when you know how many times to repeat, and while when you repeat until something happens, such as "until the player guesses right" in F0-38. D1

A safer stopping condition uses <, <=, > or >= rather than !=, because a step can jump over a single exact value but cannot jump over a whole range. Changing != to < made the flour loop stop (at 21 spoons) in this build. R5

The forensic program uses std::endl instead of '\n'. std::endl also pushes the text out at once. That matters here: the runner stops the program from outside, and text still waiting inside the program would be lost (F0-35 shows this happening). D1

How the hardware actually does it

A loop is built from the same pieces as an if (F0-32): a compare instruction and a jump. At the end of the block there is a jump backwards, to the compare at the top. When the compare says "false", a jump forwards skips past the loop. The processor has no idea it is "in a loop"; it follows jumps. That is also why it never gets bored or tired, and why it will happily run an infinite loop until something stops it. D2

Where the analogy breaks


    

  • A cook told to "fill to 20 spoons" stops at 21 and says "close enough". A loop with spoons != 20 never stops, because 21, 24, 27… are all "not 20" (forensic lab). R4
    • 

  • A cook gets tired and slows down. The processor repeats the thousandth iteration exactly like the first; it never gets tired and never gets bored. D2
    • 

  • "Stir 20 times" counts from 1 in a kitchen. Programmers often count from 0 (for (int i = 0; i < 20; ++i) also runs 20 times), which you will need for lists in F0-35. D1

Forensic lab answer key


    

  • Observation: the output goes 18, then 21, 24, 27…; it passes 20 without stopping, "The bowl is full." never appears, and the record says exit code 124 (stopped by the time limit). R4
    • 

  • First sign: the line "Spoons in the bowl: 21".
    • 

  • Root cause: line 9, while (spoons != 20). The step of 3 from 0 gives 3, 6, …, 18, 21; it never equals 20 exactly, so the condition is always true.
    • 

  • "Too slow" is ruled out: the values passed 20 and kept growing; a slow program would still stop at 20. The program was doing exactly what it was told.
    • 

  • Fix: while (spoons < 20). The fixed program never_ends_fixed.cpp stopped in this build, with the last line "Spoons in the bowl: 21" and then "The bowl is full." (If the bowl must hold exactly 20, the step itself has to change near the end: a design question for Kofi.) R5
    • 

  • Prevention: trace the loop on paper around the stop value; use a range condition; test with a step that does not divide the target.
    • 

  • How the evidence was made: a < was replaced by != on purpose; the output and the exit code are the real run R4.
