Note

Weights. KID102 is an L0–L1 course, so it uses the L0 option of guide 11.4 (owner ruling B6): quizzes 20 %, practical 50 %, course project 30 % (an exercise value, ruling A4), with encouraging written feedback.     Scenario. Dani wrote a times-table quiz for the practical and tried it with the 8 times table. "I answered all three questions right and it says 1 out of 3, three times! And the table stops at 8 x 9. The tests passed, so the bug must be in the computer."

    Evidence 1 — the source, labs/KID102-P/forensic_table.cpp, copied exactly:

    #include <iostream>
#include <vector>

// Evidence for the KID102 final exam (forensic question): Dani's times-table quiz.
// Dani says: "I got all three right and it still says 1 out of 3, and the table is too short!"

int times(int a, int b)
{
    return a * b;
}

int check_times(int a, int b, int expected)
{
    int got = times(a, b);
    if (got == expected) {
        return 0;
    }
    std::cout << "FAIL: times(" << a << ", " << b << ") = " << got << ", expected " << expected << '\n';
    return 1;
}

int test_times()
{
    int failures = 0;
    failures = failures + check_times(7, 3, 21);
    failures = failures + check_times(0, 9, 0);
    std::cout << "test_times: " << failures << " failures\n";
    return failures;
}

void print_table(int n)
{
    for (int k = 1; k < 10; ++k) {
        std::cout << n << " x " << k << " = " << times(n, k) << '\n';
    }
}

int ask(int n, int k)
{
    int answer = 0;
    std::cout << "What is " << n << " x " << k << "? ";
    if (!(std::cin >> answer)) {
        std::cout << "\nThe input ended early.\n";
        return -1;
    }
    std::cout << '\n';
    if (answer == times(n, k)) {
        std::cout << "Right!\n";
        return 1;
    }
    std::cout << "Wrong, it is " << times(n, k) << ".\n";
    return 0;
}

int main()
{
    if (test_times() != 0) {
        return 1;
    }
    int n = 0;
    std::cout << "Which table do you want to practise (1 to 12)? ";
    std::cin >> n;
    std::cout << '\n';
    if (n < 1 || n > 12) {
        std::cout << "Please choose a number from 1 to 12.\n";
        return 0;
    }
    print_table(n);

    const std::vector<int> multipliers = {4, 6, 9};
    for (int k : multipliers) {
        int score = 0;
        int result = ask(n, k);
        if (result < 0) {
            break;
        }
        score = score + result;
        std::cout << "Score: " << score << " out of " << multipliers.size() << '\n';
    }
    return 0;
}

Course project — 20 %

Goal. Build a small text game or home tool in C++ from small tested functions: a text adventure or a guessing game (the course card), or one of the ideas in the F0-38 mini-project (a times-table quiz, a pocket-money tracker with a list, a recipe scaler). It must use what the course taught: variables, decisions, a loop, at least three functions and a test function.

Requirements.

  • Functional: at least three functions besides main, each with one clear job; at least one loop and one if/else chain; a test function with cases worked out by hand, including an edge case, that main runs first, stopping with exit code 1 if any case fails; the program always ends when its input ends (F0-38's second way out).
  • Quality: builds with the course command with no warnings; good names; a comment above each function saying what it does; no index out of range (use at() or range-based for loops); every variable initialised.
  • If the program uses random numbers, the recorded run uses a fixed seed, and the report says why (F0-38).

Constraints. No hardware beyond a computer with the course toolchain (g++ 13.3.0 or the learner's recorded toolchain). About 6 hours of work spread over the course, after F0-34. One source file of at most about 150 lines is enough.

Deliverables. (1) the source file; (2) the build log made with the course flags (the .log written by run_lab.sh, or the command and its output copied); (3) one recorded run with its input file (.in) and output (.out) that can be repeated; (4) a half-page report: the functions and their jobs, the test cases and how the expected values were worked out, one bug found and how it was found (trace table, test or gdb); (5) a five-minute demo: run the tests, play one round, explain one function.

Milestones. (M1, after F0-34) plan: a list of functions with name, inputs and output, and the hand-worked test cases. (M2, after F0-35) the functions build and the test function reports 0 failures. (M3, after F0-37) the whole program runs end to end; one planted bug found with gdb or a trace. (M4, after F0-38) recorded run, report and demo.
