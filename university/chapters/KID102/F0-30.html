Story hook

Analogy

In Priya's kitchen there is a shelf of glass jars. Each jar has a label: "rice", "sugar", "buttons". You can look inside a jar without changing it. You can empty a jar and fill it with something new. But the label stays the same.

One day Priya's dad says, "Swap the rice and the sugar. Rice goes in the sugar jar, sugar goes in the rice jar." Priya thinks for a moment. If she pours the rice into the sugar jar, the sugar is still in there. What a mess!

So she fetches a third, empty jar. Rice goes into the spare jar. Sugar goes into the rice jar. Then the rice goes from the spare jar into the sugar jar. Done, with nothing spilled.

A program needs jars too. It needs places to keep numbers and words while it works. In C++ these jars are called variables. And yes, swapping two of them needs a spare jar, exactly like Priya's.

What you will be able to do

  • Explain what a variable is, using the labelled-jar picture and the precise words name, type and value.
  • Write a program that creates variables, changes their values and prints them.
  • Predict, line by line, the value inside every variable, then check your prediction with a real run.
  • Swap two variables correctly with a spare variable, and explain why the two-line swap fails.
  • Read a number typed by the user (or from an input file) into a variable.
Jargon box
Variable
Simple words: A named place that holds a value, which can change while the program runs. Analogy: A labelled jar: the label is the name, the contents are the value. Precise: A named object with a type, for example int apples = 3; reading the name gives its current value, and assignment replaces the value. R1, D1
Declaration
Simple words: The line where you first tell the computer a variable's name and type. Analogy: Putting a new empty jar on the shelf and writing its label. Precise: A statement that introduces a name and its type, such as int apples = 3; a name must be declared before it is used (F0-36 shows the error when it is not). R1, D1
Initialise
Simple words: To give a variable its first value at the moment you create it. Analogy: Filling the jar the moment you put it on the shelf. Precise: Giving a variable a value in its declaration (int apples = 3;). With the course flags, g++ refused to build a program that used a variable before giving it a value (R4). R1, R4, D1
Assignment
Simple words: Putting a new value into a variable. The old value is gone. Analogy: Emptying the jar and filling it with something new. Precise: The operator = in a statement such as apples = apples + 2; the right side is worked out first, then its value replaces the variable's old value. It is not the "is equal to" of maths; that is == (F0-32). R1, D1
std::cin
Simple words: The name C++ uses for "read what the person types". Analogy: The cook listening to an order. Precise: The standard input stream from <iostream>; the operator >> reads a value into a variable. In the lab runs the input comes from a .in file instead of a keyboard. R3, D1
const
Simple words: A word that makes a variable unchangeable after its first value. Analogy: A jar with its lid glued shut: you can look, but not change what is inside. Precise: A qualifier on a declaration (const int baked = 12;); the compiler rejects any later assignment to that variable. R3, D1

Layer 1 — the kid explanation

A program often needs to remember things. How many apples are left? What is the player's name? What is the score? It keeps each of these in a variable.

Think of a variable as a jar with a label. The label is the variable's name, like apples. What is inside is its value, like 3. You choose the name once. The value can change many times.

When the program reads a variable, it looks inside the jar. Looking does not change anything. When the program puts a new value in, the old value is gone. The jar holds only one thing at a time.

Each jar also has a shape. A jar for whole numbers holds whole numbers only. You will meet the other shapes, called types, in F0-31.

Now Priya's puzzle makes sense. To swap two jars, you need a spare jar for a moment. Otherwise one value is poured away before you can save it.

Layer 2 — the student explanation

You create a variable with a declaration. The line int apples = 3; says three things: the type is int (a whole number), the name is apples, and the first value is 3. Giving the first value at once is called to initialise the variable. R1, D1

Later you can change the value with an assignment: apples = apples + 2;. The computer works out the right side first. It reads the old value 3, adds 2, and gets 5. Only then does it put 5 into apples. So the same name can appear on both sides. R1, D1

Watch out: in C++ the sign = does not mean "is equal to". It means "put the value on the right into the variable on the left". The question "is equal to?" is written ==, and you will use it in F0-32. D1

Assignment copies values. After int pears = apples;, the variable pears holds its own copy of 5. When apples becomes 0 on the next line, pears still holds 5. The real run shows exactly this. R1

A program can also read a value from the person using it. std::cin >> cookies; waits for a number and puts it into cookies. In our lab runs the "typing" comes from a small file, cookies.in, which contains the number 5. R3, D1

Some values should never change. Writing const in front, as in const int baked = 12;, glues the lid shut. If a later line tries to change baked, the compiler refuses. R3, D1

Layer 3 — the engineer's depth

Note

For the curious. What is in a jar that was never filled? In C++, a plain int declared without a value does not start at 0 by itself; reading it before giving it a value is a mistake. With the course flags, g++ refused to build such a program and named the variable (Listing 4 in "Common mistakes"). Always initialise your variables. R4, D1

Names have rules too. A name is made of letters, digits and the underscore _, and it must not start with a digit. Names are case-sensitive: apples and Apples are two different jars. Good names say what is inside: cookies is better than c. D1

How the hardware actually does it

A computer's memory is a long row of numbered boxes, each holding a small number. You met it as the pantry in F0-05. When your program creates a variable, a few of these boxes are set aside for it. The name is for you and the compiler. The running program finds the variable by its place in memory. The jar picture hides this: real memory has no labels written on it. D2

Where the analogy breaks


    

  • A real jar can hold rice and buttons at the same time if you are careless. A variable holds exactly one value of its type. A new value replaces the old one completely. R1
    • 

  • Copying a jar's contents in a kitchen leaves the first jar emptier. Copying a variable (int pears = apples;) leaves the first variable unchanged: both now hold the same value. R1
    • 

  • A new kitchen jar is empty. A new C++ variable without a first value is not "empty" or zero: its contents are unknown, and the compiler with our flags refuses to let you read it. R4, D1
    • 

  • Real jars can hold anything. A variable has a fixed type, and the compiler checks that you only put suitable values in it (F0-31).
    •
