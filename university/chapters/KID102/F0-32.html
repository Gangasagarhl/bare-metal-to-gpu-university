Story hook

Analogy

Every morning, Noor looks out of the window before getting dressed. If it is freezing, she takes her warm coat, a hat and gloves. Otherwise, if it is cool, she takes a jumper. Otherwise, a T-shirt is fine.

Noor does not take all three. She asks the questions in order and stops at the first "yes". The order matters. If she first asked "Is it colder than a summer day?", the answer would be "yes" on a freezing morning too, and she would go out in a jumper and shiver.

Her little brother has a different rule for snacks: "If it is after school and my homework is done, I may have a snack." Both parts must be true.

Programs make decisions like this all the time. In C++, the words are almost the same as Noor's: if and else.

What you will be able to do

  • Write if, else if and else statements that choose what a program does.
  • Write conditions with the comparison operators < > <= >= == != and join them with &&, || and !.
  • Predict which branch runs for a given input, including the edge values, and check with real runs.
  • Explain why the order of an else if chain matters, and find a branch that can never run.
  • Read the compiler's warning about = inside a condition and fix it.
Jargon box
Condition
Simple words: A question with a yes or no answer that the program checks. Analogy: "Is the water boiling?" in a recipe. Precise: An expression whose value is converted to bool, used by if and by loops to decide what to do next, for example temperature < 5. R1, D4 §8.5.1, §7.3.14
Comparison operator
Simple words: Signs that compare two values: <, >, <=, >=, == and !=. Analogy: Holding two jars side by side to see which one has more. Precise: Operators that compare two values and give a bool. == means "is equal to" and != means "is not equal to"; a single = is assignment, which g++ flagged inside an if with the course flags (R3). R2, R3, D4 §7.6.9, §7.6.10, D2 §3.8
if statement
Simple words: A way to say "only do this when the condition is true". Analogy: "If it is raining, take an umbrella." Precise: A statement that runs its block only when its condition is true; an optional else block runs otherwise, and else if chains test conditions in order until one is true (R1). R1, D4 §8.5.1
Block
Simple words: A group of statements inside curly braces { }. Analogy: A boxed group of steps in a recipe that belong together. Precise: A sequence of statements enclosed in braces; the whole block belongs to the if, else, loop or function written in front of it. R1, D4 §8.4
Logical operator
Simple words: Words that join conditions: and (&&), or (||), not (!). Analogy: "Homework done AND it is after school." Precise: The operators && (true only if both sides are true), || (true if at least one side is true) and ! (turns true into false and false into true) (R2). R2, D4 §7.6.14, §7.6.15, §7.6.2.1

Layer 1 — the kid explanation

Up to now, every program did the same thing every time. Every line ran, from top to bottom. That is fine for a recipe card, but life needs choices.

An if lets a program choose. It asks a question with a yes-or-no answer. If the answer is yes, the steps inside its curly braces run. If the answer is no, those steps are skipped.

An else says what to do when the answer is no. And else if asks the next question. The program asks the questions in order, from top to bottom. It stops at the first yes. Only one of the choices runs.

Questions can be joined, as in the snack rule: "after school AND homework done". Both must be true. Another rule might say "at noon OR at six o'clock". Then one true part is enough.

One small sign causes many bugs. In C++, = means "put into the jar". To ask "is it equal?", you write two signs: ==. Luckily, with our flags, the compiler catches this mix-up inside an if.

Layer 2 — the student explanation

An if statement has a condition in round brackets and a block in curly braces: if (temperature < 5) { ... }. The condition is worked out to true or false, the bool values from F0-31. The block runs only when the condition is true. R1, D4 §8.5.1, §8.4

The comparison operators are < (less than), > (greater than), <= (less than or equal), >= (greater than or equal), == (equal) and != (not equal). Each one compares two values and gives a bool. You can store that bool in a variable, as Listing 2 does with bool after_school = hour >= 15;. R2, D4 §7.6.9, §7.6.10

An else if chain tests its conditions in order. The first true condition wins; its block runs, and all the later tests are skipped. A final else catches every case that no condition matched. With 12 degrees, the first test (12 < 5) was false and the second (12 < 18) was true, so the program printed "Wear a jumper." With exactly 18, both tests were false, and the else ran. R1, R5, D4 §8.5.1

The logical operators join conditions. a && b is true only if both are true. a || b is true if at least one is true. !a turns true into false and false into true. In Listing 2, hour 16 with homework done made after_school && homework_done true. R2, D4 §7.6.14, §7.6.15, §7.6.2.1

If you write if (eggs = 6), you put 6 into eggs instead of comparing. With our flags, g++ refused: "suggest parentheses around assignment used as truth value". Read that as: "did you mean ==?" R3, D2 §3.8

Layer 3 — the engineer's depth

Note

For the curious. With &&, if the left side is already false, the result must be false, so C++ does not even work out the right side. With ||, a true left side makes the right side unnecessary. This is called short-circuit evaluation, and later you will use it to guard a risky check, for example "the list is not empty AND its first item is …". D4 §7.6.14, §7.6.15

A condition does not have to be a comparison: any value that can turn into a bool works. A number counts as false when it is 0 and as true otherwise. That is exactly why if (eggs = 6) is legal C++ (6 counts as true) and why the compiler only warns about it, here turned into an error by -Werror. R3, D4 §7.3.14, D2 §3.8

How the hardware actually does it

The processor follows instructions one after another, as you saw in F0-29. For an if, the compiler produces instructions that compare two values and then maybe "jump" to another place in the program. (In the RISC-V family of processors, for example, one branch instruction does both: it compares two values and jumps only if the test holds.) If the condition is false, the jump makes the processor skip over the instructions of the block and continue further down. So a decision is, underneath, "compare, then maybe skip ahead". D5 §1.1.5.2

Where the analogy breaks


    

  • Noor can answer "sort of cold" or "not sure". A condition is always exactly true or false. D4 §7.3.14, §6.8.1
    • 

  • Noor would notice if two of her questions overlapped badly and fix the order herself. The computer asks in the written order, even if a later branch can never be reached (the forensic lab). R4
    • 

  • When Noor hears "is it 6?", she never changes the number of eggs. In C++, eggs = 6 inside an if really changes the variable; only the compiler's warning stopped it here. R3
