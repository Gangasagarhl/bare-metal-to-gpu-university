Story hook

Analogy

Mrs Haddad's family cookbook has a page called "Tomato sauce". Many other recipes use it. The lasagne recipe says: "Make the tomato sauce (page 12)." So does the pizza recipe, and the soup recipe.

Nobody copies the whole sauce recipe into every page. You turn to page 12, follow it, and come back with a pot of sauce. Then you continue where you left off.

Some small recipes need to know something first. "Add ___ to the pot" works for salt, for pasta, for carrots. You fill in the blank each time. Other small recipes hand you something back: the sauce, or the answer to "how many plates do we need?"

When the sauce recipe is right, every dish that uses it is better. When it is wrong, you only need to fix one page. And you can taste the sauce on its own, before it goes into the lasagne. Programs are built exactly like this, from small named recipes called functions.

What you will be able to do

  • Write functions with parameters and a return value, and call them from main.
  • Explain what happens during a call: the jump into the function, the copy of the arguments, and the return.
  • Predict the output of a program with several functions, in the order the calls happen.
  • Write a test function that checks another function with answers worked out by hand.
  • Explain why changing a parameter inside a function does not change the caller's variable.
Jargon box
Function
Simple words: A named group of steps that you can use again by calling its name. Analogy: A small recipe inside a bigger recipe: "make the sauce (see page 12)". Precise: A named block of code with a return type and parameters, for example int double_it(int number); calling it runs its body and may give back a value. R1, D3 §7.6.1.2, §8.7.3
Function call
Simple words: Using a function by writing its name with round brackets. Analogy: Turning to the sauce page and following it, then coming back. Precise: An expression such as double_it(3) that runs the function body with the given arguments and then continues after the call (R1). R1, D3 §7.6.1.2
Parameter
Simple words: A variable in a function that receives a value from the caller. Analogy: The blank in "add ___ to the pot". Precise: A variable declared in a function's parameter list; it starts as a copy of the argument when the parameter is a plain type such as int, so changing it does not change the caller's variable (R4). R1, R4, D3 §7.6.1.2
Argument
Simple words: The actual value you hand to a function when you call it. Analogy: The word you write in the blank: "add salt to the pot". Precise: An expression in a function call whose value initialises the matching parameter, such as "salt" in add_to_pot("salt"). R1, D3 §7.6.1.2
Return value
Simple words: The answer a function gives back to the code that called it. Analogy: The sauce the helper hands back when the sauce recipe is done. Precise: The value given by a return statement; a function whose return type is not void must return a value (the C++ rules say that running off its end without one is undefined behaviour); g++ warns about it, and with -Werror it refused to build one that did not (R3). R1, R3, D3 §8.7.3, D5 §3.8
void
Simple words: The word for "this function gives nothing back". Analogy: A step like "boil the water" that does not hand you anything. Precise: The return type of a function that returns no value, such as void boil_water(). R1, D3 §8.7.3
Test function
Simple words: A function that checks other functions by comparing their answers with answers you worked out by hand. Analogy: Tasting the sauce before you serve it. Precise: A function that calls the code under test with known inputs, compares the results with expected values, reports PASS or FAIL and counts failures (R2). R2

Layer 1 — the kid explanation

Your programs are growing. Soon main will be long and hard to read. Functions fix that. A function is a small recipe with a name. You write it once, and use it as often as you like.

Using a function is called calling it. You write its name and round brackets, like boil_water();. The program jumps into the small recipe, follows it to the end, and comes back to the next line of the big recipe.

Some functions need information. add_to_pot needs to know what to add. You put it inside the brackets: add_to_pot("salt"). Inside the function, that value has a name, like the blank on the recipe card.

Some functions give an answer back. double_it(3) gives back 6, and you can store it in a jar: int plates = double_it(3);.

Best of all, you can test a small recipe on its own. You work out a few answers by hand, ask the function, and compare. If they match, you can trust it in the big program. If not, you know exactly which page to fix.

Layer 2 — the student explanation

A function definition has four parts: a return type, a name, a parameter list in round brackets, and a body in braces. In int double_it(int number) { return number * 2; }, the return type is int, the name is double_it, there is one parameter number of type int, and the body returns twice the number. R1, D3 §7.6.1.2, §8.7.3

A function call such as double_it(3) gives each parameter its first value from the matching argument: here number starts as 3. The body runs. The return statement ends the function and hands its value back to the caller, so the call itself is worth 6. R1, D3 §7.6.1.2, §8.7.3

A function that hands nothing back has the return type void, like boil_water. A function whose return type is not void must return a value: if it runs off its end without one, the C++ rules do not say what happens. g++ warns about this, and with our flags (-Werror) it refused to build such a function: "no return statement in function returning non-void". R3, D3 §8.7.3, D5 §3.8

A parameter of a plain type such as int is a copy of the argument. Changing the copy inside the function does not change the caller's variable. In the forensic evidence, add_sugar made its own spoons 3, but the caller's spoons stayed 2. To get a result out, return it. R4, R5, D3 §7.6.1.2

A function must be declared before the line that calls it. Listing 1 defines its functions above main for that reason. When a call came first, g++ said "'double_it' was not declared in this scope". R6, D3 §6.5.1

A test function calls the function under test with inputs whose answers you worked out by hand. Listing 2's test function prints PASS or FAIL for each case and counts the failures; main stops with exit code 1 if any test failed. R2, R7

Layer 3 — the engineer's depth

Note

For the curious. Passing std::string thing by value makes a copy of the text for every call. For short texts that does not matter. Later (SP101) you will meet const std::string&, a way to let the function read the caller's string without copying it and without being allowed to change it. D3 §7.6.1.2, §9.4.3, §7.2.1

Each call gets its own fresh set of parameters and local variables. They exist only while that call runs. That is why two calls of add_to_pot do not mix up "salt" and "pasta", and why a function's local variable is gone after it returns. Debuggers show this as a list of active calls, the call stack (you will see one call inside another in F0-37). D3 §7.6.1.2, §6.7.5.3, D6 §8.2

Good functions do one job, have a name that says what that job is, and can be tested alone. Tests are written with values you can check by hand, including edge cases such as 0 guests. R2

How the hardware actually does it

A call is a special jump. Before jumping into the function, the processor remembers where to come back to: the address of the next instruction. The return is a jump back to that remembered address. Arguments and the return value are passed in places fixed by an agreement called the calling convention; you will meet it in later courses. (One example: in the RISC-V processor family, the jump-and-link instruction saves the address of the next instruction in a register. By agreement, that register is x1.) Because the return address is remembered, one function can call another, which calls another, and every one finds its way home. D4 §1.1.5.1

Worked example

We predict Listing 2 line by line. The function cups_needed(guests) returns guests * 2 + 1: two cups per guest, plus one spare.

  1. By hand first: 0 guests need 0 × 2 + 1 = 1 cup. 1 guest needs 1 × 2 + 1 = 3. 4 guests need 4 × 2 + 1 = 9. These are the expected values in the test function.
  2. main calls test_cups_needed(). It calls check(0, 1), which calls cups_needed(0) and gets 1. 1 equals 1, so it prints "PASS: cups_needed(0) = 1, expected 1" and returns 0.
  3. The same happens for 1 guest (3) and 4 guests (9). failures stays 0 + 0 + 0 = 0.
  4. Back in main: 0 > 0 is false, so it prints "All tests passed." and then the party line: 6 × 2 + 1 = 13 cups.

Prediction: three PASS lines, "All tests passed.", and "For a party of 6 we need 13 cups." The real run printed exactly that, with exit code 0. R2

Now break it on purpose: forget the spare cup (return guests * 2;). Prediction: 0 guests gives 0 (expected 1), 1 gives 2 (expected 3), 4 gives 8 (expected 9). Every check should fail, "Some tests failed." should appear, and the exit code should be 1. The real run in the Lab section agrees. R7

Where the analogy breaks


    

  • When you write "salt" into the blank of a paper recipe, the card is changed. A function call does not change the function: each call gets a fresh copy of its parameters (R1 used add_to_pot twice with different values). R1, D3 §7.6.1.2
    • 

  • In a kitchen, the helper who makes the sauce can add salt to your soup on the side. A C++ function with plain parameters gets copies; it cannot change your variables, as the forensic lab shows. The only way out for a result is the return value (or techniques you will learn in SP101). R4, R5
    • 

  • A cook can look ahead in the book for a page that comes later. The compiler reads the file from top to bottom and refused a call to a function it had not seen yet. R6

Forensic lab answer key


    

  • Observation: "Inside add_sugar: spoons = 3", but "After: spoons = 2". The change of 1 spoon is lost when the function returns. R4
    • 

  • Hypotheses: "the function is never called" is ruled out by the "Inside" line, which only the function prints. The remaining hypothesis: the function changes a copy.
    • 

  • Root cause: add_sugar(int spoons) takes its parameter by value. On the call, the parameter spoons starts as a copy of main's spoons (2); line 5 changes the copy to 3; when the function ends, the copy disappears. main's jar was never touched.
    • 

  • Fix: return the new value and assign it: int add_sugar(int spoons) { spoons = spoons + 1; ...; return spoons; } and spoons = add_sugar(spoons);. The fixed program sugar_fixed.cpp printed "After:  spoons = 3" in this build. R5
    • 

  • Why no warning: changing a parameter is legal, and the parameter is used (it is printed), so nothing looked suspicious to the compiler.
