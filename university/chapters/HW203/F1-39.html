Story hook

Analogy

The pantry down the corridor is not one big room. It has several aisles, each with a clerk. A clerk can have one shelf pulled out onto the counter at a time. If the next order is from that shelf, the clerk hands it over at once. If it is from another shelf in the same aisle, the clerk must push the first shelf back and pull the other one out — three times as slow. Two corridors with two trolleys lead to the pantry, so two orders can travel at once.

The restaurant grows and opens a second kitchen across the hall, with its own pantry. A cook in kitchen A can still use pantry B, but every trip crosses the hallway. Where you store each ingredient now depends on who will cook with it.

Jargon box
DRAM
Simple words: the main memory chips: dense and cheap, but slow and needing constant refreshing. Analogy: the pantry. Precise: dynamic random-access memory: each bit is stored as charge on a capacitor accessed through one transistor; reads are destructive and the charge leaks, so rows must be rewritten after reading and refreshed periodically. D1 D3
DRAM bank
Simple words: an independent part of a DRAM chip that can work on one request while another bank works on another. Analogy: a pantry aisle with its own clerk. Precise: a two-dimensional array of cells with its own row decoder and sense amplifiers; operations to different banks can overlap. D3 D1
Row buffer
Simple words: the one row of a bank that is currently "open" and can be read quickly. Analogy: the shelf pulled out onto the counter. Precise: the sense amplifiers of a bank, which hold the most recently activated row; column reads from the open row (row hits) avoid the activate step, while a different row requires precharge and activate (a row miss or conflict). D3 D1
Memory channel
Simple words: an independent path between the processor and a group of memory modules. Analogy: a corridor with its own trolley. Precise: a data and command bus with its own controller logic and modules; channels operate in parallel, and consecutive blocks are commonly interleaved across them to add their bandwidth. D3
Memory controller
Simple words: the part of the processor that talks to DRAM. Analogy: the dispatcher who decides which order goes down which corridor and in which sequence. Precise: logic that maps physical addresses to channel, rank, bank, row and column, queues requests, schedules DRAM commands (often favouring row hits) and issues refreshes. D3
NUMA
Simple words: some memory is "nearer" to some cores and faster for them. Analogy: two kitchens, each with its own pantry. Precise: non-uniform memory access: a shared-memory system in which memory is attached to several nodes (for example sockets), and a core's access to its own node's memory has lower latency and higher bandwidth than access to another node's memory over the interconnect. D3 D8
First-touch policy
Simple words: a new page is placed in the memory of the node whose core touches it first. Analogy: an ingredient is stored in the pantry of the kitchen that first asks for it. Precise: Linux's default NUMA placement: physical memory for a page is allocated, at its first page fault (F1-38), on the node of the CPU that faulted, unless a memory policy says otherwise. D8

Layer 1 — the kid explanation

Main memory is made of DRAM chips. Each bit is a tiny bucket of electric charge that slowly leaks, so the chips must top up every bucket again and again.D1

Inside the chips, memory is cut into banks, and each bank is a grid of rows. To read, the chip first copies a whole row into a fast holding area, the row buffer. Reading more from the same row is quick; switching to another row is slow.D3

Big computers have several channels to memory, like several roads, and some have several groups of processors, each with its own memory nearby. Memory near your processor is faster for you: that is NUMA.D3

Layer 2 — the student explanation

Cells, rows and the row buffer

A DRAM bank is an array of one-transistor, one-capacitor cells. An activate command copies an entire row into the sense amplifiers (the row buffer); read commands then transfer columns from the buffer; a precharge closes the row before another row can be activated.D3 D1 Access time therefore depends on the state of the bank: a row hit needs only the column read; a row miss needs precharge, activate and read. Listing 1 charges 1 unit for a hit and 3 for a miss — exercise costs, not real timings.

Banks, ranks and channels

Several banks can have different rows open and work in overlapping time; several chips work in parallel to deliver one block; a module may carry several ranks (sets of chips sharing the channel); and the processor may have several channels.D3 The memory controller chooses which address bits select the channel, bank, row and column. Putting a low bit on the channel (bit 6 in Listing 1) spreads consecutive blocks over both channels; putting the row on high bits keeps a sequential stream in one open row for a long time.D3 R1

Bandwidth needs parallelism

By Little's law (F1-32), bandwidth = bytes in flight ÷ latency. One core can keep only a limited number of misses outstanding, so one thread may not reach the bandwidth that the channels can deliver; more threads add more misses in flight.D3 On the build container, read bandwidth grew from 7.53 GB/s with one thread to 23.17 GB/s with four (measured, one session).R2

NUMA

In a multi-socket server each socket has its own memory controllers and DRAM. All memory is addressable from every core, but remote accesses travel over the inter-socket link, with higher latency and shared link bandwidth.D3 Linux reports nodes under /sys/devices/system/node/, and by default places a page on the node of the CPU that first touches it.D8 A program that initialises a large array in one thread and then processes it with threads on all nodes has put every page on one node — a classic NUMA mistake. The build container reported one node with CPUs 0–3.R3

Layer 3 — the engineer's depth

Scheduling. Controllers keep queues of requests and commonly reorder them to serve row hits first, within fairness limits; writes are buffered and drained in batches because switching the bus between reading and writing costs time.D3 Refresh. Every row must be refreshed within a fixed retention period; a bank being refreshed cannot serve requests, which adds occasional delays.D3 D1 Address hashing. Real controllers often derive bank and channel bits by combining (for example XOR-ing) several address bits, so that power-of-two strides do not all hit one bank.

Not verified — check before relying on this

The claim that real controllers XOR address bits to choose bank and channel, the number of channels, ranks and banks behind the build container, and its DRAM type are not verified; a virtual machine does not show them, and no vendor documentation was opened. Check the processor vendor's datasheet for the memory controller of a named processor, or tools that read the module information on a physical machine you control.

Untested on hardware — NUMA

The build container reported a single NUMA node, so no remote-versus-local measurement was possible. The tools usually used for this on Linux — the numactl command (to show nodes and bind a process's CPUs and memory) and the libnuma library — are named here from memory, were not run, and their options must be checked in their manual pages on a multi-node machine. The lab's NUMA step is written for such a machine and has not been tried.

Bandwidth scaling on the build container. One thread reached 7.53 GB/s; with the latency measured in F1-32 (263.6 ns for a random load over 256 MiB, same container), Little's law gives 7.53 GB/s × 263.6 ns ≈ 1985 bytes ≈ 31 blocks of 64 bytes in flight — an estimate that assumes the sequential stream sees the same latency as random loads, which hardware prefetching (F1-32) makes uncertain.R2 The near-linear growth to four threads says the limit for one thread was the core's parallelism, not the memory system; where the memory system's own limit lies on this machine was not reached with four virtual CPUs.

How the hardware actually does it

A cache miss that leaves the last-level cache becomes a request in the memory controller's queue, tagged with its physical address. The controller decodes channel, rank, bank, row and column; if the bank has the right row open it issues a column read; otherwise it precharges the bank and activates the row first, observing minimum delays between commands. The chips return the block in a burst over the channel's data bus, and the controller returns it to the cache hierarchy.D3 D1 In a multi-socket system, a request for memory on another node goes to that node's controller over the link, and coherence (F1-36) must also be maintained across the nodes, often with directories.D3

Worked example

Map the first six blocks (addresses 0x000, 0x040, ..., 0x140) with Listing 1's bit layout and predict hits and misses; all banks start with no open row.

  1. 0x000: bit 6 = 0 → channel 0; bits 15..14 = 0 → bank 0; row 0; column 0. No row open: miss (3).
  2. 0x040: bit 6 = 1 → channel 1, bank 0, row 0, column 0. Channel 1's bank 0 has nothing open: miss (3).
  3. 0x080: channel 0, column 1 (bits 13..7 = 1), row 0: row 0 is open in channel 0 bank 0 → hit (1).
  4. 0x0c0, 0x100, 0x140: hits (1 each).
  5. Total: 2 misses, 4 hits, time 2 × 3 + 4 × 1 = 10; 3 accesses per channel.
  6. Now a stride of 64 KiB (0x10000): bit 16 changes each time, bits 6–15 stay 0, so every access goes to channel 0, bank 0, and a new row: 256 accesses, 256 misses, time 768, channel 1 idle.

Where the analogy breaks


    

  1. Shelves are not pulled out for one jar. In the pantry the clerk could fetch one item from a closed shelf. In DRAM every access needs the whole row in the row buffer; there is no way to read a column from a closed row.D3
    2. 

  2. The pantry forgets. A pantry keeps its goods; DRAM cells leak and must be refreshed, even when no one uses them.D1
    3. 

  3. Programs do not choose aisles. A cook can ask for "aisle 2". A program sees only virtual addresses; physical placement (F1-38) and the controller's mapping decide bank and channel, so the effects are indirect.D1

Forensic lab


Scenario: "Power-of-two slowdown". A signal-processing team stores 256 channels of samples as a matrix with rows of exactly 64 KiB (8192 doubles), and the main loop reads sample k of every channel in turn — a 64 KiB stride. On their server it runs far slower than a loop over the same number of samples in a row. The caches are full of conflict misses (F1-33), but a reviewer asks whether DRAM makes it worse as well. Real controller mappings are not known for their server, so the team uses the course model.

Summary


    

  • DRAM stores bits as leaking charge; it needs refresh and destructive-read row activation.
    • 

  • Banks hold one open row each; row hits are cheaper than row misses.
    • 

  • Channels, ranks and banks give parallelism; the controller's address mapping decides how a pattern uses them.
    • 

  • Power-of-two strides can concentrate accesses on one bank and channel (in the model: 256 misses, one channel idle).
    • 

  • Bandwidth needs misses in flight: on the build container 1 → 4 threads raised read bandwidth from 7.53 to 23.17 GB/s.
    • 

  • NUMA: memory is local to a node; Linux places pages by first touch. Not testable on the one-node build container.

Forensic lab answer key


Observation (model, R1): sequential: 254 hits, 2 misses, 128/128 per channel, time 260; scattered: 0 hits, 256 misses, 128/128, time 768; stride 64 KiB: 0 hits, 256 misses, 256/0, time 768. Bits: 0x10000 = bit 16, so along the stride only bits 16 and up change: channel bit 6 and bank bits 15..14 stay 0 (every access to channel 0, bank 0), and the row changes on every access — the worst case: no row hits and no channel or bank parallelism. In time units it ties with scattered, but scattered spreads its misses over both channels and all banks, which a real controller can overlap; the model's time does not include that overlap, which understates the difference. Hypotheses: (H1) cache conflict misses alone (F1-33: 64 KiB stride maps to one set) — supported in the caches by F1-34's measured 32 KiB-stride slowdown (217.2 vs 24.8 ms), but that measurement does not separate cache from DRAM effects; (H2) DRAM bank/channel concentration — supported by the model only. Fix: pad each row to 64 KiB + 64 bytes (a non-power-of-two leading dimension), or transpose so the inner loop is sequential. Predicted model result for +64: accesses alternate channels (128/128) and the bank bits change over the run — see Check yourself 5. Limits: the model's mapping is an exercise geometry; real controllers may hash bits and break this pattern (unverified box), and the server's caches would absorb part of the traffic; only measurements on the server with hardware counters can apportion the time.
