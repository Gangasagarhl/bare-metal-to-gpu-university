Story hook

Analogy

The shelf by Amina's stove is divided into sections numbered 0 to 63. The pantry never sends a single jar: it sends a whole tray of neighbouring jars. To find a tray quickly, the kitchen has a rule. Every tray has a long pantry number; its middle digits say which shelf section it must go to, and nowhere else. Each section has room for a fixed number of trays, say twelve.

When Amina wants a jar, Kofi looks only in one section, reads the labels of the trays there, and either finds it (quick) or sends for it (slow). If a thirteenth tray arrives for a section that is already full, one tray has to go back, usually the one nobody touched for the longest time. That is all a cache is: trays, numbered sections, a few slots per section, and a rule for who leaves.

What you will be able to do

  • Split an address into tag, set index and block offset for a given cache geometry, by hand and with a program.
  • Explain direct-mapped, set-associative and fully associative caches and their trade-offs.
  • Trace a sequence of accesses through a small cache with LRU replacement, by hand, and check it with the course's cache simulator.
  • Read the cache geometry your operating system reports and compute sets from size, ways and line size.
  • Diagnose conflict misses from a timing measurement and a simulator run.
Jargon box
Cache line
Simple words: the fixed-size chunk of memory a cache always moves and stores as one piece. Analogy: a whole tray of neighbouring jars. Precise: the unit of storage and transfer of a cache (also called a cache block): an aligned group of 2b consecutive bytes of memory; the build container reports 64-byte lines (Listing 4). D1 ch. 6 D2 ch. 5 D11 §11.4.1
Cache hit and miss
Simple words: a hit means the data was already in the cache; a miss means it had to be fetched. Analogy: the tray is on the shelf, or someone must walk to the pantry. Precise: an access is a hit if the cache holds a valid line whose tag matches the address; otherwise it is a miss and the line is fetched from the next level; hit rate = hits ÷ accesses. D1 ch. 6 D2 ch. 5 D11 §11.4
Tag, index and offset
Simple words: three parts of an address: which byte in the line, which set, and a label to tell lines apart. Analogy: the jar's place on the tray, the shelf section, and the label written on the tray. Precise: for a cache with 2s sets and 2b-byte lines, the low b bits of an address are the block offset, the next s bits the set index, and the remaining high bits the tag stored with the line. D1 ch. 6 D2 ch. 5 D11 §11.4.1
Set
Simple words: the group of places where one particular line is allowed to live. Analogy: one numbered shelf section. Precise: a group of E line slots selected by the set index; a line can be stored only in the set its address selects. D1 ch. 6 D11 §11.4.2
Way
Simple words: one slot inside a set. Analogy: one tray slot in a section. Precise: one of the E line slots of every set; a cache with E slots per set is E-way set-associative, and its associativity is E. D1 ch. 6 D2 ch. 5 D11 §11.4.3
Direct-mapped cache
Simple words: every line has exactly one place it may go. Analogy: sections with room for one tray each. Precise: a cache with one line per set (E = 1). D1 ch. 6 D11 §11.4.1
Set-associative cache
Simple words: every line has a few places it may go, all in one set. Analogy: sections with room for several trays. Precise: a cache with S sets of E > 1 lines; lookup compares the tag with all E lines of the selected set in parallel. D1 ch. 6 D2 ch. 5 D11 §11.4.3
Fully associative cache
Simple words: any line may go anywhere. Analogy: one big section where any tray fits in any slot. Precise: a cache with a single set (S = 1); there are no index bits and every lookup compares the tag with every line. D1 ch. 6 D11 §11.4.2
LRU replacement
Simple words: when a set is full, throw out the line used longest ago. Analogy: the tray nobody touched for the longest time goes back to the pantry. Precise: least-recently-used replacement: on a miss to a full set, the victim is the line whose last access is oldest; hardware often approximates it (pseudo-LRU). D1 ch. 6 D3 ch. 2, App. B D11 §11.4.3
Conflict miss
Simple words: a miss that happens only because too many lines want the same set, even though the cache has room elsewhere. Analogy: section 0 overflows while sections 1–63 stand half empty. Precise: a miss that would not occur in a fully associative cache of the same size; one of the "three Cs" with compulsory and capacity misses (F1-34). D1 ch. 6 D3 ch. 2, App. B D11 §11.4.2

Layer 1 — the kid explanation

A cache is a small, fast shelf that keeps copies of things from the big, slow pantry. It never fetches one byte alone: it fetches a whole line of neighbouring bytes, like a tray of jars.D1 ch. 6 D11 §11.4.1

To find a line fast, the cache does not search everywhere. Part of the address says which shelf section (the set) to look in. Inside that section there are a few slots (the ways). Each slot has a label (the tag) so the cache can tell which line is in it.D1 ch. 6 D11 §11.4.1

If the label matches, it is a hit and the data comes back quickly. If not, it is a miss: the line is fetched, and if the section is full, the line used longest ago goes back.D1 ch. 6 D2 ch. 5 D11 §11.4.3

Layer 2 — the student explanation

Geometry: S, E, B

A cache is described by three numbers: S sets, E lines per set (ways) and B bytes per line. Its data capacity is C = S × E × B.D1 ch. 6 Each line also stores a tag and a valid bit (and, for writes, a dirty bit, F1-35), which are overhead not counted in C.D1 ch. 6 D2 ch. 5 The kernel of the build container reports, for the L1 data cache of CPU 0, a size of 48K, 12 ways and 64-byte lines, and 64 sets; the arithmetic agrees: 64 × 12 × 64 = 49,152 bytes = 48 KiB (Listing 4).R4

Splitting the address

With B = 2b and S = 2s, the low b bits of an address are the block offset, the next s bits the set index, and all higher bits the tag.D1 ch. 6 D11 §11.4.1 In code: offset = a & (B - 1), index = (a >> b) & (S - 1), tag = a >> (b + s). These are the mask-and-shift operations of MA102. The middle bits are used as the index (not the high bits) so that neighbouring lines go to different sets; a program walking through an array then spreads its lines over the whole cache.D1 ch. 6 D11 §11.4.1

Lookup, hit and miss

To read address a: select set index(a); compare tag(a) with the tag of every valid line in that set; on a match, return the bytes at offset(a) in that line (a hit). Otherwise fetch the whole line containing a from the next level, place it in the set, and then return the bytes (a miss).D1 ch. 6 D2 ch. 5 If the set has an invalid (empty) line, the new line goes there; otherwise a replacement policy picks a victim. Under LRU the victim is the line whose last use is oldest.D1 ch. 6 D11 §11.4.3

Three organisations

With E = 1 the cache is direct-mapped: each line has one possible place, lookup needs one comparator, and two lines with the same index evict each other even when the rest of the cache is empty. With S = 1 it is fully associative: any line can go anywhere, but every lookup compares against every line. Between them, an E-way set-associative cache needs E comparators per lookup and tolerates up to E lines with the same index.D1 ch. 6 D2 ch. 5 D11 §11.4.2 Higher associativity removes conflict misses but costs comparators, energy and possibly hit time.D3 ch. 2, App. B The worked example traces one access sequence through all three on a 64-byte cache.

Average memory access time

A common first model of a cache's effect is average memory access time = hit time + miss rate × miss penalty.D2 ch. 5 D3 ch. 2, App. B With exercise numbers 1 ns hit time, 5 % misses and 60 ns penalty: 1 + 0.05 × 60 = 4 ns. Halving the miss rate to 2.5 % gives 2.5 ns, a bigger gain than any small change to the hit time. This is why the order of accesses, which decides the miss rate (F1-34), matters so much.

Layer 3 — the engineer's depth

Replacement in real hardware. True LRU for many ways needs ordering state per set that grows quickly with E, so hardware commonly uses approximations (tree pseudo-LRU, not-recently-used bits) or other policies.D3 ch. 2, App. B The course's simulator uses exact LRU; real caches can therefore differ from it in exactly the corner cases the forensic lab probes.

Not verified — check before relying on this

The replacement policy of each cache level of the build container's processor, and whether its caches are inclusive or exclusive of each other, were not checked; vendors do not always document them. Check the vendor's optimisation reference manual for the exact model (model string in the logs), and treat measurements such as Listing 5 as evidence, not as a description of the policy. To test it you need a physical machine with a documented processor model; a virtual machine (the build container and the verifier's container) does not expose it.

Index from virtual or physical address. The address a program uses is virtual; the memory system works with physical addresses (F1-38). A first-level cache can start its set lookup with index bits from the virtual address while translation runs in parallel, and compare physical tags afterwards ("virtually indexed, physically tagged"). This works without aliasing problems when index and offset bits lie inside the page offset, that is, when S × B ≤ page size.D3 ch. 2, App. B The geometry the build container reports satisfies it exactly: 64 sets × 64 B = 4096 B, the 4 KiB page size (F1-38); the extra capacity comes from the 12 ways. Whether this processor actually uses this scheme was not verified; the arithmetic is only consistent with it.

Sectors, banks, ports. Real caches add structure the model leaves out: multiple ports or banks so that several accesses proceed per cycle, way prediction to save energy, and miss handling registers for outstanding misses (F1-32).D3 ch. 2, App. B None of this changes the tag–index–offset rule, which is why a simple simulator predicts hits and misses well for many programs.

How the hardware actually does it

A cache is built from SRAM arrays: one array for tags and status bits, one for data. The set index drives the row decoder of both arrays (a decoder, F1-12), so one row of every way is read at once; per way, a comparator checks the stored tag against the address tag and an AND gate combines it with the valid bit; the per-way hit signals are ORed into the hit output and steer a multiplexer that selects the data of the matching way.D2 ch. 5 D5 ch. 8 On a miss, a controller (a finite-state machine, F1-19) requests the line from the next level, writes it into the chosen way and updates the replacement state.D2 ch. 5 Figure 2 is this circuit at block level.

Worked example

Trace twelve byte addresses (hex) through three caches of the same total size, 64 bytes, all with 16-byte lines (4 offset bits): 00 04 40 00 44 10 80 00 40 14 84 04.

Direct-mapped, 4 sets (2 index bits, bits 5–4; tag = address ÷ 64):

  1. 00: set 0, tag 0 → miss (empty). 04: same line (offset 4) → hit.
  2. 40: 0x40 = 64 → set (64 ÷ 16) mod 4 = 0, tag 1 → miss, evicts tag 0.
  3. 00 → miss, evicts tag 1. 44: set 0, tag 1 → miss, evicts 0. 10: set 1, tag 0 → miss.
  4. 80: 0x80 = 128 → set 0, tag 2 → miss. 00, 40 → misses again. 14: set 1, tag 0 → hit. 84, 04 → misses.
  5. Total: 2 hits, 10 misses. Sets 2 and 3 were never used: three hot lines (00, 40, 80) all have index 0.

2-way, 2 sets (index = bit 4; tag = address ÷ 32): 00 miss; 04 hit; 40 (set 0, tag 2) miss into the free way; 00 hit; 44 hit; 10 miss (set 1); 80 (set 0, tag 4) miss, evicts the least recently used of tags 0 and 2, which is tag 0; then 00 misses (evicts 2), 40 misses (evicts 4), 14 hits, 84 misses (evicts 0), 04 misses (evicts 2). Total: 4 hits, 8 misses.

Fully associative, 4 ways: the four distinct lines 00, 40, 10, 80 all fit; after their four compulsory misses every access hits. Total: 8 hits, 4 misses.

Where the analogy breaks


    

  1. Nobody reads the labels one by one. Kofi checks the trays of a section one after another; the hardware compares all ways of a set at the same time, with one comparator per way (Figure 2).D2 ch. 5
    2. 

  2. A tray is never half on the shelf. In the kitchen you could take one jar off a tray. A cache line is present or absent as a whole, together with its tag and valid bit.D1 ch. 6
    3. 

  3. The section number is not chosen for convenience. A kitchen could put popular trays in empty sections. A cache has no choice: the index bits decide the set, which is why several hot addresses with the same index can fight over one set while others stand empty (the forensic lab).D1 ch. 6
    4.

Transition box

Where you came from: F1-32 measured that some loads are fast and some slow, and F1-12 built decoders and multiplexers. What carries over: latency per level, the hierarchy picture, the decoder and multiplexer as circuits, masks and shifts from MA102.D2 ch. 5 What changes: "fast or slow" is now decided by a precise rule: an address maps to exactly one set, and the set's ways and replacement policy decide whether it stays; two addresses can hurt each other merely by having the same index.D1 ch. 6 What comes next: F1-34 turns this rule into programming advice: locality, strides and loop order, measured on your own machine.

Summary


    

  • A cache moves and stores whole lines (64 bytes on the build container).
    • 

  • An address splits into tag, set index and block offset; capacity = S × E × B.
    • 

  • Direct-mapped (E = 1), set-associative (E ways), fully associative (S = 1).
    • 

  • Lookup compares the tag with every way of one set, in parallel; a valid match is a hit.
    • 

  • On a miss to a full set, a replacement policy (LRU in our model) picks a victim.
    • 

  • Addresses S × B bytes apart share a set; more of them than ways causes conflict misses.
    • 

  • Average memory access time = hit time + miss rate × miss penalty.

Forensic lab answer key


Observation: with 4096-byte spacing, time per load rises from about 1.6 ns (k ≤ 10) to roughly 3–4.6 ns from k = 12 on; with 4160-byte spacing it stays near 1.5 ns for every k (R3). Mapping: 4096 = 64 sets × 64 bytes, so records 4096 bytes apart all have set index 0 (Listing 1 shows 0x0, 0x1000, 0x2000 in set 0); 4160 = 4096 + 64 moves each record one set further, so k records use k different sets. Hypotheses: (H1) TLB pressure — ruled out as the main cause: both layouts touch exactly k pages; (H2) one set overflows its 12 ways — supported: the slowdown starts when k reaches the number of ways, and the simulator with exact LRU shows every access missing when 16 lines cycle through a 12-way set. Why k = 12 already: the model assumes exact LRU and that nothing else uses set 0; the real cache may use an approximation of LRU, and other data of the program (the stack, loop variables) or the hardware may also occupy set 0, leaving fewer than 12 ways for the records (not verified; see the unverified box in Layer 3). The loads that miss L1 are still served by L2, which is why the slowdown is a few nanoseconds, not hundreds. Fix: keep the 4160-byte spacing (one line of padding per record) or store the hot fields of all records together. Prevention: a benchmark test with k = 16 records in the continuous-integration suite, failing if the time per access rises above the padded layout's by more than a set margin. How the evidence was made: conflict.cc run once by run.sh (R3); sameset.in generated by run.sh and simulated with Listing 3 (R2).
