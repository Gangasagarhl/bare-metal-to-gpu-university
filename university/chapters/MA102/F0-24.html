Story hook

Analogy

Jonas has an old bicycle counter on his handlebars. It counts the turns of the wheel and shows three digits. One day it shows 000. Jonas pushes the bike backwards by one turn. The counter does not show "minus one". It shows 999.

Jonas thinks about it. "If I go backwards one turn from 000 and get 999, then 999 is a lot like minus one. And 998 is like minus two!" His sister Aisha adds: "So we could agree that the top half of the numbers mean negative ones."

That agreement is exactly how computers store negative numbers. A row of eight switches can show 256 patterns. We agree that the top half of the patterns stand for the negative numbers. The rule has a funny name: two's complement.

What you will be able to do

  • Explain the difference between an unsigned and a signed reading of the same eight bits.
  • Read an 8-bit two's complement number by giving the leftmost switch the value −128.
  • Find the pattern for a negative number with the rule "flip all bits, then add one".
  • State the range of an 8-bit signed number (−128 to 127) and of an unsigned one (0 to 255).
  • Diagnose the forensic case "Why is my number negative?": a byte printed through a signed type.
Jargon box
Unsigned
Simple words: a number that can never be below zero. Analogy: the bicycle counter read plainly: 000 to 999. Precise: an integer type whose bit pattern is read with all place values positive; with 8 bits it holds 0 to 255. In C++, std::uint8_t is an unsigned 8-bit type. R1 D2 §17.4.1
Signed
Simple words: a number that can be negative or positive. Analogy: the counter read with Jonas's agreement: 999 means −1. Precise: an integer type that can represent negative values; in C++, std::int8_t is a signed 8-bit type holding −128 to 127. R1 D2 §6.8.1
Two's complement
Simple words: the usual rule for writing negative numbers in binary. Analogy: going backwards from 000 on the counter. Precise: an n-bit representation where the most significant bit has place value −2n−1 and all others are positive; −x is written as the pattern of 2n − x, found by inverting all bits of x and adding 1. W1 D3 §2.1 D2 §6.8.1
Sign bit
Simple words: the leftmost bit, which tells you if a signed number is negative. Analogy: the leftmost switch, now worth −128 instead of +128. Precise: in two's complement, the most significant bit; it is 1 exactly when the value is negative. W1
Wrap-around
Simple words: going past the end of the numbers and coming back at the other end. Analogy: the counter going from 999 to 000, or from 000 back to 999. Precise: arithmetic modulo 2n: a result that does not fit in n bits keeps only its low n bits. It is one form of overflow (F0-20). W1 R1

Layer 1 — the kid explanation

Eight switches make 256 patterns. So far we used them for 0 to 255. But what about negative numbers, like a temperature of −5 degrees on a winter night?

We have no extra switch for a minus sign. So we make an agreement, like Jonas and Aisha. Patterns that start with 0 are the ordinary numbers 0 to 127. Patterns that start with 1 are the negative numbers −128 to −1.

Here is the neat part. The leftmost switch is worth −128 instead of +128. Everything else stays the same. To read a pattern, add the place values as usual, but count the leftmost one as −128.

The same eight switches can therefore mean two different numbers. If the program says "unsigned", 11111011 means 251. If the program says "signed", it means −5. The switches never change. Only the way we read them changes.

Layer 2 — the student explanation

An unsigned 8-bit number gives every switch a positive place value: 128, 64, …, 1. Its range is 0 to 255. A signed 8-bit number in two's complement gives the leftmost switch −128 instead. Its range is −128 to 127. Both use all 256 patterns; they only split them differently. W1 R1

The leftmost bit is called the sign bit. If it is 1, the signed value is negative, because −128 is bigger in size than all the other place values together (64 + 32 + 16 + 8 + 4 + 2 + 1 = 127). W1

Flip and add one. To write −x, take the pattern of x, flip every bit (0 ↔ 1), then add 1. For 5: 00000101 → 11111010 → 11111011. Why does it work? Flipping every bit of x gives 255 − x, because x plus its flip is 11111111. Adding 1 gives 256 − x. In 8 bits, 256 is the same as 0 (it needs a ninth switch, which is lost). So the pattern behaves like −x. W1 R1

The quick rule for reading a signed byte: if the sign bit is 1, read it as unsigned and subtract 256. 11111011 is 251 unsigned, so it is 251 − 256 = −5 signed. 200 unsigned (11001000) is 200 − 256 = −56 signed. W1 R1

Wrap-around follows from the wheel in Figure 2. Adding 1 to 127 (01111111) gives 10000000. Read as signed, that is −128. Our run shows exactly this: "127 + 1 stored in a signed byte reads as -128". R1

Layer 3 — the engineer's depth

Note

For the curious. Two's complement suits hardware because addition does not need to know whether the numbers are signed: the same adder circuit adds 251 + 6 = 257 → 1 (unsigned, wrapped) and −5 + 6 = 1 (signed), with the same bits. D3 §2.1 W1 Comparison and widening (copying a byte into a bigger type) are different: 251 is bigger than 6 but −5 is smaller, so they must know which reading is meant. When a signed byte is widened, its sign bit is copied into all the new high bits ("sign extension"), which is why −56 stays −56 in an int. The RISC-V manual, for example, describes a load that sign-extends the value it reads. D1 §1.1.6 D2 §7.3.8 HW102 builds the adder.

Note

What C++ says. The C++20 working draft gives an N-bit signed integer type the range −2N−1 to 2N−1 − 1 and notes that this is also known as two's complement representation D2 §6.8.1. When a whole number is converted to an integer type that cannot hold it, the result is the one value of that type that is congruent to it modulo 2N: that is the wrap-around of this chapter D2 §7.3.8. The behaviour is also shown by our run: with g++ -std=c++20 and UndefinedBehaviorSanitizer enabled, Listing 1 converted 200 to −56 and 128 to −128, and the sanitizer printed no message (run R1). Whether plain char is signed or unsigned is implementation-defined: each compiler chooses D2 §6.8.1. Check the compiler's documentation for your target before relying on it, and prefer std::uint8_t or std::int8_t, which say what they are.

How the hardware actually does it

The memory holding a byte stores only its eight bits. It does not store "signed" or "unsigned". The program's types decide what the compiled code does with those bits when it compares or widens them, and so which reading you get. Processors offer instructions for the signed reading. The RISC-V manual, for example, describes a load that sign-extends the value it reads. It also describes an arithmetic right shift that copies the original sign bit into the vacated bits. D1 §1.1.6, §1.1.4.1 That is why the same byte can print as 200 in one program and −56 in another. R1

Worked example

Write −5 in 8-bit two's complement

  1. 5 = 00000101.
  2. Flip every bit: 11111010.
  3. Add one: 11111010 + 1 = 11111011.
  4. Check with place values: −128 + 64 + 32 + 16 + 8 + 2 + 1 = −5. Unsigned: 251, and 251 − 256 = −5.

Read 11001000 as signed

Unsigned it is 128 + 64 + 8 = 200 (F0-21). The sign bit is 1, so signed it is 200 − 256 = −56. With place values: −128 + 64 + 8 = −56.

Check that 5 + (−5) = 0

00000101 + 11111011 = 1 00000000. The ninth bit does not fit in the byte and is lost, leaving 00000000 = 0. Wrap-around makes the sum come out right.

Where the analogy breaks


    

  • The bicycle counter is decimal; a byte is binary. On the counter, "flip each digit" would mean 9 minus each digit. In binary, flipping means 0 ↔ 1. The idea (counting backwards from zero wraps to the top) is the same; the details are not. W1
    • 

  • The counter has one reading; a byte has two. Jonas's counter always shows 999. A byte does not "show" anything: the program's type chooses whether 11111111 is 255 or −1 (F0-20 said the switches do not know their meaning). R1
    • 

  • Negative numbers are not symmetrical. On a number line (F0-14), −128 and +128 are mirror images. In a signed byte, −128 exists but +128 does not: the range is −128 to 127. W1
    •

Summary


    

  • Unsigned byte: 0 to 255. Signed byte (two's complement): −128 to 127.
    • 

  • In two's complement the leftmost bit (the sign bit) is worth −128.
    • 

  • To negate: flip every bit, then add one.
    • 

  • Reading a signed byte with sign bit 1: unsigned value − 256.
    • 

  • Past the end, values wrap around: 127 + 1 → −128 when stored in a signed byte.
    • 

  • Bits have no sign of their own: the type decides the reading. Keep unsigned data in unsigned types.
