Story hook

Analogy

Mei is reading out the hallway switches to her dad over the phone. "On, on, off, off, off, on, off, off." Her dad is writing it down. "Slow down!" he laughs. "That's too many words for one row."

So they invent a trick. Mei splits the row into two groups of four switches. Each group of four can only make sixteen patterns. They give each pattern one short name: 0 to 9, and then the letters A to F. Now Mei only says two symbols: "C, 8." Her dad writes "C8" and later turns it back into switches.

Engineers use exactly this trick every day. It is called hexadecimal. It is not a new kind of number. It is a short way to write binary.

What you will be able to do

  • Write the sixteen hexadecimal digits 0–9 and A–F, with their 4-bit patterns.
  • Convert between binary and hexadecimal by grouping bits in fours.
  • Convert a two-digit hexadecimal number to decimal and back.
  • Mix a colour on paper as three amounts and write it as a code like #0A00F0, then check it with a small C++ program.
  • Diagnose a missing leading zero in a hexadecimal colour code (the forensic lab).
Jargon box
Hexadecimal (hex)
Simple words: a way of writing numbers with sixteen symbols: 0 to 9, then A to F. Analogy: a one-symbol nickname for every group of four hallway switches. Precise: the base-16 place-value system; the digits A–F stand for 10–15, and each position is worth 16 times the one to its right. W1 R1
Hex digit
Simple words: one symbol of a hexadecimal number. Analogy: the nickname for one group of four switches. Precise: one of the sixteen symbols 0–9, A–F; it stands for exactly four bits, because 2 × 2 × 2 × 2 = 16. W1
Nibble
Simple words: half of a row of eight bits: four bits. Analogy: one group of four switches. Precise: a group of 4 bits; one hex digit writes one nibble. This course uses the word with exactly this meaning. W1
Hex prefix
Simple words: a label in front of a number that says "this is written in hex". Analogy: a sticky note on the row saying "read me with nicknames". Precise: the prefix 0x marks a hexadecimal literal in C++ (for example 0x2A is 42); this university also writes hex as 0x2A in running text (guide 13.3). R1 D2 §5.13.2

The idea in pictures

Figure 1 shows a row of eight switches split into two groups of four. Each group becomes one hex digit. The left group 1100 is C (twelve). The right group 1000 is 8. So the row is 0xC8.

Layer 1 — the kid explanation

Four switches make sixteen patterns, from 0000 to 1111. Hexadecimal gives each pattern a one-symbol name. The first ten names are the digits you know: 0 to 9. We have no single digit for ten, so we borrow letters. A means ten, B eleven, C twelve, D thirteen, E fourteen and F fifteen.

Now a long row of switches is easy to say. Cut it into groups of four, starting from the right. Name each group. Eight switches become two symbols. Thirty-two switches become eight symbols.

Going back is as easy. Take each symbol and write its four switches. Put the groups side by side. No adding or dividing is needed.

Hex is a shorthand, like writing "km" instead of "kilometre". The switches underneath are exactly the same.

Layer 2 — the student explanation

Hexadecimal is place value with base 16. From the right, the positions are worth 1, 16, 256 and so on, each 16 times the last. A hex digit runs from 0 to F (fifteen). W1

Why does grouping in fours work? Because 16 = 2 × 2 × 2 × 2. One hex position covers exactly four binary positions. The place values inside one group are 8, 4, 2, 1. The next group to the left is worth 16 times as much, which is exactly where the binary places 128, 64, 32, 16 sit. So you can convert one group at a time, and the groups never mix. W1

A group of four bits is called a nibble (the name this course uses), and two nibbles make a byte (bytes are the subject of F0-23). So one byte is always exactly two hex digits, from 00 to FF. FF is 15 × 16 + 15 = 255, the biggest number eight switches can hold. W1 R1

Because "10" could mean ten, two or sixteen, we mark the base. This university writes hex with the hex prefix 0x: 0x10 is sixteen. In C++, a number written 0x2A in the code is read as hexadecimal; Listing 1 shows it equals 42. R1

Converting hex to decimal uses place value: 0x2A = 2 × 16 + 10 = 42. Converting decimal to hex divides by 16: 200 ÷ 16 = 12 remainder 8, so 200 = 0xC8. This is the same ladder as F0-21, with 16 instead of 2. W1

Layer 3 — the engineer's depth

Note

For the curious. Later courses show memory addresses, register values and file contents in hex, because each digit lines up with four bits, so you can see individual bits without counting long rows of 0s and 1s. You will meet this constantly: register fields in HW102 and beyond, and memory addresses in the systems courses. Octal (base 8, groups of three bits) is another shorthand of the same kind; C++ writes an octal number with a leading 0. D2 §5.13.2 C++ also accepts binary literals such as 0b1010 and digit separators such as 0b1011'0110; the separators are ignored when the value is worked out. D2 §5.13.2 Both appear in the working draft that followed C++14 and not in the one that followed C++11, so they arrived with C++14. D3 §2.14.2 Listing 1 of F0-25 uses both, and its clean build with -std=c++20 in this course shows that our compiler accepts them.

How the hardware actually does it

Hardware never stores hex. It stores bits. Hex exists only for people: in a program's text, in a tool's display, in a printout. When Listing 1 prints C8, the program is turning the bits 11001000 into the two characters 'C' and '8' so that you can read them. R1 D1 ch. 11

Worked example

Binary to hex: 11001000

  1. Split into fours from the right: 1100 | 1000.
  2. 1100 = 8 + 4 = 12 = C. 1000 = 8.
  3. Answer: 0xC8.
  4. To decimal: 12 × 16 + 8 = 192 + 8 = 200, the same number as in F0-21.

Hex to binary: 0x2A

  1. 2 = 0010. A = ten = 8 + 2 = 1010.
  2. Put them together: 0010 1010, which is 00101010.
  3. To decimal: 2 × 16 + 10 = 42.

Mixing a colour on paper

In this lab a colour is three amounts of light: red, green and blue, each from 0 to 255. The colour code writes each amount as two hex digits, in the order red, green, blue, after a # sign.

  1. Choose red 10, green 0, blue 240 (a deep blue).
  2. 10 ÷ 16 = 0 remainder 10, so 10 = 0x0A. Write two digits: 0A.
  3. 0 = 00.
  4. 240 ÷ 16 = 15 remainder 0, so 240 = 0xF0: F0.
  5. The code is #0A00F0. Notice the zero in front of A: it keeps every amount two digits wide.

Note

Codes of the form #RRGGBB are also used by web pages. The CSS colour specification defines the six-digit form the same way as this lab: the first pair of hex digits is the red amount, the next pair green and the last pair blue, each from 00 to FF (255). Where the analogy breaks


    

  • Nicknames can be a free choice; hex digits are not. Mei and her dad could have picked any sixteen names. Hex uses exactly 0–9 and A–F, and A always means ten. If you invent your own names, nobody else can read your rows.
    • 

  • The groups of four must start at the right. In the hallway it seems natural to group from the left. But for a row of, say, six switches, 101101, grouping from the left gives 1011 | 01 and a wrong answer. Group from the right: 10 | 1101, padded to 0010 1101 = 0x2D = 45. W1
    • 

  • Saying "C8" is short, but it is not a new switch. A hex digit is not stored anywhere as a single thing: the computer still holds eight separate bits. Hex is only for writing and reading.
    •

Where you came from: F0-21 converted between binary and decimal. What carries over: place value and the division ladder, now with 16 instead of 2. Lab


Goal


Mix three colours on paper, write their codes in hex, and check them with the colour-mixer program (Listing 2).


Hardware and software needed


Paper and coloured pencils. A computer with a C++ compiler for steps 4–6, or use the recorded output above. Our run used the toolchain recorded under Sources, R2.


Safety


None beyond normal paper and computer use.


Steps


    

  1. Draw three boxes. In each, decide on three amounts between 0 and 255 for red, green and blue. Write them down.
    2. 

  2. Convert every amount to two hex digits with the division ladder (÷ 16). Keep the leading zero.
    3. 

  3. Write each colour code as # followed by six hex digits.
    4. 

  4. Put your three colours, one per line, into the input file colour_mixer.in next to Listing 2.
    5. 

  5. Build and run the program with the build command shown above (or with university/labs/run_lab.sh on the lab folder).
    6. 

  6. Compare each printed code with your paper code, digit by digit.
    7. 



Expected observations


Every code has exactly six digits. Amounts below 16 start with 0. An amount above 255 is refused with the message "each amount must be from 0 to 255", as in the recorded run. R2


Verification


All your paper codes match the program's codes. Convert one code back to three decimal amounts to prove you can go both ways.


Troubleshooting


    

  • The program prints nothing. The input file is empty or in the wrong folder; it must sit next to the listing with the same name.
    • 

  • Your code and the program's differ in one digit. Recheck that division step; 16 × 15 = 240 is a common place to slip.
    • 

  • Lowercase letters appear. The std::uppercase tool was removed; lowercase hex means the same value.

Summary


    

  • Hexadecimal is base 16, with digits 0–9 and A–F (ten to fifteen).
    • 

  • One hex digit is exactly four bits, a nibble; one byte is exactly two hex digits.
    • 

  • Binary to hex: group bits in fours from the right; hex to binary: write each digit as four bits.
    • 

  • Hex to decimal: place values 1, 16, 256; decimal to hex: divide by 16.
    • 

  • Write hex with the 0x prefix, as C++ does: 0x2A is 42.
    • 

  • Keep leading zeros when a fixed number of digits is expected.

Forensic lab answer key


Observation: only 128 128 128 -> #808080 is correct. The others are short: #FF00 (4 digits), #0FF0, #FFFF0, #A0F0, #FFA50. In each wrong line, an amount below 16 lost its leading zero (0 printed as "0", 10 as "A"). Hypotheses: (1) the input was read wrongly; (2) the printing drops digits. The decimal amounts printed before the arrow are correct, which rules out (1). Root cause: Listing 3, line 11, prints each amount with std::hex but without a width of 2 and a '0' fill, so amounts below 16 print one digit. 128 = 0x80 already has two digits, so it looks right. Ambiguity: #FFFF0 could be 255 255 0 (FF FF 0) or 255 15 240 (FF F F0): the code cannot be decoded. Fix: print each amount with std::setw(2) << std::setfill('0'), as Listing 2 does; its run prints #0A00F0 and #FF0000 R2. Prevention: a test that checks every code has exactly 7 characters (# plus six digits), and test inputs with small amounts (0 and 10). How the evidence was made: Listing 2 with the width and fill removed and the range check removed, run on its first six input lines in this build R3. Wrong answers: "the computer skips digits at random" (the run is repeatable, and only amounts below 16 are affected); "hex cannot show 0" (it can: 0x00).
