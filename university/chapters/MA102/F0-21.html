Story hook

Analogy

Grandma Rosa keeps her buttons in a tin. Her grandson Kai wants to tell his friend how many buttons there are, using only the hallway switches from F0-20. There are 45 buttons.

Kai looks at the switches: 32, 16, 8, 4, 2, 1. "Which switches do I turn on to make 45?" he wonders. He tries the big one first. 32 fits. 13 buttons are left over. 16 is too big. 8 fits, so 5 are left. 4 fits, so 1 is left. 2 is too big. 1 fits. Done!

Kai turned on 32, 8, 4 and 1. The row reads 101101. His friend reads it back by adding the switches that are on. Both of them get 45. In this chapter you will learn two quick ways to go from a number to switches, and two quick ways back.

What you will be able to do

  • Convert a decimal number up to 255 into binary, by taking away place values.
  • Convert a decimal number into binary by dividing by 2 and reading the remainders.
  • Convert a binary number into decimal, by adding place values or by doubling.
  • Name the least significant bit and the most significant bit of a binary number.
  • Diagnose a converter that writes its bits in the wrong order (the forensic lab).
Jargon box
Decimal
Simple words: the everyday way of writing numbers with the ten digits 0 to 9. Analogy: a dial with ten positions instead of a switch with two. Precise: the base-10 place-value number system; each position is worth ten times the one to its right. W1
Least significant bit (LSB)
Simple words: the bit on the far right, worth 1. Analogy: the switch at the right end of the hallway, the one that flips most often. Precise: the bit with the smallest place value, 20 = 1; it decides whether the number is odd (1) or even (0). W1
Most significant bit (MSB)
Simple words: the bit on the far left, worth the most. Analogy: the switch at the left end, the one with the biggest number written above it. Precise: the bit with the largest place value in a number of a given width; in 8 bits it is worth 27 = 128. W1
Remainder
Simple words: what is left over after sharing out equally. Analogy: sharing buttons between two jars: if one button is left over, the remainder is 1. Precise: for whole numbers, n = 2 × q + r with r equal to 0 or 1 when dividing by 2; in C++ the operator % gives the remainder and / between whole numbers gives the whole-number quotient q. W1 R1

The idea in pictures

Figure 1 shows the "divide by 2" method for 45. Each row halves the number and writes down the remainder. You then read the remainders from the bottom up. The bottom remainder is the most significant bit.

Layer 1 — the kid explanation

There are two easy ways to turn a number into switches. The first is Kai's way: take away the biggest place value that fits. Turn that switch on. Then do the same with what is left. Switches you skip stay off.

The second way is halving. Split the buttons into two equal piles. Is one button left over? Write 1. Nothing left over? Write 0. Keep one pile, and halve it again. Stop when nothing is left to halve.

The leftover buttons are the bits. But the first leftover belongs to the switch worth 1, on the right. So you write each new bit on the left of the ones you already have. Or you read your list from the bottom up, as in Figure 1.

Going back is easy too. Add the place values of the switches that are on, as in F0-20. There is also a fun "doubling" way. Start at zero. Read the bits from the left. For each bit, double what you have, then add the bit. When the bits run out, you have the answer.

Layer 2 — the student explanation

Subtracting place values. List the place values up to the first one bigger than your number. Go from the largest down. If the place value fits in what is left, write 1 and subtract it; otherwise write 0. Each number has exactly one binary pattern, so you always reach 0. W1

Repeated division by 2. Any whole number n can be written as n = 2 × q + r, where r is 0 or 1. The remainder r is the least significant bit (LSB): it says whether n is odd. The quotient q holds all the other bits, shifted one place to the right. So you repeat the step on q. The last remainder you get is the most significant bit (MSB). W1 R1

Adding place values. A binary number is the sum of the place values of its 1 bits. You already know this from F0-20. W1

Doubling (left to right). Read the bits from the MSB. Keep a running value. For each bit: value = value × 2 + bit. Doubling moves every bit already read one place to the left. That is the same as multiplying it by 2. So by the end, each bit has been doubled exactly the right number of times. W1 R1

Layer 3 — the engineer's depth

Note

For the curious. The doubling method needs no table of powers: only "multiply by the base and add". It works for any base, so the same loop reads decimal text (value × 10 + digit) or hexadecimal text (value × 16 + digit, F0-22). Listing 1's toDecimal works this way, and any program that reads a number typed as text can do the same. For whole numbers that are not negative, dividing by 2 (dropping the remainder) is exactly a shift right by one bit, and multiplying by 2 is exactly a shift left by one bit as long as the result still fits; F0-25 uses that. How the hardware actually does it

A computer does not keep its numbers in decimal: inside, they are bits, and what the bits mean depends on how the program uses them. D1 ch. 11 Decimal appears at the edges, where people read and write. Text such as "10110" or "45" reaches a program as characters, one per digit, and the program must turn those characters into a number: Listing 1's toDecimal does this for the text "10110" with the doubling rule. To print a number, a program turns bits back into digit characters: Listing 1's toBinary builds its text with the division rule. R1 The circuits that do the arithmetic itself are built in HW102.

200 to binary, by dividing by 2

200 ÷ 2 = 100 r 0; 100 ÷ 2 = 50 r 0; 50 ÷ 2 = 25 r 0; 25 ÷ 2 = 12 r 1; 12 ÷ 2 = 6 r 0; 6 ÷ 2 = 3 r 0; 3 ÷ 2 = 1 r 1; 1 ÷ 2 = 0 r 1. Reading the remainders from the last to the first: 11001000. Check: 128 + 64 + 8 = 200. It needs all eight bits. W1

10110 to decimal, by doubling

Start with 0. Read 1: 0 × 2 + 1 = 1. Read 0: 1 × 2 + 0 = 2. Read 1: 2 × 2 + 1 = 5. Read 1: 5 × 2 + 1 = 11. Read 0: 11 × 2 + 0 = 22. Check with place values: 16 + 4 + 2 = 22. W1

Where the analogy breaks


    

  • Halving buttons always works; halving in a computer drops the remainder. With real buttons, the leftover one sits on the table where you can see it. In C++, 45 / 2 is 22 and the leftover disappears unless you ask for it with %. If you forget, you lose a bit. R1
    • 

  • Kai can see all the switches at once; the division method produces them backwards. In the hallway every switch has a fixed place. The division method gives you the rightmost bit first, so you must put each new bit on the left. Forgetting this is exactly the bug in the forensic lab. R2
    • 

  • Real buttons can be any number; a computer's row has a fixed length. 200 needs eight switches. A number like 300 would need nine, and would overflow an 8-bit row (F0-20). W1
    •

Summary


    

  • Decimal to binary: subtract the biggest place value that fits, or divide by 2 and keep remainders.
    • 

  • The first remainder is the LSB; read the remainders from the bottom up.
    • 

  • Binary to decimal: add the place values of the 1 bits, or double-and-add from the left.
    • 

  • The LSB says odd (1) or even (0); the MSB has the biggest place value.
    • 

  • Always check a conversion by converting it back.
    • 

  • Test with numbers that are not the same backwards, such as 6 or 12.

Forensic lab answer key


Observation: 1, 3, 5 and 9 are right. 2 → 01, 6 → 011, 12 → 0011 and 13 → 1011 are wrong: 01 is 1, 011 is 3, 0011 is 3 and 1011 is 11. Pattern: each wrong answer is the right answer written backwards (10, 110, 1100, 1101). The right ones (1, 11, 101, 1001) read the same in both directions, so the bug cannot show on them. Hypotheses: (1) the division is wrong; (2) the bits are in the wrong order. Reversing each wrong answer gives the correct pattern, so the remainders are right and only the order is wrong: hypothesis 2. Root cause: Listing 2, line 9, bits = bits + … puts each new bit on the right; the first remainder is the LSB and must end up on the right, so later bits must go on the left. Fix: bits = std::to_string(number % 2) + bits;, exactly line 15 of Listing 1, whose run gives 45 = 101101 and 200 = 11001000 R1. Prevention: test with numbers that are not palindromes in binary (2, 6, 12), and test by converting every answer back. How the evidence was made: Listing 1's toBinary with the join order swapped and the printing removed, run in this build R2. Wrong answers: "the program fails for even numbers" (9 is right but 13, odd, is wrong); "numbers above 10 fail" (9 is right, 2 is wrong).
