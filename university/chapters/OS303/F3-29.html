Story hook

Students may not enter the school office. They come to a window, fill in a form, and a clerk does the job for them: photocopies, letters, notices. One form says "photocopy the sheet in my bag, compartment 3". The careful clerk asks to see compartment 3, checks that it really is in the student's own bag, and copies it through the window. The careless clerk reaches straight into whatever the form names.

One day a student writes "compartment 3 of the staff safe". The careless clerk dutifully reaches into the staff safe. On another day a student names a compartment that does not exist, and the careless clerk, reaching into thin air, falls over and takes the whole office down with them.

The school's fix has two parts. Clerks must check every address on a form against the student's own bag, and copy only through a special procedure that survives empty compartments. And a new rule, enforced by the building itself: staff hands simply do not work inside student bags unless the clerk has explicitly opened the "copy" procedure. This chapter builds the window (system calls), the careful clerk (checked, fault-tolerant copies) and the building rule (SMAP), and shows the careless clerk's crash in a recorded kernel dump.

What you will be able to do

  • Run code in ring 3 in its own half of the address space, with user segments and user page permissions.
  • Configure SYSCALL and SYSRET (EFER, STAR, LSTAR, FMASK) and write the entry path: swapgs, stack switch, frame, dispatch, return.
  • Define a small, stable system-call ABI with numbers and error codes, and a user library that calls it.
  • Validate user pointers without overflow, and copy user memory through routines that turn a fault into an error code using an exception table.
  • Enable SMEP and SMAP when the CPU has them, and explain what each one stops.
  • Diagnose "the kernel trusted a user pointer" from a crash dump with the faulting address, the error code and a backtrace.
Jargon box
Privilege level (ring)
Simple words: how much the code currently running is allowed to do. Analogy: staff or student. Precise: on x86, the current privilege level (CPL) is the low two bits of CS: 0 for the kernel, 3 for user code; privileged instructions and supervisor pages fault at CPL 3. D1 R2
User mode and kernel mode
Simple words: the two worlds code runs in: limited and all-powerful. Analogy: student areas and staff-only rooms. Precise: ring 3 and ring 0; the switch happens only through defined gates (system calls, interrupts, exceptions) and the return instructions. D1
System call
Simple words: a request from a user program to the kernel. Analogy: the office window and its form. Precise: here the syscall instruction with the call number in RAX and arguments in RDI, RSI, RDX (R10, R8, R9), result in RAX; the kernel's entry point is set in the LSTAR MSR. D2
SYSCALL and SYSRET
Simple words: the fast "enter kernel" and "return to user" instructions of x86-64. Analogy: the window's hatch, opening and closing. Precise: SYSCALL saves RIP in RCX and RFLAGS in R11, masks RFLAGS with FMASK, loads kernel CS/SS from STAR and jumps to LSTAR; SYSRET reverses it, loading user CS/SS from another field of STAR. Neither switches the stack. D2
Model-specific register (MSR)
Simple words: a numbered CPU configuration register, read and written with special instructions. Analogy: the settings panel in the caretaker's room. Precise: registers accessed with rdmsr/wrmsr by number in ECX; here EFER, STAR, LSTAR, FMASK, GS base and kernel GS base. D3
SWAPGS
Simple words: an instruction that swaps the user's GS base with the kernel's. Analogy: swapping the student's badge for the staff badge at the door. Precise: exchanges the GS base with the IA32_KERNEL_GS_BASE MSR, so that on entry from ring 3 %gs points at this CPU's Cpu (F3-28) and on exit back at the user's value. D1
SMEP
Simple words: the CPU refuses to run user-page code while in kernel mode. Analogy: staff never follow instructions written in a student's notebook. Precise: Supervisor Mode Execution Prevention, CR4 bit 20: an instruction fetch at CPL 0 from a user page faults. D1
SMAP
Simple words: the CPU refuses kernel reads and writes of user pages, except inside an explicitly opened window. Analogy: staff hands do not work in student bags unless the copy procedure is opened. Precise: Supervisor Mode Access Prevention, CR4 bit 21: data accesses at CPL 0 to user pages fault unless RFLAGS.AC is set, which stac sets and clac clears. D1
User pointer validation
Simple words: checking that an address and a length given by a user program describe only that program's memory. Analogy: checking that compartment 3 is in the student's own bag. Precise: here user_range_ok(addr, len): kUserBase ≤ addr ≤ kUserTop and len ≤ kUserTop − addr, written so that no sum can wrap past 264. R3
Exception table (fixup)
Simple words: a list of instructions that are allowed to fault, and where to continue if they do. Analogy: the copy procedure's "if the compartment is empty, write 'missing' on the form". Precise: pairs (faulting RIP, fixup RIP) in the section .uaccess_fixups; the page-fault handler, on a kernel-mode fault, looks the RIP up and resumes at the fixup, which returns an error. D5 R2
Canonical address
Simple words: a 64-bit address whose top bits are all copies of bit 47. Analogy: a locker number in the valid format. Precise: with 4-level paging only 48 address bits are translated; bits 63–48 must equal bit 47, or any access raises a general-protection fault. D1

The idea in pictures

Layer 1 — the kid explanation

Analogy

Students stay in student areas; staff-only rooms are locked, and the building itself enforces it. To get something done, a student asks at the office window. A good clerk never trusts what a form says about where things are: they check it, and they copy carefully, so that a wrong address on a form gets a polite "no" instead of an accident.

A user program runs with less power than the kernel. It cannot touch the kernel's memory or run special instructions. When it needs something, it asks the kernel with a system call. The kernel must treat every address in that request as a possible mistake or trick.

Layer 2 — the student explanation

Ring 3. The GDT of F3-28 already contains user code and data descriptors (selectors 0x20 and 0x18, used with privilege bits 3, so 0x23 and 0x1B). The first entry into ring 3 uses iretq: enter_user pushes the frame an interrupt from ring 3 would have pushed (SS, RSP, RFLAGS with IF set, CS, RIP), clears every general register so that no kernel value leaks, swaps GS and "returns" into user code. The test program prints its own CS: 0x23, privilege level 3 R2.

Memory. Every process has its own page tables (F3-30 builds them). Their entry 0 at the top level is copied from the kernel's and has no user bit, so the kernel is mapped but inaccessible from ring 3; entry 1 holds the user half, with the user bit on every level (Figure 2). A user program that reads the kernel's address 0x100000 takes a page fault with "protection" in the error code: u_peek is killed, the kernel carries on.

Entering the kernel. Interrupts and exceptions from ring 3 already work (F3-19's IDT): the CPU loads RSP from the TSS's rsp0, which F3-26's scheduler sets to the current thread's stack top at every switch. For system calls the lab uses the faster syscall instruction. It does much less than an interrupt: it saves RIP in RCX and RFLAGS in R11, clears the RFLAGS bits named in the FMASK MSR, loads fixed kernel selectors from STAR and jumps to LSTAR. It does not change RSP. The first instructions of syscall_entry therefore have to find a kernel stack without using the user's: swapgs makes %gs point at this CPU's Cpu, the user RSP is parked at %gs:16, and RSP is loaded from %gs:8, the current thread's kernel stack top (also set by the scheduler). Then the registers are pushed as a SyscallFrame and syscall_dispatch runs as ordinary C++.

The ABI. B12 asks for "a system-call table with a stable numbering documented in the design note" C1. This is the OS303 kernel's, defined in process.h. It is this kernel's own ABI, not Linux's numbering.

RCX and R11 are destroyed by syscall itself, so the wrapper in ulib.h lists them as clobbered, and a fourth argument would travel in R10 instead of RCX.

Never trust a user pointer. sys_write receives a buffer address and a length chosen by the user program. Before touching anything it checks that the whole range lies in the user half (user_range_ok). Even a range that passes can contain unmapped pages, so the copy itself must be able to fault safely: copy_from_user calls uaccess_copy, whose single copying instruction is listed in an exception table. If it faults, the page-fault handler finds the instruction in the table, moves RIP to the fixup code, and the copy returns "bytes not copied"; sys_write returns −2. The B12 test program u_badptr tries a kernel address, an unmapped user address, a length that runs past its stack into unmapped memory, a length that wraps around 264, and a bad file descriptor; each got its error code and the kernel kept running R2.

Privileged instructions. u_priv executes hlt in ring 3. The CPU raises a general-protection fault; the trap handler sees that it came from ring 3 (from_user), prints a report and ends the process with status 0x100 | 13 = 0x10D, and the kernel continues.

SMEP and SMAP. Two CR4 bits make the hardware help. SMEP makes the CPU refuse to execute user pages in ring 0, which defeats the classic exploit of making the kernel jump to user-supplied code. SMAP makes it refuse to read or write user pages in ring 0 unless RFLAGS.AC is set; the copy routines set it with stac just before copying and clear it with clac right after, so every other kernel access to user memory faults. The lab enables both when CPUID reports them; QEMU's default CPU model does not, so the user tests run with -cpu max, and the log says "SMEP on, SMAP on" R2.

Layer 3 — the engineer's depth

Every instruction of the entry path is load-bearing

FMASK clears IF. Between syscall and the stack switch the CPU runs on the user's stack pointer. An interrupt there would push its frame onto user memory (or fault on it). FMASK therefore clears IF, and syscall_entry enables interrupts only after the frame is on the kernel stack (line 23). It also clears TF (no single-step trap on the first kernel instruction), DF (the ABI requires it clear; rep movsb would otherwise copy backwards) and AC (a user who sets AC would otherwise switch SMAP off for the kernel) (syscall.cc line 30).

swapgs must be balanced. Every path from ring 3 into the kernel must execute swapgs exactly once, and every path back exactly once. trap.S decides by looking at the saved CS: only if the interrupted code was in ring 3 does it swap (F3-26's trap.S lines 22–24 and 61–63). An interrupt that arrives while the kernel is handling a system call comes from ring 0 and must not swap again. Getting this wrong gives a kernel whose this_cpu() points into user memory: a classic source of security bugs D4.

SYSRET has a sharp edge. SYSRET loads RIP from RCX. If a kernel ever returns with a non-canonical RCX, Intel CPUs raise the general-protection fault in ring 0 with the user's stack pointer already loaded D1. This kernel never changes the saved RIP, so RCX is always the address after the user's own syscall instruction; a kernel that implements signals or ptrace must check it or return with iretq. The claim itself is from memory and listed in the unverified box.

Preemption inside a system call. Interrupts are enabled during syscall_dispatch, so a system call can be preempted like any kernel code. That is safe because everything the return path needs is on the thread's own kernel stack, and %gs already holds the kernel value; when the thread runs again, perhaps on another CPU, it reads this_cpu() afresh.

The range check that does not overflow

The tempting check is addr ≥ base && addr + len ≤ top. With len chosen by an attacker, addr + len can wrap past 264 and become small, and the check passes for a range that covers the whole kernel. user_range_ok never forms the sum: it checks addr ≤ top and then len ≤ top − addr, which cannot wrap. The host test (Listing 6) runs both versions on the same nine cases under UBSan: the naive check accepts two malicious ranges, the real one rejects them R3. The same pattern guards every sum in F3-30's ELF checker.

The order of decisions in the page-fault handler

A page fault now has four possible meanings, tried in order in trap.cc lines 65–80: (1) a user page that exists in the program but is not mapped yet: map it and retry (demand paging, F3-30); (2) a fault in kernel mode at an instruction listed in the exception table: resume at its fixup; (3) a fault in user mode: kill the process; (4) anything else is a kernel bug: crash with a dump. The order matters: a copy from a not-yet-mapped page of a valid buffer must be satisfied by demand paging (1) before it is treated as a bad pointer (2). Note what SMAP does to case 2: under SMAP, a direct kernel read of a user page outside stac/clac is a protection fault at an instruction that is not in the table, so it ends in case 4 — loudly.

Copy first, then check what you copied

sys_spawn copies the path and every argument string into kernel buffers before using them, and sys_write copies into a 256-byte kernel chunk before printing. Reading user memory twice (once to check, once to use) invites a "time of check to time of use" attack: another thread of the same process can change the memory in between. With one thread per process (F3-30) that cannot happen here yet, but the habit costs nothing.

Deviations from B12 and simplifications

  • B12's second test names "a misaligned length". This kernel has no alignment requirement for write, so the test uses the two length errors that do matter: a length that runs past mapped memory and one that wraps around 264. The owner may want a different reading (NOTES).
  • nosmap=1 on the command line switches off both SMEP and SMAP; it exists only for the forensic lab.
  • No floating-point state is saved for user programs; they are compiled with -mgeneral-regs-only (F3-26).

How the hardware actually does it

On syscall the CPU performs, in one instruction: RCX ← RIP of the next instruction; R11 ← RFLAGS; RFLAGS ← RFLAGS AND NOT FMASK; CS ← STAR[47:32], SS ← STAR[47:32] + 8 (with fixed flat descriptors loaded internally); RIP ← LSTAR. sysretq does RIP ← RCX; RFLAGS ← R11; CS ← STAR[63:48] + 16 | 3, SS ← STAR[63:48] + 8 | 3. That fixed "+8" and "+16" is why the GDT places user data (0x18) right before user code (0x20) and STAR[63:48] holds 0x10 D2. The page walk checks the user/supervisor bit at every level: a ring-3 access needs U = 1 on all of them, which is why user_pte in F3-30 sets it on every level it creates. A page fault pushes an error code whose bits say present/protection (bit 0), write (bit 1), user (bit 2), reserved bit (bit 3) and instruction fetch (bit 4) — the decoding print_pf_error prints.

Not verified — check before relying on this

Written from memory and not checked in this build: the MSR numbers EFER 0xC0000080 (SCE bit 0), STAR 0xC0000081, LSTAR 0xC0000082, FMASK 0xC0000084, KERNEL_GS_BASE 0xC0000102; the STAR field layout and the +8/+16 selector rule for SYSRET; RFLAGS bits TF 8, IF 9, DF 10, AC 18; CPUID leaf 7 subleaf 0 EBX bit 7 (SMEP) and bit 20 (SMAP); CR4 bits 20 (SMEP) and 21 (SMAP); the page-fault error-code bits; the selector values 0x1B/0x23; the SYSRET non-canonical-RCX behaviour on Intel CPUs; the exact behaviour of rep movsb when it faults (RCX holding the bytes left, which uaccess_copy relies on). The runs below show that this configuration works on QEMU 8.2.2's TCG model with -cpu max; they prove nothing about real CPUs. Check against Intel SDM Vol. 2 (SYSCALL, SYSRET, SWAPGS, STAC, CLAC, MOVS), Vol. 3 ("Paging": access rights, SMEP, SMAP, page-fault error code) and Vol. 4 (MSRs), and AMD64 APM Vol. 2 "SYSCALL and SYSRET" (D1, D2, D3).

Note

Untested on hardware. QEMU's default CPU model in this build (qemu64) reports neither SMEP nor SMAP (the other chapters' logs say "SMEP off, SMAP off"), so this chapter's runs use -cpu max. Whether a given real CPU has them is a CPUID question for that CPU.

Worked example

STAR, by hand. STAR[47:32] must give the kernel's CS on syscall: 0x08, so the kernel's SS is 0x08 + 8 = 0x10. STAR[63:48] must give, on sysretq, SS = value + 8 = 0x18 and CS = value + 16 = 0x20, so the value is 0x10; the CPU adds RPL 3, giving 0x1B and 0x23. The 64-bit MSR value is therefore (0x10 << 48) | (0x08 << 32) = 0x0010_0008_0000_0000, exactly line 26 of syscall.cc. And indeed u_hello printed CS = 0x23.

FMASK, by hand. Bits 8, 9, 10 and 18: 0x100 + 0x200 + 0x400 + 0x40000 = 0x40700.

The wrapping length of u_badptr. The program passes its stack buffer top (near 0xFF_FFFF_Exxx) with length 264 − 16. user_range_ok: the address is inside the user half, but len ≤ kUserTop − addr is false (about 4 KiB versus almost 264), so −2 is returned without touching memory. The naive check would compute addr + len = addr − 16 (mod 264), which is inside the user half, and accept.

The length that runs into unmapped memory. sys_write(1, top, 8192): top is in the stack's top page, and the 8 KiB range ends above kUserTop − 4096, in the unmapped page above the stack (Figure 2). The range check passes (it is all in the user half). The copy faults when rep movsb reaches the unmapped page; demand paging declines (the page does not belong to the process); the exception table sends RIP to the fixup; uaccess_copy returns the bytes left; sys_write returns −2. The first chunks may already have been printed; a real kernel's write would return the count written so far, which is an ABI choice this kernel makes differently.

Where the analogy breaks


    

  • The window is not polite. A system call is not a request that waits for a clerk to look up: the CPU switches privilege level and jumps to a fixed kernel address in one instruction, and the "clerk" is the same CPU now running kernel code.
    • 

  • Staff rooms are visible from student areas. The kernel is mapped in every process; it is only marked "supervisor". The protection is a bit in the page tables checked on every access, not a wall.
    • 

  • SMAP is not about trust in students. It protects against the kernel's own bugs: it makes accidental direct accesses fault, so they are found in testing instead of exploited later.
    • 

  • Bags can change while the clerk reads them. Another thread of the same program can modify the buffer during the copy; real clerks do not face shape-shifting bags.
    • 




Common mistakes and debugging


    

  • Using the user stack in the entry path. Any push or call before RSP is switched writes to user memory. Read the first three instructions of syscall_entry again.
    • 

  • Unbalanced swapgs. Symptom: this_cpu() returns garbage after the first interrupt that arrives during a system call, or user programs crash on the first %gs access. Check every entry and exit path.
    • 

  • Dereferencing a user pointer in the kernel. Works in all tests with valid pointers; crashes or leaks with malicious ones. With SMAP on it faults on the first test with a valid pointer — which is the point.
    • 

  • addr + len in a range check. Wraps. Write the subtraction form.
    • 

  • Forgetting the U bit on intermediate page-table levels. The user page faults although its own entry has U = 1. Decode the error code: "protection, user mode" on an address you mapped means a missing permission somewhere up the walk.
    • 

  • Debugging method. For a crash in a system call: CR2 and the error code tell you who accessed what (bit 2 clear = the kernel did it); RIP and the backtrace through syscall_dispatch tell you which call; the argument registers in the dump (RDI, RSI, RDX at entry; here often RBX or RDI by the time of the crash) tell you which user value it was.
    • 




Transition box

Where you came from: F3-26 to F3-28: threads, locks and all CPUs, all in ring 0. What carries over: the per-CPU area and GS base (now swapped with swapgs), each thread's kernel stack top (now loaded on every entry from ring 3), F3-19's trap handling, F3-21's page tables. What changes: code runs in ring 3 in its own address-space half; it reaches the kernel only through SYSCALL and a numbered ABI; the kernel copies user memory only through checked, fault-tolerant routines, and SMEP/SMAP make mistakes fault. What comes next: F3-30 turns "a user program" into processes: an ELF loader that refuses malformed files, demand paging, an initial stack with argv and the auxiliary vector, spawn, exit and wait, and an init that starts ten children.

Summary


    

  • Ring 3 code runs with user segments (CS 0x23) in the user half of its address space; the kernel half is mapped but supervisor-only.
    • 

  • SYSCALL saves RIP/RFLAGS in RCX/R11, masks RFLAGS, loads kernel selectors and jumps to LSTAR without switching stacks; syscall_entry uses swapgs and the per-CPU area to find the kernel stack.
    • 

  • A small numbered ABI (exit, write, getpid, spawn, wait, yield) with negative error codes; RCX and R11 are destroyed by the instruction.
    • 

  • User pointers are checked without sums that can wrap, and copied only by routines in an exception table, which turns faults into −2.
    • 

  • SMEP and SMAP make kernel execution and accidental access of user pages fault; stac/clac open a narrow window for the copy routines.
    • 

  • The three B12 tests passed in QEMU with -cpu max; the forensic kernel crashed on a valid pointer under SMAP and on an unmapped one without it. Nothing was tested on hardware.
    •

Forensic lab answer key


Observation, Evidence 1. Page fault in thread 2 'u_hello.elf', CR2 = 0x80_0040_2000, error code 0x1: protection violation, read, supervisor mode. RBX and RDI hold the same value as CR2, and RDX = 0x17 (23, the length of "hello from ring 3: pid "). The address is the start of u_hello's third LOAD segment (0x80_0040_2000, read-only data, .rodata): the string being printed. The page is present (the user's ulen already read it), and the kernel read it directly: SMAP refused, and the RIP was not in the exception table, so the kernel crashed.


Observation, Evidence 2. u_hello printed normally (without SMAP the direct read of a valid, mapped page "works"). u_badptr's first call (valid buffer) also worked. The crash is in thread 3 'u_badptr.elf': CR2 = 0x90_0000_0000, error code 0x0: not present, read, supervisor. RBX = RDI = 0x90_0000_0000 and RDX = 0x10: the second call, "unmapped user address", length 16. addr2line: console_write_raw (console.cc:79) ← sys_write (syscall.cc:104, the bug branch) ← syscall_dispatch (line 165) ← syscall_entry (syscall.S:25, the instruction after the call). RCX = 0x3fd is probably the port number of COM1's line status register (base 0x3F8 + 5), which console_write_raw polls; it confirms the console code was running (register-level detail from memory).


Root cause. sys_write under BUG_TRUST_USER_POINTER passes the user's address straight to the console: no range check, no exception-table copy. Any fault there is a kernel-mode fault at an unlisted instruction, i.e. a crash. With a kernel address the same code would have printed kernel memory to the user (an information leak) instead of crashing.


Fix. Use the safe branch: user_range_ok, then copy_from_user into a kernel buffer (lines 106–120).


Prevention. Code review rule: a value that came from a system-call argument is an integer, never a pointer, until a copy_*_user routine has used it (Linux marks such pointers with an annotation checked by a static analyser; the idea is easy to copy with a distinct C++ type). Hardware configuration: keep SMAP (and SMEP) enabled in every test configuration, so that the very first direct access faults during testing, as Evidence 1 shows. And fuzz the system-call interface (mini-project).
