C. Facts (keyed to the chapter's claim tags)

  1. F1 [D9a §Interrupt Claim Process] A target reads its claim/complete register; the PLIC returns the ID of the highest-priority pending interrupt for that context (0 if none) and clears its pending bit. Confirmed; matches the chapter. Used in: layer3 (PLIC claim), jargon.
  2. F2 [D9a §Interrupt Completion] The target writes the same interrupt ID back to the claim/complete register to signal completion; the PLIC then may deliver that source again. Confirmed. Used in: layer3 (end-of-interrupt), unverified box (PLIC part removed).
  3. F3 [D9a §Interrupt Priorities, §Interrupt Enables, §Memory Map] Each source has a priority register (base + 4 × source); each context has enable bits (base + 0x2000, 0x80 per context), a priority threshold (base + 0x200000, 0x1000 per context) and a claim/complete register (base + 0x200004, 0x1000 per context). Confirmed; the chapter states the structure, not the offsets. Used in: jargon, layer3 (per-context enables).
  4. F4 [D9b] ACLINT provides MTIMER (a memory-mapped MTIME and per-hart MTIMECMP), MSWI (per-hart MSIP) and SSWI (SETSSIP) devices; it is backward compatible with the SiFive CLINT. Confirmed. Used in: jargon (PLIC and ACLINT).
  5. F5 [D4, D5, D6, D8, D10] Not checked: 8259A OCW2 EOI commands, IOAPIC redirection table, local APIC EOI and x2APIC rules, GICv3 priority drop versus deactivation, NVIC. Stay in the unverified box; QEMU's own register dumps (R3) are evidence of QEMU's model only. Used in: layer2, layer3.
  6. F6 [D7] Not opened; MSI/MSI-X capability IDs come from L1 (opened). Used in: layer3.
