C. Facts (keyed to the chapter's claim tags)

  1. F1 [D2 §11.1, §11.4, §11.9] A class may be declared with the class-key struct; its data members are declared in the member-specification; members of a class defined with struct "are public by default", with class private by default. Used in: jargon (struct, Member), layer2, layer3.
  2. F2 [D2 §11.4, §9.4.1] A brace-or-equal-initializer on a non-static data member "specifies a default member initializer"; in aggregate initialization an element that is not explicitly initialized "is initialized from that initializer". Used in: jargon (Default member initializer), layer2.
  3. F3 [D2 §9.4.1] With a positional initializer-list the explicitly initialized elements are "the first n elements of the aggregate". Used in: jargon (Aggregate initialization), layer2.
  4. F4 [D2 §9.4.4] Designators "shall form a subsequence of the ordered identifiers in the direct non-static data members"; example "error: designator order does not match declaration order". Used in: jargon (Designated initializer), layer2.
  5. F5 [D2 §6.7.6, §7.6.2.5] Alignment is the number of bytes between successive addresses at which an object can be allocated; alignof yields it. Used in: jargon (Alignment).
  6. F6 [D2 §7.6.2.4] For a class, sizeof includes "any padding required for placing objects of that type in an array". Used in: jargon (Padding), layer2.
  7. F7 [D2 §11.4 p19] Non-static data members with the same access control are allocated so that "later members have higher addresses"; alignment may leave gaps between adjacent members. Used in: layer2.
  8. F8 [D2 §17.2.4, §9.1] offsetof (from <cstddef>, same semantics as C's); a static_assert with a false condition makes the program ill-formed. Used in: layer3.
  9. F9 [D2 §6.7.4, §9.4] An automatic object that is not initialized has an indeterminate value; reading it is undefined behaviour (with narrow exceptions). Used in: breaks.
  10. F10 [D4 F.16, F.17, F.20] Read-only struct parameters by const&, in-out by &, results by return value. Used in: layer2, answers.
  11. F11 [D5 §3.1.2] On x86-64: char size and alignment 1, double size and alignment 8; structures take the alignment of their most strictly aligned member; "Each member is assigned to the lowest available offset with the appropriate alignment. The size of any object is always a multiple of the object's alignment"; padding. Used in: jargon (Padding, Alignment), figure, layer2, hardware.
  12. F12 [D6 (Machine-Level Programming IV)] A structure is a block of memory, fields ordered by declaration, the compiler fixes positions, and in assembly only offsets remain; memory is accessed in aligned chunks of 4 or 8 bytes, and data spanning cache lines or pages is less efficient or trickier. Used in: layer2, hardware, breaks.
  13. F13 [R1–R5] All sizes (24, 16, 10), offsets (0, 8, 16; 0, 8, 9), alignof(double) = 8, outputs and the designator-order message are copied from the recorded runs. Used in: throughout.
