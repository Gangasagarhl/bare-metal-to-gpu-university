C. Facts (keyed to the chapter's claim tags)

  1. F1 [D6 NvmeBar] Register offsets in the controller BAR: CAP 0x0 (64-bit), VS 0x8, INTMS 0xc, INTMC 0x10, CC 0x14, CSTS 0x1c, NSSR 0x20, AQA 0x24, ASQ 0x28 (64-bit), ACQ 0x30 (64-bit). Used in: layer3 trace walk (register reads at 0x0/0x4/0x8, 0x1c; writes at 0x14, 0x24, 0x28/0x2c, 0x30/0x34), unverified box
  2. F2 [D6 CC/CAP/AQA fields] CC: EN at bit 0, IOSQES shift 16 (4 bits), IOCQES shift 20 (4 bits). CAP: MQES bits 15:0, DSTRD bits 35:32. AQA: ASQS bits 11:0, ACQS bits 27:16. Used in: layer3 (0x460001 = EN + 64-byte SQ entries + 16-byte CQ entries; 0xff003f = 63 and 255), doorbell-stride sentence
  3. F3 [D6 enums] Admin opcodes: Create I/O SQ 0x1, Create I/O CQ 0x5, Identify 0x6. NVM opcodes: Write 0x1, Read 0x2, Dataset Management 0x9 (deallocate attribute = bit 2). Identify CNS: 0x0 namespace, 0x1 controller. Used in: layer3 trace walk, forensic pack, F1-49 D7 (TRIM equivalent)
  4. F4 [D6 _nvme_check_size] Build-time assertions: NvmeCmd is 64 bytes and NvmeCqe is 16 bytes. Used in: layer3 (entry sizes), unverified box
  5. F5 [D4] QEMU's nvme device is added with -drive file=…,if=none,id=… -device nvme,serial=…,drive=…; properties max_ioqpairs (default 64) and msix_qsize (default 65); the controller implements version 1.4 of the NVM Express specification; by default it uses a QEMU-allocated PCI vendor/device ID (use-intel-id=false). Used in: layer2 (queue limits), hardware section, R2 explanation
  6. F6 [R1] Listing 1: with 4 slots the fourth command is refused ("SQ full, cid 4 must wait"); outstanding = (tail − head) mod n; the first CQ pass writes phase 1 into zeroed memory, the second pass phase 0, and the host stops at the stale entry with the old phase. Used in: pictures (Figure 2), layer2, layer3, checks 2 and 8
  7. F7 [R2] info pci reports the device as vendor 1b36 device 0010, class 0264 (decimal) = 0x0108 as info qtree prints it; pci.ids names 1b36 Red Hat, Inc. and 0010 QEMU NVM Express Controller. Used in: layer2 (finding the device), hardware
  8. F8 [R3] Trace order: reads of 0x8/0x0/0x4; write 0x14 = 0; read 0x1c; write 0x24 = 0xff003f; writes 0x28/0x2c = 0x7fdd000; 0x30/0x34 = 0x7fde000; write 0x14 = 0x460001 ("setting controller enable bit succeeded"); doorbell 0x1000 = 1 ("doorbell_sq sqid 0 new_tail 1"); Identify cns 0x1 cid 0; Create CQ (cqid 1, qsize 255, vector 0, ien 0); Create SQ (sqid 1, cqid 1); Identify cns 0x0 for NSID 1–256; doorbell offsets 0x1000/0x1004/0x1008/0x100c; Read of LBA 0; debug-console line "boot sector arrived from NVMe LBA 0 and is running"; exit 33. Used in: layer3 trace walk, forensic key, summary, check 3

D. Not found / not opened

  1. N1 The NVM Express Base Specification (D1) was not opened: its names for the queue concepts (submission/completion queue, doorbell, phase tag, namespace, command identifier, PRP), the ready bit CSTS.RDY, the term "0's based" for size fields and the rule that a Create I/O SQ must name an existing CQ are stated in the chapter from the lab trace and QEMU's header (D6) and remain unconfirmed against the specification's own wording. The chapter's unverified box says so.
  2. N2 The PCIe Transport Specification (D2) was not opened: the doorbell formula SQ y tail = 0x1000 + (2y × (4 << DSTRD)), CQ y head = 0x1000 + ((2y + 1) × (4 << DSTRD)) is confirmed by the trace only for DSTRD = 0 and stays in the unverified box.
  3. N3 The NVM Command Set Specification (D3) was not opened: Read/Write/Flush opcodes and the Dataset Management deallocate attribute are cited from QEMU's enum (D6) as "what this implementation does".
  4. N4 The Linux NVMe host driver (D5) was not opened: "one I/O queue pair per CPU" and "write barrier before the doorbell" are stated as design practice (the curriculum's own milestone C6 wording and F1-37) rather than as quoted driver facts.

F. Hardware facts

No physical NVMe SSD was used; the only device is QEMU 8.2.2's emulated controller (PCI id 1b36:0010, R2), which QEMU documents as implementing NVMe 1.4 (D4). To test on hardware the reference kit's x86-64 test PC with an NVMe SSD that may be erased (build/KIT.md) and a driver of the learner's own (milestone C6) would be needed; the chapter says so.
