C. Facts (keyed to the chapter's claim tags)

  1. F1 [D2 §6.8] Object representation: the N unsigned char objects taken up by an object (N = sizeof); value representation: the bits that hold the value. Used in: jargon (Value), hardware.
  2. F2 [D2 §7.6.2.4] sizeof yields bytes; it is 1 for the narrow character types; other fundamental types have implementation-defined sizes; the result has type std::size_t; for a class it includes padding. Used in: jargon (sizeof), note box, figure.
  3. F3 [D2 §17.2.1, §17.2.4] size_t is declared in <cstddef>; it is an implementation-defined unsigned integer type large enough for the size of any object. Used in: jargon (std::size_t).
  4. F4 [D2 §7.3, §7.4] Standard conversions are implicit; the usual arithmetic conversions convert the other operand to double if one operand is double; integral promotions first; a signed operand is converted to unsigned when the unsigned type has greater or equal rank. Used in: jargon (Conversion), layer2, layer3.
  5. F5 [D2 §7.3.10] Floating-to-integer conversion "truncates; that is, the fractional part is discarded"; undefined if the truncated value does not fit. Used in: jargon (static_cast, Truncation), layer2.
  6. F6 [D2 §7.6.1.8] static_cast performs an explicit conversion, including the standard conversions. Used in: jargon (static_cast).
  7. F7 [D2 §9.4.4] A narrowing conversion (for example floating to integer) inside list-initialization makes the program ill-formed. Used in: jargon (Narrowing conversion).
  8. F8 [D2 §7.1, §6.8.1] A result "not in the range of representable values for its type" is undefined behaviour; "Overflow for signed arithmetic yields undefined behavior"; "Unsigned arithmetic does not overflow"; unsigned arithmetic is "performed modulo 2N"; signed range −2N−1 to 2N−1−1; Table 12 minimum widths (int 16, long long 64); each listed signed type at least as large as the one before. Used in: jargon (Signed overflow, Unsigned wrap-around), layer2, note box, answers, forensic key.
  9. F9 [D2 §3.30] Undefined behaviour: "behavior for which this document imposes no requirements", from unpredictable results to terminating. Used in: jargon (Undefined behaviour), breaks.
  10. F10 [D2 §7.6.5] Integer / discards the fractional part; % yields the remainder. Used in: layer2.
  11. F11 [D2 §7.3.14, §7.3.6] Zero converts to false, any other value to true; types of lower rank than int are promoted to int. Used in: layer2, layer3.
  12. F12 [D7 §7.12.9.7] lround rounds "to the nearest integer value, rounding halfway cases away from zero". Used in: layer2.
  13. F13 [D3 §3.8, §3.5, §3.12] -Wconversion warns "for implicit conversions that may alter a value" including real-to-integer; -Wsign-compare is enabled by -Wall in C++; -Wnarrowing is in -Wall; -fsanitize=undefined enables UndefinedBehaviorSanitizer including signed-integer-overflow checks. Used in: layer2, layer3, answers.
  14. F14 [D5 ES.23, ES.46] "Prefer the {}-initializer syntax"; "Avoid lossy (narrowing, truncating) arithmetic conversions". Used in: layer2.
  15. F15 [D6 (Goldberg)] 0.1 "cannot be represented exactly" in binary; double has p = 53 (Table D-1); comparing within an error bound "is hardly a cure-all". Used in: layer2, hardware, breaks.
  16. F16 [D8 §3.1.2, §3.2.3] On x86-64 Linux: int 4 bytes, long long 8, double 8 (IEEE-754 double); INTEGER arguments in %rdi, %rsi, …; SSE (floating-point) arguments in vector registers. Used in: note box, hardware.
  17. F17 [D9 (Bits, Bytes, and Integers)] UMax = 2w − 1; TMin = −2,147,483,648 and TMax = 2,147,483,647 for w = 32; addition discards the carry; TAdd and UAdd have identical bit-level behaviour. Used in: layer2, hardware.
  18. F18 [R1–R8] All sizes, limits, printed values, warnings and the sanitizer message are copied from the recorded runs. Used in: throughout.
