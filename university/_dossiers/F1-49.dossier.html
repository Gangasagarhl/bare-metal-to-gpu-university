C. Facts (keyed to the chapter's claim tags)

  1. F1 [D3 §37.1] A disk presents an array of 512-byte sectors (blocks) numbered 0 to n−1, each readable and writable; nearby blocks are faster to reach than distant ones and sequential access is fastest ("unwritten contract"). Used in: jargon, layer2, summary
  2. F2 [D3 §37.2] Platters on a spindle spun by a motor; data in concentric tracks of sectors; one head per surface on an arm that moves across the surface. Used in: jargon, pictures (Figure 1), layer1, layer2
  3. F3 [D3 §37.3] Rotational delay: wait for the sector to rotate under the head; average about half a rotation (R/2). Seek: moving the arm to the track (accelerate, coast, decelerate, settle). Transfer: the data passes under the head. Seeks and rotations are among the most costly operations; the drive has a track buffer (cache). Used in: jargon, layer2, worked example Task A, hardware
  4. F4 [D3 §37.4] T_I/O = T_seek + T_rotation + T_transfer (Equation 37.1); random small reads are hundreds of times slower than sequential reads ("use disks sequentially"). Used in: jargon, layer2, summary
  5. F5 [D3 §37.5] Disk scheduling reorders queued requests (SSTF, SCAN, SPTF), often inside the drive, which knows the head position; the OS sends several requests at once. Used in: breaks, hardware
  6. F6 [D4 §44.1] Flash cells store charge in a transistor; SLC stores 1 bit per cell, MLC 2 bits with four levels, TLC 3 bits; more bits per cell means slower and less durable cells. Used in: layer2 (NAND flash)
  7. F7 [D4 §44.2–44.3] Pages (a few KB) are the unit of read and program; blocks (e.g. 128 or 256 KB) are the unit of erase; a page can be programmed only after its block was erased; erase destroys the whole block's contents. Used in: jargon, pictures, layer1, layer2, summary
  8. F8 [D4 §44.4] Each program/erase cycle adds wear; blocks fail after a rated number of cycles (MLC rated at about 10,000, SLC about 100,000); read and program disturbs flip bits in neighbouring pages. Used in: jargon (wear levelling), layer2, layer3 (error correction and read disturb), breaks
  9. F9 [D4 §44.5, §44.7] The FTL maps logical blocks to physical flash; modern FTLs are log-structured: each write goes to the next free page and the old copy becomes garbage; the mapping table records where each logical block lives; write amplification = total write traffic issued to the flash ÷ write traffic issued by the client. Used in: jargon, pictures (Figure 2), layer2, worked example Task B
  10. F10 [D4 §44.8] Garbage collection finds a block with dead pages, copies its live pages to the end of the log and erases the block; the ideal victim has only dead pages; over-provisioning (extra flash beyond the advertised capacity) lets cleaning run in the background; the TRIM command tells the device which addresses were deleted so it need not preserve them. Used in: jargon, layer2, layer3, forensic key, summary
  11. F11 [D4 §44.10] Wear levelling spreads erases across blocks so that all wear at about the same rate, moving long-lived data when needed, at a cost in write amplification. Used in: jargon, layer2
  12. F12 [D4 §44.11] The log-structured design turns random writes into sequential ones; the random/sequential gap on SSDs is smaller than on disks but still matters. Used in: layer2 (why the toy's random run costs more is a property of its greedy cleaning, R1)
  13. F13 [D7 §36.3–36.7] A device presents status, command and data registers; the OS polls or takes an interrupt when the device finishes; a DMA engine moves data between memory and the device with little CPU work and interrupts on completion; device registers are reached by memory-mapped I/O or explicit I/O instructions; the storage stack is file system → generic block layer → driver → device. Used in: hardware, transition box
  14. F14 [R1] Toy FTL run: program refused on a programmed page; logical page 7 → physical 0, 1, 2; sequential WA 1.00, random WA 2.17 (240 host, 520 flash, 280 copies, 123 erases); erase counts 12–21. Used in: pictures, layer2, worked example, code, summary
  15. F15 [R2] LBA 5 × 512 = 2560; 4096/512 = 8 logical per physical sector; LBA 16 → physical sector 2 slot 0. Used in: layer2, worked example Task C
  16. F16 [R3] Build VM: virtio block devices, ROTA 1, LOG-SEC 512, PHY-SEC 4096. Used in: layer2, hardware, mistakes, summary
  17. F17 [R4] Forensic run: flash per host write 1.12 (50 % full), 3.30 (95 %), 3.42 (deleted, no TRIM), 1.00 (TRIM). Used in: layer3, breaks, forensic key

The NVMe form (Dataset Management, Deallocate) is confirmed in the F1-50 dossier (D3 there).

  3. N3 That a partial write of a 4096-byte physical sector forces a read-modify-write: not stated in the opened sources; the sentence is kept as a consequence of the block rule (D3 §37.1: sectors are the unit of write) and marked as reasoning, not a quoted fact.
  4. N4 Controllers that keep a bad-block list and retire worn blocks, and that read errors are corrected by an ECC engine in the controller: OSTEP §44.4 covers wear and disturbs but not the controller's mechanisms; the chapter keeps these sentences conservatively worded and tagged to §44.4 and §44.5 (the FTL "handles" reliability); the ECC detail is deferred to F1-54.
