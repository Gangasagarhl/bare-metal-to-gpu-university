C. Facts (keyed to the chapter's claim tags)

  1. F1 [D9 ch. 10] Linux splits interrupt work into a top half (the handler, which must run in minimum time and cannot sleep) and a bottom half (tasklets, workqueues) run later. "The first step usually consists of clearing a bit on the interface board." /proc/interrupts shows how many interrupts have been delivered to each CPU. Confirmed. Used in: layer3 (top half / bottom half); layer3 (/proc/interrupts, partly).
  2. F2 [D3] Edition confirmed only. The definitions of an interrupt as an asynchronous exception, state saving and return were not checked at section level. Used in: jargon, layer2, transition.
  3. F3 [D4, D5] Not checked: registers saved on entry, IDT/vector table, IRET/exception return. Stay in the unverified box. Used in: layer2, layer3.
  4. F4 [D7] Not opened; the column meaning of /proc/interrupts is partly covered by D9 ch. 10 ("The /proc Interface") and by the run R3 itself. Used in: layer3.
  5. F5 [L1] Header constants as listed (opened). Used in: jargon (overrun), listings.
