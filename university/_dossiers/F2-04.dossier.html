C. Facts (keyed to the chapter's claim tags)

  1. F1 [D2 §7.6.1.2] "each parameter … is initialized … with its corresponding argument"; if there is none, the default argument is used. Used in: jargon (Pass by value, Default argument), layer2.
  2. F2 [D2 §9.3.3.2] "A reference can be thought of as a name of an object" (note); "It is unspecified whether or not a reference requires storage". Used in: jargon (Reference), hardware.
  3. F3 [D2 §9.4.3] A reference is bound at initialization and "cannot be changed to refer to another object"; argument passing is initialization; an lvalue reference to a non-const type cannot bind to an rvalue (literal or temporary). Used in: jargon (Reference, Pass by reference, Const reference), figure, layer2, layer3.
  4. F4 [D2 §9.3.3.6] A default argument is given in a parameter declaration and "will be used in calls where trailing arguments are missing"; it "cannot be redefined by a later declaration (not even to the same value)". Used in: jargon (Default argument), layer2, lab troubleshooting.
  5. F5 [D2 §6.4.3] A name declared in a block is local to it, from its point of declaration to the end of the block. Used in: jargon (Scope), layer2.
  6. F6 [D2 §6.2] A function declaration without a body is not a definition. Used in: layer2.
  7. F7 [D2 §12.2, §12.4.3] Functions with the same name and different parameter lists are overloads; a viable function wins only if it is better than all others, "otherwise the call is ill-formed" (ambiguous). Used in: jargon (Overloading), layer2, layer3, mistakes.
  8. F8 [D2 §12.4.3.1.1, §12.4.3.2] Conversions have Exact Match, Promotion or Conversion rank (Table 16); "an Exact Match is a better conversion than a Promotion, which is a better conversion than a Conversion". Used in: layer3, breaks, answers, forensic key.
  9. F9 [D2 §6.7.5.3, §6.7.3] Storage of a block-scope variable lasts until its block exits; after an object's lifetime ends, a glvalue referring to it may be used only in limited ways (a dangling reference). Used in: layer3.
  10. F10 [D4 F.16, F.17, F.20] Pass cheaply-copied "in" parameters by value and others by reference to const; "in-out" by reference to non-const; prefer return values for outputs; passing a string by value is "potentially expensive". Used in: layer2, breaks.
  11. F11 [D5 §5.1.2, §5.1.5.2] Mangled names encode parameter types: i = int, d = double. Used in: layer2.
  12. F12 [D5 §3.1.2.5] "Reference parameters are handled by passing a pointer to the object bound to the reference." Used in: hardware.
  13. F13 [D6 §3.2.3] INTEGER-class arguments go in "the next available register of the sequence %rdi, %rsi, %rdx, %rcx, %r8 and %r9". Used in: hardware.
  14. F14 [D7 (Machine-Level Programming III)] Procedures pass their first six arguments in registers, the rest on the stack. Used in: hardware.
  15. F15 [R1–R8] All printed results, symbol names (_Z8portionsi, _Z8portionsii, _Z8portionsdd) and messages are copied from the recorded runs. Used in: throughout.
