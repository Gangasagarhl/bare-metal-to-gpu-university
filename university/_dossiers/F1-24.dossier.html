C. Facts (keyed to the chapter's claim tags)

  1. F1 [R1] The trace of the sum program: cycle 9 lw r4, 0(r1) with A = 1, ALU 1, memory read of address 1 giving 3, r4 = 3; cycle 8 bne with A = 0, B = 4, ALU −4, next PC 3 (branch taken); five memory reads (cycles 4, 9, 14, 19, 24); final r3 = 29; cpu.in outputs 42 after 26 instructions. Used in: layer 2, worked example, code walk-through, answers.
  2. F2 [R1 (u16.h)] Machine::step performs fetch, decode and register read, ALU, memory, next PC and write back in order; write back only if rd != 0 (line 327); the control signals RegWrite, AluSrcImm, ReadRdAsB, MemRead, MemWrite, MemToReg, BranchEq/BranchNe/Out/Halt. Used in: layer 2 "The parts and the wires", forensic key.
  3. F3 [R2] The RISC-V disassembly of F1-23 places instructions at byte offsets 0, 2, 6, 8 … Used in: layer 3 "Word addressing".
  4. F4 [R3] Kofi's program: slt results 1, 0, 1, 0 in cycles 5, 11, 17, 23; add r0, r0, r5 shows ALU 1 but write-back "-"; out r0 prints 0. Used in: forensic lab.
  5. F5 [D1 ch. 4, D2 ch. 7 (as named)] Datapath built by collecting the parts each instruction needs and joining them with multiplexers; the register file read combinationally and written at the edge; the single-cycle clock set by the longest path (a load); separate instruction and data memories in textbook designs (caches in real processors); the multicycle alternative. Chapters located, text not opened. Used in: jargon, layer 2, layer 3, hardware, breaks, transition.
