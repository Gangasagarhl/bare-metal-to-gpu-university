C. Facts (keyed to the chapter's claim tags)

  1. F1 [D2 §4.2, §4.3] Subclass 1 is the boot interface subclass; protocol 1 is keyboard and 2 is mouse. A boot keyboard can be used by firmware (BIOS) without parsing the report descriptor. Confirmed; matches the capture (R3). Used in: layer3 (HID keyboard).
  2. F2 [D2 §7.2.4, §7.2.6] Set_Idle is request 0x0A; Set_Protocol is 0x0B with 0 = boot protocol and 1 = report protocol. Confirmed; matches the chapter's reading of the capture. Used in: layer3.
  3. F3 [D2 §4.4] A HID interface must have an interrupt In endpoint. Confirmed. Used in: layer3.
  4. F4 [D1] Not checked: speed names and rates, frame/microframe periods, bInterval encoding, bMaxPower units, transfer-type guarantees, enumeration steps, packet types. Stay in the unverified boxes / inline notes. Used in: jargon, layer2, layer3.
  5. F5 [D4] Not checked: Address Device command and the absence of SET_ADDRESS from the per-device capture. Stays in the unverified box. Used in: layer3.
  6. F6 [L1] Header definitions as used (opened). Used in: jargon, layer2, layer3.
