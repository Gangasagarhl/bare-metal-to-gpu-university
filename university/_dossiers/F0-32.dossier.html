C. Fact list

One entry per tagged claim in the chapter (the claim text as it stands after the verification pass, the tag that supports it, and the chapter section). Every document section named in a tag was opened and the fact was found there; R-ids are this build's lab runs.

  1. F1 Simple words: A question with a yes or no answer that the program checks. Analogy: "Is the water boiling?" in a recipe. Precise: An expression whose value is converted to bool, used by if and by loops to decide what to do next, for example temperature < 5. source: R1, D4 §8.5.1, §7.3.14; used in: F0-32-jargon
  2. F2 Simple words: Signs that compare two values: <, >, <=, >=, == and !=. Analogy: Holding two jars side by side to see which one has more. Precise: Operators that compare two values and give a bool. == means "is equal to" and != means "is not equal to"; a single = is assignment, which g++ flagged inside an if with the course flags (R3). source: R2, R3, D4 §7.6.9, §7.6.10, D2 §3.8; used in: F0-32-jargon
  3. F3 Simple words: A way to say "only do this when the condition is true". Analogy: "If it is raining, take an umbrella." Precise: A statement that runs its block only when its condition is true; an optional else block runs otherwise, and else if chains test conditions in order until one is true (R1). source: R1, D4 §8.5.1; used in: F0-32-jargon
  4. F4 Simple words: A group of statements inside curly braces { }. Analogy: A boxed group of steps in a recipe that belong together. Precise: A sequence of statements enclosed in braces; the whole block belongs to the if, else, loop or function written in front of it. source: R1, D4 §8.4; used in: F0-32-jargon
  5. F5 Simple words: Words that join conditions: and (&&), or (||), not (!). Analogy: "Homework done AND it is after school." Precise: The operators && (true only if both sides are true), || (true if at least one side is true) and ! (turns true into false and false into true) (R2). source: R2, D4 §7.6.14, §7.6.15, §7.6.2.1; used in: F0-32-jargon
  6. F6 An if statement has a condition in round brackets and a block in curly braces: if (temperature < 5) { ... }. The condition is worked out to true or false, the bool values from F0-31. The block runs only when the condition is true. source: R1, D4 §8.5.1, §8.4; used in: F0-32-layer2
  7. F7 The comparison operators are < (less than), > (greater than), <= (less than or equal), >= (greater than or equal), == (equal) and != (not equal). Each one compares two values and gives a bool. You can store that bool in a variable, as Listing 2 does with bool after_school = hour >= 15;. source: R2, D4 §7.6.9, §7.6.10; used in: F0-32-layer2
  8. F8 An else if chain tests its conditions in order. The first true condition wins; its block runs, and all the later tests are skipped. A final else catches every case that no condition matched. With 12 degrees, the first test (12 < 5) was false and the second (12 < 18) was true, so the program printed "Wear a jumper." With exactly 18, both tests were false, and the else ran. source: R1, R5, D4 §8.5.1; used in: F0-32-layer2
  9. F9 The logical operators join conditions. a && b is true only if both are true. a || b is true if at least one is true. !a turns true into false and false into true. In Listing 2, hour 16 with homework done made after_school && homework_done true. source: R2, D4 §7.6.14, §7.6.15, §7.6.2.1; used in: F0-32-layer2
  10. F10 If you write if (eggs = 6), you put 6 into eggs instead of comparing. With our flags, g++ refused: "suggest parentheses around assignment used as truth value". Read that as: "did you mean ==?" source: R3, D2 §3.8; used in: F0-32-layer2
  11. F11 For the curious. With &&, if the left side is already false, the result must be false, so C++ does not even work out the right side. With ||, a true left side makes the right side unnecessary. This is called short-circuit evaluation, and later you will use it to guard a risky check, for example "the list is not empty AND its first item is …". source: D4 §7.6.14, §7.6.15; used in: F0-32-layer3
  12. F12 A condition does not have to be a comparison: any value that can turn into a bool works. A number counts as false when it is 0 and as true otherwise. That is exactly why if (eggs = 6) is legal C++ (6 counts as true) and why the compiler only warns about it, here turned into an error by -Werror. source: R3, D4 §7.3.14, D2 §3.8; used in: F0-32-layer3
  13. F13 … mpare two values and then maybe "jump" to another place in the program. (In the RISC-V family of processors, for example, one branch instruction does both: it compares two values and jumps only if the test holds.) If the condition is false, the jump makes the processor skip over the instructions of the block and continue further down. So a decision is, underneath, "compare, then maybe skip ahead". source: D5 §1.1.5.2; used in: F0-32-hardware
  14. F14 Noor can answer "sort of cold" or "not sure". A condition is always exactly true or false. source: D4 §7.3.14, §6.8.1; used in: F0-32-breaks
