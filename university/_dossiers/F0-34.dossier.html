C. Fact list

One entry per tagged claim in the chapter (the claim text as it stands after the verification pass, the tag that supports it, and the chapter section). Every document section named in a tag was opened and the fact was found there; R-ids are this build's lab runs.

  1. F1 Simple words: A named group of steps that you can use again by calling its name. Analogy: A small recipe inside a bigger recipe: "make the sauce (see page 12)". Precise: A named block of code with a return type and parameters, for example int double_it(int number); calling it runs its body and may give back a value. source: R1, D3 §7.6.1.2, §8.7.3; used in: F0-34-jargon
  2. F2 Simple words: Using a function by writing its name with round brackets. Analogy: Turning to the sauce page and following it, then coming back. Precise: An expression such as double_it(3) that runs the function body with the given arguments and then continues after the call (R1). source: R1, D3 §7.6.1.2; used in: F0-34-jargon
  3. F3 Simple words: A variable in a function that receives a value from the caller. Analogy: The blank in "add ___ to the pot". Precise: A variable declared in a function's parameter list; it starts as a copy of the argument when the parameter is a plain type such as int, so changing it does not change the caller's variable (R4). source: R1, R4, D3 §7.6.1.2; used in: F0-34-jargon
  4. F4 Simple words: The actual value you hand to a function when you call it. Analogy: The word you write in the blank: "add salt to the pot". Precise: An expression in a function call whose value initialises the matching parameter, such as "salt" in add_to_pot("salt"). source: R1, D3 §7.6.1.2; used in: F0-34-jargon
  5. F5 Simple words: The answer a function gives back to the code that called it. Analogy: The sauce the helper hands back when the sauce recipe is done. Precise: The value given by a return statement; a function whose return type is not void must return a value (the C++ rules say that running off its end without one is undefined behaviour); g++ warns about it, and with -Werror it refused to build one that did not (R3). source: R1, R3, D3 §8.7.3, D5 §3.8; used in: F0-34-jargon
  6. F6 Simple words: The word for "this function gives nothing back". Analogy: A step like "boil the water" that does not hand you anything. Precise: The return type of a function that returns no value, such as void boil_water(). source: R1, D3 §8.7.3; used in: F0-34-jargon
  7. F7 Figure 1. The calls of Listing 1. Each call jumps to a function (solid arrows); when the function ends, the program returns to the line after the call (dashed arrows). double_it hands back the value 6. The order matches the real output of Listing 1. source: R1, D3 §7.6.1.2, §8.7.3; used in: F0-34-pictures
  8. F8 A function definition has four parts: a return type, a name, a parameter list in round brackets, and a body in braces. In int double_it(int number) { return number * 2; }, the return type is int, the name is double_it, there is one parameter number of type int, and the body returns twice the number. source: R1, D3 §7.6.1.2, §8.7.3; used in: F0-34-layer2
  9. F9 A function call such as double_it(3) gives each parameter its first value from the matching argument: here number starts as 3. The body runs. The return statement ends the function and hands its value back to the caller, so the call itself is worth 6. source: R1, D3 §7.6.1.2, §8.7.3; used in: F0-34-layer2
  10. F10 A function that hands nothing back has the return type void, like boil_water. A function whose return type is not void must return a value: if it runs off its end without one, the C++ rules do not say what happens. g++ warns about this, and with our flags (-Werror) it refused to build such a function: "no return statement in function returning non-void". source: R3, D3 §8.7.3, D5 §3.8; used in: F0-34-layer2
  11. F11 A parameter of a plain type such as int is a copy of the argument. Changing the copy inside the function does not change the caller's variable. In the forensic evidence, add_sugar made its own spoons 3, but the caller's spoons stayed 2. To get a result out, return it. source: R4, R5, D3 §7.6.1.2; used in: F0-34-layer2
  12. F12 A function must be declared before the line that calls it. Listing 1 defines its functions above main for that reason. When a call came first, g++ said "'double_it' was not declared in this scope". source: R6, D3 §6.5.1; used in: F0-34-layer2
  13. F13 For the curious. Passing std::string thing by value makes a copy of the text for every call. For short texts that does not matter. Later (SP101) you will meet const std::string&, a way to let the function read the caller's string without copying it and without being allowed to change it. source: D3 §7.6.1.2, §9.4.3, §7.2.1; used in: F0-34-layer3
  14. F14 Each call gets its own fresh set of parameters and local variables. They exist only while that call runs. That is why two calls of add_to_pot do not mix up "salt" and "pasta", and why a function's local variable is gone after it returns. Debuggers show this as a list of active calls, the call stack (you will see one call inside another in F0-37). source: D3 §7.6.1.2, §6.7.5.3, D6 §8.2; used in: F0-34-layer3
  15. F15 … assed in places fixed by an agreement called the calling convention; you will meet it in later courses. (One example: in the RISC-V processor family, the jump-and-link instruction saves the address of the next instruction in a register. By agreement, that register is x1.) Because the return address is remembered, one function can call another, which calls another, and every one finds its way home. source: D4 §1.1.5.1; used in: F0-34-hardware
  16. F16 When you write "salt" into the blank of a paper recipe, the card is changed. A function call does not change the function: each call gets a fresh copy of its parameters (R1 used add_to_pot twice with different values). source: R1, D3 §7.6.1.2; used in: F0-34-breaks
