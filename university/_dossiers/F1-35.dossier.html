C. Facts (keyed to the chapter's claim tags)

  1. F1 [D11 §11.4.1] Write-through: writes update the cache and memory together. Write-back: writes update only the cache and set a dirty bit; memory is updated on eviction; "most modern caches use write-back because it amortizes repeated writes". A write to a conflicting address with a valid, dirty line first saves the old block to memory, then loads the new one. Used in: jargon (write-through, write-back, dirty bit), layer 1, l2-hit, l2-miss, l2-evict, Figures 1 and 2.
  2. F2 [D11 §11.4] On a miss the CPU waits for memory and loads the data into the cache, "even for writes"; modified data must be written back to memory before eviction. Used in: jargon (dirty bit), Figure 2.
  3. F3 [D9 ch. 5] Cachegrind's simulated D1 is write-allocate: "when a write miss occurs, the block written to is brought into the D1 cache". Used in: jargon (write-allocate), Figure 2 caption, answers 2.
  4. F4 [D4 §6.4.2, §6.4.3] GetM "obtains the block in the Modified (read-write) state"; Upg upgrades a read-only block to Modified without a data transfer; an invalidate protocol removes other cached copies before a core writes. Used in: layer 3 (write-allocate and the read before the write), breaks 2.
  5. F5 [D1 ch. 6 / D2 ch. 5 / D3 ch. 2, App. B (titles only)] No-write-allocate (write-around) and the usual pairings; the write buffer; write-back preferred lower in the hierarchy; I/O and cache consistency; the cache controller forming the victim address from tag and index. Chapter text not openable; cited at chapter level. Used in: jargon (no-write-allocate, write buffer), l2-hit, l2-miss, l2-evict, layer 3, hardware, breaks.
  6. F6 [S1 / D7 (not opened)] Memory types, MTRRs and PAT are named from the curriculum map only; the Intel manual was not opened. Used in: layer 3 (memory types).
  7. F7 [R1–R3] writepolicy: write-back + write-allocate 5 block reads, 4 write-backs, 0 single writes; write-through + no-write-allocate 3 block reads, 0 write-backs, 8 single writes. writeback_bug: memory holds 14, 15, 10, 11, 12, 13 (6 of 6 wrong); diff against writeback_fixed is line 47 (block * 16 instead of line.block * 16). writes.cc: read 12.33 GB/s, fill 7.43 GB/s (60 %), copy 17.32 GB/s; two memcpy calls in objdump. Used in: worked example, code walk-through, forensic lab and key.
