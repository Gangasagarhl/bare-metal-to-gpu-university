C. Fact list

One entry per tagged claim in the chapter (the claim text as it stands after the verification pass, the tag that supports it, and the chapter section). Every document section named in a tag was opened and the fact was found there; R-ids are this build's lab runs.

  1. F1 Simple words: A named place that holds a value, which can change while the program runs. Analogy: A labelled jar: the label is the name, the contents are the value. Precise: A named object with a type, for example int apples = 3; reading the name gives its current value, and assignment replaces the value. source: R1, D3 §7.6.19; used in: F0-30-jargon
  2. F2 Simple words: The line where you first tell the computer a variable's name and type. Analogy: Putting a new empty jar on the shelf and writing its label. Precise: A statement that introduces a name and its type, such as int apples = 3; a name must be declared before it is used (F0-36 shows the error when it is not). source: R1, D3 §6.5.1; used in: F0-30-jargon
  3. F3 Simple words: To give a variable its first value at the moment you create it. Analogy: Filling the jar the moment you put it on the shelf. Precise: Giving a variable a value in its declaration (int apples = 3;). With the course flags, g++ refused to build a program that used a variable before giving it a value (R4). source: R1, R4, D3 §9.4, D4 §3.8; used in: F0-30-jargon
  4. F4 Simple words: Putting a new value into a variable. The old value is gone. Analogy: Emptying the jar and filling it with something new. Precise: The operator = in a statement such as apples = apples + 2; the right side is worked out first, then its value replaces the variable's old value. It is not the "is equal to" of maths; that is == (F0-32). source: R1, D3 §7.6.19, §7.6.10; used in: F0-30-jargon
  5. F5 Simple words: The name C++ uses for "read what the person types". Analogy: The cook listening to an order. Precise: The standard input stream from <iostream>; the operator >> reads a value into a variable. In the lab runs the input comes from a .in file instead of a keyboard. source: R3, D3 §29.4.3; used in: F0-30-jargon
  6. F6 Simple words: A word that makes a variable unchangeable after its first value. Analogy: A jar with its lid glued shut: you can look, but not change what is inside. Precise: A qualifier on a declaration (const int baked = 12;); the compiler rejects any later assignment to that variable. source: R3, D3 §7.2.1, §7.6.19; used in: F0-30-jargon
  7. F7 You create a variable with a declaration. The line int apples = 3; says three things: the type is int (a whole number), the name is apples, and the first value is 3. Giving the first value at once is called to initialise the variable. source: R1, D3 §9.4; used in: F0-30-layer2
  8. F8 Later you can change the value with an assignment: apples = apples + 2;. The computer works out the right side first. It reads the old value 3, adds 2, and gets 5. Only then does it put 5 into apples. So the same name can appear on both sides. source: R1, D3 §7.6.19; used in: F0-30-layer2
  9. F9 Watch out: in C++ the sign = does not mean "is equal to". It means "put the value on the right into the variable on the left". The question "is equal to?" is written ==, and you will use it in F0-32. source: D3 §7.6.19, §7.6.10; used in: F0-30-layer2
  10. F10 A program can also read a value from the person using it. std::cin >> cookies; waits for a number and puts it into cookies. In our lab runs the "typing" comes from a small file, cookies.in, which contains the number 5. source: R3, D3 §29.4.3; used in: F0-30-layer2
  11. F11 Some values should never change. Writing const in front, as in const int baked = 12;, glues the lid shut. If a later line tries to change baked, the compiler refuses. source: R3, D3 §7.2.1, §7.6.19; used in: F0-30-layer2
  12. F12 For the curious. What is in a jar that was never filled? In C++, a plain int declared inside a function without a value does not start at 0 by itself: the C++ rules call its value "indeterminate"; reading it before giving it a value is a mistake. With the course flags, g++ refused to build such a program and named the variable (Listing 4 in "Common mistakes"). Always initialise your variables. source: R4, D3 §6.7.4, D4 §3.8; used in: F0-30-layer3
  13. F13 Names have rules too. A name is made of letters, digits and the underscore _, and it must not start with a digit. Names are case-sensitive: apples and Apples are two different jars. Good names say what is inside: cookies is better than c. source: D3 §5.10; used in: F0-30-layer3
  14. F14 A computer's memory is a long row of numbered boxes, each holding a small number. You met it as the pantry in F0-05. When your program creates a variable, a few of these boxes are set aside for it. The name is for you and the compiler. The running program finds the variable by its place in memory. The jar picture hides this: real memory has no labels written on it. source: D3 §6.7.1; used in: F0-30-hardware
  15. F15 A new kitchen jar is empty. A new C++ variable without a first value is not "empty" or zero: its contents are unknown, and the compiler with our flags refuses to let you read it. source: R4, D3 §6.7.4; used in: F0-30-breaks
