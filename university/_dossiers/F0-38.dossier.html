C. Fact list

One entry per tagged claim in the chapter (the claim text as it stands after the verification pass, the tag that supports it, and the chapter section). Every document section named in a tag was opened and the fact was found there; R-ids are this build's lab runs.

  1. F1 Simple words: A recipe that produces numbers that look random. Analogy: A very long, fixed shuffled list of numbers that you start reading at some place. Precise: An algorithm that produces a sequence of numbers from a starting value (the seed); the same seed gives the same sequence, as R3 shows with seed 2026. This course uses std::mt19937 with std::uniform_int_distribution. source: R3, D2 [rand.req.eng], §26.6.5, §26.6.8.2.1; used in: F0-38-jargon
  2. F2 To pick a secret, the program creates a pseudo-random number generator, std::mt19937, from the header <random>, and gives it a seed. A second object, std::uniform_int_distribution<int> with the limits 1 and 100, turns the generator's large numbers into a number from 1 to 100. source: R1, D2 §26.6.3.2, §26.6.5, §26.6.8.2.1; used in: F0-38-layer2
  3. F3 The name mt19937 names a well-known generator algorithm, the "Mersenne Twister". It is fully deterministic: it keeps a block of numbers in memory and mixes them with arithmetic each time you ask for a number. It is good for games and simulations, not for secrets such as passwords; that needs a generator designed for security. source: D2 §26.6.3.2, §26.6.5, D4; used in: F0-38-layer3
  4. F4 … step that turns the generator's numbers into a number from 1 to 100: they only require that every number from 1 to 100 is equally likely. So another compiler's standard library may give a different secret for seed 2026. This build tested only g++ 13.3.0 and its standard library, so the chapter promises "same seed, same secret, same toolchain", which is what the comment on line 6 of Listing 1 says. source: R1, R3, D2 §26.6.5, §26.6.8.2.1, §26.6.2.6; used in: F0-38-layer3
  5. F5 The processor has no dice. Every instruction it runs gives the same result for the same inputs (F0-29). The generator is ordinary arithmetic on numbers stored in memory, so a fixed seed leads to a fixed series of numbers, exactly as R3 showed. source: R3, D2 §26.6.3.2; used in: F0-38-hardware
  6. F6 For a seed that changes, the program asks the outside world. std::random_device is meant to give numbers that cannot be predicted; the C++ rules allow a library that cannot do this to use an ordinary generator instead, and they leave the details to each library. In R3 it gave five different seeds and so five different secrets. source: R3, D2 §26.6.6; used in: F0-38-hardware
  7. F7 … Linux kernel gathers "environmental noise from device drivers and other sources" into a pool that programs can read, but whether g++ 13.3.0's standard library reads from that pool or uses a special processor instruction is not documented in the sources opened. To check it, read the standard library's own source code for random_device at the GCC 13.3.0 release and record the answer in the dossier. source: D2 §26.6.6, D5; used in: F0-38-hardware

D. Not found / conflicting

  • N1 Where std::random_device of g++ 13.3.0's standard library gets its values on Linux: not documented in the sources opened (the C++ draft leaves it implementation-defined, D2 §26.6.6; random(4) describes only the kernel's pool, D5). Stays in a "Not verified" box that names what is needed: the standard library's source for random_device at the GCC 13.3.0 release (tier 4).
  • N2 Whether another standard library gives secret 22 for seed 2026 was not tested; the draft (D2 §26.6.5, §26.6.8.2.1, §26.6.2.6) shows why it may differ (the engine is fully specified, the distribution's algorithm is not). The former "Not verified" box became a note with this answer.
  • N3 The text of "A Tour of C++" section 17.5 Random Numbers and of Petzold's "Code" was not opened; further reading only.
