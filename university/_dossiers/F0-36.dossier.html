C. Fact list

One entry per tagged claim in the chapter (the claim text as it stands after the verification pass, the tag that supports it, and the chapter section). Every document section named in a tag was opened and the fact was found there; R-ids are this build's lab runs.

  1. F1 Simple words: A message from the compiler that says it cannot build your program, and where it got stuck. Analogy: The helper saying: "I cannot rewrite this recipe; step 6 is missing its end." Precise: A diagnostic that stops compilation; g++ prints file:line:column: error: followed by a description and the source line with a marker (R2). source: R2, D2 §3.7; used in: F0-36-jargon
  2. F2 Simple words: A message from the compiler that says "this is allowed, but it looks like a mistake". Analogy: The helper saying: "You bought pears but never used them. Did you mean to?" Precise: A diagnostic about legal but suspicious code, enabled by flags such as -Wall and -Wextra; with -Werror ("Treat all warnings as errors", R7) every warning stops the build (R5). source: R5, R7, D2 §3.8; used in: F0-36-jargon
  3. F3 A g++ message starts with file:line:column:, then the kind (error, warning or note), then a description. Below it, g++ prints the source line with the line number and a marker (^~~~) under the place it means. Often the first line says which function the problem is in: "In function 'int main()'". source: R2, R3, D2 §3.7; used in: F0-36-layer2
  4. F4 Some messages contain suggestions. In Listing 3, g++ wrote "did you mean 'apples'?" and showed the corrected word. That suggestion was right. In F0-34, for a function used before its definition, g++ suggested "did you mean 'double'?", which was wrong. Suggestions are only guesses: check them before you follow them. source: R3, D2 §3.7; used in: F0-36-layer2
  5. F5 Error messages use precise words for types. In Listing 4, the text "three" is described as const char*, which is how C++ sees a string literal here. You do not need to understand every word. "invalid conversion from … to 'int'" already says: "this kind of value does not fit into an int jar". source: R4, D4 §5.13.5; used in: F0-36-layer2
  6. F6 For the curious. The square brackets at the end of a warning name the flag that controls it, such as [-Werror=parentheses] in F0-32 or [-Werror=uninitialized] in F0-30. That lets you look the warning up in the GCC manual by name. A line "cc1plus: all warnings being treated as errors" means the build failed only because of -Werror. source: R5, D2 §3.7, §3.8; used in: F0-36-layer3
  7. F7 The compiler is not the only tool that can complain. In SP101 you will meet the linker, which joins pieces of a program together (the last of the compiler's stages) and has its own messages. They look different because a different tool prints them. source: D2 §3.2; used in: F0-36-layer3
  8. F8 … ur program ever reaches the processor. The compiler is itself a program running on the processor, reading your text from top to bottom. When it cannot fit the next word into the rules of C++, it stops translating and writes messages instead. No executable is produced, so there is nothing for the processor to run. That is why a program with a compiler error can never cause a crash: it never starts. source: R2, D2 §3.2; used in: F0-36-hardware
