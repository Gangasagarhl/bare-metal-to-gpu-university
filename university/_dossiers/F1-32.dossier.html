C. Facts (keyed to the chapter's claim tags)

  1. F1 [D11 §11.1] The memory hierarchy orders devices from registers, cache and main memory to flash disk, traditional disk and remote storage; "devices with higher capacities offer lower performance"; faster devices cost more per byte; most systems have several cache levels (small fast L1 near the ALU, larger slower L2, an L3 shared by cores). Used in: jargon (memory hierarchy), Figure 1, layer 1, l2-why.
  2. F2 [D11 §11.4] A cache is "a small, fast storage device on a CPU that holds limited subsets of main memory"; on a miss the CPU waits for memory and loads the data into the cache; loading into a full cache evicts resident data. Used in: jargon (cache), layer 1, breaks 2.
  3. F3 [D11 §11.3] Temporal and spatial locality; fetching data also fetches the surrounding data; LRU eviction when the cache is full. Used in: l2-why (locality), breaks 2 and 3.
  4. F4 [D11 §13.3.4] The TLB is a small hardware cache of page-to-frame mappings; a hit avoids the extra memory access for the page-table lookup. Used in: layer 3 (virtual memory joins the curve).
  5. F5 [D6 30.7.7] steady_clock: time_point values never decrease and advance at a steady rate; "the clock may not be adjusted"; is_steady is true. Used in: layer 3 (measurement discipline).
  6. F6 [D1 ch. 6 (title only)] CS:APP3e chapter 6 is the memory hierarchy chapter and ships the memory-mountain program (mem/mountain/mountain.c). The claims tagged D1 (hierarchy, caches hold copies, working sets, memory mountain, prefetching) were not checked against the chapter text; the hierarchy and cache claims are confirmed by F1–F3 (D11). Used in: all D1 tags.
  7. F7 [D2 ch. 5 / D3 ch. 2 (title only)] Chapter titles confirmed from the publishers' pages. The claims tagged D2 (SRAM vs DRAM speed and cost, larger memories are slower, the path of a miss) and D3 (non-blocking caches, outstanding misses, memory-level parallelism, Little's law applied to memory, hardware prefetchers, the memory controller) were not checked against the chapter text; see "Not found". Used in: all D2 and D3 tags.
  8. F8 [R1] Recorded random-chain output: about 1.9–2.0 ns per load up to 32 KiB, 5.4–6.2 ns from 64 KiB to 512 KiB, 7.9 ns at 1 MiB, 38 ns at 2 MiB, climbing to 263.64 ns at 256 MiB; the sequential chain stays low. Re-run on the verifier's machine (R5): same shape, 205 ns at 256 MiB. Used in: code walk-through, lab expectations, forensic lab.
  9. F9 [R3] littles.cpp prints 1,000 bytes = 15.6 blocks in flight for 100 ns and 10 GB/s, and 0.64 GB/s one-at-a-time; the measured line gives about thirty blocks. Used in: l2-two, l2-little, worked example.
