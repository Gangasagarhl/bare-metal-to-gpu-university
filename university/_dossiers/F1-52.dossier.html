Source dossier — F1-52 NIC descriptor rings and DMA

Prepared by: Source Researcher / Fact-Checker agent, verification pass. Date: 2026-10-10. Status: approved (G1), with the open items listed under "Not found".

A. Scope

Course HW205 (Storage and network hardware), level L3. The chapter was written in the 2026-10-09 build without internet access; this dossier records the verification pass of 2026-10-10. The evidence is QEMU 8.2.2's e1000e trace events and tshark's list of the same run's frames (R3), QEMU's PCI listing of three emulated NICs (R2), and the course's own ring model (R1, R4; ruling A2: it stands for the e1000e receive ring the lab traced). QEMU's own hw/net/e1000_regs.h (D7) confirms the ten ring register names; Intel's 8254x Software Developer's Manual (D1) was reached but the fetched text was truncated before the register-map chapter; the 82574 datasheet, the VIRTIO specification, LDD3 and the kernel documents (D2–D5) were not opened because the shared web-fetch budget ran out. Every register name that QEMU did not print therefore stays in an unverified box.

C. Facts (keyed to the chapter's claim tags)

  1. F1 [R2] QEMU's e1000 is PCI 8086:100e (pci.ids "82540EM Gigabit Ethernet Controller"), one memory BAR and one I/O BAR; e1000e is 8086:10d3 ("82574L Gigabit Network Connection"), three memory BARs and one I/O BAR; virtio-net is 1af4:1000 ("Virtio network device"), an I/O BAR, a small memory BAR and a 64-bit prefetchable memory BAR. Used in: jargon, layer2, layer3 "hardware differences", worked example
  2. F2 [R3 setup] Register writes in order: 0x3800 ← 0x7f5da00, 0x3804 ← 0, 0x3808 ← 0x100, 0x3818 ← 0 (transmit ring, 256 bytes); 0x2800 ← 0x7f5db00, 0x2808 ← 0x100, 0x2818 ← 0 (receive ring); 0x5400 ← 0x12005452 and 0x5404 ← 0x80005634 (MAC 52:54:00:12:34:56 in little-endian bytes); 0x2818 ← 8 printed by QEMU as "Setting RDT[0] = 8". Used in: layer3 trace walk, worked example task 2
  3. F3 [R3 rounds] Five rounds: transmit tail writes 1…5 to 0x3818 each followed by e1000e_tx_descr whose low 16 bits are 0x1ad = 429, 0x46 = 70, 0x1ad = 429, 0x1b9 = 441, 0x2a = 42, matching tshark's frame lengths (DHCP Discover, IPv6 router solicitation, DHCP Discover, DHCP Request, ARP); receive descriptors fetched at 0x7f5db00, +0x10, +0x20, +0x30 ("length: 16"); "Received packet written to guest"; interrupt cause register 0xc0 going 0x0 → 0x80 → 0x80000083; RDT raised one at a time from 8 to 12; the ARP frame of 42 bytes is the fifth transmit. Used in: pictures (Figure 2), layer2, layer3, summary, checks
  4. F4 [R3 derived] 256 / 16 = 16 descriptors per ring; the ROM gives the NIC 8 of 16 at first and one more after each frame it consumes. Used in: layer3, worked example
  5. F5 [R1] Toy ring: NIC writes slots from head up to but not including tail; head == tail means the NIC owns nothing and drops the frame (ring_model.h line 33); the driver refills by advancing tail; the kept-back slot distinguishes full from empty. Used in: pictures (Figure 1, with owner letters), layer2, code walk-through
  6. F6 [R4] rx_stall: when the driver stops advancing the tail the NIC's missed counter climbs while nothing reaches memory; the stall is visible only in the counter. Used in: forensic pack and answer key
  7. F7 [D7] E1000_RDBAL 0x02800, RDBAH 0x02804, RDLEN 0x02808, RDH 0x02810, RDT 0x02818; TDBAL 0x03800, TDBAH 0x03804, TDLEN 0x03808, TDH 0x03810, TDT 0x03818. The header does not define ICR, RAL/RAH, RCTL/TCTL or the descriptor bits (they are in e1000x_regs.h, not opened). Used in: layer3 trace walk (ring setup sentences), unverified box
  8. F8 [D1 title page] The manual is titled "PCI/PCI-X Family of Gigabit Ethernet Controllers Software Developer's Manual", covering the 82540EP/EM, 82541xx, 82544GC/EI, 82545GM/EM, 82546GB/EB and 82547xx controllers, Revision 4.0; this confirms that QEMU's e1000 (82540EM) is covered by it. Used in: sources D1 entry only (register names could not be read)

D. Not found / not opened

  1. N1 Confirmed from QEMU v8.2.2 hw/net/e1000_regs.h (D7): the ten ring registers RDBAL…RDT and TDBAL…TDT. Still not checked: RAL0/RAH0 (0x5400/0x5404) and the address-valid bit, ICR (0xc0) and its bits, the transmit descriptor command bits (0xb), the 82574L receive descriptor format — the Intel manuals were not readable past the introduction and QEMU's hw/net/e1000x_regs.h was refused by the budget; the unverified box names both.
  2. N2 The VIRTIO specification (D3): split virtqueue layout (descriptor table, available ring, used ring), 16-bit free-running indices and the notification mechanism stay in the second unverified box; only the device's existence and BARs (R2) were observed.
  3. N3 Linux names dma_alloc_coherent, dma_map_single, wmb()/dma_wmb(), rmb()/dma_rmb(), the NAPI API and the e1000e driver's barrier-before-tail rule (D5): not opened; third unverified box kept.
  4. N4 LDD3 (D4): not opened; the sentences it tags (DMA ownership, network driver structure) are general and also carried by R1/R3.

F. Hardware facts

No physical NIC was used; e1000, e1000e and virtio-net are QEMU 8.2.2 emulations (R2, R3). Step 6 of the lab (ethtool -S on a physical NIC) is marked untested and names what is needed. The glossary term was renamed "Descriptor (NIC ring)" because HW204 defines "Descriptor" with the USB meaning (ruling A7); "Descriptor ring" duplicates HW204 F1-44, whose wording is canonical.
