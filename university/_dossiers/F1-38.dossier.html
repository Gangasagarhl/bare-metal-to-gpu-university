C. Facts (keyed to the chapter's claim tags)

  1. F1 [D11 §13.3.3] Pages (virtual) and frames (physical) have the same size, 4 KB as a common default; the MMU splits a virtual address into page number and offset; the offset carries over unchanged; the page number indexes the page table to find the frame number; one PTE per virtual page with frame number and valid bit. Used in: jargon (virtual memory, page), layer 1, l2-why, l2-split.
  2. F2 [D11 §13.3.4] When the valid bit is 0 the MMU traps to the OS (page fault); the OS finds a free frame, reads the page, updates the PTE and restarts the instruction; replacement with LRU and the dirty bit; the TLB is a small hardware cache of page-to-frame mappings, a hit avoids the page-table memory access; the PTBR is swapped on a context switch. Used in: jargon (TLB, page fault), layer 1, l2-why.
  3. F3 [D12 ch. 18] Per-process page table storing translations for each virtual page; VPN and offset split; PTE holds PFN plus valid, protection, present, dirty and reference bits; the page-table base register; physical address = PFN shifted, joined with the offset; page tables live in memory so each reference needs an extra memory access, which can slow a process by a factor of two or more without hardware support. Used in: jargon (page table), layer 1, l2-walk, Figure 1 caption.
  4. F4 [D8 THP] /sys/kernel/mm/transparent_hugepage/enabled: always, madvise (THP "only enabled inside MADV_HUGEPAGE regions"), never; PMD-sized pages (2M in the examples); AnonHugePages per mapping in /proc/PID/smaps; a region must be "hugepage naturally aligned"; khugepaged collapses base pages; memory compaction; "a 2M page might be allocated instead of a 4k page for no good". Used in: jargon (huge page), l2-reach, layer 3 (huge pages cost), Listing 3 table, mistakes table.
  5. F5 [D8 madvise(2) (man-pages 6.19, 2026-02-08)] MADV_HUGEPAGE enables THP for the range; MADV_NOHUGEPAGE prevents it; memory "may only be replaced by huge pages on hugepage-aligned boundaries"; available only with CONFIG_TRANSPARENT_HUGEPAGE. Used in: l2-reach, Listing 3 (lines 59–60).
  6. F6 [D8 proc_pid_smaps(5) (man-pages 6.19)] AnonHugePages appears in the smaps sample output; smaps_rollup is not described on that page. Used in: Listing 3 (lines 69–75).
  7. F7 [D7 (not opened) / D1 ch. 9 / D3 (titles only)] x86-64 4-level paging: 48 bits used, four 9-bit indices, 512 entries × 8 bytes per table, CR3, 2 MiB pages by a level-2 entry, PCIDs; multi-level TLBs, hardware page walker through the caches, VIPT L1 with S × B ≤ page size, TLB shootdown, minor versus major faults. Not confirmed from an opened source; now covered by the extended unverified box in Layer 3 (paging figures) and chapter-level citations. Used in: jargon (page table, walk, huge page, TLB reach), l2-split, l2-walk, layer 3, hardware, Figure 1.
  8. F8 [R3, R4, R5] first_touch: pass 1 201.2 ms with 65,539 minor faults, passes 2–3 about 37 ms with 0 faults (65,536 pages); tlb_reach: madvise returned 0, AnonHugePages 131072 kB, at 16384 blocks spread 91.11 ns, packed 11.22 ns, spread+huge 46.58 ns, step at 128 blocks in both spread columns; page size 4096, THP mode madvise. Used in: Listing 3 and 4 readings, lab expectations, forensic lab and key, summary.
