Fact list (keyed to the chapter's claim tags)

  1. F1 (jargon) a language such as Verilog or VHDL whose descriptions can be simulated and synthesised into hardware; most statements describe hardware that runs concurrently. — source: D6 “HDL: Hardware Description Language”, “HDL Simulation”, “HDL Synthesis”
  2. F2 (jargon) the Verilog unit of design: a port list, declarations and statements; modules are instantiated inside other modules to build a hierarchy. — source: D6 “SystemVerilog Modules”, “Module Declaration”
  3. F3 (jargon) a module's interface signal, declared input , output or inout with a width. — source: D6 “Module Declaration”
  4. F4 (jargon) a procedural block with an event control; always @(posedge clk) describes edge-triggered storage, always @(*) describes combinational logic. — source: D6 “always Statement”, “Combinational Logic using always”
  5. F5 (jargon) a procedural assignment that completes before the next statement executes; the right style for combinational always @(*) blocks. — source: D6 “Blocking vs. Nonblocking Assignment”
  6. F6 (jargon) a procedural assignment whose update is scheduled after all right-hand sides in the time step are evaluated; the right style for clocked always @(posedge clk) blocks, matching the behaviour of flip-flops. — source: D6 “Blocking vs. Nonblocking Assignment”, “Rules for Signal Assignment”
  7. F7 (jargon) a module constant, such as a width, that each instance can override. — source: D6 “Parameterized Module”
  8. F8 (jargon) … reports problems without simulating; Verilator's lint mode ( --lint-only , "Lint, but do not make output") reports, for example, width mismatches, unused signals and blocking assignments in clocked blocks, as runs R4 and R7 show. — source: D4; R4; R7
  9. F9 (jargon) a tool that maps a synthesisable HDL description to a netlist of cells of a target technology. — source: D6 “HDL Synthesis”; D5 synth
  10. F10 (jargon) the constructs a synthesis tool accepts; delays such as #5 , $display and most initial blocks are for simulation only. — source: D6 “Testbenches”
  11. F11 (layer2) "what part does this make?" Layer 2 — the student explanation The shape of a module Every Verilog file in this course has the same shape — source: D6 “Module Declaration”, “Parameterized Module”
  12. F12 (layer2) Despite its name, a reg does not always become a register — source: D6 “Combinational Logic using always”
  13. F13 (layer2) If yes, it is stored in flip-flops, one per bit, and changes only at the edge — source: D6 “D Flip-Flop”
  14. F14 (layer2) If it is assigned in always @(*) but some path leaves it unassigned, it becomes a latch, as F1-16 's forensic lab showed — source: D6 “Latch”, “Combinational Logic using case”
  15. F15 (layer2) All flip-flops sample at the same instant, so this is how real flip-flops behave, and the order of lines does not matter — source: D6 “Blocking vs. Nonblocking Assignment”
  16. F16 (layer2) Two rules cover this course — source: D6 “Rules for Signal Assignment”
  17. F17 (layer2) These belong to the simulation world only — source: D6 “Testbenches”
  18. F18 (layer3) Blocking assignments update at once, in the order the statements appear; non-blocking assignments take effect together, as if simultaneously, after the right-hand sides have been read — source: D6 “Blocking vs. Nonblocking Assignment”
  19. F19 (layer3) Yosys, for example, has equiv_make and related commands, which build an equivalence-checking model from two presumably equivalent modules — source: D5 equiv_make
  20. F20 (layer3) In Listing 1's report, $_SDFFE_PP0P_ is read as: a D flip-flop ( DFF ) with a synchronous reset ( S ) and an enable ( E ), positive clock edge, active-high reset, reset value 0, active-high enable — source: D5 cell help $_SDFFE_PP0P_
  21. F21 (layer3) "A positive edge D-type flip-flop with positive polarity synchronous reset and positive polarity clock enable (with reset having priority)" — source: D5 cell help $_SDFFE_PP0P_
  22. F22 (layer3) VHDL (IEEE standard 1076) is the other long-established HDL — source: D6 “HDL: Hardware Description Language”
  23. F23 (layer3) SystemVerilog extends Verilog: the Verilog standard IEEE 1364 was superseded by the SystemVerilog standard IEEE 1800 — source: D3
  24. F24 (hardware) The synthesis tool reads the text once and produces a netlist: a list of cells and the wires between them ( F1-11 introduced netlists) — source: D6 “HDL Synthesis”
  25. F25 (hardware) For an FPGA ( F1-22 ), later tools turn the netlist into a configuration that is downloaded onto the device — source: D7 “FPGA Design Flow”
  26. F26 (worked) Storage: pc is assigned only inside always @(posedge clk) (line 18), so its 8 bits (WIDTH = 8) are 8 flip-flops — source: D6 “D Flip-Flop”
  27. F27 (breaks) Testbench code is not synthesisable — source: D6 “Testbenches”
  28. F28 (transition) What carries over: the hardware ideas: flip-flops sample at edges, combinational logic sits between them, and every design has a self-checking test — source: D6 “Rules for Signal Assignment”
