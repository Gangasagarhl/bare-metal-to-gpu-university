C. Facts (keyed to the chapter's claim tags)

  1. F1 [D11 §11.3] Temporal locality: programs tend to access the same data repeatedly over time; spatial locality: accesses near recently accessed addresses; loop variables and the array base are reused; arrays are contiguous; the row-major mat[i][j] traversal is about five times faster than mat[j][i] in the book's example; fetching data also fetches its surroundings. Used in: jargon (temporal, spatial, stride, row-major), layer 1, l2-loc, l2-loops, Figure 1 and 2 captions.
  2. F2 [D11 §11.4.2] Compulsory (cold-start), capacity and conflict misses. Used in: jargon (compulsory, capacity), l2-threec.
  3. F3 [D11 §11.5] Cachegrind simulates the cache hierarchy; invoked as valgrind --tool=cachegrind --cache-sim=yes; reports Ir, I1mr, ILmr, Dr, D1mr, DLmr, Dw, D1mw, DLmw; the column-order example shows 1,062,996 D1 read misses against 62,688 for row order at N = 1000. Used in: layer 3 (simulated counts), forensic lab.
  4. F4 [D9 ch. 5] Cachegrind models independent I1 and D1 caches backed by a unified last-level cache; --cache-sim=yes enables it; --I1/--D1/--LL take size, associativity, line size; the configuration is otherwise detected with the x86 CPUID instruction; write misses bring the block into D1 (write-allocate); the LL "typically replicates" the L1 entries without strict inclusion; the simulation "is not a true representation", uses virtual addresses, ignores kernel and other processes, and does not model TLB misses or speculative execution. Used in: layer 3, mistakes table (Cachegrind warning), Sources.
  5. F5 [D8 perf_event_open(2)] glibc provides no wrapper (use syscall); PERF_TYPE_HARDWARE events include PERF_COUNT_HW_CPU_CYCLES, _CACHE_REFERENCES and _CACHE_MISSES ("usually" last-level); PERF_TYPE_SOFTWARE events include PERF_COUNT_SW_PAGE_FAULTS; read with read(2); PERF_EVENT_IOC_ENABLE/DISABLE/RESET. The ENOENT entry of ERRORS was not in the text windows read. Used in: layer 3, forensic evidence (4), Sources.
  6. F6 [D1 Cache Lab (labs page, cachelab.pdf)] CS:APP3e labs page lists Cache Lab (cachelab.tar, cachelab.pdf, README-cachelab, cachelab-release.html, cachelab-handout.tar; "Updated 5/2/16"); the writeup "15-213/18-213, Fall 2012: Cache Lab: Understanding Cache Memories": Part A csim.c for arbitrary s, E, b, ignoring instruction accesses; usage ./csim-ref [-hv] -s <s> -E <E> -b <b> -t <tracefile>; trace lines "operation address,size" with I, L, S, M; csim-ref uses LRU; test-csim, test-trans, driver.py; Part B transpose on s = 5, E = 1, b = 5 for 32×32, 64×64, 61×67; must run on 64-bit x86-64; uses Valgrind for traces. Used in: lab (Cache Lab paragraph), Sources.
  7. F7 [D6 23.3.13.1] std::vector is "a contiguous container" (element type other than bool). Used in: jargon (row-major), l2-loops.
  8. F8 [D1 ch. 6 / D2 ch. 5 / D3 ch. 2, App. B (titles only)] Memory mountain, stride-k reference pattern, blocking, loop interchange, hardware prefetchers: cited at chapter level; chapter text not openable. The locality, miss-classification and row-major claims are confirmed by D11. Used in: jargon (memory mountain), l2-stride, l2-mountain, layer 3 (blocking), hardware, breaks.
  9. F9 [R2, R5] traversal n = 4096: rows 24.8 ms, cols 217.2 ms (ratio 8.8). Cachegrind n = 2048: D refs 4,714,810 rd; rows D1 read misses 536,800 (11.4 %); cols 4,206,815 (89.2 %); writes 4,364,369 with 526,502 D1 write misses in both; LLd read misses cols 4,202,308 → 7,606 with a 256 MiB LL.
