C. Facts (keyed to the chapter's claim tags)

  1. F1 [D5 [intro.abstract] ¶8] Accesses through volatile glvalues are evaluated strictly according to the rules of the abstract machine; the paragraph lists them among the observable behaviours an implementation must preserve. Confirmed. Used in: jargon (volatile), layer3 (compiler and volatile), transition.
  2. F2 [D5] Forward progress ([intro.progress]): NOT checked (page not opened). The chapter's sentence that a compiler may assume a loop without observable behaviour terminates is supported only by the compiler's observed behaviour (R2). Noted in Sources. Used in: layer3.
  3. F3 [D6 Extended Asm, Machine Constraints] asm volatile prevents the asm from being removed or moved out of loops ("Volatile" subsection). x86 constraints: "a" is the a register, "d" the d register, "N" an unsigned 8-bit constant for in/out. So "Nd" means an 8-bit immediate or the dx register, as the chapter's Listing 3 note says. Confirmed. Used in: layer2 (Listing 3), listing notes.
  4. F4 [D4] Landing page: the manual set is at version 093; Volume 1 covers the basic architecture (including the I/O instructions), Volume 3A system programming (memory types, cache control). The chapters themselves were not opened; the I/O-privilege refusal is shown by R4 instead. Memory-type claims stay in the unverified box. Used in: jargon (port I/O), layer3, transition.
  5. F5 [D7] Not opened. Register offsets come from L1 (opened). Used in: jargon (side effect), layer3.
  6. F6 [L1] serial_reg.h defines UART_RX/TX at 0, IER at 1, LSR at 5, LSR_DR 0x01, LSR_OE 0x02 (opened). Used in: layer3, worked example 2.
